# 작업별 절차

<a id="select"></a>
## 종류 선택과 조합

요청에 필요한 구역을 선택하고, 여러 종류가 겹치면 함께 적용한다. 공통적인 요청 확인·권한·기록·검증·종료는 [공용 절차](<공용 절차.md#entry>)를 따르며, 아래에는 작업별 추가 행동을 둔다. 종류를 나눈다는 이유만으로 Task·Issue·담당자·파일을 추가하지 않는다.

<a id="planning"></a>
## 설계와 계획

- 제품 요구나 실행 계획을 다루면 [역할·우선관계](<../docs/문서 관리 기준.md#product-and-plan>)에 따라 제품이 충족할 요구와 단계별 실현 범위를 구별한다. Phase의 범위·수용 조건을 관련 제품 요구와 대조하고, 단계별 결과·의존 관계·남은 범위를 정한다. 알려진 요구로 계획하되 필요한 상세와 미정은 구체화할 작업에 연결한다.
- 목표와 조건·제약에 맞춰 작업 순서·의존 관계와 필요한 확인을 정리한다.
- 새 선택이 필요한 경우 기존 결정과 구별하고, 대안의 작동 방식·책임·장단점·영향을 비교한다.
- 검토 가능한 안과 남은 선택을 제시하고, 합의한 내용·제안·미정을 구별한다. 계획 작성 완료와 실제 채택·실행 결과를 구별한다.

<a id="change"></a>
## 일반 작업과 변경

일반 작업은 [공용 절차의 수행과 확인](<공용 절차.md#verification>)을 따른다. 문서나 작업 기록을 변경하면 아래 문서 작성과 갱신 구역을 함께 적용한다. 기록 단위의 생성·등록이 필요한 경우 [생성과 등록 절차](<문서 관리.md#create>)를 따른다.

<a id="review"></a>
## 리뷰

- 제품 요구·계획을 검토하면 [역할·우선관계](<../docs/문서 관리 기준.md#product-and-plan>)에 비춰 단계 배치를 제품 요구로 반복 관리하는지, 계획 변경으로 제품 요구를 암묵적으로 변경하거나 일부 구현·Phase 완료를 전체 요구 충족으로 확대했는지 확인한다.
- 현재 대상을 요구·수용 조건·관련 원자료와 대조해 오류·누락·모순과 영향을 찾는다.
- 지적에는 위치·근거·영향과 수정 방향을 제시한다.
- 검토 범위와 확인하지 못한 핵심 원자료를 밝히고, 리뷰 수행 완료와 대상의 통과 여부를 구별한다.
- 수정 후 재검수에서는 지적의 조치 여부와 영향을 받는 연결을 실제 수정본에서 확인한다.

<a id="document"></a>
## 문서 작성과 갱신

- [문서 기준](<../docs/문서 관리 기준.md#current>)에 따라 담당 원천을 확인하고 현행 결론·제안·합의·과거 사건을 구별한다.
- 제품 요구·계획을 작성하거나 갱신하면 [역할·우선관계](<../docs/문서 관리 기준.md#product-and-plan>)에 따라 내용을 담당 문서에 둔다. 새 제품 선택은 제안·합의를 구별하고, 합의한 요구 변경은 담당 제품 문서와 영향을 받는 계획에 반영한다.
- 참조·정정·영향은 [참조와 변경 기준](<../docs/문서 참조와 변경 기준.md#current>)으로 판단하고, 실제 조작에 필요한 [관리 절차](<문서 관리.md#entry>)를 적용한다.
- 본문의 의미와 적용 조건을 대조하고 관련 참조를 확인한다. 링크 검사만으로 내용의 정합성을 판정하지 않는다.

<a id="bug"></a>
## 버그와 오류 대응

- 기대한 결과와 실제 결과의 차이, 대상·입력·발생 조건과 관찰 근거를 확인한다.
- 재현 가능 여부를 확인하고, 확인된 원인과 가설·미확인을 구별한다.
- 수정이 허용된 경우 [실패 대응 절차](<공용 절차.md#failure>)에 따라 수정하고 원래 오류와 관련 영향을 재확인한다.
- 별도 선행 작업으로 전환해야 하면 [작업 전환 절차](<문서 관리.md#transition>)를 따른다. 오류가 발생했다는 이유만으로 새 Bug Issue를 만들지 않는다.
