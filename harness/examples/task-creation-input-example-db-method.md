<a id="purpose"></a>

## 목적

개발용 DB를 어떤 방법으로 생성할지 사용자와 논의해 방법 선택의 불확실성을 줄인다.

<a id="result"></a>

## 기대 결과

후보 비교 자료와 사용자가 최종 선정한 방법·이유·후속 실행 조건을 남긴다. 실제 DB 생성 결과는 맡지 않는다.

<a id="scope"></a>

## 이미 정해진 조건

- 조건: DB 생성 방법의 조사·비교·사용자 논의·선정 내용 정리까지 맡긴다. 현재 허용은 계획·자료 검토·논의이며 DB 생성·DDL 시험 실행·기존 DB 변경·커밋은 허용하지 않는다.
  - 적용 범위: 전체 배정과 현재 행동의 허용 범위
  - 확정 근거: 가상 부모의 논의 과제 배정
- 조건: 기존 데이터를 보존하며 반복 재현성·되돌릴 수 있는지·기존 개발 흐름과의 일치로 후보를 비교한다.
  - 적용 범위: 후보 비교와 방법 선정
  - 확정 근거: 가상 부모가 전달한 기존 제약·판정 기준
- 조건: 대상 환경 설명·기존 제약·판정 기준은 부모가 제공했다고 가정한다. 시험 실행 환경·권한은 미확보이며 필요해지면 해당 실행 전에 확인한다. 자료 검토·명령 초안 작성 허용을 시험 실행 허용으로 확대하지 않는다.
  - 적용 범위: 선행 입력과 시험 실행의 제한
  - 확정 근거: 가상 부모의 입력 제공·실행 제한

<a id="decisions"></a>

## Task에서 결정할 사항

- 결정할 사항: 어떤 DB 생성 방법을 채택할 것인가. 현재 미정이다.
  - 결정 범위: 위 대상 환경·기존 제약 안에서 사용할 방법의 선정
  - 판단 기준: 반복 재현성·복구 가능성·기존 개발 흐름과의 일치
  - 결정 주체: 후보 비교 후 사용자가 최종 선정한다. AI는 조사 순서와 비교 자료 구성을 판단하도록 위임받았다고 가정한다. 근거는 가상 부모의 배정이며 실제 DB 실행 권한을 뜻하지 않는다.

<a id="acceptance"></a>

## 완료 조건과 확인 방법

- 완료 조건: 후보 비교 자료가 부모의 세 판정 기준을 다룬다.
  - 확인 방법: 후보별 비교 내용·근거를 판정 기준과 대조한다.
- 완료 조건: 사용자가 선정한 방법·이유·남은 실행 조건이 기록된다.
  - 확인 방법: 사용자 논의 근거와 선정 기록을 대조한다. 미선정 방법이나 미발생 완료 결과를 미리 채우지 않는다.
