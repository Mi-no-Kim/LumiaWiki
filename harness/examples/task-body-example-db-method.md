## 논의 후 본문을 갱신하는 예시

위 생성 직후 본문에서 전체 계획 합의·공통 준비를 마치고 후보 비교 결과를 논의하는 시점으로 진행했다고 가정한다. 아래는 [계획 갱신 흐름](<../Task 공통 절차.md#plan-update>)을 설명하는 변경 부분만의 발췌다. 실제 승인·수행 근거가 아니며 실제 Task에 전후 내용을 누적하는 형식도 아니다.

<a id="additional-comparison-response"></a>

가정한 사용자 응답: “후보별 복구 경로와 필요한 권한을 자료로 더 비교해 줘. 방법은 그다음에 고를게.”

기존 복구 가능성 기준 안의 추가 비교이므로 같은 할 일에 보완 조사와 재논의를 묶는다. Task 태그는 이미 `조사, 논의, 결정, 검수`를 포함하므로 그대로다. 해당 할 일에 `조사`를 추가하며 DB 실행·커밋은 계속 허용하지 않는다.

| 위치 | 갱신 전 → 갱신 후 |
|---|---|
| 현재 합의 | 전체 계획 합의·자료 논의 → 기존 합의를 유지하고 추가 비교 요청·방법 선정 보류와 그 근거를 반영 |
| 남은 결정 | DB 생성 방법 미정 → 보완 비교 후 사용자가 선정. 추가 조사 요청을 선택 완료로 바꾸지 않음 |
| 같은 할 일 | `work-discuss`의 후보 비교 결과 논의 / `논의` → 복구 조건 보완 비교와 후보 재논의 / `조사, 논의`. 기존 식별자·수행 근거 연결 유지 |
| 현재 요약 | 비교 결과 논의 → 허용된 자료로 복구 조건을 보완 비교한 뒤 재논의. 이 독립 준비가 가능하므로 진행 중 유지 |

현재 본문에는 영향을 받은 항목을 다음처럼 교체한다. 공통 준비·전달본 참조·나머지 할 일은 유효한 내용을 유지한다.

```markdown
- 다음 행동: 기존 자료에서 후보별 복구 경로·필요 권한을 보완 비교하고 사용자와 다시 논의한다.
- 막힌 조건: DB 방법은 미정이며 보완 비교 후 사용자가 선정한다. DB 생성·DDL·기존 DB 변경·커밋은 허용되지 않았다.

- 현재 합의: 전체 계획과 자료 검토·사용자 논의의 허용을 유지한다. [사용자의 추가 비교 요청](#additional-comparison-response)에 따라 복구 경로·필요 권한을 자료로 보완 비교한다. 방법 선정은 보류했고 실제 DB 실행·커밋은 허용하지 않는다.
- 남은 결정: 보완 비교 후 사용자가 DB 생성 방법을 선정한다. 판단 기준과 결정 주체는 [배정](<task-creation-input-example-db-method.md#decisions>)을 유지한다.

<a id="work-discuss"></a>

#### 복구 조건 보완 비교와 후보 재논의

- 태그: 조사, 논의
- [ ] 수행·확인 완료
- 할 일: 기존 복구 가능성 기준 안에서 후보별 복구 경로·필요 권한의 근거와 미확인을 보완하고 사용자에게 비교 결과를 제시해 논의한다. DB 명령은 실행하지 않는다.
- 확인: 추가 질문에 대한 자료 근거·미확인과 실제 재논의 응답을 확인한다. 자료 제시나 무응답만으로 완료하지 않으며 방법 선정은 별도 결정으로 남긴다.
- 수행 기록: <기존 work-discuss 구역의 실제 링크를 유지. 보완 과정·당시 태그·변경 이유는 같은 구역에서 갱신>
```

이후 사용자가 후보 A를 명시적으로 선정하면 `현재 합의`에 선택·이유·실제 응답 근거를 반영하고 해결된 `남은 결정`을 정리한다. 단순히 “자료는 괜찮다”는 응답이면 선정은 미정으로 유지한다. 결정 할 일은 필요한 기록·확인을 갖춘 뒤 완료 표시하고, Task와 할 일의 `논의, 결정` 태그는 유지한다. 선정 결과 검수·종료 처리는 계속 남으며 방법 선정이 DB 실행 권한을 만들지 않는다.
