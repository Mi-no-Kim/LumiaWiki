# Task 생성 시 입력 양식

[Task 본문 생성 지시서](<../Task 생성 지시서.md>)

[입력 예시: Task 43-002](../examples/task-creation-input-example-43-002.md) · [입력 예시: DB 생성 방법 논의](../examples/task-creation-input-example-db-method.md)

각 구역에는 Issue에서 전달받은 내용을 적는다. 적용할 내용이 없음을 확인했으면 `없음`, 아직 결정하지 않았으면 `미정`, 확인하지 못했으면 `미확인`으로 표시한다. 전달되지 않은 내용을 임의로 확정하지 않는다.

<a id="assignment-body"></a>

- 태그: <조사·논의·결정·실행·검수·커밋 중 이 Task의 전체 활동에 필요한 여러 개>

태그는 쉼표로 구분한다. 생성 시 전달할 활동 요약이며 권한·위임을 부여하지 않는다. 판별하지 못한 태그는 미정·미확인으로 남기고 필요한 확인을 적는다. 행동 규칙은 [태그 기준](<../Task 공통 절차.md#tag-rules>)을 따른다.

<a id="purpose"></a>

## 목적

어떤 대상의 어떤 문제를 왜 해결하려는지 적는다.

<이 Task가 다루는 대상·해결하려는 문제·해결이 필요한 이유>

<a id="result"></a>

## 기대 결과

Task가 끝난 뒤 달성할 상태나 남길 산출물을 적는다. 조사·설계·논의 과제라면 어떤 판단 자료나 결론까지 맡기는지 드러나게 쓴다.

<Task가 끝난 뒤 달성할 상태나 남길 산출물>

<a id="scope"></a>

## 이미 정해진 조건

Issue에서 확정되어 이 Task가 따라야 하는 조건을 한 항목에 하나씩 적는다. 수행 범위·권한·기존 결정·선행 입력 등 이번 Task에 실제로 필요한 조건만 작성한다.

- 조건: <반드시 지켜야 할 구체적인 내용>
  - 적용 범위: <이 조건이 적용되는 대상이나 행동>
  - 확정 근거: <Issue의 결정 기록 또는 채택한 원천>

<a id="decisions"></a>

## Task에서 결정할 사항

생성 후 이 Task에서 답을 정할 질문을 적는다. 이미 결정된 조건과 구별하며, Task를 생성하면서 답을 대신 정하지 않는다.

- 결정할 사항: <이 Task에서 답을 정할 질문>
  - 결정 범위: <답을 정할 대상과 경계>
  - 판단 기준: <충족하거나 비교해야 할 기준>
  - 결정 주체: <사용자와 결정할 사항인지, AI에 위임된 사항인지와 그 근거>

<a id="acceptance"></a>

## 완료 조건과 확인 방법

기대 결과를 어떤 기준으로 수용할지 적는다. 구체적인 명령·도구·수행 순서는 생성 후 Task 계획에서 정한다.

- 완료 조건: <결과가 충족해야 할 상태나 기준>
  - 확인 방법: <무엇을 관찰하거나 대조해 충족 여부를 판단할 것인가>
