# GitHub Phase 게시 양식

로컬 Phase를 milestone에 반영하는 양식이다. [단위·상태 대응](<../../docs/작업 기록 체계.md#github>)과 [반영 절차](<../문서 관리.md#github-update>)를 따른다. 로컬 원본의 현재 계획·조건·판단과 실제 결과를 옮겨, 설명만으로 Phase의 진행과 수용 근거를 검토할 수 있게 작성한다. 원본 파일이 아직 원격에 없으면 로컬 경로를 적고 존재하지 않는 문서 링크를 만들지 않는다.

## 등록 정보

| 항목        | 값                                                                                 |
| ----------- | ---------------------------------------------------------------------------------- |
| 대상 저장소 | 실제 등록할 저장소                                                                 |
| 로컬 원본   | 담당 `phase.md`                                                                    |
| 등록 대상   | milestone                                                                          |
| 상태        | [로컬 상태 대응](<../../docs/작업 기록 체계.md#github-state>)에 따른 Open / Closed |
| 기한        | 합의된 기한이 있을 때만 설정                                                       |

## 제목

```text
Phase <로컬 순번> — <Phase 제목>
```

## 설명

```markdown
## 현재 요약
- 상태: <로컬 상태>
- 현재 진행 위치: <Phase에서 준비·수행·확인 중인 내용>
- 다음 판단·행동: <다음에 결정하거나 수행할 일>
- 막힌 조건·근거: <진행을 막는 구체 조건과 근거. 해당 시>

## 목표와 범위
- 공동 목표·기대 결과: <이번 Phase에서 실현할 결과>
- 포함 범위: <이번 단계에서 수행할 범위>
- 제외 범위·현재 제약: <후속 단계와의 경계 및 적용 제약>
- 기준 원천: <관련 제품 요구·기준과 이번 단계에 적용할 내용>

## 수용 조건
- <충족해야 할 Phase 수용 조건>

## 계획과 의존
- 준비·수행 순서: <단계별 결과와 실현 순서>
- 의존·착수 조건: <선행 자료·작업 및 시작에 필요한 조건>
- 예정 확인: <확인할 대상·기대 결과·방법>

## 조건부 사항과 미정
- 조건부 사항: <적용 조건·기준 원천·확인 대상과 시점·현재 판단>
- 미정·제안·후속: <항목별 구분·결정 시점·관련 원천>

## 주요 결정
- <논의한 문제·결정·이유·적용 조건과 근거>

## 수용 판단과 검증 근거
- <수용 조건별 실제 판정과 그 이유·근거>
- <수행한 확인의 대상·입력·기준·방법과 실제 관찰>
- <미확인 사항·확인 범위와 한계>

## 결과와 미해결
- 종료 구분·실제 결과: <완료·취소·미완료 인계 판단과 수용 대비 결과>
- 미반영·미확인·남은 일: <실현하지 못한 범위와 그 영향>
- 다음 행동·재개 조건: <후속 처리와 필요한 조건>
- 취소 이유·부분 효과: <취소 시 이유와 실제 남은 결과·처리>

## 원본과 관련
- 원본: <로컬 Phase 기록의 경로와 접근 가능한 링크>
- 관련 작업: <관련 Phase·Issue와 관계·의존 이유. 보유와 구별>
```

[작성 시점](<../../docs/작업 기록 작성 기준.md#minimum>)에 맞춰 알려진 계획과 미정을 구별한다. 주요 결정·검증 결과·종료 구역은 실제 사건이 생겼을 때 포함하고, 수행하지 못한 필수 확인이나 진행을 막는 미해결은 현재 요약에 남긴다. 조건부 항목이 없으면 해당 줄·구역을 생략한다.

소속 Issue는 실제 milestone 연결로 관리하고 수동 상태 체크리스트를 복사하지 않는다. 로컬 Phase 순번과 GitHub milestone 번호는 별개다. 중요한 계획·판단·검증 결과는 설명에 직접 적고 원본 링크로 세부 근거를 연결한다.
