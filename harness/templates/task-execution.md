# Task 수행 기록 생성 양식

첫 할 일 착수 때 수행 기록 파일을 한 번 만드는 생성용 양식이다. Task 본문 생성 시에는 사용하지 않는다.

[최초 생성 절차](<../Task 공통 절차.md#execution-creation>) · [생성 후 수행 기록 예시](<../examples/task-execution-example.md>)

<a id="execution-body"></a>

## 최초 생성

담당 Issue의 `artifacts/task-<실제 순번>-execution.md`에 아래 코드 블록만 복사한다. 바깥 설명·예시는 복사하지 않는다. Task 식별자·본문 링크와 현재 착수한 할 일의 식별자·역방향 링크를 실제 입력에 맞추고 상대링크를 보정한다. 미착수 할 일의 구역·미발생 결과는 만들지 않는다.

생성 후에는 파일 머리말의 규칙과 기록 기준을 따른다. 후속 할 일은 실제 기록의 작업 표식부터 세 항목 끝까지 구조만 주석 없이 추가하고 이전 실제 값은 복사하지 않는다. 머리말·규칙 주석은 반복하지 않으며 이 양식을 다시 찾지 않는다.

```markdown
# Task <부모 Issue 번호>-<실제 순번> 수행 기록

- Task: <실제 Task 본문 링크>
- 기록 기준: [Task 공통 절차](<../Task 공통 절차.md#recording-proposal>)

<!-- execution-rule:recording

할 일의 태그·배정 조건에 따라 실제 조치·선택과 이유·근거를 남긴다. 파일 수정 없는 논의도 기록하고 제안·미결·합의·철회를 구별한다.
논의·사용자 결정은 실제 응답으로, AI 결정은 명시 위임·실제 선택으로 확인한다. 필수 논의를 생략하지 않는다.
확인은 계획·전달본을 참조하고 실제 대상·방법·관찰·판정·근거·한계를 남긴다. 변경본은 검증한 버전·범위를 식별하고 달라진 영향만 다시 확인한다.

보완·재시도는 같은 구역을 갱신한다. 식별자는 순서와 구별하고 삭제·분할·병합에도 수행·판단/실패 근거·당시 기준·본문 연결을 보존한다.
코드·diff·테스트 원문·명령별 로그를 복사·누적하지 않는다. 미발생 승인·결과나 단순 확인용 증명 파일을 만들지 않는다.
세부 작성 조건은 위 기록 기준을 따르고 생성 양식으로 돌아가지 않는다.

## <착수한 할 일 이름>

- 할 일: <Task 본문의 해당 할 일 링크>

- 조치·판단: <실제 수행과 필요한 판단·이유. 결정이 있으면 적용 범위·주체·근거와 제안/미결/합의/철회 구별>
- 확인: <수행·검증 결과 또는 필요한 논의·결정이 배정/위임 조건을 충족했는지에 대한 판정·근거·한계>
- 잔여: <이 할 일의 미해결 문제·제한·재개 조건과 다음 행동. 없음을 확인했으면 없음>
```
