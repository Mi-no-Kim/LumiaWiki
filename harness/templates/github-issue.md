# GitHub Issue 게시 양식

과제 전체의 필요성·범위·기대 결과와 완료 기준을 공유한다. [GitHub 역할과 대응](<../../docs/작업 기록 체계.md#github>) 및 [공통 작성 규칙](<../문서 관리.md#github-projection>)을 따른다.

## 등록 정보

| 항목 | 작성·설정 기준 |
|---|---|
| 게시 원천 | 검증한 로컬 Issue 본문. 번호 발급 전에는 전체 본문 초안 사용 |
| milestone | 소속 Phase의 실제 milestone. 독립 Issue는 설정하지 않음 |
| 라벨·상태 | `unit:issue`와 [실제 상태에 대응하는 설정](<../../docs/작업 기록 체계.md#github-state>) |

## 제목

```text
<해결할 문제 또는 달성할 결과가 드러나는 제목>
```

## 게시 본문

```markdown
## 배경과 목적
<어떤 문제가 있으며, 이 과제가 왜 필요한지>

## 범위와 조건
- 포함 범위: <이번 과제에서 다룰 대상>
- 제외 범위: <명시적으로 확인된 제외 사항>
- 확정 조건·제약: <지켜야 할 요구와 중요한 선행 조건>

## 기대 결과와 완료 기준
<과제 전체가 달성할 상태 또는 남길 산출물>

- [ ] <전체 결과를 수용할 수 있는 조건과 확인 방법>

<미정인 기준이 있다면 그 대상과 결정할 질문·필요 시점>

## 결정할 사항
<이 과제에서 답을 정해야 할 초기 질문을 원문·순서대로 작성>
<질문별 결정 범위와 판단 기준을 함께 작성>

## 참고 자료
- <자료 링크> — <작업을 이해하는 데 필요한 이유>
```

## Issue 작성 시 확인

- 세부 범위·전체 수용 조건은 미정일 수 있다. 확인된 조건만 완료 기준으로 쓰고, 아직 정하지 않은 기준은 결정할 질문·필요 시점과 함께 남긴다. 내부 논의를 시작하기 위한 준비 체크를 전체 완료 기준으로 옮기지 않는다.
- 초기 질문 없음이 확인되면 결정할 사항 구역을 생략한다. 목록 미확인은 가짜 질문 대신 확인 대상·시점을 남긴다.
