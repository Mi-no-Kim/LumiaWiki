# GitHub Issue 게시 양식

로컬 Issue를 GitHub issue에 반영하는 양식이다. [단위·상태 대응](<../../docs/작업 기록 체계.md#github>)과 [신규 등록](<../문서 관리.md#create>)·[갱신](<../문서 관리.md#github-update>) 절차를 따른다. 로컬 원본의 현재 계획·조건·판단과 실제 결과를 옮겨, 본문만으로 Issue의 진행과 수용 근거를 검토할 수 있게 작성한다. 원본 파일이 아직 원격에 없으면 로컬 경로를 적고 존재하지 않는 문서 링크를 만들지 않는다.

## 등록 정보

| 항목 | 값 |
|---|---|
| 대상 저장소 | 실제 등록할 저장소 |
| 원본 | 담당 `issue.md` 또는 [번호 발급 전 등록용 초안](<../문서 관리.md#create>) |
| milestone | 소속 Phase의 실제 milestone. 독립 Issue는 설정하지 않음 |
| 라벨 | `unit:issue`와 자신의 로컬 상태에 대응하는 [상태 라벨](<../../docs/GitHub 라벨 기준.md#labels>) |
| 담당자 | 실제로 지정된 경우에만 설정 |
| 상태·종료 사유 | [로컬 상태 대응](<../../docs/작업 기록 체계.md#github-state>) 적용 |

## 제목

```text
<로컬 Issue 제목>
```

## 본문

```markdown
## 현재 요약
- 상태: <예정·진행 중·중단·완료·취소 중 실제 상태>
- 현재 진행 위치: <실제 작업·근거 위치>
- 다음 행동·막힌 조건: <현재 허용된 행동·제한과 해소 조건>

## 목적과 기대 결과
<목적·기대 결과·확정 조건과 생성 근거. Phase 연결은 소속이 있을 때만 포함>

## 진행 순서
1. 입력·준비 확인: <실제 확인·준비와 남은 조건>
2. 논의·결정: <유효한 결정·이유·근거와 Task 배정>
3. Task 생성: <실제 생성·참조와 남은 실행 제한>
4. 최종 검사: <Issue 전체 수용 조건별 실제 판정·근거·한계>

## 결정과 결과
<현재 유효한 결정·이유·권한·조건과 실제 결과. 검토·종료가 발생한 범위만 포함>
- 반영·미반영·잔여·재개 조건: <실제 결과와 다음 행동>

## 원본과 관련
- 원본: <담당 로컬 기록의 경로·실제 접근 가능한 링크>
- 관련 과제: <관계·이유. 실제 Task는 sub-issue 관계로 연결>
```

[작성 시점](<../../docs/작업 기록 작성 기준.md#minimum>)에 맞춰 알려진 계획과 미정을 구별한다. 주요 결정·검증 결과·종료 구역은 실제 사건이 생겼을 때 포함하고, 수행하지 못한 필수 확인이나 진행을 막는 미해결은 현재 요약에 남긴다. 조건부 항목이 없으면 해당 줄·구역을 생략한다.

보유 Task는 실제 sub-issue 관계로 연결한다. 본문에는 Task 분해 이유·통합 계획과 실제 결과를 적고, Task별 상세 실행·상태 목록을 복제하지 않는다. 현재 계획·판단·검증 결론은 본문을 갱신하고 세부 근거는 원본의 artifacts로 연결한다. [기록 경계](<../../docs/작업 기록 작성 기준.md#recording-boundary>)에 따라 실행 경과와 기록 날짜를 누적하지 않는다.
