# GitHub Task 게시 양식

로컬 Task를 부모 Issue 아래의 sub-issue에 반영하는 양식이다. [단위·상태 대응](<../../docs/작업 기록 체계.md#github>)과 [반영 절차](<../문서 관리.md#github-update>)를 따른다. 로컬 원본의 실제 대상·계획·판단과 수행·검증 결과를 옮겨, 본문만으로 Task의 수행과 완료 근거를 검토할 수 있게 작성한다. 원본 파일이 아직 원격에 없으면 로컬 경로를 적고 존재하지 않는 문서 링크를 만들지 않는다.

## 등록 정보

| 항목 | 값 |
|---|---|
| 대상 저장소 | 실제 등록할 저장소 |
| 로컬 원본 | 담당 `task-<순번>.md` |
| 부모 Issue | 실제 GitHub Issue를 sub-issue 부모로 연결. 본문 링크로 대신하지 않음 |
| milestone | 부모 Issue가 속한 Phase의 실제 milestone. 독립 Issue 아래라면 설정하지 않음 |
| 라벨 | `unit:task`와 자신의 로컬 상태에 대응하는 [상태 라벨](<../../docs/GitHub 라벨 기준.md#labels>) |
| 담당자 | 실제로 지정된 경우에만 설정 |
| 상태·종료 사유 | [로컬 상태 대응](<../../docs/작업 기록 체계.md#github-state>) 적용 |

## 제목

```text
Task <부모 Issue 번호>-<로컬 Task 순번> — <Task 제목>
```

## 본문

```markdown
## 현재 요약
- 상태: <로컬 상태>
- 현재 진행 위치: <완료한 부분과 수행·확인 중인 내용>
- 다음 행동·막힌 조건: <다음에 할 일과 진행을 막는 조건·근거>

## 목표와 범위
- 목적·기대 결과: <이번 Task가 만들어야 할 결과>
- 실제 대상·입력: <변경·확인할 대상과 사용할 자료·환경>
- 허용 범위·제약: <작업 범위와 적용할 제약>
- 기준 원천: <관련 요구·기준과 적용 내용>

## 완료 조건
- <충족해야 할 Task 자체의 완료 조건>

## 수행 계획과 예정 검증
- 준비·선행 조건: <필요한 준비·의존 작업과 미정>
- 수행 계획: <주요 작업과 순서>
- 예정 검증: <확인할 결과·방법과 필요한 별도 검수>
- 조건부 사항: <적용 조건·기준 원천·확인 대상과 시점·현재 판단. 해당 시>

## 수행과 주요 판단
- <실제 수행한 변경과 확인한 사실>
- <확인 가능한 날짜·중요한 결정·이유·적용 조건과 근거>
- <발견한 실패·관찰과 실제 수정 범위. 해당 시>

## 검증과 근거
- 대상·입력·기준·방법: <실제로 확인한 대상·입력·환경과 확인 기준·방법>
- 기대·관찰·판정: <기대 결과와 실제 관찰·판정 및 그 이유>
- 미확인·한계: <수행하지 못한 확인과 결과의 적용 범위·한계>
- 근거: <출력·첨부·관련 검증 기록>

## 중단과 재개
- 멈춘 상태·이유: <실제 수행한 부분과 중단·전환 이유>
- 전환·선행 대상: <관련 작업과 관계. 해당 시>
- 복귀·재개 조건: <다시 시작할 조건과 다음 행동>

## 결과와 잔여
- 종료 구분·실제 결과: <완료·취소·미완료 인계 판단과 요구 대비 결과>
- 반영·미반영·미확인: <실제 반영 범위와 한계·남은 일>
- 후속·인계: <다음 허용 행동과 재개 조건, 필요한 자료·보존·정리 결과>
- 취소 이유·부분 효과: <취소 시 이유와 실제 남은 결과·처리>

## 원본과 관련
- 원본: <담당 로컬 Task 기록의 경로와 접근 가능한 링크>
- 관련 과제: <의존 과제와 그 관계·이유>
```

[작성 시점](<../../docs/작업 기록 작성 기준.md#minimum>)에 맞춰 알려진 계획과 미정을 구별한다. 수행·판단·실제 검증·중단·종료 구역은 실제 사건이 생겼을 때 포함하고, 수행하지 못한 필수 확인이나 진행을 막는 미해결은 현재 요약에 남긴다. 조건부 항목이 없으면 해당 줄·구역을 생략한다.

Task의 GitHub 번호와 로컬 Task 순번은 구별한다. 중요한 수행 내용·판단·검증 결과는 본문에 직접 적고 원본 링크로 세부 근거를 연결한다.
