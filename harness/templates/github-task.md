# GitHub Task 게시 양식

로컬 Task를 부모 Issue 아래의 sub-issue에 반영하는 양식이다. [단위·상태 대응](<../../docs/작업 기록 체계.md#github>)과 [반영 절차](<../문서 관리.md#github-update>)를 따른다. 로컬 원본의 실제 대상·계획·판단과 수행·검증 결과를 옮겨, 본문만으로 Task의 수행과 완료 근거를 검토할 수 있게 작성한다. 원본 파일이 아직 원격에 없으면 로컬 경로를 적고 존재하지 않는 문서 링크를 만들지 않는다.

로컬 Task가 참조하는 배정 원본과 적용 근거를 함께 읽어 확정 조건을 반영한다. 게시물의 사본을 별도 배정 원본으로 갱신하거나 Task 완료만으로 부모의 수용을 표시하지 않는다.

## 등록 정보

| 항목 | 값 |
|---|---|
| 대상 저장소 | 실제 등록할 저장소 |
| 로컬 원본 | 담당 `task-<순번>.md` |
| 부모 Issue | 실제 GitHub Issue를 sub-issue 부모로 연결. 본문 링크로 대신하지 않음 |
| milestone | 부모 Issue가 속한 Phase의 실제 milestone. 독립 Issue 아래라면 설정하지 않음 |
| 라벨 | `unit:task`와 자신의 로컬 상태에 대응하는 [상태 라벨](<../../docs/GitHub 라벨 기준.md#labels>) |
| 담당자 | 실제로 지정된 경우에만 설정 |
| 상태·종료 사유 | [로컬 상태 대응](<../../docs/작업 기록 체계.md#github-state>) 적용 |

## 제목

```text
Task <부모 Issue 번호>-<로컬 Task 순번> — <Task 제목>
```

## 본문

```markdown
## 현재 요약
- 상태: <예정·진행 중·중단·완료·취소 중 실제 상태>
- 현재 진행 위치: <실제 작업·근거 위치>
- 다음 행동·막힌 조건: <현재 허용된 행동·제한과 해소 조건>

## 전달사항 참조
- 부모 Issue: <실제 부모>
- 적용 전달본·식별·확정 근거: <로컬 Task와 같은 원본·기준 기록>
- 담당 결과·범위·완료 조건: <게시물 검토에 필요한 적용 요지. 원본은 로컬 확정 전달본>

## 계획과 합의
- 현재 합의·남은 결정: <유효한 결정·이유·권한과 사용자 확인 조건>
- 전체 수행 계획: <행동 단위·태그·선행 조건·필수 확인과 수행 기록 연결>
- 화면·검증 계획: <제품 기능의 화면 선행과 화면/내부 확인. 해당 시>

## 결과
- 실제 결과·완료 조건별 확인: <관찰·판정·근거·한계>
- 반영·미반영·잔여: <현재 결과·해결되지 않은 조건>
- 종료·인계·재개 조건: <실제 종료/취소/인계와 필요한 보존·정리 결과>

## 원본과 관련
- 원본: <담당 로컬 Task 기록의 경로·실제 접근 가능한 링크>
- 수행 기록: <실제 수행 기록과 해당 할 일 구역>
- 관련 과제: <의존과 관계·이유>
```

[작성 시점](<../../docs/작업 기록 작성 기준.md#minimum>)에 맞춰 알려진 계획과 미정을 구별한다. 수행·판단·실제 검증·중단·종료 구역은 실제 사건이 생겼을 때 포함하고, 수행하지 못한 필수 확인이나 진행을 막는 미해결은 현재 요약에 남긴다. 조건부 항목이 없으면 해당 줄·구역을 생략한다.

Task의 GitHub 번호와 로컬 Task 순번은 구별한다. 현재 판단·검증 결론은 본문을 갱신하고 세부 근거는 원본의 artifacts로 연결한다. [기록 경계](<../../docs/작업 기록 작성 기준.md#recording-boundary>)에 따라 실행 경과와 기록 날짜를 누적하지 않는다.
