# GitHub Task 게시 양식

부모 Issue에서 맡은 구체적 작업·산출물과 완료 확인 방법을 공유한다. [GitHub 역할과 대응](<../../docs/작업 기록 체계.md#github>) 및 [공통 작성 규칙](<../문서 관리.md#github-projection>)을 따른다.

## 등록 정보

| 항목       | 작성·설정 기준                                                                         |
| ---------- | -------------------------------------------------------------------------------------- |
| 게시 원천  | 로컬 Task와 실제 적용 중인 확정 전달사항·배정 근거                                     |
| 부모 Issue | 실제 부모를 GitHub sub-issue 관계로 연결. 본문 링크로 대신하지 않음                    |
| milestone  | 부모 Issue의 소속 Phase milestone. 독립 Issue 아래라면 설정하지 않음                   |
| 라벨·상태  | `unit:task`와 [실제 상태에 대응하는 설정](<../../docs/작업 기록 체계.md#github-state>) |

## 제목

```text
Task <부모 Issue 번호>-<로컬 Task 순번> — <담당 작업 제목>
```

## 게시 본문

```markdown
## 담당 작업과 산출물
<부모 과제의 어떤 결과에 기여하는 작업인지>

- 담당 작업: <이번 Task가 수행할 구체적 작업>
- 기대 산출물: <제출할 결과와 요구되는 수준>

## 범위와 조건
- 담당 범위: <작업할 대상과 경계>
- 제외 범위: <명시적으로 확인된 제외 사항>
- 확정 조건·제약: <지켜야 할 요구와 필수 선행 입력>
- 실행 경계: <이번 배정에 명시된 실행 제한·사용자 확인 조건>

## 완료 기준과 확인 방법
| 완료 기준 | 확인 방법 |
|---|---|
| <결과가 충족해야 할 조건> | <무엇을 관찰하거나 대조할지> |

## 결정할 사항
- 질문: <이 Task에서 답을 정할 질문>
  - 결정 범위: <정할 대상과 경계>
  - 판단 기준: <충족하거나 비교해야 할 기준>
  - 결정 주체: <누가 결정하며, 위임된 범위가 있다면 그 범위>

## 참고 자료
- <자료 링크> — <수행·검증에 필요한 이유>
```

## Task 작성 시 확인

- Task 본문만으로 배정을 추정하지 않고 실제 확정 전달사항과 부모의 배정 근거를 함께 읽는다. 담당 결과·허용 범위·결과 수준의 완료 조건/확인 방법이 부족하면 보완을 반환한다. 상세 설계·도구·명령·수행 순서는 생성 후 정할 수 있다.
- 조사·비교·제안·선정·실제 실행 중 맡은 범위를 보존한다. 결정할 질문이 있으면 범위·판단 기준·결정 주체를 남기고 생성하면서 답을 대신 채우지 않는다. 게시물을 별도 배정 원본으로 관리하지 않는다.
