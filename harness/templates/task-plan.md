# Task 상세 계획 양식

<a id="body"></a>

Issue의 `artifacts/task-<순번>-plan.md`에 다음 본문을 작성한다. 첫 제안부터 같은 파일을 갱신한다. 단계 제목의 순번은 실행 순서이며 ID는 한번 정하면 유지한다. 실제 태그·완료 기준·확인 방법과 순서 있는 세부 작업을 채운다.

```markdown
# Task <부모 Issue 번호>-<로컬 순번> 상세 계획

<!-- task-plan-rule:recording
단계 순서·세부 작업·완료 체크는 이 파일에서 관리한다.
실제 결과·필수 확인·기록을 갖춘 단계만 완료 표시하고 실행 근거로 연결한다.
단계 ID는 실행 순서와 별개로 유지하며 주요 변경 이유는 현재 합의와 관련 근거에 남긴다.
-->

- Task: [Task <실제 식별자>](../task-<순번>.md#summary)
- 적용 전달본: [<실제 개정 식별>](task-<순번>-assignment.md)
- 계획 합의: 제안

<a id="stage-<식별자>"></a>

## 1. stage-<식별자> — <단계 이름>

- 태그: <단계 활동>
- [ ] 단계 완료
- 선행 입력: <실제 의존 입력 또는 없음>
- 완료 기준: <확인 가능한 결과>
- 확인: <검증할 대상·방법>
- 확인·결정 지점: <사용자 확인 또는 결정 주체·시점, 해당 없으면 없음>
- 수행 기록: 미생성

### 세부 작업

1. <실행할 첫 행동>
```
