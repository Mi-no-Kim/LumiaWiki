# 공용 절차

<a id="entry"></a>

## 적용

요청 확인부터 수행·검증·결과 반환까지 연결한다. [작업별 행동](<작업별 절차.md#select>)과 [문서·기록 관리](<문서 관리.md#entry>)는 필요한 구역만 사용한다. 이미 확인한 유효한 기준과 근거는 재사용하며, 보조 절차 하나의 성공으로 요청 전체의 완료를 판정하지 않는다.

<a id="start"></a>

## 요청과 현재 작업 확인

### 공통

- 원하는 결과·대상과 입력·허용 범위·수용 조건을 확인한다.
- [권한 기준](<../docs/details/operations/권한과 실행 범위.md>)에 따라 이미 아는 정보를 다시 요구하거나 허용된 일을 반복 승인받지 않는다.
- 조회·계획·리뷰를 수정이나 실행으로 확대하지 않는다.
- 독립적인 단순 조회에 기록 탐색이나 새 Task 생성을 강제하지 않는다.
- 기존 작업에 관한 추가·변경 요청은 [추가 요청 판단 스킬](<../.agents/skills/triage-additional-request/SKILL.md>)로 착수 전 소속·커밋 분리와 필요한 알림을 판단한다.

### 맥락 확인이 필요한 경우

- 담당 기록의 현재 요약부터 읽는다. 담당 기록의 위치를 모르면 [work 안내](../work/README.md#start)에서 찾는다.
- 관련 기준의 결론과 이번 판단에 필요한 적용 조건을 확인한다.

### 입력·원천·권한·기준의 부족 또는 충돌 발생 시

- 부족·충돌 내용과 해결에 필요한 정보나 판단을 알리고, 그에 의존하는 행동과 완료 판정을 제한한다.
- 독립적으로 허용된 일은 계속한다.

<a id="verification"></a>

## 수행과 확인

### 수행

- 작업 대상의 실제 상태와 기존 사용자 변경을 확인한다.
- 수행 전에 [검증과 완료 기준](<../docs/details/operations/검증과 완료.md>)으로 필요한 확인과 시점을 정한다. [별도 검수 조건](<../docs/details/operations/별도 검수.md>)에 해당하면 검토자를 연결한다.
- 기능·동작 변경은 동작 구현 전에 [사용자 확인 목록](<../docs/details/operations/검증과 완료.md#user-verification>)을 작성·공유하고 같은 사례를 자동 검사·직접 조작 검증에 연결한다.
- 다른 에이전트나 외부 실행 환경에 작업을 맡길 때는 담당 범위·허용 행동·필요한 원천과 제한을 함께 전달한다. 해당 환경에서 필요한 지침과 자료를 사용할 수 있는지 확인하고, 전달·접근하지 못한 부분은 미확인으로 남긴다.
- 원본과 유효한 근거를 보호하며 허용된 일을 수행한다.
- 의미 있는 판단·수행·확인 결과와 관찰·피드백은 [기록 작성 기준](<../docs/작업 기록 작성 기준.md#minimum>)에 따라 담당 기록에 남긴다.

### 확인과 재확인

- 도구·검토자의 결과를 포함한 실제 근거를 주 진행 AI가 요청과 수용 조건에 대조한다.
- 자체·별도 검수의 구체적 수행에는 [검수 스킬의 공통 구역](<../.agents/skills/review-work/SKILL.md#common-review>)을 적용한다. 커밋 준비에는 해당 스킬의 커밋 전 구역도 적용한다.
- 변경한 범위의 관련 영향과 정상 동작을 확인한다.
- 수정이나 대상·입력·기준의 변화로 이전 근거의 효력이 달라지면 영향을 받는 확인을 다시 수행한다.
- 필수 확인과 수정이 충족되면 해당 반복을 끝낸다. 새 실패나 미해결 우려가 생기면 영향을 받는 부분으로 돌아간다.

<a id="finish"></a>

## 완료와 인계

### 완료 판단

- 요청한 결과와 실제 반영·미반영, 필수 확인 결과와 잔여를 대조한다.
- 필수 조건이 불충족이거나 미확인이면 해당 범위를 완료로 판정하지 않는다.
- [종료 절차](<문서 관리.md#close>)에 따라 정상 완료·취소·미완료 인계를 구별해 처리한다. 필요한 기록·보존·정리의 결과까지 확인해 최종 완료를 판단한다.
- 자기 작업의 완료를 부모 작업의 수용이나 별도로 필요한 사용자 승인으로 확대하지 않는다.

### 다음 작업 안내 전 확인

- 현재 작업의 내용 수용·로컬 완료 표시만으로 다음 작업의 착수를 안내하지 않는다. [종료 절차](<문서 관리.md#close>)에 따른 처리가 남아 있으면 현재 작업의 다음 미완료 절차를 다음 행동으로 반환하고, 종료 처리가 끝난 뒤 다음 작업을 안내한다.
- 종료 범위는 요청과 권한을 따른다. 검수·커밋·PR·통합·정리가 포함되면 [Git 작업 절차](<Git 작업 절차.md#entry>)에서 실제 남은 단계를 확인한다. 실행 권한이나 필수 확인이 부족하면 그 조건과 필요한 판단을 반환한다.
- 사용자가 별도 작업으로의 전환을 명시한 경우에는 [전환 절차](<문서 관리.md#transition>)에 따라 현재 작업을 보존하고 처리한다.

### 결과 반환과 후속 요청

- 실제 결과·관련 파일과 근거·검증 범위와 한계·미해결·다음 허용 행동을 반환한다.
- 기능·동작의 결과 확인을 요청할 때는 [사용자 확인 기준](<../docs/details/operations/검증과 완료.md#user-verification>)에 따라 실제 접속·실행 방법·대상 버전/자료와 사전 확인 목록, AI의 검증 결과·미확인을 함께 전달한다. 사용자 확인 결과는 응답을 받은 뒤 구분해 기록한다.
- 문서 작성이나 검사 통과를 실제 적용·동작 확인·전체 완료로 확대하지 않는다.
- 종료된 작업에 수정·재수행·새 작업이 필요한 요청이 오면 [새 요구·수용 실패·기록 오류](<../docs/작업 기록 작성 기준.md#close>)를 구별한 뒤 처리한다.

<a id="failure"></a>

## 실패·전환·복구

### 실패 시

- [실패 기준](<../docs/details/operations/실패와 복구.md>)에 따라 실제 관찰·부분 반영·원인과 가설·수정 범위를 기록한다.
- 수정이 허용된 경우 필요한 수정을 수행하고, 원래 실패와 영향을 받는 관련 동작을 재확인한다.

### 전환·중단 시

- 계획한 전환은 다음 작업 착수 전에 [현재 작업 보존과 다음 작업 준비](<문서 관리.md#transition>)를 처리한다.
- 예기치 않은 중단은 [복구 절차](<문서 관리.md#recovery>)에 따라 실제 파일·사용자 변경·완료·부분 반영·미수행부터 확인한다. 무조건 재실행하거나 덮어쓰지 않는다.

### 계속할 수 없는 경우

- 실제 상태·남은 문제·보존 근거·재개 조건·다음 허용 행동을 인계한다.
- 중단·취소·인계를 자동 완료로 처리하거나 재개에 필요한 자료를 자동 정리하지 않는다.

<a id="feedback"></a>

## 관찰과 개선 연결

- 관찰 자체를 수정 권한이나 개선 성공으로 확대하지 않으며, 모든 요청에 새 개선 과제를 만들지 않는다.

### 개선이 필요한 경우

- [개선 기준](<../docs/details/operations/관찰과 개선.md>)에 따라 원인과 최소 변경·영향을 판단한다.
- 허용된 범위에서 반영·재확인하고, 후속 사용에서 효과와 한계를 확인한다.
