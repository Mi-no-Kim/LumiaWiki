# Issue 파일 생성 지시서

## 역할

Phase 진행 AI와 독립 요청을 받은 AI가 같은 create-issue skill·입력·본문 양식을 사용한다. 실제 부모 배정이 있으면 Phase 하위로, 독립 요청이면 독립으로 처리한다. 현재 Phase가 있다는 이유만으로 귀속시키지 않으며 소속 판단이 필요한 경우 관련 근거부터 확인한다.

생성 근거는 공통으로 기록한다. 부모 Phase 행과 Phase 보유 목록·milestone 연결은 Phase 하위에만 적용하고 독립 Issue에서는 해당 행만 생략한다. 나머지 구조·주석·네 단계·상태·Task 배정과 수용 조건은 같다.

[생성 입력](<templates/issue-input.md>)을 [본문 양식](<templates/issue.md>)에 옮겨 전체 로컬 본문을 작성·검증한다. 번호 발급 전에는 번호·URL·정식 경로만 미발급인 초안으로 두고, 실제 발급 후 식별 정보와 최종 위치의 링크를 보정한다. 이 지시서는 이 두 시점의 대조에 사용하며 이후 갱신은 본문의 규칙 주석과 공통 절차를 따른다.

이 지시서가 맡는 본문 작성 단계와 [생성 요청의 전체 범위](<../docs/작업 기록 체계.md#creation-scope>)를 구별한다. 생성 요청을 처리하는 AI는 [생성·등록 절차](<문서 관리.md#create>)와 create-issue skill로 GitHub 발급·로컬 저장·게시와 연결 확인을 마친다. 본문 작성만으로 기본 생성 범위를 완료했다고 반환하지 않는다.

파일을 작성하면서 결론·Task 배정·준비 성공을 대신 확정하지 않는다. 새 Issue의 생성 적합성 판단이나 실제 등록·브랜치 준비·Task 생성은 이 작성 단계에서 수행하지 않는다.

## 입력 반영

| 생성 입력 | 본문의 위치 |
|---|---|
| 목적·기대 결과·이미 정해진 조건 | 1단계의 각 구역 |
| Issue에서 결정할 사항 | 진행 순서 뒤의 결정 구역(Task 분해·배정 전에 답을 확정할 초기 질문) |

- 문구·항목·순서·불확실성, 조건의 적용 범위·근거와 질문의 결정 범위·판단 기준을 보존한다. 입력에 없는 조건·질문·기준을 추가하거나 최초 입력 사본을 만들지 않는다. 질문 없음이 확인된 입력은 결정 구역에 그 사실·근거를 쓰고 예시 `결정 1` 구역을 만들지 않는다. 질문 목록 미확인은 대상·입력의 확인 항목에 두고 임의의 결정 질문으로 바꾸지 않는다.
- 초기 질문에 Task가 만들어야 할 조사·설계 결론이 섞였거나 소속이 애매하면 원문·미정을 유지해 사용자 확인 대상으로 남긴다. 생성 중 질문을 삭제·재분류하거나 답을 대신 확정하지 않으며, 목록의 편집 제한과 배정 전 확정 조건은 [논의·결정](<Issue 공통 절차.md#step-2>)을 따른다.
- 제목·체크·번호·표식은 양식에 맞춰 부여하되 질문을 요약·분할·병합·재배열하지 않는다. 결정 번호는 단계 번호와 별개로 유지한다.
- 상대링크는 입력·양식 각각의 원래 위치에서 해석하고 최종 Issue 위치에서 같은 원천·구역을 가리키도록 보정한다. 표시 문구는 보존한다. 원래 위치·대상을 확인 못하면 원문 링크를 유지하고 미확인으로 표시한다.

## 본문 복사와 초기값

양식의 `markdown` 코드 블록만 복사한다. 바깥 제목·사용 안내·예시 안내는 복사하지 않는다. 코드 블록의 구역·필드·링크·표식과 규칙 주석을 유지하며, 주석을 새로 해석해 작성하거나 축약하지 않는다. 공통 규칙의 전문을 추가로 복사하지 않는다.

모든 규칙 주석은 양식의 `issue-rule:` 형식으로 복사하고 해당 조건에서 준수한다. 식별자 추가로 변경 보호·훅 검사 범위를 확대하지 않는다. 변경 보호 대상은 `issue-rule:start`·`issue-rule:state`·`issue-rule:position`·`issue-rule:completion` 네 주석이며, 사용자 명시 요청 범위 외에는 이 네 주석의 식별자·내용·경계를 수정·삭제하지 않는다. 진행 중 작성 방법은 [본문의 규칙 주석 안내](<templates/issue.md#recording-guide>)를 따른다.

| 대상 | 생성 직후의 값 |
|---|---|
| 전달된 입력의 없음·미정·미확인 | 원문 그대로 |
| 입력 항목에서 전달되지 않은 값·확인 못한 사실 | 미확인 |
| 새 결정의 내용·이유·근거, 미확정 Task 배정 | 미정 |
| 전달사항 파일·전달본 식별·확정 근거 | 확인한 입력만 반영. 미작성·미확정·미확인은 실제 상태대로 구분 |
| 아직 생성하지 않은 Task | 미생성 |
| 네 단계와 결정 체크 | 모두 미체크 |
| 단계별 실제 진행 기록 | 미수행 |

명시적으로 확정된 Task별 배정 입력만 담당 결과·근거 결정에 반영한다. 적용할 전달사항이 확정된 경우 해당 파일·전달본 식별을 연결하고, 근거 결정에서 그 전달본의 확정 근거도 확인할 수 있게 한다. 배정만 확정되고 전달사항이 아직 작성·확정되지 않았다면 그 상태를 남긴다. Issue의 기대 결과만으로 Task 개수·배정·전달본의 작성/확정을 추론하지 않는다. 실제 Task 생성과 전달사항·배정 기준 기록의 작성 순서는 [공통 절차의 3단계](<Issue 공통 절차.md#step-3>)를 따른다.

확인된 부모·식별·전달 입력·추가 필요 자료·논의의 허용 범위·지침·준비와 근거는 양식의 해당 필드에 적는다. 미정·미확인에는 확인/결정 방법과 필요한 시점을 남긴다. 논의를 시작할 최소 기준과 2단계에서 정할 상세 결과 기준은 구분한다. 기준의 확정 입력이 없으면 미정으로 두고 결정 항목·시점을 연결하며, 최소 기준도 미정이면 본작업 시작 전 보완 대상으로 남긴다.

### 같은 정보의 기록 위치

입력 원문은 지정된 구역에 보존하고, 같은 정보는 담당 구역에서 갱신한 뒤 다른 곳에 필요한 요약과 해당 위치를 연결한다.

| 항목 | 기록할 내용 |
|---|---|
| 대상·입력 | 전달 원천·추가 필요 자료의 확인/제공 상태·확인 방법과 시점. 목적·기대 결과·확정 조건의 전문을 다시 쓰지 않는다. |
| 범위·권한 | 현재 논의의 허용 범위·권한·근거·위임. 확정 조건은 원문 구역을 참조한다. |
| 준비 근거 | 등록·부모 연결·브랜치·환경·선행 결과 등 실제 준비 값과 근거. 입력·권한의 준비 판단에는 위 기록을 참조한다. |
| 적용 지침 | 상단의 공통 안내를 재사용하고 이번 Issue에 추가로 적용할 지침과 확인 상태를 적는다. 미확인을 임의로 없음으로 바꾸지 않는다. |
| 최소 기준·전체 수용 조건 | 각각의 판단 조건·확인 방법과 필요한 결정/확인 시점을 적고 실제 입력·권한·준비 값은 해당 기록으로 연결한다. |
| 요약·단계 진행 기록 | 주석이 요구하는 제한 번호·행동·미충족·해소 조건과 상세 위치, 수행·확인 요지를 남긴다. 상세 근거·확인 목록·공통 절차를 반복하지 않는다. |

목적·기대 결과와 수용 조건, 논의 최소 기준과 전체 수용 조건은 구별한다. 미정 사항의 소관·확정 시점은 [Issue와 Task의 논의·결정 경계](<Issue 공통 절차.md#step-2>)에 따라 관련 판단 전에 확인하고 임의의 선행 조건을 추가하지 않는다.

현재 요약의 초기값은 다음과 같다. 필드별 작성 규칙을 따르며, 현재 하려는 행동의 진행 단계나 허용 범위를 판단할 수 없으면 본문 주석의 예외를 적용한다.

- 상태: 예정.
- 현재 진행 위치: 본문의 1단계 내부 링크 하나.
- 다음 행동: 1번에서 허용된 입력 대조·질문 행동 하나.
- 막힌 조건: 실제 제한 번호·행동·미충족·해소 조건과 상세 위치. 번호 미정·제한 미확인도 그대로 남긴다.

후속 단계의 막힘을 현재 단계의 허용된 보완 금지로 확대하지 않는다. 입력을 옮기거나 양식을 복사한 것을 단계 수행·준비·결정 완료로 처리하지 않는다. 이후 수행·검증·수용·종료 결과나 빈 결과 구역·미래 표식을 미리 만들지 않는다.

## 발급 전 본문 확인과 발급 후 보정

- 입력의 네 구역과 질문 원문·순서·번호·표식·규칙 식별자, 불확실성 표시를 대조한다.
- 구역·필드·단계 순서와 모든 규칙 주석이 양식대로 빠짐없이 복사됐는지 확인한다. 변경 보호 대상 네 주석은 식별자·내용·경계가 같은지 대조한다.
- 발급 전에는 내용·주석·내부 표식·초기값을 확인한다. 실제 번호를 얻은 뒤 식별 정보와 최종 위치의 상대링크를 보정하고 정식 파일의 자동 주석/상태 검사를 확인한다.
- 초기값과 Task 배정이 위 기준에 맞고 미발생 결과·실제 Task가 만들어지지 않았는지 확인한다.
- 필수 정보·실제 준비 부족, 초기 결정 전체 확정과 Task 배정/생성 조건의 제한이 공통 절차에 따라 현재 요약·상세 기록에 연결됐는지 확인한다.
- 같은 정보의 원문·실제 값·근거를 여러 구역에서 별도로 갱신하게 만들지 않았는지 확인한다. 요약의 필수 제한 요소와 필요한 확인 시점은 생략하지 않는다.
- 요약에서도 [초기 질문 목록 확인](<Issue 공통 절차.md#step-1>)(1단계 완료 전)과 [답 확정](<Issue 공통 절차.md#step-2>)(Task 분해·배정 전)을 구별하고 상세 위치를 연결했는지 확인한다.
