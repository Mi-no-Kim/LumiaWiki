# Task 본문 생성 지시서

Issue에서 확정한 전달사항으로 최초 Task 본문을 작성한다. 생성 후 계획·실행·기록 갱신은 실제 Task의 주석과 [Task 공통 절차](<Task 공통 절차.md>)를 따른다. 생성 지시서·본문 양식은 최초 작성에만 사용한다.

이 지시서는 [생성 요청의 전체 범위](<../docs/작업 기록 체계.md#creation-scope>) 중 본문 작성 단계를 맡는다. 생성 요청을 처리하는 AI는 create-task skill과 [등록 절차](<문서 관리.md#task-create>)로 로컬 저장·부모 등록과 GitHub sub-issue 발급·연결 확인까지 마친 뒤 결과를 반환한다. 본작업 착수 권한은 생성 권한과 구별하며, 같은 요청에 착수가 명시됐으면 기본 범위의 조건에 따라 이어간다.

## 입력 확인

- 부모 Issue의 배정 기록과 [입력 양식](<templates/task-input.md#assignment-body>)에 따른 확정 전달사항 파일
- Issue의 배정 결정에 기록·참조된 Task 식별자·저장 경로·순번 충돌 확인 근거
- [Task 본문 양식](<templates/task.md>)

식별자·저장 경로를 [경로·식별 기준](<../docs/작업 기록 체계.md#paths>)과 Issue의 확인 근거에 대조한다. 정보가 부족하면 부모 보유 목록·실제 파일을 확인하고 미확인을 남긴다. 번호·경로를 추론해 정식 본문을 완성하거나 기존 파일을 덮어쓰지 않는다.

전달사항은 `artifacts/task-<순번>-assignment.md`에 둔다. 원본 경로·전달본 식별·확정 근거는 [기록 책임](<Task 공통 절차.md#assignment-record>)에 따라 Issue의 배정 기준 기록과 Task 본문 참조에서 관리한다. 입력 양식에 관리 항목을 다시 요구하거나 확인되지 않은 전달본·확정 사실을 만들지 않는다.

## 입력 반영

- 목적·기대 결과·이미 정해진 조건·Task에서 결정할 사항·완료 조건과 확인 방법을 확인한다. 내용의 의미·범위·근거를 유지하고 입력에 없는 조건·질문·권한을 추가하지 않는다.
- 입력의 Task 태그를 제목 아래에 반영한다. 전달된 할 일의 태그는 보존하고, 명시 태그가 없으면 배정·합의로 확인한 행동만 기존 조건을 넓히지 않는 범위에서 분류한다. 중요한 해석이 필요하면 미정·미확인과 확인 시점을 남긴다. 전달되지 않은 계획·권한을 태그로 대신 확정하지 않는다.
- 전달사항 원문은 확정 파일에서 관리하고 본문은 이를 참조한다. 목적·범위·완료 조건의 사본을 별도로 갱신하지 않는다.
- 미정인 선택과 미확인 사실을 구별하고 필요한 확인·보완 내용과 시점을 남긴다. 부족한 배정·권한·승인을 추론해 채우지 않는다.
- Task에서 결정할 질문의 답은 생성 후 논의 대상으로 남긴다. 생성 전에 모두 확정하도록 요구하지 않는다. [방법 선정 과제 예시](<examples/task-creation-input-example-db-method.md#db-method-assignment-example>)처럼 기대 결과·판단 기준·결정 주체와 실제 실행 허용을 구별한다.

## 본문 복사와 링크 보정

1. 본문 양식의 **Task 본문 코드 블록만** 복사한다. 바깥 설명·예시는 복사하지 않는다.
2. 구역·필드·표식과 모든 `task-rule:` 주석의 식별자·내용·경계를 그대로 복사하고 제목·식별자·부모 관계를 실제 입력에 맞게 채운다. 생성된 본문에는 양식·생성 지시서로 돌아가는 진행용 링크를 넣지 않는다.
3. 입력·양식의 상대링크를 각각 원래 위치에서 해석하고 최종 저장 위치에서도 같은 파일·구역을 가리키도록 보정한다. 원래 대상을 확인하지 못하면 원문 링크를 유지하고 미확인으로 남긴다.

## 구역별 기입

| 구역 | 작성할 내용 |
|---|---|
| **현재 요약** | 확인한 상태·현재 위치·다음 행동·막힌 조건 |
| **전달사항 참조** | 부모 Issue·적용 전달사항·전달본 식별·배정 확정 근거와 Issue 기준 기록 |
| **계획과 합의** | 실제 대상·입력·준비 상태·유효한 합의·이미 합의한 계획과 남은 질문 |
| **결과** | 실제 결과가 발생한 뒤 작성할 자리. 수행·검증·승인·완료 결과를 미리 채우지 않음 |

계획과 합의에서는 다음을 구별한다.

- 배정 합의와 현재 전체 계획의 제안/합의 사실. 각각 적용 범위·근거와 보완 시점을 표시한다.
- Task에서 결정할 질문·범위·판단 기준·결정 주체. 원본으로 연결하고 답의 미정을 유지한다.

전체 수행 계획은 `###` 제목으로 구분하고 각 할 일은 `####` 행동 제목과 복수 태그·완료 체크·할 일·확인·수행 기록으로 작성한다. 전달된 계획이 없으면 양식의 작성 틀과 미정을 유지하며 행동·계획 합의를 임의로 만들지 않는다.

## 상태 초기 기입

- 신규 생성 직후 허용된 활동에 미착수한 Task는 **예정**으로 기입한다.
- 이미 계획·논의가 진행 중이거나 중단 사유가 확인됐다면 실제 상태를 우선한다. 기존 Task의 재개·복구·이관 상태를 초기화하지 않는다.
- 참조 예시의 미확정 상태를 실제 값으로 추론하지 않는다. 허용 상태와 전환은 [상태 규칙](<Task 공통 절차.md#state-rules>)을 따른다.

## 수행 기록과 생성 후 계획

- 수행 기록은 Task당 한 파일의 **예정 경로**만 둔다. 이미 계획한 할 일이 있으면 예정 구역도 표시한다. 첫 할 일 착수 때만 [수행 기록 최초 생성 안내](<Task 공통 절차.md#execution-creation>)를 사용하고 이후에는 실제 기록의 주석을 따른다.
- Task 생성 후 첫 실행 전에 [전체 계획을 수립·합의](<Task 공통 절차.md#sequence-rules>)한다. 생성 시 전달되지 않은 전체 계획을 임의로 확정하지 않는다.
- 이후 논의 응답·새 사실·조건 변경은 실제 Task의 주석과 [계획 갱신 흐름](<Task 공통 절차.md#plan-update>)에 따라 합의·남은 결정·할 일·태그에 반영한다. 생성 입력을 현재값으로 덮어쓰지 않는다.
- 현재 허용·실행 선행 조건은 계획과 연결하고 [착수 확인](<Task 공통 절차.md#start-check>)을 따른다. 배정·계획 합의나 계획에 적힌 구현·커밋을 새로운 실행 권한으로 해석하지 않는다.

## 작성 후 확인

- 식별자·저장 경로·부모 관계가 입력과 일치한다.
- 본문 양식의 구역·필드·표식과 `task-rule:` 주석의 식별자·내용·경계를 유지하고 설명·예시를 섞어 복사하지 않았다.
- 생성 후 작성에 필요한 규칙이 본문 주석과 직접 연결한 공통 절차에 있으며 양식·생성 지시서로 돌아가는 진행용 링크가 없다.
- Task·할 일의 태그가 [태그 기준](<Task 공통 절차.md#tag-rules>)에 맞고 필요한 활동을 함께 표시한다. 미정·미확인은 그대로 유지하며 태그를 권한·결정 위임·실행 완료로 해석하지 않았다.
- 확정 전달사항을 정확히 참조하며 입력의 의미·범위·근거를 누락하거나 바꾸지 않았다.
- 본문 네 구역에서 미정·미확인과 보완 시점이 드러나고, 남은 질문을 확정 결과나 생성 선행 조건으로 바꾸지 않았다.
- 신규·미착수는 예정이며 기존 실제 상태를 초기화하지 않았다.
- 링크가 최종 위치에서 같은 원천·구역을 가리킨다. 확인 못한 대상은 원문·미확인 표시를 유지했다.
- 실제로 발생하지 않은 준비·수행·검증·승인·완료 결과를 작성하지 않았다.
