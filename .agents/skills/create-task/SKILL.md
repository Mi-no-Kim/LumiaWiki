# Task 본문 생성

<!-- inventory-dependencies: ["harness/templates/task-input.md", "harness/Task 생성 지시서.md", "harness/templates/task.md", "harness/Task 공통 절차.md"] -->

## 입력과 원천

Phase 하위·독립 Issue 아래 Task에 같은 절차를 사용한다. [배정 확인과 생성](../../../harness/문서%20관리.md#task-create)에 따라 실제 부모의 확정 배정·전달사항·확정 근거·식별/경로와 순번 충돌 확인을 읽는다. 이미 있는 답을 재사용하고 없는 필수값·번호·권한은 추론하지 않는다.

- [입력 양식](../../../harness/templates/task-input.md): 목적·기대 결과·확정 조건·Task에서 결정할 사항·완료 조건과 확인 방법 및 태그.
- [생성 지시서](../../../harness/Task%20생성%20지시서.md): 실제 입력을 본문에 옮기는 방법과 작성 후 대조.
- [본문 양식](../../../harness/templates/task.md): 최초 복사할 네 구역·규칙 주석·전체 계획 작성 틀.

## 생성 판단과 작성

배정 결과·범위·완료 조건·원본/확정 근거와 실제 식별이 부족하면 핵심 부족·필요 이유·보완할 내용을 반환한다. Task 내부 방법·조사 결론·상세 계획은 생성 후 논의할 수 있다. 지연 입력은 필요한 실행 시점과 제한을 남기며 생성 조건과 구분한다.

요청과 기존 권한에서 허용한 초안 또는 신규 경로에만 작성한다. 대화·메모리 검토 요청은 파일을 쓰지 않는다. 실제 번호·부모를 만들거나 기존 기록을 새 양식으로 덮어쓰지 않는다. Task 태그로 위임·실행 허용을 추가하지 않는다.

본문 코드 블록을 사용하고 주석·표식·원문 의미·불확실성을 유지한다. 배정 전문은 확정 전달본에서 관리하고 Task에는 적용 전달본·식별·부모의 기준 기록을 참조한다. 신규·미착수만 예정이며 실제 활동이 있으면 실제 상태를 우선한다. 전체 계획이 없으면 제안/미정과 계획 합의 시점을 남기며 합의·결정·수행·완료를 만들어 채우지 않는다.

## 확인과 반환

입력과 본문을 대조해 배정/상세 합의·생성/실행 경계, 주석·식별·초기값과 최종 위치의 링크를 확인한다. 실제 저장 후 부모 보유 목록·자식의 부모 연결을 허용된 범위에서 맞춘다. 부모가 기존 기록이고 수정이 금지돼 있으면 그 제한과 미등록 상태를 반환하며 몰래 갱신하지 않는다.

신규 실제 기록은 공통 주석 검사기의 작업 파일 검사로 자동 적용을 확인한다. 예외 목록에 추가하지 않는다. 수행 기록은 첫 할 일 착수 때 공통 절차의 최초 생성 안내로 만들며 생성 시 미착수 구역·결과를 만들지 않는다.

실제 작성 범위·확인 결과·미완료 등록과 실행 제한·다음 행동을 반환한다. 이 skill은 본작업·DB 변경·커밋·GitHub 발급을 수행하지 않는다. 생성 후 전체 계획·진행·기록·종료는 실제 본문 주석과 [Task 공통 절차](../../../harness/Task%20공통%20절차.md)를 따른다.
