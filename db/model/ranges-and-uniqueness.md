# D2 — 번호 범위·정렬·이름 중복

<a id="current"></a>

[공통 표](common-tables.md#current)의 확정 번호 범위·중복 금지·이름 비교 계약이다. 메이저·마이너 각각 0~99는 사용자 확인을 받은 사실이며 실제 목록·누락/충돌 사례를 조사한 것은 아니다. D1은 [이름·날짜](names-and-dates.md#current)에서 다룬다. 구현·격리 검증과 승인한 로컬 적용은 [결과](../migration/application-status.md#current)를 따른다. 실제 자료 작업은 계속 보류한다.

## 업무 키와 기존 정렬

- 내부 ID와 업무 값은 별개다. 시즌 번호 UNIQUE, 패치의 (season_id, major_no, minor_no) UNIQUE와 기존 하한 검사를 유지한다.
- 시즌 정렬은 시즌 번호+9, 패치 정렬은 시즌 정렬×10000+메이저×100+마이너다. 번호/정렬은 별도 저장하며 실제 번호를 정렬 충돌 회피용으로 고치지 않는다.
- 종류는 같은 부모 아래와 루트끼리의 동명을 금지한다. 다른 부모의 동명은 허용한다.

## D2-P — 번호 범위와 패치 정렬

메이저·마이너 각각 **0~99 CHECK와 패치 정렬값 UNIQUE**를 적용한다. 사용자가 번호 범위를 확인했고 N1~N5 추천안을 채택했다. 각 번호가 두 자릿수 구간을 넘지 않으므로 기존 식의 시즌·패치 순서와 정렬값을 맞출 수 있다.

범위 확인의 근거는 사용자 응답이다. 실제 게임 자료 조사·대조나 제약 생성 검증은 수행하지 않았다. 0~99를 벗어난 입력은 거부하고 계약과 충돌하는 자료는 확인받는다. 번호를 자르거나 새 번호/정렬식으로 자동 변환하지 않는다.

정렬값 UNIQUE만으로 번호의 자리 넘침과 순서 역전까지 해결하지 못한다. 아래는 실제 게임 자료가 아닌 산술 사례다.

| 합성 사례                         | 기존 식의 결과 | 의미                         |
| --------------------------------- | -------------- | ---------------------------- |
| 시즌 1의 (0,100)과 (1,0)          | 둘 다 100100   | 같은 시즌에서 충돌           |
| 시즌 1의 (100,0)과 시즌 2의 (0,0) | 둘 다 110000   | 시즌 사이 충돌               |
| 시즌 1의 (101,0), 시즌 2의 (0,1)  | 110100, 110001 | 값이 달라도 시즌 순서와 역전 |

시즌 sort_order의 추가 UNIQUE는 이번 선택에 포함하지 않는다. 기존 시즌 번호 UNIQUE와 sort_order=season_number+9 검사로 이미 유일성이 따라온다. 물리 INTEGER/BIGINT 범위를 실제 게임 번호의 허용 상한으로 해석하지 않는다.

## D2-N — 확정한 중복 금지 범위

| 대상                  | 중복 금지의 비교 범위                           | 범위 밖 재사용                            |
| --------------------- | ----------------------------------------------- | ----------------------------------------- |
| item_grade.name       | 등급 목록 안                                    | 무기 종류 등 다른 목록과 같은 문자열 가능 |
| weapon_type.name      | 무기 종류 목록 안                               | 등급 등 다른 목록과 같은 문자열 가능      |
| item_grade.sort_order | 등급 목록 안. 동순위 금지                       | 지역 등 다른 목록의 정렬값과 무관         |
| 지역 이름             | 같은 조회 패치에 등장하는 지역끼리              | 다른 패치에서 같은 이름 재사용 가능       |
| 지역 sort_order       | 같은 조회 패치에 등장하는 지역끼리. 동순위 금지 | 다른 패치에서 같은 순서 재사용 가능       |

각 목록의 서로 다른 대상과 한 패치 안의 지역을 구별하고 표시 순서를 정하기 위한 계약이다. 실제 자료에 중복이 없음을 확인했다는 뜻은 아니다. 충돌 입력은 자동 병합·이름 변경·순서 재배치 없이 확인받는다.

지역 이력 전체의 이름/정렬값을 전역 UNIQUE로 묶지 않는다. 조회 패치에서 동시에 유효한 값의 비교와 이력 행의 키는 별개다. 물리 제약·검사 수단은 D4의 유효 범위 표현과 함께 검토하며 이름 자동 정규화는 하지 않는다.

N1에 따라 season.display_name·season.season_name·game_patch.version_name에는 추가 UNIQUE를 두지 않는다. 식별과 업무 중복은 기존 ID·시즌 번호/패치 번호 조합으로 처리하며 이름 재사용을 허용한다.

## N2 — 이름 중복 비교

region.display_name·item_category.name·item_grade.name·weapon_type.name·region_map_member.name에 COLLATE "C"를 명시한다. 저장 문자열을 그대로 비교하며 대소문자·앞뒤 공백·Unicode 표현 차이를 구별한다. 빈값 거부와 기존 UNIQUE의 비교 범위는 유지하고 자동 trim/정규화·동명 병합은 하지 않는다. 공개 검색의 정규화/유사어 처리는 후속 검색 계약에서 정한다. [PostgreSQL 비교 규칙](https://www.postgresql.org/docs/18/collation.html)을 근거로 하며 실제 DB 검증 범위는 [적용 결과](../migration/application-status.md#current)를 따른다.

## 남은 입력과 물리 설계

| 항목                         | 담당·필요 입력                                                  | 시점                                               |
| ---------------------------- | --------------------------------------------------------------- | -------------------------------------------------- |
| 실제 번호 입력의 계약 적합성 | 0~99는 사용자 확인 완료. #45의 실제 입력을 001이 계약과 대조    | 자료 작업 재개 뒤 등록/교정 전                     |
| 실제 이름·순서의 충돌        | #45의 실제 목록과 001의 목록/조회 패치별 중복 대조              | 자료 등록/교정 전                                  |
| 제약별 이름·배치             | 001이 명시적 이름과 확정한 C 비교·전체 구조를 DDL 초안에서 제시 | 구현 파일 생성 보류 해제 뒤, 실제 생성 직전 재확인 |
| 지역 유일성 검사 수단        | 001이 D4 패치 유효 범위·갱신과 대조, 004가 동일 패치 조회 확인  | 지역 이력의 최종 DDL/갱신 구현 전                  |

자료 확인에도 기존 보류가 적용된다. 확정한 중복 금지 범위를 다시 선택하지 않으며 실제 입력이나 구현 수단을 임의로 확정하지 않는다.

## 후속 확인 사례

- 가상 산술 사례·사용자의 번호 범위 확인·실제 게임 자료 조사를 구별한다.
- 채택 기준에 맞춰 0·99 수용/100 거부, 시즌/패치 업무 중복과 정렬 충돌을 별도로 검증한다.
- 등급/무기 종류의 각 목록 안 동명, 등급 동순위, 같은 조회 패치의 지역 동명/동순위는 거부한다.
- 다른 패치에서의 지역 이름/순서 재사용과 서로 다른 목록의 같은 문자열을 잘못 차단하지 않는다.

선택·검증 근거와 작업 상태는 [D1·D2 기록](../../work/records/phase-001/issue-43/artifacts/task-001-d1-d2-review.md#current)이 소유한다.
