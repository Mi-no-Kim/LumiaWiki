# D1 — 이름·날짜·시각의 미확인 값

<a id="current"></a>

[공통 표](common-tables.md#current)의 확정한 NULL 등록 계약이다. 실제 값·누락 사례는 조사하지 않았다. 계약의 확정과 테이블·스키마·SQL 생성은 별개이며 실제 생성은 보류한다.

## 필수값과 값 보존

- 시즌 번호·표시 이름·정렬값, 패치의 시즌/번호·정렬값과 이미 정한 핵심 참조는 필수다. 미확인 값을 0·빈 문자열·다른 이름으로 대체하지 않는다.
- 실제 시즌명·패치 이름은 번호 표기/표시 이름과 별도다. 날짜는 DATE, 정확한 적용 시점은 UTC 초 단위이며 시간대 미확인·날짜만 있는 입력을 임의 자정으로 보완하지 않는다.
- 적용 시각 미확인이면 현재/예정도 미확인이다. [기존 기준](<../../docs/개발 기준.md#datetime>)을 유지한다.

## NULL 등록 허용 범위

아래 5개 필드의 NULL을 허용한다. 핵심 식별·참조가 완전하면 메타정보가 미확인인 행도 등록할 수 있다. 이름/달력 정보 누락 때문에 번호로 식별되는 자료 전체를 막지 않기 위한 계약이다.

| 대상                    | 저장 의미                             | 함께 지킬 경계                                         |
| ----------------------- | ------------------------------------- | ------------------------------------------------------ |
| season.season_name      | 확인된 실제 이름이 없으면 NULL        | 표시 이름을 실제 시즌명으로 복사하지 않음              |
| game_patch.version_name | 확인된 별도 이름이 없으면 NULL        | 번호에서 만든 표기를 이름으로 저장하지 않음            |
| season.start_date       | 확인된 시작일이 없으면 NULL           | 오늘 날짜 등으로 보완하거나 시작 여부를 추정하지 않음  |
| season.end_date         | 확인된 종료일이 없으면 NULL           | NULL만으로 진행 중/종료 전/해당 없음으로 판정하지 않음 |
| game_patch.applied_at   | 확인된 정확한 적용 시점이 없으면 NULL | 현재/예정이나 최신 기본 선택을 임의 판정하지 않음      |

NULL은 해당 필드에 확인된 값을 저장하지 않았다는 뜻이다. 이름은 미등록, 날짜·시각은 미확인으로 다룬다. 공식 이름 자체가 없음·진행 중·해당 없음을 이 값 하나로 판정하지 않는다. 그런 구분을 화면/업무에서 요구한다면 필요한 사실과 저장 표현을 먼저 확인하며 상태 열·교정 장부를 자동 추가하지 않는다.

명시한 패치의 조회와 시간에 따른 현재/예정 판정을 구별한다. 날짜 누락만으로 명시 조회 전체를 제외하지 않는다. 현재 패치 기본 선택·공개 조건·실제 DTO/API는 004/담당 기능에서 확인한다. 확인된 기간 양끝의 역전 금지와 이름 빈값 거부는 유지한다.

## 필요한 입력과 담당

| 확인할 것                 | 담당·필요 입력                                                          | 시점                                      |
| ------------------------- | ----------------------------------------------------------------------- | ----------------------------------------- |
| 실제 이름과 누락 이유     | #45의 실제 이름 제공 여부·누락 사례, 001의 저장 경계 확인               | 실제 자료 작업 재개 뒤 등록/교정 전       |
| 기간·적용 일시의 품질     | #45의 누락/미종료/날짜만 존재/시간대 미확인 사례                        | 실제 자료 작업 재개 뒤 필요한 범위만 확인 |
| 조회에서 필요한 추가 구분 | 004/담당 기능과 사용자가 미등록·미확인 표시, 현재/예정·기본 선택을 확인 | 해당 조회 구현 전                         |

NULL 허용 정책은 다시 선택하지 않는다. 실제 값과 누락 이유를 확인한 것으로 처리하지 않으며 테이블 생성·자료 작업 재개도 뜻하지 않는다.

## 후속 확인 사례

- 필수 번호/표시 이름은 있고 실제 이름은 미확인인 합성 입력: 이름 NULL 보존, 실제 이름 자동 생성 없음.
- 날짜만 알려진 패치 또는 시간대 미확인: 적용 시점 임의 생성 없음, 현재/예정 미확인.
- 종료일 NULL: 진행 중/해당 없음으로 자동 표기하지 않음.
- 필수 번호/참조 누락, 빈 실제 이름, 확인된 기간 역전: NULL 허용 정책으로 검사 우회 없음.

선택·검증 근거와 작업 상태는 [D1·D2 기록](../../work/records/phase-001/issue-43/artifacts/task-001-d1-d2-review.md#current)이 소유한다.
