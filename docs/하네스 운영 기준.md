# 하네스 운영 기준

<a id="current"></a>
## 현재 결론

이 문서는 AI가 허용 범위 안에서 작업하고, 필요한 확인을 수행하며, 실제 근거에 따라 완료·미해결·인계를 판단하는 기준을 정한다.

구체적인 수행 순서는 `harness/`의 절차를 따르고, 실제 논의·변경·검증 결과는 `work/`의 담당 기록에 남긴다. 문서에 기준이 있다는 사실을 실제 준수나 동작 성공의 증거로 사용하지 않는다.

상세 기준은 아래 하위 문서에서 직접 관리한다. 이 진입 문서에는 적용 범위와 읽기 안내를 둔다.

## 필요한 문서 선택

권한과 검증·완료 기준은 공통으로 적용한다. 해당 판단이 필요할 때 담당 문서를 확인하고, 이미 현재 문맥에서 확인한 유효한 기준을 매번 다시 읽을 필요는 없다. 상황별 기준은 아래 조건에 해당할 때 추가로 확인한다.

| 판단 상황 | 담당 문서 |
|---|---|
| 작업 범위·승인·입력 부족 판단 | [권한과 실행 범위](<details/operations/권한과 실행 범위.md>) |
| 필요한 확인·판정·보호·화면 디자인 선행과 기능 검증·개별 작업 완료와 인계 | [검증과 완료](<details/operations/검증과 완료.md>) |
| 검수 요청, 운영 규칙 자체 변경, 보존 원본 이전·삭제, 유일 근거를 잃을 수 있는 참조 변경 | [별도 검수](<details/operations/별도 검수.md>) |
| 실패 수정·반복 종료·중단·재개·복구 | [실패와 복구](<details/operations/실패와 복구.md>) |
| 관찰에 따른 업무 방식의 개선 판단 | [관찰과 개선](<details/operations/관찰과 개선.md>) |
| 브랜치·커밋·PR·병합 판단 | [Git 작업 기준](<Git 작업 기준.md#current>) |
| GitHub 저장소 옵션·기능 지원 판단 | [저장소 설정 기준](<GitHub 저장소 설정 기준.md#current>) |
| 초기 하네스 전체의 사용 능력 평가 | [검증과 완료의 전체 평가 구역](<details/operations/검증과 완료.md#overall-evaluation>) |

## 수행 절차와 기록

요청부터 수행·결과 반환까지의 흐름은 [공용 절차](<../harness/공용 절차.md#entry>), 전환·복구·종료의 구체 처리는 [문서 관리 절차](<../harness/문서 관리.md>), 기록의 상태와 관계는 [작업 기록 체계](<작업 기록 체계.md>)를 따른다.
