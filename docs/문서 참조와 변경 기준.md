# 문서 참조와 변경 기준

<a id="current"></a>
## 현재 결론

링크 작성이나 문서의 수정·이동·분할 때 필요한 구역을 읽는다. 원천 선택과 해석은 [문서 관리 기준](<문서 관리 기준.md#current>), 실제 조작은 [문서 관리 절차](<../harness/문서 관리.md#entry>)를 따른다.

<a id="references"></a>
## 참조와 당시 근거

현재 기준은 담당 주제와 적용 조건으로, 작업 관계는 실제 기록으로, 당시 판단은 사건과 원자료·관찰 근거로 연결한다. 보존 자료는 정확한 대상을 식별할 위치와 필요한 버전·시점, 접근 한계를 밝힌다.

안내 링크에는 문서·구역을 읽을 목적과 조건을 드러내고, 필요한 전제·예외 문맥도 함께 찾을 수 있게 연결한다.

- 저장소 내부 링크는 링크를 작성하는 파일 기준의 상대 경로를 쓴다. 구분자는 `/`, 같은 파일의 구역은 `#표식`, 공백 있는 대상은 꺾쇠로 감싼다.
- 긴 자료의 특정 판단은 구역으로 연결하고 링크 문구에 의미를 드러낸다. 없는 경로는 일반 표기로 설명하며 이동·양식 복사 후에는 최종 위치에서 링크를 맞춘다.
- 직접 참조할 구역에는 필요한 때 HTML `a` 요소의 `id`를 둔다. 영문 소문자로 시작하고 소문자·숫자·하이픈으로 문서 안에서 고유하게 만든다. 참조된 표식은 유지하고 다른 사건에 재사용하지 않는다.

주소·번호·버전·커밋은 확인한 값을 사용한다. 유효한 근거는 재사용하며 접근 불가와 대상 불확실성을 구별한다. 이력 보존이 필요한 근거를 현재 링크로 재현할 수 없으면 당시 조건·발언·관찰을 보존한다. 표식이나 줄 번호만으로 내용이 보존되지는 않는다.

<a id="history"></a>
## 주제 이력과 작업 기록

현행 본문에는 유효한 결론·이유·조건을, work에는 [기록 범위](<작업 기록 작성 기준.md#recording-boundary>)에 해당하는 논의·승인·수행·검증을 둔다. 중요한 변화·정정은 필요한 경우 docs/history에 당시 결론·이유·영향과 작업 근거를 요약해 연결한다. 이력에 현행 본문이나 실행 로그를 복제하지 않는다.

<a id="correction"></a>
## 정정과 근거 보존

[기록 범위](<작업 기록 작성 기준.md#recording-boundary>)에 따라 현재 안의 갱신과 사실 이력의 보존을 구별한다. 당시 사실의 보존이 필요한 정정은 원 사건의 의미를 유지하고 대상·이유·근거와 확인 사실을 연결한다.

없던 승인·성공을 사후 추가하거나 이력으로 보존할 당시 사실을 현재 안으로 덮어쓰지 않는다. 보존 자료의 이전·삭제는 허용 범위와 보존·참조 영향을 확인하며 이미 허용된 범위를 반복 승인받지 않는다. 위치 이동을 내용 채택으로 보지 않는다.

<a id="impact"></a>
## 변경 영향

변경한 규칙·조건을 사용하는 문서·절차·양식·실제 대상과 관련 의존을 확인한다. 직접 링크 검색이나 고정 깊이만으로 범위를 단정하지 않는다.

변경·유지 판단에 필요한 이유와 미확인 범위를 담당 기록에 남기며 무관한 파일의 미수정 이유를 나열하지 않는다. 오류를 사용한 후속 판단도 확인하고, 유효한 근거는 재사용하며 효력이 바뀐 부분만 재확인한다.
