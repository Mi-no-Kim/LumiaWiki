# 실패와 복구

## 현재 결론

실패 수정·반복 종료·중단·재개는 현재의 실제 상태와 허용 범위에 따라 판단한다. 수정 권한은 [권한과 실행 범위](<권한과 실행 범위.md>), 재확인과 완료 판정은 [검증과 완료](<검증과 완료.md>)를 함께 적용한다.

## 실패와 반복 종료

실패가 발생하면 실제 관찰·부분 반영·원인과 가설·미해결을 구분한다. 허용된 범위에서 필요한 수정을 수행하고, 원래 실패와 영향을 받는 관련 동작을 재확인한다.

필수 확인이 충족되고 필수 수정 사항이 해소되면 해당 검토·수정 반복을 종료한다. 새 변경·실패·미해결 우려가 생기면 영향을 받는 확인으로 돌아간다.

실패나 미확인을 감추기 위해 기준을 낮추거나 임의 횟수만큼 시도했다는 이유로 성공 처리하지 않는다. 반복 상한이 정해진 작업은 그 범위를 따르며, 별도 합의 없는 횟수를 모든 작업의 공통 규칙으로 만들지 않는다.

같은 조건에서 같은 방법을 반복해도 새 근거나 해결의 진전이 없다면 원인·접근·필요한 입력을 다시 살핀다.

해결 불가·정체·입력 변경·권한 부족·사용자 판단 필요로 계속할 수 없으면 실제 상태와 남은 문제, 보존한 근거, 재개 조건과 다음 허용 행동을 인계한다.

## 중단과 복구

예기치 않은 중단 뒤에는 실제 파일·입력·사용자 변경과 완료·부분 반영·미수행을 먼저 확인한다. 현재 권한과 근거에 따라 복구·재개 여부를 판단한다.

서비스·DB 등 외부 상태를 변경한 작업은 파일이나 Git 변경을 되돌린 것만으로 복구 완료를 판단하지 않는다. 외부 대상의 실제 상태와 남은 영향을 확인하고, 복구한 부분·남은 문제·확인하지 못한 범위를 구별한다.

무조건 전체 재실행·덮어쓰기·되돌림을 하지 않는다. 사후에 확인한 사실을 사전 승인이나 사전 기록으로 꾸미지 않는다. 취소·인계·중단을 자동 완료로 처리하거나, 재개에 필요한 자료를 자동 정리하지 않는다.

계획한 전환과 예기치 않은 중단의 구체 처리는 [문서 관리 절차](<../../../harness/문서 관리.md>)를 따른다.

다른 기준의 선택은 [운영 기준 안내](<../../하네스 운영 기준.md>)에서 확인한다.
