# 검증과 완료

## 현재 결론

필요한 확인과 개별 작업의 완료·인계를 같은 근거로 판단한다. 허용 범위와 입력 부족의 처리는 [권한과 실행 범위](<권한과 실행 범위.md>)를 함께 적용한다.

## 필요한 확인과 판정

검수는 요청·수용 조건·적용 기준·원자료를 실제 결과와 대조해 범위의 필요성·완전성, 내용의 정확성, 관련 영향과 검증 근거의 충분성, 기록·실제 상태의 일치를 판단하는 활동이다. 검수 수행 완료와 대상의 수용 조건 충족은 구별한다. 구체적인 수행은 [검수 스킬의 공통 구역](<../../../.agents/skills/review-work/SKILL.md#common-review>)을 따른다.

요청의 수용 조건과 실제 변경 범위에 맞춰 필요한 확인을 선택한다. 원천·대상·관련 영향·기존 내용 보호와 필요한 기록·등록·보존·종료 조건을 함께 확인한다.

자체·별도 검수에서는 제출할 파일의 필요성과 본문·기존 이력과의 중복을 내용·형식보다 먼저 확인한다. 첨부는 [기록 체계의 첨부 기준](<../../작업 기록 체계.md#paths>)을 적용하며, 작성자가 정한 파일 목록 자체도 검토 대상으로 삼는다.

재사용할 검증 사례가 없어도 요청에 필요한 확인은 수행한다. 도구나 입력을 사용할 수 없으면 실제 이유·확인 범위와 남은 필수 확인을 구별한다. 사례의 조건·기대 결과와 실제 실행 결과의 작성은 [기록 작성 기준](<../../작업 기록 작성 기준.md#verification-cases>)을 따른다.

| 구분 | 적용 기준 |
|---|---|
| 필수 확인 | 요청·수용 조건·적용 지침이 요구하는 확인 |
| 조건부 필수 확인 | 변경 영향·실패 수정·자료 정리 등 해당 조건이 생겼을 때 필요한 확인 |
| 선택적 확인 | 남은 불확실성을 줄이기 위한 추가 확인. 완료 판정에 필요해지면 필수 확인으로 다룸 |

확인 결과는 충족·불충족·미확인·해당 없음으로 구분하고, 작업의 진행 상태와 구별한다. 실제 부재와 접근 불가를 구별하며, 수행하지 못한 필수 확인을 해당 없음으로 처리하지 않는다.

대체 방법을 사용하면 같은 속성을 충분히 확인하는지와 남는 한계를 밝힌다. 형식·참조 검사, 내용 검토, 실제 실행은 서로 다른 근거이며 어느 하나의 통과를 다른 속성의 성공으로 확대하지 않는다.

현재 대상과 조건이 같아 유효한 과거 근거는 재사용할 수 있다. 대상·입력·기준이 바뀌면 영향을 받은 확인을 다시 수행한다.

원본·기존 사용자 변경·유효한 과거 근거와 관련 정상 동작을 보호한다. 자료를 이전하거나 제거할 때는 필요한 보존·복원 근거와 참조 영향을 확인한다.

## 화면 디자인 선행과 화면을 통한 검증

제품 기능의 동작을 구현하기 전에 먼저 해당 기능의 화면을 디자인한다. 실제로 볼 수 있는 화면을 마련해 입력·출력·주요 상태와 사용 흐름을 검토한 뒤 동작을 구현한다.

Issue·Task를 구성할 때 화면 디자인과 동작 구현의 선후 관계, 사용할 화면의 위치와 검증할 흐름을 계획에 연결한다. 공통 화면이나 앞선 작업에서 만든 화면을 사용할 때도 해당 화면과 이번 기능의 관계를 명확히 한다.

제품 기능의 검증은 화면이 있는 상태에서 수행하는 것을 기본으로 한다. 구현한 기능을 화면에서 조작하고 처리 결과와 표시를 확인하며, 계산·저장·데이터 정합성 등 필요한 내부 확인을 함께 수행한다. 내부 검사 통과만으로 화면을 통한 기능 확인을 대신하지 않는다.

화면 디자인 검토와 구현 후 실제 동작 검증은 구별한다. 화면이 있다는 사실만으로 기능 구현이나 동작 검증을 완료한 것으로 판정하지 않는다.

## 구현 전 사용자 확인 목록과 결과 전달

기능·동작을 구현하거나 변경할 때는 사용자가 직접 확인할 조작·기대 결과 목록을 동작 구현 전에 작성하고 공유한다. 화면이 있는 기능은 앞의 화면 설계·검토와 연결한다. 내부 함수마다 별도 목록을 만들지 않고 해당 기능의 핵심 정상 흐름과 필요한 실패·경계 상황을 기준으로 작성한다.

- 사전 목록에는 준비 조건·자료와 진입 위치, 구체 조작·입력, 관찰 가능한 기대 결과를 둔다. 담당 Task 또는 직접 수행 Issue의 기존 계획·검증 구역에서 관리하고 자동 테스트·브라우저 확인에 같은 사례를 연결한다. 목록 공유 자체를 매번 별도 승인 대기로 만들지 않으며 새 선택·권한이 필요한 부분만 확인한다.
- 요구가 바뀌면 목록·테스트·영향 범위를 함께 갱신한다. 구현 결과에 맞춰 기대값을 임의로 낮추거나 기존 확인 근거를 그대로 재사용하지 않는다.
- 사용자에게 확인을 요청하기 전에 AI가 가능한 자동 검사와 직접 조작 검증을 먼저 수행한다. 자동 검사·AI 직접 조작·사용자 확인의 실제 결과와 근거·미확인을 구분하고, 자동 테스트 통과를 브라우저 확인으로 표시하지 않는다. AI가 확인하지 못한 부분은 이유·한계와 함께 전달한다.
- 결과를 확인할 수 있을 때 실제 실행·접속 방법, 확인 대상 버전이나 후보·필요 자료, 같은 조작·기대 결과 목록을 전달하고 확인을 요청할 항목을 명시한다. 화면이 없는 동작은 사용자가 관찰할 요청/응답 예시나 재현 절차를 제공한다. 존재하지 않는 주소·자료·결과를 만들거나 내부 구현 검사를 사용자에게 떠넘기지 않는다.
- 사용자 응답 전에는 사용자 확인을 미확인으로 유지한다. 사용자 확인이 필수인 수용 조건은 그 확인 전 완료로 판정하지 않는다. 다른 항목에 일괄 사용자 승인 대기를 새로 강제하지 않으며 기존 검수·커밋·PR·통합·종료 절차를 따른다.

새 사용자 동작이 없는 순수 포맷·단순 설정 등에는 사용자 조작 목록을 형식적으로 만들지 않고 영향에 맞는 검증을 수행한다. 같은 목록을 여러 문서에 복제하거나 목록 작성을 위한 별도 파일·도구·에이전트를 매번 추가하지 않는다. 필요한 필수 검수는 유지한다.

## 개별 작업의 완료와 인계

개별 작업은 해당 요청의 범위와 수용 조건으로 판정한다. 필요한 변경·확인·관련 영향·기록·보존·종료 처리가 충족됐는지 실제 근거와 대조한다.

필수 조건이 불충족이거나 미확인이면 해당 범위를 완료로 판정하지 않는다. 완료한 부분과 남은 부분을 구분하고, 미해결과 다음 허용 행동을 반환한다.

결과에는 실제 변경·확인 범위와 한계·미해결·다음 행동 및 관련 파일·근거를 제시한다. 안내는 실제 준비·사용 방법·결과와 일치해야 하며, 생성 과정의 내부 자료 없이 필요한 운영 원천을 찾을 수 있어야 한다.

문서 작성·파일 생성·적용·실행·동작 확인을 구별한다. 작업의 완료 판정은 별도로 필요한 사용자 승인이나 상위 작업의 수용을 대신하지 않는다.

기록의 상태와 관계는 [작업 기록 체계](<../../작업 기록 체계.md>), 구체적인 종료 처리는 [문서 관리 절차](<../../../harness/문서 관리.md>)를 따른다.

## 초기 하네스 전체의 사용 능력 평가

초기 하네스 전체의 사용 능력을 평가할 때는 다음 항목을 실제 사례와 근거로 확인한다. 이 항목은 개별 요청마다 전부 수행해야 하는 선행 검사표가 아니다.

| 평가 항목 | 확인할 결과 |
|---|---|
| 인계와 재개 | 목표·허용 범위·실제 진행·미해결·근거·다음 허용 행동을 찾을 수 있다. |
| 정상 작업 | 대표 지원 요청에서 원천·준비·수용 조건을 찾고, 허용된 수행·검증·종료 또는 인계까지 연결할 수 있다. |
| 결정과 정정 | 현재 결론·이유·조건과 과거 근거를 구분해 찾고, 필요한 변경·정정을 담당 원천에 반영할 수 있다. |
| 실패 발견과 대응 | 현재 결과에서 실패를 확인하고, 허용된 수정·관련 재검증 또는 구체적인 인계로 연결할 수 있다. |
| 변경 영향과 최신화 | 직접 참조와 간접 사용처를 확인하고, 필요한 관련 반영·유지 이유·미확인을 남길 수 있다. |
| 개선 | 최소 한 대표 개선 사례에서 관찰·원인 판단·최소 변경·관련 확인·후속 사용의 효과와 한계를 연결할 수 있다. |
| 중단과 복구 | 실제 부분 반영·원본·사용자 변경을 구별하고, 허용된 복구·재개와 관련 확인을 수행할 수 있다. |

각 평가에도 앞의 범위·권한 준수, 현재 원천과 실제 근거에 따른 판정, 기존 내용 보호, 안내의 사용성과 운영 원천의 독립성을 적용한다.

개별 사례와 도구의 준비·실행 상태는 해당 작업 기록의 실제 근거로 확인한다. 문서·참조 검토를 실제 대표 개선 주기나 전체 사용 능력 검증 완료로 확대하지 않는다.

## 관련 기준

별도 검수의 적용 조건과 예외는 [별도 검수](<별도 검수.md>), 실패나 중단이 생겼을 때의 판단은 [실패와 복구](<실패와 복구.md>)에서 확인한다. 다른 기준의 선택은 [운영 기준 안내](<../../하네스 운영 기준.md>)를 따른다.
