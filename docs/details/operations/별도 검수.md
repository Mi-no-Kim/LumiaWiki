# 별도 검수

## 현재 결론

자체 대조를 기본으로 하며, 다음 경우에는 별도 검토자를 연결한다.

- 사용자·수용 조건·적용 지침이 별도 검수를 요구한 경우
- 새 작업 결과를 커밋하기 전의 별도 에이전트 검수. 문서·단순 수정·WIP의 적용과 기검수 결과의 통합은 [커밋 기준](<../git/작업 커밋 기준.md#working-commits>)을 따른다.
- 원천의 소유·등록 책임, 권한, 상태·종료·검증의 의미와 조건, 공용 절차의 책임 등 운영 규칙 자체를 새로 정하거나 변경하는 경우
- 보존 원본을 이전·삭제하거나, 광범위한 참조 변경으로 유일한 근거를 잃을 수 있는 경우

커밋 전 조건과 별개로, 기존 기준에 따른 등록·현황 갱신·같은 의미의 표현 보완은 그 자체만으로 별도 검수 대상이 되지 않는다. 파일 수만으로 검수를 강제하지 않는다.

검토자는 필요한 원자료와 현재 대상을 확인한다. 작성자는 지적을 근거와 대조해 반영하고 관련 부분을 재확인한다. 충돌은 근거로 해소하거나 미확인으로 남기며, 다수의 동의만으로 통과시키지 않는다.

실제 검토 범위와 한계를 밝힌다. 같은 모델의 역할·문맥 분리를 다른 모델의 검증이나 맹검 검증으로 보고하지 않는다.

## 실행자와 별도 검토자의 원천

별도 검수가 필요한 경우 실행자에게는 실제 목표·완료 조건·허용 범위·위임·필수 전제와 필요한 자료를 충분히 전달한다. 검토자는 원래 요청·현재 기준·실제 산출물·관찰·실패/보완 근거를 직접 대조한다. 실행자가 쓴 성공 문구나 요약만으로 판정하지 않으며, 주 진행 AI가 검토 결과와 실제 반영을 최종 확인한다.

행동 평가 시험에서 추가 예상 판정표·과거 정답 출력을 실행자에게 주지 않는 경우에도, 실제 Task의 요구·A/B 대안·수용 조건이나 배정 전제를 빠뜨려 다른 입력으로 바꾸지 않는다. 지연 제공 자료·모의 사건과 실제 응답을 구별하고 전달·접근 범위를 밝힌다. 역할 분리를 OS 접근 차단으로 주장하지 않는다. 이 구역은 기존 별도 검수 조건에서 적용하며 모든 일상 작업에 새 검토자·증명 파일을 강제하지 않는다.

## 관련 기준

검수의 실제 확인과 완료 판정에는 [검증과 완료](<검증과 완료.md>)를 적용한다. 다른 기준의 선택은 [운영 기준 안내](<../../하네스 운영 기준.md>)에서 확인한다.
