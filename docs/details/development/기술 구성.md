## 도구·의존성 버전 관리

| 대상           | 합의한 관리 기준                                                                                                                                                   |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| JDK            | Java 21 계열. 배포판·패치 버전은 강제하지 않고 기존 Oracle JDK 21.0.11 사용                                                                                        |
| Node.js        | 지원 중 LTS 사용. 사용자 선택으로 개발·CI 기준을 24.22.3 LTS로 갱신. Task 42-002에서 로컬 24.22.3 적용·기존 웹/실행기 재검증 완료. 세부 실행 근거는 담당 기록 확인 |
| npm            | 프로젝트 잠금 파일을 정상적으로 설치할 수 있는 버전 사용. 현재 11.19.1 유지                                                                                        |
| Docker·Compose | 필요한 기능을 지원하는 기존 버전 사용. 정확한 버전은 강제하지 않으며 DB 실행 때 엔진 연결 확인                                                                     |
| 라이브러리     | React·Vite·TypeScript·Spring Boot 등 기존 선택 버전을 유지하고 패키지 선언·잠금 파일·Boot 의존성 관리로 실제 구성을 관리                                           |
| Gradle         | 전역 설치 버전 강제 대신 저장소의 Wrapper 9.9.1 사용                                                                                                               |
| DB 이미지      | 공식 `postgres:18.6` 사용 확정. 이미지 태그를 저장소의 Compose 설정에서 관리                                                                                       |

개발·CI에서 호환 조건을 충족하는 환경으로 실제 설치·타입 검사·빌드를 확인하고 사용 버전을 기록한다. 로컬 도구의 정확한 버전 차이만으로 업그레이드를 요구하지 않는다. 이번 Node 변경은 최신 DOM 테스트 환경의 요구를 충족하려는 사용자 선택이며, 24.22.3 동봉 npm도 기존과 같은 11.19.1이다. 기존 JDK 배포판을 교체하지 않는다. 결정 근거와 적용·재검증 범위는 [Task 42-002](../../../work/records/phase-001/issue-42/artifacts/task-002-verification.md#implementation-decisions)에서 관리한다.

의존성을 의도적으로 추가·변경할 때 `npm install`로 `package-lock.json`을 함께 갱신·검토하고, 깨끗한 환경·CI에서는 `npm ci`로 설치한다. Wrapper 파일을 저장소에 포함하고 Java 빌드 대상은 21로 맞춘다. Wrapper만으로 JDK·외부 라이브러리까지 고정됐다고 판단하지 않는다. 미지정 보조 도구의 실제 패치 버전은 기반 구축에서 채택한 도구와 호환되는 안정 버전으로 명시·잠금하고 검증한다.

## 서버 생성·기본 실행 설정

| 생성 옵션                   | 값·상태와 이유                                                                                             |
| --------------------------- | ---------------------------------------------------------------------------------------------------------- |
| Project / Language / Java   | Gradle - Groovy / Java / 21. 기존 합의·사용자 확정                                                         |
| Spring Boot                 | 4.1.2 확정                                                                                                 |
| Packaging                   | Jar 확정. 내장 서버로 API 앱을 실행하기에 적합                                                             |
| Configuration               | YAML(`application.yaml`) 확정. 환경별 설정 묶음을 읽기 쉽게 유지                                           |
| Group / Package name        | `io.github.minokim` / `io.github.minokim.lumiawiki` 확정. 저장소 소유자 이름의 하이픈을 제거한 코드 식별자 |
| Artifact / Name             | `lumiawiki-api` 확정                                                                                       |
| Description / 프로젝트 버전 | `Lumia Island Wiki API` / `0.0.1-SNAPSHOT` 확정. 앱 개발 버전이며 게임 자료의 v1.0.0과 독립                |
| 기본 의존성                 | 아래 기본·테스트 의존성 8개 구성 확정. Initializr 선택명은 아래 안내 참조                                  |
| DB 접근·구조 변경           | JPA(Spring Data JPA) + Flyway 사용 확정. PostgreSQL용 Flyway 모듈도 필요                                   |

Initializr에서 Spring Web·Validation·Spring Data JPA·Flyway Migration·PostgreSQL Driver·Lombok·SpringDoc OpenAPI를 선택한다. 앱 버전은 생성물에서 확인하고 Gradle 버전은 생성 후 Wrapper에 맞춘다. 아래 PostgreSQL 지원 모듈·테스트 의존성은 생성된 빌드에 포함됐는지 확인해 빠졌으면 추가한다. 포트·환경변수·JPA·Flyway는 생성 후 설정 파일에서 연결한다.

앱 이름은 `lumiawiki-api`, 로컬 서버 기본 포트는 `8080`이다. DB 환경변수·Flyway·`ddl-auto=validate`·SQL 자동 초기화 `never`는 [DB 기준](<DB 환경.md#db-config>), 프로필·로그·JPA 조회 범위·오류 연결은 [공통 서버 기준](<../../개발 기준.md#server-profiles>)을 따른다.

## 서버 의존성

| 의존성                                                       | Gradle 범위          | 용도                           |
| ------------------------------------------------------------ | -------------------- | ------------------------------ |
| `org.springframework.boot:spring-boot-starter-webmvc`        | `implementation`     | MVC 기반 JSON API·내장 Tomcat  |
| `org.springframework.boot:spring-boot-starter-validation`    | `implementation`     | 요청 입력 검증                 |
| `org.springframework.boot:spring-boot-starter-data-jpa`      | `implementation`     | 합의한 JPA·저장소 접근         |
| `org.springframework.boot:spring-boot-starter-flyway`        | `implementation`     | 합의한 Flyway와 Boot 자동 구성 |
| `org.flywaydb:flyway-database-postgresql`                    | `runtimeOnly`        | Flyway의 PostgreSQL 지원       |
| `org.postgresql:postgresql`                                  | `runtimeOnly`        | JDBC 접속 드라이버             |
| `org.springframework.boot:spring-boot-starter-webmvc-test`   | `testImplementation` | API 계층 테스트                |
| `org.springframework.boot:spring-boot-starter-data-jpa-test` | `testImplementation` | JPA 계층 테스트                |

Boot starter와 Boot가 관리하는 외부 라이브러리 버전은 Boot 의존성 관리에 맞춘다. Hibernate·내장 서버·JSON·기본 로그를 중복 추가하지 않는다. 테스트 DB 지원은 [테스트 기준](<테스트와 TDD.md#current>)에 따라 연결한다.

Lombok은 Boot 관리 버전의 `compileOnly` + `annotationProcessor`로 구성한다. 테스트에서 사용하면 테스트용 설정도 확인한다. `@RequiredArgsConstructor`·`@Getter`·`@Slf4j` 등 필요한 기능만 사용하고 JPA 엔티티에 `@Data`를 일괄 적용하지 않는다.

API 문서는 `org.springdoc:springdoc-openapi-starter-webmvc-ui:3.2.0` + Swagger UI를 사용한다. 환경별 문서 노출·공개 범위는 배포 환경을 정하는 담당 설계에서 확정한다. REST Docs·React Compiler 등 비교 자료나 생성 템플릿의 부속 도구를 함께 채택한 것으로 보지 않는다.

## API 형식·로컬 연결

| 항목           | 채택 기준                                                                                                                                                                                                      |
| -------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| API 경로       | `/api/v1` 아래 기능별 리소스 경로. 이 v1은 API 계약 버전으로 게임 자료 v1.0.0·앱 버전과 독립                                                                                                                   |
| 요청·성공 응답 | JSON·camelCase. 요청/응답 DTO를 사용하고 JPA 엔티티를 직접 반환하지 않음. 성공 응답은 필요한 데이터·목록 메타데이터를 직접 담고 모든 응답에 공통 성공 wrapper를 강제하지 않음                                  |
| HTTP 상태      | 정상 조회·빈 검색 결과는 200, 잘못된 입력은 400, 없는 대상은 404, 예상하지 못한 서버 오류는 500. 기능별 상세 매핑은 해당 API 설계 때 결정                                                                      |
| 오류 응답      | Spring `ProblemDetail`의 RFC 9457 형식 `application/problem+json`으로 통일. 필요한 업무 오류 코드·필드별 입력 오류는 확장 필드로 추가. 내부 예외·SQL·비밀값을 그대로 노출하지 않음                             |
| 로컬 연결      | 프런트 `localhost:5173`, 서버 `127.0.0.1:8080`을 기본으로 하고 충돌 시 설정 변경. 브라우저는 상대 경로 `/api/v1/...`를 호출하고 Vite 개발 프록시가 `/api`를 서버로 경로 변경 없이 전달                         |
| 로컬 접근      | 위 프록시 경로를 기본으로 삼아 프런트 호출용 전면 CORS 허용을 추가하지 않음. 직접 교차 출처 접근이 필요하면 필요한 출처만 명시. 배포 연결 방식은 배포 설계 때 결정하며 개발 프록시로 운영 구성을 대신하지 않음 |

공통 규칙은 현재 Task 003에서 확정했고 기능별 경로·필드·페이지 처리·오류 코드 목록은 Task 005가 배정할 해당 기능/API 설계에서 정한다. 실제 연결·공통 오류 처리 골격은 첫 기반 구축에서 확인한다.

## 프런트 공통 구성

| 역할           | 채택 구성·이유                                                                                                                                                                    |
| -------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 화면 이동      | React Router의 Data Mode(`createBrowserRouter`). 검색·상세·루트의 URL과 브라우저 뒤로 이동을 처리하고 `ScrollRestoration`을 활용. Framework Mode·별도 프런트 서버는 추가하지 않음 |
| 화면 입력 상태 | React `useState`·`useReducer`, 여러 화면에서 공유해야 할 때 좁은 Context. 검색어·필터는 URL 검색 매개변수를 기준으로 복원하고 일시 UI 상태는 필요한 화면 범위에 보관              |
| 서버 조회 상태 | TanStack Query. 검색·상세·미리보기의 요청·로딩·오류·캐시를 관리. API 호출은 공통 fetch 함수로 DTO·ProblemDetail을 처리하고 Router loader와 중복 조회 계층을 만들지 않음           |
| 렌더링         | Vite 기반 클라이언트 렌더링 SPA로 시작. 직접 주소 진입·새로고침의 SPA fallback은 배포 설정에서 확인하며 API 오류를 HTML로 바꾸지 않음                                             |
| 스타일         | CSS Modules(`*.module.css`) + 공통 CSS 변수. 색상·간격·글꼴 기준과 공통 컴포넌트를 재사용. 초기에는 Tailwind·대형 UI 라이브러리를 함께 도입하지 않음                              |

기존 화면 합의와 다음 관계를 유지한다.

- 검색어·필터 변경으로 조회 키를 갱신해 자동 조회한다. 입력 지연·페이지 처리·취소의 구체 규칙은 검색 기능 설계에서 정하며 오래된 응답이 현재 조건 결과를 덮어쓰지 않게 한다.
- 목록 복귀는 검색어·필터와 스크롤을 함께 복원한다. Router의 스크롤 기능만으로 완성됐다고 보지 않고 명시적 '목록으로'와 브라우저 뒤로 이동, 목록 데이터/배치 준비 후 복원을 해당 기능에서 검증한다. Declarative Mode에서 ScrollRestoration을 쓸 수 있다고 전제하지 않는다.
- 루트는 입력 중 값과 실제 계산 요청 조건·결과를 구분한다. 계산은 버튼으로만 실행하며 TanStack Query의 자동 재조회·재시도로 계산이 실행되지 않게 한다. 입력 변경 뒤 기존 결과는 원래 계산 조건에 대응해 '변경 전 조건의 결과'로 유지한다.
- 조회 캐시의 키·유효 기간·재조회/재시도 정책은 검색·상세·계산의 성격에 맞춰 구현 시 명시한다. Redux·Zustand는 초기 공통 의존성으로 추가하지 않는다.

React Router·TanStack Query는 기반 구축에서 호환되는 안정 버전과 실제 패치 버전을 명시해 관리하고, React 19.3.1·TypeScript 7.0.2·Vite 8.3.7·현재 Node와의 설치·타입 검사·빌드를 확인해 기록한다. TanStack Query 공식 문서는 TypeScript 5.7 이상 지원과 패치 버전 고정을 권고한다. 특정 최신 버전이 이미 설치·검증됐다고 기록하지 않는다.
