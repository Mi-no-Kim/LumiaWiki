# 작업 커밋 기준

<a id="current"></a>
## 적용

작업 중 작성하는 커밋의 단위·완료 시 반영 사항·메시지 기준을 둔다. [Git 공통 기준과 참조·닫기 규칙](<../../Git 작업 기준.md#current>)을 함께 적용하며, 실제 실행은 [결과 제출 절차](<../../../harness/Git 작업 절차.md#commit>)를 따른다. PR 병합으로 만드는 커밋은 [통합 메시지 기준](<PR과 병합 기준.md#integration-messages>)을 적용한다.

<a id="working-commits"></a>
## 커밋

하나의 변경 목적을 단위로 하며, 해당 변경에 필요한 구현·자료·테스트·문서·작업 기록을 함께 포함한다. 파일 수나 시간으로 나누지 않고, 하나로 완결되는 변경을 구현과 문서 정리로 억지로 나누지 않는다. 목적이 다른 구현·오류 수정·독립적인 구조 정리는 나눌 수 있으며, 하나의 Issue·Task에 여러 커밋을 허용한다. Task 없이 직접 작업하는 독립 Issue에도 같은 규칙을 적용한다.

작업을 마치는 경우에는 현재 작업 브랜치에서 담당 기록의 결과·검증 근거·상태, 해당하는 부모의 진행 요약·필요한 등록, 관련 기준·안내와 표시 대상 현황까지 같은 변경에 반영한다. 자기 완료 조건을 충족한 작업은 완료로 표시하되 부모 완료로 자동 전파하지 않는다. PR 생성·병합이 아직 발생하지 않았다는 이유로 문서 갱신을 미루지 않으며, 그 사실을 미리 기록하지 않는다. 검수 후 수정에도 같은 원칙을 적용한다.

새로 작성·변경한 작업 결과는 문서·단순 수정도 커밋 전에 자체·별도 에이전트 검수를 마친다. [검수 절차](<../../../.agents/skills/review-work/SKILL.md#before-commit>)로 실제 커밋 후보와 검수 근거의 일치를 확인하며, 필수 결함·미확인이 남으면 정상 결과로 커밋하지 않는다. 기검수 결과의 통합은 대상·입력·기준·관련 의존이 같아 유효한 근거를 재사용할 수 있다.

메시지는 `<유형>: <변경 내용의 한국어 요약>` 한 줄로 쓰고, 필요한 이유·제약·잔여만 본문에 보완한다.

| 유형 | 용도 |
|---|---|
| `feat` | 기능 추가 |
| `fix` | 오류 수정 |
| `refactor` | 동작을 유지하는 구조 변경 |
| `test` | 테스트 추가·수정 |
| `data` | 게임 자료 등록·정정·패치 반영 |
| `docs` | 문서 변경 |
| `chore` | 도구·설정·기타 정비 |
| `wip` | 중단을 위한 미완성 상태 보존 |

중단 보존이 필요하면 `wip:`를 사용하고 본문에 미완성·미검증 범위를 남긴다. WIP도 자체·별도 에이전트 검수를 수행하며 미완성 보존과 정상 결과의 수용을 구별한다. 필수 검수의 미수행을 WIP로 우회하지 않는다.
