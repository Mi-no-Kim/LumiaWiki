# 아이템 탐색과 상세

<a id="current"></a>
## 현재 결론

아이템을 찾고 개별 아이템의 정보·패치 이력·조합법을 확인할 수 있게 한다. 품질 방향은 [프로젝트의 핵심 품질](<../../프로젝트 목표와 범위.md#quality>)을 따르며, 구체 화면·상호작용과 품질 판정 방법은 미정이다.

[초기 공개 조건](<../../프로젝트 목표와 범위.md#delivery>)과 [모바일 지원 경계](<../../프로젝트 목표와 범위.md#limits>)는 프로젝트 목표와 범위를 따른다. 이 문서는 아이템 탐색/개별 페이지와 정보 범위를 소유하며, 계산 입력/필터·결과는 [루트 계산기](<루트 계산기.md#current>)가 소유한다. 목록/개별 페이지의 버전 선택은 [화면별 버전 선택](<#version-selection>)에서 현재 요구·향후 검토·조건부 동작을 구분한다.

<a id="item-information"></a>
## 아이템 정보의 범위

아이템 자료는 다음 다섯 묶음을 기본 틀로 정리한다. 항목은 정보 예시이며 최종 필드/화면 구성 전체가 아니다.

| 묶음 | 포함할 정보 예시 |
|---|---|
| 기본 정보 | 내부 식별값·이름·종류·등급·장비 부위·이미지·최대 중첩 수량 |
| 능력치 | 스탯 종류와 값 |
| 아이템 스킬 | 연결된 스킬 대상·버전과 설명 정보 |
| 제작 | 재료 A·재료 B·제작 결과 수량. 재료별 소비량은 각각 1개 |
| 획득 | 획득 지역·획득 수량(현재 배달당 수량과 공통)·배달 가능 여부·배달 비용 |

장비 부위는 무기·옷·머리·장식·다리의 5개다. 과거 ‘팔’에서 ‘장식’으로 명칭이 바뀌었다는 사용자 설명을 유지하며 적용 버전/시점은 아직 제공되지 않았다. 일반 재료와 조합법·장비 정보를 다루며 상세 분류/필드의 완결된 목록은 아직 정하지 않았다.

아이템 기본 정보에 이름·종류·등급·장비 부위·이미지를 포함한다. 내부 식별값은 [공통 식별 기준](<게임 데이터 변경 관리.md#identity-information>)을 따른다. 이미지의 구체 보관 방식은 후속 설계에서 정한다.

캐릭터 스킬 등과 관련된 조합법을 표시하기 위해 보조용 임시 아이템을 등록하는 방식을 사용한다. 제공 SQL의 `searchable`은 이러한 임시 아이템을 검색에서 제외하기 위한 값이다. 임시 아이템의 구체 필드·관계와 P1 적용 범위는 후속 설계에서 정하며, 루트 계산에서의 취급은 해당 기능을 만들 때 결정한다. 일반 아이템 제작의 고정 소비량 규칙을 이 설명만으로 변경하지 않는다.

정보를 보존하는 범위와 개별 페이지에 크게 노출하는 범위는 구별한다. 아이템 스킬의 대상·버전·텍스트·JSON과 해석 범위는 [공통 데이터 기준](<게임 데이터 변경 관리.md#item-skills>)을 따른다. 초기 공개 시 제공할 전체 아이템 정보·변경 이력의 기간은 [공개 조건](<../../프로젝트 목표와 범위.md#delivery>)을 따른다. 실제 자료 준비·임시 변환은 [P1의 자료 확보·임시 변환 계획](<../../../work/records/phase-001/phase.md#input-workflow>)에서 다룬다.

<a id="classification"></a>
### 종류와 등급의 분류

아이템 종류는 상위·하위 분류를 지원하며 구체적인 종류 목록은 자료를 입력하면서 정한다. 장비 아래에 무기 카테고리가 있고, 무기 아래에 무기 종류가 놓이는 계층이다. 종류의 이름·상하위 관계가 바뀌면 변경된 게임 패치에 새 버전을 등록하고 다음 변경 전까지 사용한다. 과거 조회에서는 당시 이름과 계층을 보존해 보여준다. 구체적인 테이블과 아이템 버전의 연결 방식은 후속 설계에서 정한다.

캐릭터의 사용 무기와 무기 스킬을 연결하는 무기 종류(`weapon_type`)는 초기부터 별도 대상으로 두고 아이템 종류 계층과 연결해 관리한다. 구체적인 관계와 키·제약은 DB 설계 때 정한다. 별도 대상을 마련하는 결정이 캐릭터·무기 스킬 기능 자체의 P1 구현을 뜻하지는 않는다.

등급은 종류 분류와 구별한 별도 정보로 관리하고 이름·정렬 순서를 둔다. 등급 목록과 순서는 자료를 입력하면서 정하며, 등록한 등급 자체의 이름·순서는 변경하지 않는 전제다. 이 전제는 개별 아이템의 등급이 바뀌는 경우와 구별한다.

<a id="stat-information"></a>
### 능력치 종류와 값

백분율 능력치는 능력치 이름 끝에 ` (%)`를 붙여 구별한다. 예를 들어 `공격력`과 `공격력 (%)`는 서로 다른 능력치 종류다. 한 아이템의 같은 버전 정보에 같은 종류의 능력치를 여러 개 등록하지 않는다. 백분율 값은 `5%`를 `5`로 저장한다. 구체적인 수치 자료형과 소수 정밀도는 아직 정하지 않았다.

능력치 종류별 값과 다른 테이블 간의 관계를 다루는 `item_stat`을 원본으로 삼는다. `stat_json`은 아이템 단건 표시를 위한 캐시 필드로 두며 이 원본에서 만든다. 조회할 아이템 버전의 원본과 캐시가 같은 능력치를 나타내도록 한다. 아이템 버전과의 구체 연결 및 캐시 생성·갱신 시점과 방식은 후속 설계에서 정한다.

<a id="acquisition-methods"></a>
### 획득 방법

획득 방법으로 채집·사냥·획득을 구분하며, 여기서 `획득`은 상자 획득을 뜻한다. 같은 아이템에 여러 획득 방법을 연결할 수 있다. 방법별 세부 대상·조건과 지역 연결 방식은 아직 정하지 않았다.

사냥 관련 대상 정보는 별도로 관리한다. 명칭과 세부 구조는 후속 설계에서 정한다. 별도 테이블로 관리하는 방향과 후속 배치는 [담당 기록](<../../../work/records/phase-001/issue-15/task-001.md#deferred-target-design>)을 따른다.

<a id="acquisition-quantity"></a>
### 획득 수량과 배달당 수량

현재는 획득 수량과 배달당 수량을 공통 항목으로 저장한다. 실제로 두 수량이 달라지는 상황이 발생하면 별도의 배달당 수량 항목을 생성해 분리할 계획이다. 배달 가능 여부와 배달 비용도 저장한다. 제작 결과 수량은 획득 수량과 별도 항목으로 저장한다.

지역별 총 출현 개수는 해당 지역에 배치되는 아이템의 총 개수이며, 획득·배달당 수량 및 제작 결과 수량과 구별해 원자료로 보존한다. 제공 SQL의 `item_region_spawn.count`와 그 이력의 `count`가 이 수량을 뜻한다. 루트 계산에는 총 출현 개수를 수량 제한으로 사용하지 않고 지역별 획득 가능 여부만 사용한다.

아이템 개수에 해당하는 수량은 정수로 저장한다. 허용 범위의 제한은 후속 설계에서 정한다. 이 규칙은 능력치 값의 자료형·소수 정밀도를 정하는 것은 아니다.

최대 수량은 인벤토리 한 칸에 겹쳐 담을 수 있는 최대 중첩 개수를 뜻하며 등록 정보에 포함한다. 게임 자료의 최대 중첩 수량과 저장 필드의 허용 범위 제한은 구별한다.

<a id="search-and-filters"></a>
## 목록·이름 검색과 필터

- 장비 부위에 따라 결과를 볼 수 있어야 하며 장비 부위 필터도 제공한다. 이를 탭·그룹·특정 화면 배치로 확정하지 않는다.
- 이름으로 아이템을 검색할 수 있어야 한다. 정확/부분 일치·자동완성·오타 처리 등의 세부는 아직 정하지 않았다.
- 필터는 가능한 폭넓은 옵션에 적용할 수 있어야 하며 능력치와 아이템 스킬도 필터 대상이다. 최종 옵션 목록은 아직 정하지 않았다.
- 아이템 스킬은 이름으로 찾는 방식과 설명에 포함된 효과·키워드로 아이템을 찾는 방식을 모두 지원한다. 두 검색 기준의 지원은 현재 요구이며 검색 일치 규칙·입력/표시의 세부는 미정이다. 효과·키워드 검색을 스킬 수식화나 계산 가능한 효과 구조의 채택으로 확대하지 않는다.
- 스킬 버전의 이름은 내부 이름이다. 이름 검색에 이를 사용할지, 별도 표시 이름을 둘지와 템플릿 도입 시 설명 검색에 사용할 텍스트의 범위는 아직 정하지 않았다.
- 필터의 편의성과 가시성을 특히 잘 챙긴다. 입력 방식·현재 조건의 표시·필터 구성과 조작 방식은 상세 설계에서 구체화한다.
- 목록 검색 필터와 루트 계산의 장비 탐색 필터는 관련되지만 같은 기능으로 자동 합치지 않는다. 목록에서 여러 검색 조건을 함께 지정하면 지정한 모든 조건을 만족하는 아이템만 표시한다. 스킬 이름과 설명 키워드를 함께 지정했을 때도 두 조건을 모두 만족해야 한다. 값 입력·각 조건의 일치 규칙과 한 입력 안의 여러 단어/복수 선택을 다루는 세부는 아직 정하지 않았다. 루트 필터의 확정 규칙은 해당 문서를 따른다.

<a id="preview-and-detail"></a>
## 검색 결과와 개별 아이템 페이지

검색 결과의 아이템에 마우스를 올리면 간단한 상세정보를 보여주고, 클릭하면 그 아이템의 개별 페이지로 이동한다. 미리보기의 정보 항목·배치와 로딩/상호작용 상세는 미정이다.

현재 없는 아이템은 검색 목록 아래에 별도 항목/구역으로 표시하여 과거 정보·변경 이력을 조회할 개별 페이지로 찾아갈 수 있게 한다. 기본 목록의 현재 아이템과 구별한다. 구체 디자인·표시 형식, 과거 아이템의 검색 판정에 사용할 버전과 개별 페이지 진입 시 처음 보여줄 버전은 상세 설계에서 정한다.

제공 SQL의 `is_deleted`는 게임에서 삭제된 상태를 뜻한다. 서비스에서 저장 기록을 삭제·무효화하는 의미로 쓰지 않으며, 게임 내 삭제 전의 아이템 정보와 변경 이력은 보존한다. 삭제가 적용된 게임 패치와 과거 존재 상태를 판정할 구체 저장·조회 방식은 DB 설계에서 정한다. 검색 제외용 `searchable`과 게임 내 삭제 상태는 별개다.

| 검색 가능 여부 | 게임 내 상태 | 검색 노출 |
|---|---|---|
| 가능 | 존재 | 현재 아이템 목록에 표시 |
| 가능 | 삭제 | 과거 아이템 구역에 표시하고 과거 정보·이력으로 연결 |
| 제외 | 어느 상태든 | 현재 목록과 과거 아이템 구역 모두에서 제외하고 필요한 조합 관계 표시는 유지 |

개별 아이템 페이지에서는 스펙을 포함한 기본 정보와 아이템 스킬을 주요 정보로 다룬다. 역대 패치 이력과 조합법도 제공하며, 아래 획득 정보의 낮은 비중이 이 두 요구를 철회하는 것은 아니다. 정확한 화면 배치와 필드 목록은 아직 확정하지 않았다.

<a id="version-selection"></a>
## 화면별 버전 선택

| 구분 | 요구와 적용 범위 |
|---|---|
| 현재 요구 — 아이템 목록 | 현재 아이템의 기본 목록은 항상 ‘현재 적용된 제일 최신 패치’의 아이템 정보를 표시한다. 현재 없는 아이템은 [검색 목록 아래의 별도 구역](<#preview-and-detail>)에 표시한다. 목록에서 패치 버전을 고르는 기능은 현재 고려사항이 아니다. |
| 현재 요구 — 개별 아이템 페이지 | 버전 선택 기능을 제공해 과거 버전의 정보도 볼 수 있게 한다. |
| 향후 검토 | 패치노트 위키의 성격상 목록에서 과거 버전을 바로 조회하는 기능을 고려할 수 있다. 현재 구현할 기능으로 채택한 것은 아니며 도입 여부/시점은 미정이다. |
| 조건부 동작 | 향후 목록의 버전 지정을 도입한다면 목록에서 선택한 버전을 개별 아이템 페이지에서도 이어서 표시할 수 있게 한다. 이 조건만으로 목록 버전 선택을 현재 요구로 승격하지 않는다. |

‘현재 적용된 제일 최신 패치’라는 사용자 표현을 유지한다. 게임 패치의 현재/예정은 [패치 적용 시각 기준](<게임 데이터 변경 관리.md#version-information>)을 따른다. 서비스 자료의 공개·적용 방식과 자료 갱신/공개 시점의 연계, 선택 UI/유지 방식과 해당 버전에 아이템이 없거나 자료가 부족할 때의 동작은 아직 정하지 않았다. 저장 구조·캐시 구현이나 [루트 계산의 현재/도입 예정 버전 범위](<루트 계산기.md#data-boundary>)를 이번 결정으로 바꾸지 않는다.

<a id="acquisition-display"></a>
## 획득·배달 정보의 표시 비중

획득 정보는 주요 스펙·아이템 스킬과 구분하여 짧게 표시한다. 획득 지역은 개별 페이지의 보조 정보이며, 루트 계산에서 더 의미 있게 활용한다. 개별 페이지에서 없애기로 한 것은 아니다.

배달 가능한 아이템은 가격 정도를 표시하는 방향이다. 개별 페이지의 배달 정보에 모든 수량/횟수 계산을 펼치기로 정한 것은 아니다. 배달 가능 여부·배달당 수량 등 계산에 필요한 원자료는 계속 보존한다. 배달 비용은 아이템 정보에 유지하되 [루트 계산에서는 제외](<루트 계산기.md#constraints>)한다.

## 재귀적인 조합법 표시

개별 아이템의 조합법을 보여주고 하위 재료의 조합법도 아래까지 재귀적으로 표시한다. 이는 하위 제작 관계를 볼 수 있어야 한다는 요구다.

같은 버전의 한 아이템에 여러 대체 조합법은 없으며, 조합법이 있는 아이템은 하나의 조합법을 갖는다. 버전에 따른 조합법 변경 이력은 보존한다.

수량은 제작 1회를 기준으로 한다. 한 번의 조합은 재료 A와 재료 B를 각각 반드시 1개씩 소비하는 `1개 + 1개` 방식이다. 별도 재료별 필요 수량 필드는 두지 않는다. 목표 제작 개수에 따른 총 필요 수량은 조합 관계와 제작 결과 수량으로 계산한다.

반대 방향으로 해당 아이템을 재료로 사용하는 상위 제작 아이템을 확인하고 찾아가는 기능도 포함한다. 상위 제작 관계를 보여줄 범위·재귀 깊이와 화면/탐색 방식은 상세 설계에서 정한다. 하위 조합법 트리의 초기 펼침 깊이·접기/펼치기, 반복 재료·수량 표현과 세부 조작 방식도 후속 설계 대상이다.

## 역대 패치 이력과 표현 구상

개별 아이템 페이지에서 역대 아이템 패치 이력을 제공한다. 당시 상태·버전 일치와 공통 패치/요약 요구는 [패치 이력과 요약](<패치 이력과 요약.md#versioned-history>)을 따른다.

사용자 구상은 “제일 최신 메이저 패치부터의 변경사항을 기존과 비교하여 보여주면 좋겠다”이다. 텍스트만으로 의도가 변질될 수 있으므로 상세 구현 때 구체적인 표현을 확인해 확정한다. 이 구상은 아직 확정된 표시 사양이 아니다.

메이저 패치의 경계, ‘기존’의 비교 기준, 표시 기간·누적/단계별 비교와 시각적 표현은 미정이다. 최신 메이저 패치부터 비교한다는 구상 때문에 더 오래된 이력의 제공 범위를 없애지 않는다. 임의의 두 버전을 골라 상태를 직접 비교하는 별도 기능을 이번 구상으로 추가 확정하지 않는다.
