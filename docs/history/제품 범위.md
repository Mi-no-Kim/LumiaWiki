# 제품 범위의 주요 변화

이 파일은 중요한 제품 범위 추가·명확화와 당시 판단을 요약하고 현행 제품 문서·Phase 계획으로 연결한다. 현재 요구의 상세와 구현 진행은 각 담당 문서에서 확인한다.

<a id="item-scope-recording"></a>

## 2026-10-30 아이템 우선·초기 공개와 탐색/상세 요구 기록

### 당시 상태와 반영 이유

루트의 기본 운영 문서 초판에는 하네스 준비에 필요한 제품 맥락을 선별해 두었고 아이템 탐색/상세의 전용 문서는 없었다. 이후 사용자가 제품 범위 입력이 아직 끝나지 않았음을 알리고 기존 입력을 재확인한 뒤 아이템 우선·공개 조건과 검색/상세 요구를 추가했다. 이번에는 현재까지 정리한 요구를 기록하라는 명시 지시에 따라 현행 product 문서에 연결했다.

### 주요 추가·명확화

- 아이템 외 대상의 설명은 현재 보류하고 아이템 관련 기능을 우선한다. 우선 구현을 마칠 수준은 마일스톤 설계 때 결정한다. 현재 모바일 의향이 없으며 초기 공개는 딜량 계산기를 제외한 모든 기능 구현 후다. 현행 원천은 [프로젝트 범위](<../프로젝트 목표와 범위.md#delivery>)이다.
- 후발 서비스의 편의성·가시성·비주얼을 중시하며 부위/이름 탐색, 폭넓은 필터와 능력치·아이템 스킬 필터, 미리보기·개별 페이지·재귀 조합법을 요구했다. 개별 페이지는 스펙/스킬을 중심으로, 획득 정보는 짧게 표시한다. 현행 원천은 [아이템 탐색과 상세](<../details/product/아이템 탐색과 상세.md#current>)이다.
- 역대 아이템 패치를 보여주되 “제일 최신 메이저 패치부터의 변경사항을 기존과 비교”하는 표현은 사용자 구상이며 상세 구현 때 확정한다. 기간/비교 기준을 임의로 정하거나 역대 이력·별도 두 버전 비교의 범위를 바꾸지 않는다. 현행 구분은 [아이템 패치 표현](<../details/product/아이템 탐색과 상세.md#patch-history>)에 둔다.
- 앞서 확인한 루트 입력/필터·조건/결과와 초기 자료·변경/권한 요구는 각각 [루트 계산기](<../details/product/루트 계산기.md#current>)와 [게임 데이터 변경 관리](<../details/product/게임 데이터 변경 관리.md#current>)에 보완했다. 배달 가격 표시와 루트 비용 제외, 데이터 보존과 현재/도입 예정 계산용 캐시의 구분, 텍스트 스킬 관리/수식 보류를 유지한다.

### 반영의 한계

당시 반영 범위에서는 이전 설계·제품 대화 기록과 검수·배포 기준본의 수정을 제외했다. 당시 문서 반영을 제품 범위 입력 전체 완료·구현/공개·전체 하네스 사용 검증 완료로 확대하지 않는다.

## 2026-10-30 목록 최신 기준과 개별 페이지 버전 선택

이전 기록에서는 아이템 화면별 버전 선택/전환의 이용 흐름을 넓게 미정으로 뒀다. 사용자가 목록은 항상 ‘현재 적용된 제일 최신 패치’를 보여주고 개별 아이템 페이지에는 버전 선택을 넣겠다고 설명해 현재 범위를 구체화했다.

목록에서 과거 버전을 직접 보는 기능은 향후 검토 가능성으로 남긴다. 그 기능을 도입한다면 선택 버전을 개별 페이지에도 이어서 표시하는 조건을 기록하되, 현재 도입을 승인한 것으로 취급하지 않는다. 현행 원천은 [아이템의 화면별 버전 선택](<../details/product/아이템 탐색과 상세.md#version-selection>)이다.

현재 요구·향후 검토·조건부 동작을 먼저 대화에 제시한 뒤 같은 구분으로 기록하라는 사용자 지시에 따라 반영했다. 구체 UI·최신 판정/갱신·자료 부재의 처리, 패치 비교 표현과 루트 계산 범위를 함께 확정한 것은 아니다.

## 2026-10-30 스킬 이름과 설명의 효과·키워드 검색

기존에는 아이템 스킬도 필터 대상이라는 요구만 두고 구체 검색/분류 기준을 미정으로 남겼다. 사용자는 스킬 이름으로 찾는 방식과 설명에 포함된 효과·키워드로 아이템을 찾는 방식을 모두 원한다고 설명했고 필터 편의성·가시성을 다시 강조했다.

두 검색 기준의 지원을 현재 요구로 구체화했다. 검색 일치 규칙·조건 결합·입력/표시의 세부와 스킬 수식/계산 구조의 후속 결정은 유지한다. 현행 원천은 [아이템 탐색](<../details/product/아이템 탐색과 상세.md#search-and-filters>)이다.

## 2026-10-30 지정한 검색 조건을 모두 충족하는 결과

이전에는 아이템 스킬의 두 검색 기준만 확인하고 목록 검색의 다중 조건 결합은 미정으로 남겼다. 여러 조건을 함께 사용할 때 모두 만족하는 아이템만 표시할지 묻자 사용자가 동의해 이 결합 원칙을 현재 요구로 구체화했다.

스킬 이름과 설명 키워드를 동시에 지정하면 둘 다 맞는 아이템을 표시한다. 각 조건의 일치·입력/표시 규칙과 한 입력 안의 여러 단어/복수 선택 세부는 미정으로 남긴다. 현행 원천은 [아이템 탐색](<../details/product/아이템 탐색과 상세.md#search-and-filters>)이다.

## 2026-10-30 초기 공개의 아이템 자료 제공 기간 확정

이전에는 시즌1·버전1.0.0을 자료 준비의 시작 기준으로 두고 초기 공개 시 과거 자료의 제공 기간/충실도는 미정으로 남겼다. 사용자가 초기 공개 때 시즌1·버전1.0.0부터 공개 시점의 최신 패치까지 아이템 정보와 변경 이력을 모두 조회할 수 있게 할 계획이라고 설명해, 이 기간의 전체 조회를 초기 공개 조건에 포함했다.

현행 원천은 [프로젝트 공개 조건](<../프로젝트 목표와 범위.md#delivery>)이며 아이템 문서와 자료 준비 안내의 관련 표현도 맞췄다. 구체 필드·자료 완성 판정/검증 절차·저장 방식은 후속 결정으로 남긴다. 과거 메이저 패치 비교 표현이나 목록 버전 선택 도입까지 확정한 것은 아니다.

## 2026-10-30 AI 변환·검토·공개 적용의 단계적 전환 방향

이전에는 제품 AI 변환의 검토/공개 적용 정책을 넓게 미정으로 남겼다. AI 변환 후 관리자가 확인·수정하고 공개 적용하는 흐름인지 묻자 사용자는 초반에는 그렇게 운영하고, 점진적으로 전환해 최종적으로 AI가 처리할 계획이라고 설명했다.

초반 관리자 확인 운영과 최종 AI 처리 목표를 현재 요구로 구체화했다. 현행 원천은 [데이터 운영의 단계적 전환](<../details/product/게임 데이터 변경 관리.md#ai-transition>)이다. 중간 단계/전환 조건·시점·검증/예외 처리·관리자 개입 및 초기 공개 시 도달 단계는 후속 설계로 남긴다.

## 2026-10-30 현재 없는 아이템의 검색 진입·상위 제작 탐색과 초기 공개 AI 단계

현재 없는 아이템의 조회 진입과 상위 제작 탐색의 포함 여부, 초기 공개 때의 AI 운영 단계가 구체화되지 않아 사용자에게 범위 확인점으로 안내했다. 사용자는 현재 없는 아이템을 검색 목록 아래 별도 항목으로 표시하고 디자인은 나중에 정하겠다고 했으며 상위 제작 탐색도 포함하고 초기 공개는 AI 변환 단계에서 진행하겠다고 답했다.

현재 아이템의 기본 목록은 최신 패치 기준으로 유지하면서 과거 아이템의 별도 검색 진입을 제공한다. 상위 제작 아이템을 확인/탐색하는 기능도 포함하며 두 기능의 구체 표시/동작은 후속 설계로 남긴다. 현행 원천은 [검색 결과/개별 페이지](<../details/product/아이템 탐색과 상세.md#preview-and-detail>)와 [조합법/상위 제작 탐색](<../details/product/아이템 탐색과 상세.md#recipes>)이다.

초기 공개는 AI 변환·관리자 확인/수정·공개 적용 단계로 정했다. 현행 원천은 [프로젝트 공개 조건](<../프로젝트 목표와 범위.md#delivery>)이며 최종 AI 처리 목표와 이후 점진적 전환의 후속 결정은 유지한다.

## 2026-10-30 속성별 변경 선택·계산용 버전 범위·상위 제작 탐색의 표현 정정

직전 검수에서 기존 합의의 구체성이 약해진 두 문구와 혼동될 수 있는 용어 한 곳을 발견했다. 사용자 지시에 따라 [속성별 개별 변경의 선택](<../details/product/게임 데이터 변경 관리.md#change-and-correction>), [현재 버전과 도입 예정 버전의 계산용 자료](<../details/product/루트 계산기.md#data-boundary>), [해당 아이템의 상위 제작 탐색](<../details/product/아이템 탐색과 상세.md#recipes>)으로 명확히 했다. 기존 합의의 표현 정정이며 새 기능/기술 채택은 아니다.

관련 구현·자료·표시의 미정/후속과 선택한 변경의 영향 전체 반영 원칙은 유지한다. 기존 합의의 표현을 바로잡았으며 이후 입출력·계산기 설명 보완과 구별한다.

## 2026-10-30 AI 변환의 입·출력과 후반 딜량 계산기의 입력·목적 보완

앞선 대조에서 과거 합의 정리본보다 현행 제품 문서의 설명이 축약된 두 항목을 확인했다. 사용자 요청에 따라 [AI 변환](<../details/product/게임 데이터 변경 관리.md#ai-transition>)의 신규 패치노트 원문→해석/구조화→서비스 데이터라는 입·출력과 [후반 딜량 계산기](<../프로젝트 목표와 범위.md#damage-calculator>)의 입력·피해량 계산/미적용 변경 조건의 성능 예측 목적을 현행 본문에 보완했다.

기존 기능 도입 순서·초기 공개 조건과 AI 단계적 전환 방향은 유지한다. 게시 감지/수집·변환 자료 형식/검증, 피해 종류·공식·검증 기준과 아이템 스킬 수식의 후속 설계를 새로 확정하지 않는다. 앞선 미반영 확인 뒤 두 설명을 보완한 것이며 이전 확인을 기록 오류로 해석하지 않는다.

## 2026-10-30 7개 Phase 정식 계획 등록과 딜량 계산기 도입 단계 정리

사용자의 이관 지시에 따라 검수한 P1~P7 수정안을 Phase 001~007의 정식 계획으로 등록했다. 현재 목표·범위·미정과 계획상 완료 기준은 각 Phase가 소유하며 등록 당시 사용자 지시·계획과 실제 구현을 구별했다. 계획 등록 상태는 모두 예정이고 실제 구현이나 Issue/Task 생성은 수행하지 않았다.

기존에 후반 도입으로 요약했던 딜량 계산기는 [P3 내부 Beta](../../work/records/phase-003/phase.md#goal)의 수식·계산 기반과 [P7 공개용 계산기](../../work/records/phase-007/phase.md#goal)의 완성으로 시점을 구분했다. [프로젝트 범위](<../프로젝트 목표와 범위.md#damage-calculator>)와 관련 제품 문서의 표현도 맞췄다. Beta는 비공개이며 딜량 계산기의 초기 공개 제외 조건은 유지한다.

P1 최소 작동·P2 관련 정보 확장·P5 합의 기능/비주얼 완성의 계획 연결을 정비했다. 각 단계의 미정·후속과 검토용 완료 조건을 유지하며 P5 최적화, 구체 대상/기간·규칙·공식·검증을 새로 확정하지 않는다. P6 이후·P7 이전 초기 공개 위치는 제안, 최종 AI 처리 확대는 후속이다.
