<a id="goal"></a>

## 목표와 범위 및 수용 조건

아래는 해당 단계의 범위와 검토용 수용 조건이다. 합의된 제품 요구를 기준으로 진입 또는 관련 Issue 착수 전에 세부 수용 기준을 확정한다.

**공동 목표/기대 결과**

수식과 계산 구조를 실제로 사용해 볼 수 있는 내부용 딜 계산기를 만든다. 실제 사용자에게는 공개하지 않는다.

**포함 범위**

- 아이템·캐릭터·특성·게임 규칙 중 선정한 계산 범위에 필요한 입력을 연결한다.
- 해당 범위의 수식과 계산 처리 구조를 논의·구현한다.
- 아이템 스킬 설명 텍스트를 보존하면서 필요한 계산 표현을 설계한다.
- 내부에서 계산 과정과 결과를 확인할 수 있게 한다.

**완료 조건 — 검토 기준**

- 선정한 범위의 계산이 확보한 게임 규칙과 자료를 기준으로 작동한다.
- 계산 과정과 결과를 확인하고 근거와 대조할 수 있다.
- 지원·미지원·미확정 규칙이 구분돼 있다.
- 계산에 사용하는 자료와 규칙의 버전이 일치한다.
- 내부 사용 범위가 유지된다.

**기준 원천**

## 계획과 주요 의존

계획상 [Phase 002](../phase-002/phase.md#goal)까지의 관련 자료를 입력으로 사용한다. 실제 게임 규칙과 자료를 확보한 범위에서 내부 계산을 다루며 공개용 완성은 [Phase 007](../phase-007/phase.md#goal)에 연결한다.

실제 착수 전에는 아래 미정과 [필요한 착수 정보](<../../../docs/작업 기록 작성 기준.md#minimum>)를 확인한다.

<a id="entry-decisions"></a>

### Phase 진입 또는 Issue에서 정할 사항

- Beta가 지원할 계산 종류·조건·버전과 입력 범위.
- 실제 게임 수식·규칙의 원천과 불확실한 부분의 처리.
- 수식·효과·발동 조건 등을 표현하고 계산하는 방식.
- 결과 검증 기준과 내부 확인 화면.
- P7에서 확장하거나 완성할 항목.

<a id="planned-checks"></a>

### 예정 확인

선정한 지원 범위의 계산 과정/결과·규칙과 자료의 버전 일치·내부 사용 범위를 확인할 방법을 정한다.

실제 검증 결과는 수행한 때 기록한다. 현재는 계획만 등록한 상태다.

<a id="activity"></a>

## 주요 논의와 판정 근거

아래는 계획 등록 당시 근거다. 이후 계획 변경과 실제 수행은 후속 기록으로 구별한다.

<a id="registration"></a>

### 2026-10-30 검수한 구상 수정안의 정식 계획 등록

사용자의 이관 지시에 따라 검수한 수정안의 목표·범위·검토용 완료 조건·진입/Issue 결정 사항을 이 문서에 등록했다. 미정·후속·제안은 유지했으며 등록을 Phase 착수·완료로 판정하지 않았다. 공통 도입 순서와 반영 이유는 [제품 범위 이력](<../../../docs/history/제품 범위.md#seven-phase-formalization>)에서 확인한다.

<a id="role-separation"></a>

### 2026-11-05 제품 요구와 단계 계획의 역할 정리

사용자의 전체 반영 지시에 따라 단계 경계와 제품 요구·다른 단계의 참조를 정리했다. 포함 범위·검토용 수용 조건과 예정 상태를 유지했으며 기능 구현·Phase 완료를 판정하지 않았다.

<a id="result"></a>

## 결과와 미해결

계획 등록을 마쳤으며 Phase 목표의 실행 결과나 완료 판정은 아직 없다. 남은 결정은 [진입/Issue 결정 사항](#entry-decisions)에서 관리한다.
