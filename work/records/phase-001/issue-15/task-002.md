# Task 15-002 — 화면 목록·사용 흐름·디자인 범위 정하기

<a id="summary"></a>
## 현재 요약

- GitHub sub-issue: [Mi-no-Kim/LumiaWiki #22](https://github.com/Mi-no-Kim/LumiaWiki/issues/22)
- 상태: 예정
- 현재 진행 위치: 화면 목록과 디자인 담당 범위를 정할 계획을 준비했다.
- 다음 행동: Task 001의 합의 범위를 바탕으로 필요한 화면·구역과 대표 흐름을 정리한다.

<a id="goal"></a>
## 목적과 허용 범위 및 완료 조건

- 부모 Issue: [Issue #15](<issue.md#goal>)
- 목적: P1의 사용자 기능을 어떤 화면에서 확인할지와 각 기능 과제가 디자인할 범위를 정한다.
- 입력: [Task 001 결과](<task-001.md#goal>), [아이템 탐색 요구](<../../../../docs/details/product/아이템 탐색과 상세.md#current>), [루트 요구](<../../../../docs/details/product/루트 계산기.md#current>).
- 결과 반영: 이 Task의 현재 화면 목록·흐름·디자인 담당 범위를 Task 005의 Issue 구성에 연결한다.

### 범위

- 검색, 아이템 상세, 제작 관계, 루트 입력·결과, 등록 자료 확인에 필요한 화면과 화면 안의 구역을 정한다. 화면 구분은 Task 001의 지원 범위를 따른다.
- 화면마다 목적, 진입 경로, 핵심 입력·출력, 다음 이동과 필요한 주요 상태를 적는다.
- 검색 결과 없음·계산 결과 없음 등 지원 기능에 필요한 상태를 구별하고, 대표적인 사용 흐름을 시작부터 결과까지 연결한다.
- 새로 디자인할 부분과 공통·재사용할 부분을 기능 묶음별로 구분한다. Task 005에서 담당 Issue와 연결할 수 있게 한다.
- 자료 확인용 기존 화면을 활용할 수 있는지 판단한다. P1의 임시 자료 입력 흐름을 상시 업로드·관리 화면의 도입으로 확정하지 않는다.

실제 화면 디자인은 담당 기능 Issue에서 동작 구현보다 먼저 수행한다. 이 Task는 화면 목록·사용 흐름·디자인 담당 범위를 정하며 화면 제작·동작 구현은 수행하지 않는다.

### 완료 조건

- Task 001에서 정한 사용자 기능이 화면 또는 화면 구역과 연결되어 있다.
- 각 화면의 목적·진입·입력·출력·이동·필요 상태가 정리되어 대표 흐름을 따라갈 수 있다.
- 시즌·버전과 등록 내용이 필요한 위치에서 확인되는 흐름을 포함한다. 버전 선택의 P1 지원 여부는 Task 001의 범위를 따른다.
- 기능 묶음별 디자인 범위와 재사용 관계가 정리되어 Issue에 배정할 수 있다.
- [화면 디자인 선행 기준](<../../../../docs/details/operations/검증과 완료.md#screen-first>)을 적용할 디자인·구현·검증의 선행 관계가 드러난다.

<a id="plan"></a>
## 계획과 예정 검증

- 선행 조건: Task 001의 P1 포함 범위와 수용 조건.
- 수행: 기능을 화면·구역에 연결 → 대표 흐름과 필요한 상태 정리 → 디자인 담당 범위·재사용·선행 관계 정리.
- 예정 검증: 지원 기능 누락, 연결이 끊긴 흐름, 실제 디자인을 이번 Task에 포함한 항목, 불필요한 신규 관리 화면이 없는지 대조한다.
- 후속 연결: [Task 003](<task-003.md#goal>)은 기능·화면 요구를 기술 선택의 입력으로 사용하고, [Task 005](<task-005.md#goal>)는 담당 Issue를 구성한다.
