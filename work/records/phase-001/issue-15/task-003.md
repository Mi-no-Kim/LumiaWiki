### TDD 자동화의 담당·실행 시점과 착수 조건

사용자는 단순한 후속 표기로 구현이 누락되지 않도록 시점·담당을 명확히 할 것을 요청했다. P1 테스트 환경과 연결할 최소 hook 구현을 첫 기반 구축 과제의 필수 결과로 둔다.

| 시점 | 담당·완료 확인 |
|---|---|
| 현재 Task 003 | TDD 적용 규칙과 hook의 검사·예외·근거·비용 기준을 확정. 기준이 미정이면 이 Task의 해당 완료 조건은 미충족 |
| Task 005의 실행 과제 배치 | 첫 기반 구축 Issue에 테스트 환경·최소 TDD hook 연결·검증을 배정하고 수용 조건·첫 기능 구현의 착수 조건에 명시. 배정이 빠지면 Task 005 완료 조건은 미충족 |
| 계획 Issue #15의 종료 후 첫 기반 구축 과제 초반 | 프로젝트 골격·실행 가능한 테스트 명령을 마련한 직후 최소 hook을 연결하고 실제 동작을 검증. 해당 기반 과제의 필수 완료 조건으로 확인 |
| 첫 제품 기능의 동작 구현 전 | hook 연결·검증 근거를 확인한 뒤 기능 구현에 착수. 미완료·미확인이면 선행 조건 미충족으로 처리 |

최소 자동화의 수용 확인에는 필요한 TDD 근거가 누락됐을 때의 검사 실패, 유효한 근거·테스트 통과 시의 정상 처리, 비동작 변경 예외 처리를 포함한다. 테스트가 실제 요구를 검증하는지는 검수에서 판단한다. 매 도구 호출의 전체 테스트 실행이나 별도 AI 판정으로 비용을 늘리는 구현은 초기 범위로 잡지 않는다. 검사 시점·예외·근거·비용 기준은 아래 문서로 채택했고 실제 연결·증거 기록 형식의 구현은 첫 기반 구축 과제에서 수행한다.

검사 시점·조건·예외·비용과 원자료 비교는 [채택한 최소 TDD hook 기준](<artifacts/task-003-tdd-hook-proposal.md>)에 정리했다. 최초 검수 보완 뒤 자체·별도 재검수에서 필수 문제가 없음을 확인해 채택했다. 도구 기능은 공식 문서 확인이며 현재 환경에 연결해 실행한 검증 결과는 아니다.

현재 실제 번호가 있는 배정 담당은 [Task 005](<task-005.md#goal>)다. 첫 기반 구축 Issue 번호는 아직 발급 전이므로 임의 번호를 만들지 않고, Task 005가 등록할 때 담당 기록과 [Phase 착수 조건](<../phase.md#tdd-readiness>)에 실제 과제를 연결한다. 이 기록상의 완료·착수 조건과 실제 hook이 동작하는 상태는 구별한다.

일곱 완료 조건을 [수용 대조표](<artifacts/task-003-handoff.md#acceptance>)와 실제 결과로 대조해 충족 판정했다. 자체 검수는 HEAD `98ca7d5d30bae4d410222cbb67b209d5bff63353` 대비 관련 추적 변경과 미추적 문서 30개를 포함했다. 핵심 정책·표 11개 블록의 원문 보존(코드 품질은 링크 경로 정규화), 기존 첨부 앵커 30개, 로컬 참조·앵커 386개와 공백 형식을 확인했다. 링크 검사를 의미 검수·실행 검증의 대체 근거로 쓰지 않았다.
