# 후속 Issue 계획 — 검색·기본 상세와 자료 확인 화면

담당: [Task 005](<../task-005.md#summary>) · [전체 구성](<task-005-issue-outline.md#issues>)

Issue 경계·실행 순서와 아래 Task 구성·수용 조건을 사용자와 합의했다. 실제 Issue·Task 번호는 발급 전이며, 상세 실행·검증 계획과 아래 남은 결정은 담당 Issue를 준비하거나 구현하기 전에 구체화한다. 실제 자료 작업 보류를 유지하고 이번에는 과제 등록·구현·자료 작업을 수행하지 않는다.

## 목표와 범위

실제 자료 등록 전에 검색·기본 상세를 마련해 원자료와 등록값을 같은 화면에서 확인할 수 있게 한다. 검색·미리보기·기본 상세·탐색 상태를 한 Issue에서 맡는다.

## 선행 결과와 필요한 입력

- 실행 기반의 웹/API·이미지 제공 골격과 [DB Issue](<task-005-proposal-database.md#database>)의 필요한 조회 결과를 사용한다. 화면 디자인·공통 표현을 먼저 검토한다.
- [Task 002의 검색·상세 기준 시안과 흐름](<../task-002.md#screen-scope>)을 상세화한다. 빈 상태·통제한 입력으로 준비하고 실제 자료 전체 등록을 선행 조건으로 요구하지 않는다.

## 검색·기본 상세와 자료 확인 화면

| Task 제목 | 만들 결과·선후 관계 |
|---|---|
| 공통 표현과 검색·기본 상세 화면 설계 | 메뉴·시즌/버전 표시·아이템 요약/미리보기·기본 상태 표현과 두 화면을 먼저 디자인·검토. 제작·루트가 공통 표현을 재사용 |
| 검색·필터·목록·미리보기 | 이름·부위·추가 필터·초기 목록·자동 갱신·초기화·미리보기를 구현. 실제 필터 항목/일치 규칙은 구현 전에 결정 |
| 기본 상세와 탐색 상태 | 기본 정보·능력치·스킬·획득/배달 표시, 상세 이동·목록 복귀의 조건/스크롤 유지와 빈 상태를 연결. 제작 구역의 기능은 제작 Issue로 인계 |

합의한 수용 조건:

- 실제 자료 등록 전에 검색·기본 상세 화면과 DB/API 연결이 준비된다. 등록 후 원자료의 값·이미지·연결을 같은 화면에서 확인할 수 있다.
- 이름/부위/추가 필터·자동 갱신·초기화·미리보기·상세 이동과 목록 복귀가 합의한 대로 동작한다. 검색 제외/삭제 노출 구분과 미등록/검색 결과 없음의 빈 상태를 유지한다.
- 상세는 탭 없는 세 구역 구성을 유지하며 P1의 기본 정보·능력치·스킬 텍스트·획득/배달을 표시한다. 제작 구역 전체 기능·버전 선택기 완성을 이 Issue의 수용으로 확대하지 않는다.

## Task 선후 관계와 남은 결정

- 공통 표현과 검색·상세 화면을 먼저 디자인·검토한 뒤 검색 기능과 기본 상세/탐색 상태를 연결한다. 두 구현 Task의 의존이 없는 부분은 병행할 수 있다.
- 필터 항목/일치 규칙·미리보기/목록 분할·스크롤 복원 등은 필요한 입력을 받아 구현 전에 결정한다. 공통 표현은 제작·루트가 재사용한다.
- 기본 상세의 자료 표시는 이 Issue가 맡고 제작 트리·탐색·수량 계산은 [제작 Issue](<task-005-proposal-crafting.md#crafting>)에서 같은 페이지에 연결한다.
