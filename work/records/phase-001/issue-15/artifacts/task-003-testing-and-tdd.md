# Task 003 — 테스트 구성·TDD 개발 기준

담당 기록: [Task 003](<../task-003.md#summary>). 이 문서는 해당 주제의 상세 기록이며 Task 상태·남은 결정·전체 인계는 담당 기록에서 관리한다.

<a id="current"></a>

## 테스트·TDD 합의

사용자는 서버 JUnit·Mockito/MockMvc, DB Testcontainers, 프런트 Vitest·React Testing Library와 TDD 적용을 확정했다. 현재 규칙은 [실제 테스트·TDD 기준](<../../../../../docs/details/development/테스트와 TDD.md#current>)으로 옮겼으며 실제 환경·테스트는 첫 기반 구축과 각 기능에서 구현한다. 선택 시 Boot·Testcontainers·Vitest·Testing Library 공식 문서를 확인했으며 설치·실행 검증은 하지 않았다.

<a id="frontend-testing"></a>
### 프런트 동작 테스트

[프런트 검증 기준](<../../../../../docs/details/development/테스트와 TDD.md#frontend-testing>)에 연결했다. 라이브러리 내부를 다시 검사하는 대신 제품 조작·기대 결과와 실제 브라우저 사용 흐름을 확인한다.

<a id="user-checklist"></a>
## 사용자 확인 목록의 공용 기준과 적용

사용자가 요청한 구현 전 조작·기대 결과 공유와 구현 후 AI 선검증·사용자 확인 안내는 [공용 검증 기준](<../../../../../docs/details/operations/검증과 완료.md#user-verification>)을 따른다. 사례·공유 여부와 실제 결과는 각 기능의 담당 Task 또는 직접 수행 Issue에 남긴다. P1의 TDD·자동 테스트·실제 브라우저 확인과 같은 사례를 연결하며 테스트 도구 선택은 앞의 합의를 유지한다.

앞선 조치는 이 Task의 기록·인계에만 반영해 공용 원천 적용이 빠졌다. 사용자 지적에 따라 검증·기록 기준, 공용·계획 절차와 Task/직접 수행 Issue 양식에 연결했고 이 문서의 규칙 전문은 공용 원천 링크로 대체했다. 이번 수정은 Task 003에서 합의한 개발·검증 기준의 적용 누락 보완으로 같은 작업에 포함한다. 새 과제·도구·hook 구현을 추가하지 않는다.

이전 문서 검수의 '필수 문제 없음'은 당시 Task·인계에 한정된 판단이며 공용 원천 반영 완료의 근거가 아니다. 이번 공용 문서 변경은 여섯 공용 파일의 HEAD 대비 차이와 담당 기록을 자체·읽기 전용 별도 검수해 원천·절차·양식 연결과 수용 조건 보존을 확인했고 필수 수정 문제는 없었다. 변경한 8개 문서의 로컬 참조·앵커 105개와 공백 형식도 확인했다. 검수 범위는 실제 변경된 공용 문서·관련 기록이며 실제 기능 실행이나 사용자 확인 결과는 아직 없다.

<a id="tdd"></a>
## TDD 적용·후속 인계

화면 설계 → 작은 동작의 실제 실패 → 최소 구현·통과 → 리팩터링·재검증 → 실제 화면 확인의 순서는 [실제 TDD 기준](<../../../../../docs/details/development/테스트와 TDD.md#tdd>)을 따른다. 대표 근거·예외·비용 기준과 실제 구현 담당은 [Task 인계](<../task-003.md#tdd-automation-handoff>)로 연결한다. 기준 채택을 실제 테스트·hook 구현 완료로 확대하지 않는다.
