# Task 004 — P1 수용 조건별 검증 계획

담당: [Task 004](<../task-004.md#summary>). 자료 준비·등록/교정 순서는 [자료 계획](<task-004-data-plan.md#workflow>)을 따른다. 아래는 [합의한 검증 B](<task-004-data-plan.md#direction-discussion>)를 구체화한 계획이다. 전체 내부 검사와 대표 화면 확인을 병행하고 자료 내용도 기존 화면에서 사용자와 함께 원자료에 대조한다. 실제 테스트·화면·DB·게임 자료 검증을 수행한 결과가 아니다.

## 대표 사례와 기대 결과

모든 사례는 담당 화면 디자인·검토, 구현 전 사용자 확인 목록 작성·공유, 기능 구현 후 자동 검사·AI 화면 확인에 같은 조건으로 연결한다. 사용자에게는 실제 실행 방법·후보/자료·조작·기대 결과와 AI 확인 범위/미확인을 전달한다. 사용자 확인 결과는 응답 전 미확인으로 둔다. 근거: [공통 검증 기준](<../../../../../docs/details/operations/검증과 완료.md#user-verification>).

표의 A/B/X 등과 숫자는 계산 규칙을 설명하는 통제한 검증 입력안이다. 실제 게임 사실·수집한 자료가 아니며 이번에 입력 파일을 만들거나 실행하지 않는다. 실제 자료의 경우 원자료에서 독립적으로 예상 결과를 정하고 기능 출력에 맞춰 기대값을 낮추지 않는다.

| 사례 | 전제·조작·입력 | 기대 결과·판정 방법 |
|---|---|---|
| V01 기준/출처·기본 왕복 | 시즌 1·v1.0.0 실제 자료와 출처를 연결해 등록 후 검색·상세 조회. 등록 대상 전체의 목록/건수·필수 정보/관계 대응과 내부 ID·정렬값 대조 | 시즌 정렬 10·버전 정렬 100000 및 별도 버전 이름 보존. 원자료→등록값→API→화면 대응. 큰 ID는 문자열 왕복에서 값이 변하지 않음. 일부 화면 표본만으로 전체 등록을 판정하지 않음 |
| V02 수치/JSON/시각 | 실제 능력치·설명/JSON·날짜를 등록/조회. 별도 검증 입력으로 같은 능력치 종류 중복·잘못된 JSON 문법/중복 키·미확인 시간대/일시 경계 확인 | 백분율 5%는 값 5, 소수/기본 합산 및 원본/캐시 값 보존. 입력 문제·미확인을 조용히 덮어쓰거나 임의 값으로 메우지 않음. JSON은 의미 값 보존, 설명 원문 별도 보존. 날짜/시각은 채택 기준에 따른 정규화·왕복·화면 표시 대조 |

| V07 순환/자료 누락 | 조합법 없는 기본 재료, 조합법이 누락된 대상, 순환 참조를 구분한 입력으로 상세/필요량 계산 | 기본 재료를 정상 종료점으로 취급하되 누락을 필요량 0으로 계산하지 않고 순환으로 무한 계산하지 않음. 내부 판정·화면 상세 처리는 구현 전 설계, 미등록 화면 값은 빈 상태 유지 |

## 실행 근거·미확인과 후속 인계

영향 범위만 보류하는 합의에 따라, 확인한 범위·보류 대상/이유·의존하는 관계/계산을 구분해 기록한다. 부족 자료에 의존하는 결과를 검증 완료로 처리하지 않으며, 일부 범위의 통과를 전체 자료 수용으로 확대하지 않는다. 작업 단위는 테이블별로 정한다. 구체 처리 순서는 참조 관계에 맞춰 정한다. 검증 B에 따라 전체 내부 검사와 대표 화면 확인을 병행하며 자료 내용은 같은 화면에서 사용자와 함께 대조한다. 실제 대조 대상·실행 절차는 제공 자료와 화면이 준비된 뒤 정한다.

실제 실행은 해당 Task 또는 직접 수행 Issue의 기존 검증 구역에 대상 후보/버전·자료/출처·입력·기대 결과·방법·관찰/출력·판정·미확인·필요한 재확인 범위를 남긴다. 필요한 실제 첨부만 보존하고 사례마다 증명 파일을 만들지 않는다. 자동 검사와 화면 조작·원자료 대조는 서로의 대체가 아니다.

Task 005는 다음을 담당 과제의 범위·수용 조건·선후 관계에 배정한다.

- 자료/DB·API·조회: 입력/출처 준비, V01·V02·V05·V11·V12와 실제 원자료 대응.
- 검색·상세/공통 디자인: V03·V04와 등록 전 확인 화면, 조건/스크롤 복귀 및 빈 상태.
- 제작·루트: V06~V10, 실제 최초 보유 입력·수량 대조 및 재료 합산 대안의 반복 실험. 구체 입력·환경·평가 기준은 실행 계획에서 확정.
- 자료·보존: Java/Spring 기본 교정·독립적인 직접 DB 수정 예외·최초 등록 수단·실패 복구·관련 결과 재확인. 현재 선택기를 구현하지 않아도 과거 상태/참조 보존은 검증.
