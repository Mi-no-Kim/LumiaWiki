### 범위

- 독립적인 목표와 수용 조건을 기준으로 후속 Issue의 경계를 정한다.
- Issue별 목표·범위·수용 조건·대상 화면·필요 입력·의존 관계와 미정의 결정 시점을 정리한다.
- 각 Issue의 Task는 나눌 결과·역할·선후 관계의 윤곽까지 정한다. 작은 Issue는 Task 없이 직접 수행할지 판단한다.
- 최소 실행·등록 기반, 시즌·버전의 구현·초기 등록·자료 연결, 아이템 정보·조회·제작 관계·루트·보존·검증을 담당할 과제가 빠지지 않게 한다.
- 공통·기존 화면의 사용 관계와 화면 디자인 → 동작 구현 → 화면이 있는 상태에서 검증하는 순서를 연결한다.
- [Task 003의 TDD 기준](<task-003.md#tdd>)에 따라 기반 구축에는 테스트 실행 환경을, 기능 과제에는 화면 설계 → 실패 테스트·최소 구현·통과·리팩터링 → 실제 화면 검증을 연결한다. 적용 범위·예외의 이유와 대표 검증 근거는 담당 Task의 검증 계획·기록에 포함한다.
- [TDD 자동화 인계](<task-003.md#tdd-automation-handoff>)에 따라 첫 기반 구축 과제의 초반에 테스트 환경 구성 후 최소 hook을 연결·검증하도록 범위·수용 조건을 배정한다. 이를 첫 기능 동작 구현의 선행 조건으로 명시하고 등록 시 실제 과제를 [Phase 착수 조건](<../phase.md#tdd-readiness>)에 연결한다.
- [공통 검사·포맷 인계](<artifacts/task-003-code-quality.md#handoff>)에 따라 첫 기반 구축 과제에 TypeScript lint 호환 구성, 문서·일괄 포맷 명령, 파일 생성/수정 자동 포맷과 제출 후보 검사·실제 검증을 배정한다. TypeScript 병행과 포맷 방식은 Task 003의 채택 기준을 따른다.
- [CI 인계](<artifacts/task-003-handoff.md#handoff-decisions>)에 따라 첫 기반 구축 Issue에 CI 도구·트리거·명령·영향 영역의 설계와 검사·테스트·빌드 독립 실행 연결·검증을 배정한다. 로컬 명령을 마련한 뒤 연결하고 해당 기반 과제 완료 전 실제 통과/실패 처리를 확인하도록 수용 조건에 명시한다. 실제 번호는 등록 시 연결하며 이번 Task 005에서 CI를 구현하지 않는다.
- [사용자 확인 목록](<artifacts/task-003-testing-and-tdd.md#user-checklist>)에 따라 각 기능 과제의 동작 구현 전에 조작·기대 결과를 작성·공유하고, 구현 후 AI의 실제 검증 결과와 사용자 확인 절차·미확인을 구분해 전달하도록 실행·검증 계획에 연결한다. 같은 사례를 자동 테스트·브라우저 확인에 재사용한다.

- [Task 003의 최종 의존·인계](<artifacts/task-003-handoff.md#dependencies>)에서 기반·저장/조회·확인용 화면·등록·제작·루트의 선행 관계와 [후속 미정](<artifacts/task-003-handoff.md#handoff-decisions>)의 담당·입력·시점을 실제 과제에 배정한다. 배포 환경별 API 문서 노출·SPA fallback·운영 권한/로그/백업도 해당 환경 적용 전 결정할 담당으로 연결한다.

- [Task 001의 이월 목록](<artifacts/task-001-discussion-details.md#handoff-decisions>)의 각 P1 상세 결정을 담당 기능 묶음과 결정 시점에 배정한다. DB 관계·일치 검사·캐시 갱신, 자료/정정 수단, 루트·임시 아이템 취급과 재료 합산 실험을 누락하지 않는다. 독립 관리 전환은 후속 추적에 연결하고 수식은 딜량 계산기 작업 전의 선행 조건으로 두지 않는다.

상세 Task의 범위·완료 조건·실행·검증 계획은 각 후속 Issue를 준비할 때 정한다. 첫 착수 Issue만 상세 Task 계획을 미리 작성하는 작업도 이 Task에 포함하지 않는다. 실제 번호가 없는 과제는 제목과 관계로 관리한다.

### 완료 조건

- Task 001의 P1 포함 범위 전체가 담당 Issue 구성안에 연결되고 누락·중복 보유가 없다.
- Issue별 목표·범위·수용 조건·대상 화면·필요 입력·의존 관계가 정리되어 독립적으로 수용 판단할 경계가 드러난다.
- Task 윤곽 또는 직접 수행 판단과 선후 관계가 정리되어 있다.
- 디자인·동작 구현·화면 검증, 확인용 페이지·자료 입력의 선행 관계가 반영되어 있고 의존 순환이 없다.
- 테스트 환경 구축과 기능별 TDD 절차·대표 검증 근거, 구현 전 사용자 확인 목록 작성·공유와 구현 후 확인 안내가 Task 003 기준에 따라 배정되어 있다.
- 첫 기반 구축 과제의 테스트 환경·최소 TDD hook 연결·실제 검증과 첫 기능 구현의 선행 조건이 빠짐없이 배정돼 있다. 해당 배정 없이 Task 005를 완료로 처리하지 않는다.
- 첫 기반 구축 Issue에 CI 구축·독립 실행 검증의 담당과 시점(로컬 명령 준비 후, 기반 과제 완료 전), 정상 통과·통제한 검사/테스트 실패의 CI 반영, 후속 기능 PR에서의 결과 확인이 배정돼 있다. 해당 배정 없이 Task 005를 완료로 처리하지 않는다.
- 후속으로 남길 항목과 결정할 시점·담당 과제가 구별되어 있다.
- 다음 착수 Issue와 착수 준비 조건이 정해져 있다. Task의 상세 실행 계획 작성이나 제품 구현을 이 Task의 완료로 요구하지 않는다.

## 계획과 예정 검증

- 선행 조건: Task 001~004의 결과.
- 수행: 범위를 독립 결과로 묶기 → Issue별 경계·수용 조건 작성 → Task 윤곽·직접 수행 판단 → 화면·자료·기술 의존 연결 → 순서·다음 착수 대상 선정.
