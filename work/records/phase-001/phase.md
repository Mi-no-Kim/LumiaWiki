<a id="goal"></a>
## 목표와 범위 및 수용 조건

아래는 해당 단계의 범위와 검토용 수용 조건이다. 합의된 제품 요구를 기준으로 진입 또는 관련 Issue 착수 전에 세부 수용 기준을 확정한다.

**공동 목표/기대 결과**

시즌 1·버전 1.0.0의 아이템 정보를 DB에 등록하고, 조회·제작 관계·기본 루트 계산을 통해 자료가 실제로 작동하는 상태를 만든다.

**포함 범위**

- 시즌·버전 구조를 마련하고 시즌 1과 버전 1.0.0을 등록한다.
- 아이템 및 관련 데이터 구조를 논의·결정하고 생성한다. 능력치·아이템 스킬 설명·조합법·획득 지역·배달 정보 등 필요한 연결도 함께 다룬다.
- 자료 입력 전에 간단한 검색 페이지와 개별 아이템 페이지를 마련해 입력 결과를 확인할 수 있게 한다.
- 상·하위 제작 관계를 연결하고 표시한다.
- 이 단계에서 확정한 최소 옵션으로 루트 계산을 구현한다.
- 후속 패치를 반영해도 기준 자료를 잃지 않도록 버전 연결과 원자료 보존 원칙을 갖춘다.

**완료 조건 — 검토 기준**

- v1.0.0 아이템 자료가 확정한 정보 항목을 기준으로 DB에 등록돼 있다.
- 간단한 검색·개별 페이지에서 등록 내용과 연결 관계를 확인할 수 있다.
- 확정한 최소 범위의 제작 관계 표시와 루트 계산이 실제 자료로 작동한다.
- 미지원 옵션과 P5에서 완성할 기능이 구분돼 있다.

<a id="plan"></a>
## 계획과 주요 의존

아이템 관련 기능을 우선 구현하는 계획의 첫 단계다. 사용자 제공 실제 자료와 기준 버전, 필요한 관련 정보의 확보 여부를 확인하고 시작한다.

실제 착수 전에는 아래 미정과 [필요한 착수 정보](<../../../docs/작업 기록 작성 기준.md#minimum>)를 확인한다.

<a id="input-workflow"></a>
### 자료 확보·임시 변환 계획

실제 자료는 사용자가 제공한다. 웹사이트·엑셀 등 자료와 해석 방법을 채팅으로 제공받고 AI가 변환을 도우며, 사용자가 지적한 오류를 함께 교정하는 임시 방식이다. 특정 자료 형식·전체 상태/변경 자료 중 하나나 입력 화면의 직접 타이핑으로 한정하지 않는다.

이 임시 작업을 서비스의 상시 업로드·관리 화면이나 영구 운영 절차로 확정하지 않는다. 변환 산출물 형식·검증·저장·반영과 정식 운영으로의 전환은 미정이다. 실제 자료 확보·처리는 사용자 보류 요청이 유지되고 있으므로 재개 요청 뒤 제공 위치·출처·버전과 허용 범위를 확인한다. 자료가 필요하다는 이유로 관련 없는 문서·하네스 준비를 막지 않는다.

<a id="input-readiness"></a>
### 2026-11-01 입력 준비 현황 — 구현 착수 전 조사

| 자료/항목 | 확인 상태·근거 | 부족 입력/다음 확인 |
|---|---|---|
| 정식 출시·시즌1·v1.0.0 아이템 정보 | 현재 일반 작업 영역에서 실제 입력 파일을 찾지 못함. 루트 바로 아래 및 docs/harness/work의 xlsx/xls/csv/tsv/json/zip/sql 목록에 해당 파일 없음 | 실제 경로/URL, 출처·버전/시점 근거, 이름·분류·능력치·스킬 등 포함 정보 확인 |
| 조합법·획득 지역 | 별도 제공 위치/원자료가 현재 기록에 지정돼 있지 않음 | 재료/수량·완성품 관계, 획득 지역 범위와 v1.0.0 적합성 확인 |
| 배달 등 기본 루트 관련 조건 | 현재 요구/계획은 있음. 실제 값의 출처·버전은 미확인 | 필요한 정보와 최소 지원 범위를 진입/관련 Issue에서 정하고 자료와 대조 |
| 기존 요구·제품사양 보관본 | 문서가 있음. 요구/논의의 근거이며 실제 게임 수치 자료로 수용한 것이 아님 | 자료 제공과 요구 기록을 구별. 사용자 원본·ERD/ZIP 내용은 이번 입력 조사에서 열지 않음 |
| 외부 웹/엑셀·보존 자료 내부 | 미확인. 외부 자료를 제공/지정받거나 내용을 조사하지 않음 | 파일이 전혀 없다고 단정하지 않음. 지정받으면 접근·출처·시점/포함 정보부터 확인 |

이는 입력 현황 조사 결과이며 입력 확보/검증·변환·DB 등록·Phase 착수 완료가 아니다. 특정 형식·기술·테이블·옵션을 확정하지 않았다. 필요한 자료는 경로/URL과 출처·시점/버전 근거를 함께 제공받는다.

<a id="entry-decisions"></a>
### Phase 진입 또는 Issue에서 정할 사항

- 실제 제공 자료와 등록 항목, 필요한 테이블·관계·식별 방식.
- 입력 확인용 페이지의 최소 표시·검색 옵션.
- 제작 관계의 초기 표시 범위와 조작 방식.
- 기본 루트 계산의 입력 방식·지원 옵션·결과 항목.
- 자료 정정·검증 방법과 버전 연결의 구체 구현.

<a id="planned-checks"></a>
### 예정 확인

확정한 등록 범위와 실제 자료, 조회·제작 관계·최소 루트 동작을 목표/완료 조건과 대조할 방법을 진입 시 정한다.

실제 검증 결과는 수행한 때 기록한다. 현재는 계획만 등록한 상태다.

## 주요 논의와 판정 근거

아래는 계획 등록 당시 근거다. 이후 계획 변경과 실제 수행은 후속 기록으로 구별한다.

<a id="registration"></a>
### 2026-10-30 검수한 구상 수정안의 정식 계획 등록

사용자의 이관 지시에 따라 검수한 수정안의 목표·범위·검토용 완료 조건·진입/Issue 결정 사항을 이 문서에 등록했다. 미정·후속·제안은 유지했으며 등록을 Phase 착수·완료로 판정하지 않았다. 공통 도입 순서와 반영 이유는 [제품 범위 이력](<../../../docs/history/제품 범위.md#seven-phase-formalization>)에서 확인한다.

<a id="role-separation"></a>
### 2026-11-05 제품 요구와 단계 계획의 역할 정리

사용자의 전체 반영 지시에 따라 단계 경계와 제품 요구·다른 단계의 참조를 정리했다. 포함 범위·검토용 수용 조건과 예정 상태를 유지했으며 기능 구현·Phase 완료를 판정하지 않았다.

<a id="result"></a>
## 결과와 미해결

계획 등록을 마쳤으며 Phase 목표의 실행 결과나 완료 판정은 아직 없다. 남은 결정은 [진입/Issue 결정 사항](<#entry-decisions>)에서 관리한다.
