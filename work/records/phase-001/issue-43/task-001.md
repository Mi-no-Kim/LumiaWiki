## 목적과 허용 범위 및 완료 조건

- 부모 Issue: [Issue #43](issue.md#summary)
- 목적/요청 결과: 시즌·게임 패치·지역·종류 계층·등급·별도 무기 종류를 구별하고 다른 Task가 사용할 식별·참조 기반을 만든다.
- 허용 범위·실제 대상/입력·제약: 최초 구동 구현 파일과 격리 DB 검증은 허용한다. 대상은 db/bootstrap·Compose/예제 환경값·실행기·Spring local 접속 설정과 관련 테스트다. 개인 .env·기존 개발 DB/볼륨·실제 게임 자료와 D1~D4를 가정한 공통 도메인 표 구현은 포함하지 않는다. DB 관련 설명은 [DB 안내](../../../../db/README.md#current)의 목적별 문서도 갱신하며 한 문서에 실행 경과나 전체 설계를 누적하지 않는다. 이번 범위는 물리 설계 문서까지다. 테이블 생성 직전 전체 구조를 사용자에게 다시 보여주고 확인받는 조건은 격리 생성/신규 Flyway 적용 전에도 지킨다.
- 자기 완료 조건·현재 기준/권한 근거: 완료하려면 공유 논리 관계의 선행 검토와 현재 결정 가능한 부분의 사용자 확인, 담당 공통 모델의 승인된 스키마·매핑·저장/조회와 예정된 검증, 후속 참조 계약이 준비돼야 한다. 실제 자료 의존 미정을 선행 검토의 편의를 위해 강제로 확정하지 않는다. 미정인 범위/날짜 허용을 실제 확인 없이 정하거나 실제 자료 등록을 완료로 표시하지 않는다. 담당 미정은 [공통 모델·범위·일시·검증 경로](#decisions)다. 기준은 [부모의 합의한 수용 조건](issue.md#acceptance)과 위 정보 요구다. 현재 구현 범위는 최초 구동과 격리 검증이다.

### 조건부 항목의 적용 판단과 기록

- 실제 자료 의존: 필요한 값·관계가 아직 미확인이고 자료 작업 보류가 적용된다. [자료 단계](issue.md#data-timing)와 아래 미정 표를 기준으로 #45의 입력 확인이 필요한 범위를 구분하며, 보류 해제·입력 확인 전에는 의존하는 설계값·구현·완료 판정을 확정하지 않는다.
- 화면·확인 경로: 저장·조회 확인 경로의 구체 선택이 남아 있다. [공통 검증 경계](issue.md#execution)를 유지하고 새 API/개발용 화면 등 선택이 필요하면 범위·대안·영향을 사용자에게 먼저 제시해 결정받는다. 응답 전에는 해당 동작을 구현하지 않는다.
- 별도 검수: [별도 검수 기준](../../../../docs/details/operations/별도 검수.md)에 따른 커밋 전 검수는 실제 커밋 준비 때 적용한다. 현재 요청은 공유 관계·공통 키/검사/갱신 수단 검토이며 커밋·운영 규칙 변경을 수행하지 않는다.
