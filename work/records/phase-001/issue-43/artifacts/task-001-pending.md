# Task 43-001 — 남은 결정·자료/구현 재개·조건부 예외

<a id="current"></a>

확정한 구현 계약·담당/입력/시점과 범위별 재개·조건부 예외를 확인할 때 읽는다. 담당 상태·수용 판단은 [Task 43-001](../task-001.md#summary), 전체 길잡이는 [설계 안내](task-001-shared-version-references.md#summary)를 따른다. N1~N5와 번호 각각 0~99는 확정이며 합의한 파일/검증과 승인한 로컬 8개 표 적용은 [생성 결과](task-001-creation.md#current)를 따른다. 실제 자료 작업은 계속 보류한다.

<a id="conditional-exceptions"></a>

## 조건부 복원·정비 — 실제 필요가 생길 때 결정

사용자 승인에 따라 아래 예외 절차를 일반 저장/조회 구현의 일괄 선행 조건에서 분리한다. 일반 ID 자동 발급·중복/참조 검사·기존 PK 변경 거부와 최초 구동 검증은 그대로 구현/확인한다. 예외의 보류는 PK/권한 정책의 완화나 실제 실행 승인이 아니다.

| 조건부 작업                          | 담당·필요 입력                                                                               | 결정/검증 시점                                                                                                                        |
| ------------------------------------ | -------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| 새 행에 기존 ID를 보존하는 입력/복원 | 001의 ID/참조 계약, 실제 자료 담당 #45·정비 주체. 보존 대상/원본 ID·충돌/참조·백업/복구 입력 | 그 복원/특수 입력이 실제로 필요할 때 override/COPY 등 수단과 검증을 먼저 확인. 일반 INSERT 구현에 전체 복원 절차 완성을 요구하지 않음 |
| 기존 PK의 키 재배치                  | 001과 해당 참조 담당. 실제 재배치 이유·관련 참조/소유·보존/실패 범위와 사용자 선택           | 개별 예외 검토 전에는 기존 PK 일반 변경 금지 유지. 실제 필요 시 별도 확인하며 지금 우회 경로를 만들지 않음                            |
| 복원 후 시퀀스 보정                  | 001·정비 주체. 실제 보존 ID/발급 상태와 충돌 가능성, 대상 범위                               | 해당 복원/수동 입력이 발급 상태에 영향을 줄 때 검토. 모든 정상 등록에 보정 작업이나 관리 API를 선행시키지 않음                        |
| 기존 DB 소유/권한 이관               | 001, 결합 확인 004. 허용된 상태 조회·기존 객체/자료·보존/차이 입력                           | 기존 DB를 계속 쓸 때 T-A대로 최초 P1 설치 전에 필요한 대상별 이관은 수행해야 함. 빈 새 DB 검증에 범용 이관 도구 완성을 요구하지 않음  |
| 서비스 밖 예외 쓰기                  | 해당 Task와 001. 실제 대상·이유·사전/사후 검사·동시 변경 통제·실패/복구 입력                 | S1대로 해당 예외 쓰기 전에 개별 검토. 일반 구현에 모든 미래 정비 명령·자동 복구 체계를 미리 만들지 않음                               |

실제 복원·이관·정비는 승인한 대상/범위만 진행한다. 현재 승인한 로컬 역할/최소 권한·빈 Flyway 관리 표 소유 준비는 [결과](task-001-creation.md#current)를 따르며, 다른 기존 객체 변경이나 복원은 필요한 새 선택과 범위를 먼저 확인한다. 실제 자료 작업은 계속 보류한다. 자동 볼륨 삭제·권한 확대·비밀번호 교체·검토 없는 재실행은 추가하지 않는다.

## 확정한 구현 계약과 남은 준비

Task 43-001의 8개 표와 N1~N5는 확정 계약이다. 메이저·마이너 각각 0~99는 사용자 확인을 받은 사실이며 패치 정렬값 UNIQUE를 적용한다. 실제 자료는 조사하지 않았다. 제품 DDL은 새 격리 검증 뒤 승인한 로컬에 적용했으며 [생성 결과](task-001-creation.md#current)를 따른다. 실제 자료 작업은 계속 보류한다.

| 결정 | 확정 내용·담당 원천 |
| --- | --- |
| N1 | 시즌 표시 이름·실제 시즌명·패치 이름에 추가 UNIQUE 없음. [저장 구조](../../../../../db/model/table-layout.md#current) |
| N2 | 중복 검사 대상 이름에 COLLATE "C" 명시. 문자열 그대로 비교하고 자동 trim/정규화 없음. [비교 계약](../../../../../db/model/ranges-and-uniqueness.md#name-comparison) |
| N3 | Spring 서비스·저장/조회 코드와 격리 통합 테스트·재현 절차가 초기 구현 범위. 새 HTTP API·관리 화면은 해당 기능에서 설계. [확인 경로](../../../../../db/model/writes-and-checks.md#failure-and-verification) |
| N4 | 확인된 입력 오류 400·없는 조회 대상 404·예상 밖 DB 실패 500, 업무 전체 롤백. 기존 설정에 따른 잠금 대기·추가 시간 제한/자동 재시도 없음. P1 오류 계약 유지 |
| N5 | 제약 이름 명시·새 빈 격리 환경의 V1__create_common_model.sql 한 파일·최초 적용 검증은 새 격리 DB. [설치 계약](../../../../../db/model/permissions-and-installation.md#current) |

위 범위의 기본 정책을 다시 선택할 필요는 없다. 실제 제약별 이름·정확한 실행 환경·재현 명령은 구현 초안과 생성 직전 확인에서 제시한다. 새로운 의미/권한/정책 선택이 생기면 확정 전에 대안과 추천 이유를 먼저 요청한다.

### 실제 자료·DB·구현의 재개 경계

| 실제 작업 | 재개 조건 |
| --- | --- |
| 공통 도메인 구현 파일·DB 없는 검사 | 사용자 보류 해제로 허용. 합의 DDL/매핑·저장/조회·단위 테스트와 관련 문서 작성 |

합의한 파일/검증과 승인한 로컬 8개 표 적용은 완료했다. 실제 자료 작업은 계속 보류하며 후속 신규 구조는 생성 직전 전체 구조/정확한 대상을 다시 확인받는다. 자료 단계는 [부모 Issue](../issue.md#data-timing)를 유지하고 최초 구동 검증·현재 도메인 파일 작성·실제 자료 수용·Task 완료를 구별한다.

## 추가 검토 후보

기본 PK/FK/UNIQUE/NOT NULL/CHECK·업무 트랜잭션·종류 비순환 관계·패치 이력과 정확한 버전 참조를 적용한다. 8개 표·region 작업용 이름·N1~N5·번호 각각 0~99는 확정 계약이다. 파생 정렬 계산/매 기동 전수 검사/외부 비밀 관리 등 아래 항목은 추가 요구가 생길 때 비교하며 초기 구현의 선행 조건이 아니다.

| 후보                                      | 검토 조건과 현재 기준                                                                                                                |
| ----------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| 파생 정렬값의 저장/조회 계산              | 현재는 M2의 저장/계산 규칙을 따른다. 실제 조회 형태와 재계산 비용이 구체화되면 비교하며 성능 이점을 가정해 저장 방식을 변경하지 않음 |
| 매 기동 권한/소유 전수 검사               | 현재는 최초 설치 검증과 기본 기동 오류 처리. 권한 변화 탐지가 필요하거나 공개 운영 경계를 설계할 때 범위를 검토                      |
| 외부 비밀 관리·별도 마이그레이션 프로세스 | 현재는 개인 .env와 같은 Spring 프로세스의 app/Flyway 접속. 운영 배포의 비밀값 공급·격리 요구가 정해질 때 검토                        |

새 선택은 대안·추천 이유·보호 차이를 먼저 확인한다. 실제 자료 작업은 계속 보류한다. 승인한 공통 8개 표의 구현/격리·로컬 적용과 후속 변경의 허용 범위는 구별한다.
