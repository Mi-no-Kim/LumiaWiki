추가하는 `item_version` 컬럼은 기존 행에서 전부 `NULL`로 시작하고, 새 획득 표는 빈 상태로 시작한다. 기존 아이템·능력치·스킬과 그 참조를 보존한다. 장착 부위는 종류로 판별하므로 저장하는 부위 컬럼은 없다. [V2 키와 참조](../../../../../db/migration/V2__create_item_storage.sql) · [V3 컬럼·권한](../../../../../db/migration/V3__complete_item_storage.sql)

### 새 계산용 획득 표

`item_acquisition`의 각 행에 하나의 획득 방법을 저장한다.

| 컬럼              | 자료형                        | 초기값·제약                                                                                               |
| ----------------- | ----------------------------- | --------------------------------------------------------------------------------------------------------- |
| `id`              | `BIGINT` IDENTITY             | 기본키. 기존 PK 변경 방지 함수를 적용한다.                                                                |
| `item_id`         | `BIGINT`                      | 필수. `item(id)`를 직접 참조한다.                                                                         |
| `item_version_id` | `BIGINT`                      | 필수. `item_version`을 참조하며 소속 아이템과 시작 패치가 아래 복합 외래 키에 맞아야 한다.                |
| `game_patch_id`   | `BIGINT`                      | 필수. `game_patch(id)`를 직접 참조한다. 소속 아이템 버전의 시작 패치다.                                   |
| `method`          | `acquisition_method` (`ENUM`) | 필수. 채집 `GATHERING`, 상자 `CHEST`, 사냥 `HUNTING` 중 하나를 저장한다.                                  |
| `region_id`       | `BIGINT`                      | `region(id)`를 참조한다. 상자는 필수이며 채집·사냥에서 `NULL`은 조회 패치 지도에 속한 전 지역이다.        |
| `spawn_count`     | `INTEGER`                     | 상자는 지역 총 출현 개수를 저장하며 `NULL`과 `0`을 허용한다. 채집·사냥은 무한을 뜻하는 `NULL`을 저장한다. |

- **참조.** `(item_id, item_version_id)`와 `(item_version_id, game_patch_id)`는 각각 기존 `item_version(item_id, id)`와 `item_version(id, from_game_patch_id)`를 참조한다. 지역은 지속 ID를 참조하고, Spring에서 해당 관계의 유효 구간에 속하는 지도 구성을 검사한다. 외래 키의 참조 중 삭제 제한과 비지연 검사는 V2와 같은 방식으로 둔다. [기존 제약](../../../../../db/migration/V2__create_item_storage.sql) · [지역 참조와 유효 구간 검사](../../../../../db/model/consumer-references.md#current)
- **중복·지역 충돌.** `EXCLUDE USING gist` 한 개를 둔다. 소속 버전과 방법은 각각 양끝이 같은 범위의 등호로 비교하고, 지역은 지정 ID의 단일점 범위 또는 전 지역의 열린 범위로 겹침을 비교한다. 방법 비교에는 획득 `ENUM`을 원소로 하는 범위 타입을 둔다. 같은 버전·방법의 동일 지역, 전 지역 두 행, 전 지역과 특정 지역을 거부한다. 서로 다른 특정 지역이나 서로 다른 방법은 함께 저장할 수 있다. [PostgreSQL 사용자 정의 범위](https://www.postgresql.org/docs/18/sql-createtype.html) · [배타 제약](https://www.postgresql.org/docs/18/rangetypes.html#RANGETYPES-CONSTRAINT)
- **조회와 권한.** 획득의 `item_version_id`와 A·B 재료의 아이템 ID에 각각 B-tree 인덱스를 둔다. Flyway 계정이 제품 객체를 소유하고 `lumia_app`에는 획득 표의 `SELECT`·`INSERT`·`UPDATE`·`DELETE`와 방법 타입의 `USAGE`를 부여한다. [기존 설치 경로](../../../../../db/migration/README.md#current)

아래는 `ENUM`과 배타 제약에 사용할 타입 정의 예시다.

```sql
CREATE TYPE public.acquisition_method AS ENUM ('GATHERING', 'CHEST', 'HUNTING');

CREATE TYPE public.acquisition_method_range AS RANGE (
    SUBTYPE = public.acquisition_method
);
```

```sql
EXCLUDE USING gist (
    (numrange(item_version_id::numeric, item_version_id::numeric, '[]')) WITH =,
    (public.acquisition_method_range(method, method, '[]')) WITH =,
    (numrange(region_id::numeric, region_id::numeric, '[]')) WITH &&
)
```

## Spring 저장·조회 흐름

1. **기존 아이템 버전 저장을 확장한다.** `ItemCatalogService`의 신규 등록·버전 생성·같은 패치 정정·삭제/복귀 흐름에 제작·배달 정보를 연결한다. 기존 입력을 사용하는 정정은 새 필드를 생략할 때 현재 값을 보존한다. 실제 변경은 새 버전으로 기록하고, 같은 패치 정정은 기존 ID를 유지한다. 삭제 적용 버전은 조합 필드와 획득 행을 비우며 삭제 전 버전은 보존한다.
2. **획득 행은 개별 추가·수정·삭제한다.** 행의 소속으로 아이템과 시작 패치를 구해 세 참조를 일치시킨다. 같은 행의 방법·지역·수량을 변경하거나 그 행을 삭제하면 같은 버전의 나머지 행을 유지한다. 새 버전에 승계할 행은 새 버전과 시작 패치로 복사한다. Spring과 DB가 발견한 충돌은 기존 업무 오류 변환 경로에서 같은 의미로 전달한다. 별도 사냥 자료를 대조할 수 있을 때 그 자료와의 차이는 경고로 전달하고 요청한 행을 저장한다.
3. **여러 아이템의 추가·변경은 하위부터 저장한다.** 같은 패치에 묶인 요청 전체에서 신규·변경 조합을 읽어 최종 참조와 영향받는 직·간접 상위를 파악한다. 조합에서 참조할 하위 아이템과 버전의 추가·변경을 끝낸 뒤 상위 아이템을 저장한다. 같은 패치에 상위 버전이 있으면 직접 변경을 유지하고 재료 참조를 갱신한다. 완성된 자체 변경 입력의 등급 검사는 기존대로 적용하며, 재료 참조만 바뀌는 파생 버전은 이관 행의 빈 등급을 포함해 이전 값을 승계하는 안이다. 순서가 성립하지 않거나 저장에 실패하면 요청 전체를 되돌린다. [기존 등급 저장 기준](task-002-execution.md#remaining-storage-design)
4. **동시 쓰기는 기존 잠금 기준에 맞춘다.** 패치·지도 기준을 먼저 잠그고 기존 능력치 잠금을 이어서 잡는다. 제작 변경으로 영향을 받는 아이템과 최종 조합의 재료 아이템을 ID 순으로 잠근 뒤 사용처와 최종 참조를 다시 읽는다. 잠금 범위 밖의 새 의존이 확인되면 요청을 되돌리고 충돌을 알린다. 지도·패치 순서 변경에서도 획득 행의 지역 유효성을 대조한다. [공통 잠금 순서](../../../../../db/model/writes-and-checks.md#catalog-locking) · [아이템 쓰기](../../../../../backend/src/main/java/io/github/minokim/lumiawiki/catalog/ItemCatalogService.java)
5. **조회 계약을 인계한다.** 버전 ID로 조합·배달 값과 획득 행을 읽고 저장된 재료 버전을 따른다. 조회 패치에 맞는 아이템 버전과 지도 구성을 결합하는 확인은 [43-004](../task-004.md#plan)에 연결한다. #44는 상세 표시, #46은 제작 관계·총량, #47은 획득 가능 지역·배달 계산에 이 계약을 사용한다.

## 구현 전에 정할 범위

- **후속 패치 구간.** 같은 요청에 신규 아이템을 참조할 때는 요청 안의 키로 대상을 찾고 저장 시 실제 아이템·버전 ID로 연결한다. 과거 패치 삽입·정정으로 후속 버전의 유효 구간이 바뀌는 경우는 43-004의 결합 조회·갱신과 대조한다.
- **#45 자료가 필요한 항목.** 실제 수량 범위, 상자 수량 누락이나 `0`의 의미, 배달 비용의 단위, 사냥·임시 대상과 삭제·복귀 사례를 확인한다. 자료가 필요한 검사와 수용은 입력이 도착한 범위에서 판정한다. [#45 자료 입력](../../issue-45/issue.md#data)
