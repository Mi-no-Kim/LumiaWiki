# Phase 007 — 공개용 딜 계산기 완성

<a id="summary"></a>
## 현재 요약

- 제목: 공개용 딜 계산기 완성
- 구상상 구분: P7
- 상태: 예정
- 현재 진행 위치: 제품 요구와 단계 계획의 역할에 맞춰 범위·참조를 정리했다. 기능 구현에는 착수하지 않았다.
- 다음 판단/행동: 공개 계산의 제품 요구를 합의하고, 내부 기반의 확장 범위·자료 준비와 검증 방법을 구체화한다.

<a id="goal"></a>
## 목표와 범위 및 수용 조건

아래는 해당 단계의 범위와 검토용 수용 조건이다. 합의된 제품 요구를 기준으로 진입 또는 관련 Issue 착수 전에 세부 수용 기준을 확정한다.

**공동 목표/기대 결과**

P3의 내부용 계산기를 확장·정비하여, 정한 계산 범위를 실제 사용자에게 제공한다.

**포함 범위**

- 공개할 계산 종류·조건·버전과 입력을 완성한다.
- 아이템·캐릭터·특성·게임 규칙에 따른 계산을 확장하고 검증한다.
- 게임 실행 없는 피해량 계산과 미적용 변경 조건의 성능 예측을 제공한다.
- 입력 화면·결과 표현·지원 범위 안내 등 사용자 기능을 완성한다.

**완료 조건 — 검토 기준**

- 확정한 공개 계산 범위가 검증 기준을 충족한다.
- 사용 자료·규칙·수식의 버전이 일치한다.
- 사용자가 입력·결과·지원 범위를 이해하고 이용할 수 있다.
- 미지원·불확실한 계산 조건이 구별돼 있다.
- 공개에 필요한 확인을 마치고 사용자에게 제공할 수 있다.

**기준 원천**

[딜량 계산기의 입력·지원 요구](<../../../docs/details/product/딜량 계산기.md#current>) · [아이템 스킬과 계산 표현의 경계](<../../../docs/details/product/게임 데이터 변경 관리.md#item-skills>)

<a id="stage-boundary"></a>
## 단계 경계

미지원·미확정 계산을 자동 포함하지 않는다. 이번 공개 범위와 검증 기준을 진입 또는 관련 Issue에서 확정한다.

<a id="plan"></a>
## 계획과 주요 의존

계획상 [Phase 006](<../phase-006/phase.md#goal>) 뒤에 배치한다. [Phase 003](<../phase-003/phase.md#goal>)의 내부 계산 기반과 확보한 게임 자료/규칙을 사용한다. 초기 공개의 정확한 배치는 P6의 제안 상태를 유지한다.

실제 착수 전에는 아래 미정과 [필요한 착수 정보](<../../../docs/작업 기록 작성 기준.md#minimum>)를 확인한다.

<a id="entry-decisions"></a>
### Phase 진입 또는 Issue에서 정할 사항

**제품 요구로 합의·반영할 사항**

- 단발 피해·지속 피해·DPS 등 공개 계산 종류, 공격·방어·발동·지속·중첩 조건, 지원 버전과 미적용 변경 조건의 지정 방식.
- 사용자 화면·결과 표현·공개 범위와 계산 결과의 허용 기준. 결정은 [딜량 계산기 요구](<../../../docs/details/product/딜량 계산기.md#pending>)에 반영한다.

**이 단계의 준비·구현 선택**

- P3 기반의 재사용·확장 범위와 필요한 자료·게임 규칙의 확보.
- 합의된 허용 기준에 대조할 수식 검증의 근거·방법과 단계 수용 판단.

<a id="planned-checks"></a>
### 예정 확인

공개 계산 범위의 정확성·자료/규칙 버전·지원 범위 안내·사용자 이용 흐름을 정한 기준과 대조한다.

실제 검증 결과는 수행한 때 기록한다. 현재는 계획만 등록한 상태다.

<a id="activity"></a>
## 주요 논의와 판정 근거

아래는 계획 등록 당시 근거다. 이후 계획 변경과 실제 수행은 후속 기록으로 구별한다.

<a id="registration"></a>
### 2026-10-30 검수한 구상 수정안의 정식 계획 등록

사용자의 이관 지시에 따라 검수한 수정안의 목표·범위·검토용 완료 조건·진입/Issue 결정 사항을 이 문서에 등록했다. 미정·후속·제안은 유지했으며 등록을 Phase 착수·완료로 판정하지 않았다. 공통 도입 순서와 반영 이유는 [제품 범위 이력](<../../../docs/history/제품 범위.md#seven-phase-formalization>)에서 확인한다.

<a id="role-separation"></a>
### 2026-11-05 제품 요구와 단계 계획의 역할 정리

사용자의 전체 반영 지시에 따라 단계 경계와 제품 요구·다른 단계의 참조를 정리했다. 포함 범위·검토용 수용 조건과 예정 상태를 유지했으며 기능 구현·Phase 완료를 판정하지 않았다.

<a id="result"></a>
## 결과와 미해결

계획 등록을 마쳤으며 Phase 목표의 실행 결과나 완료 판정은 아직 없다. 남은 결정은 [진입/Issue 결정 사항](<#entry-decisions>)에서 관리한다.
