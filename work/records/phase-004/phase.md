# Phase 004 — 다음 메이저 패치 반영과 변경 처리·표현 정비

<a id="summary"></a>
## 현재 요약

- 제목: 다음 메이저 패치 반영과 변경 처리·표현 정비
- 구상상 구분: P4
- 상태: 예정
- 현재 진행 위치: 제품 요구와 단계 계획의 역할에 맞춰 범위·참조를 정리했다. 기능 구현에는 착수하지 않았다.
- 다음 판단/행동: 목표 메이저 패치·중간 패치 목록·대상 범위를 확정하고 표현 준비와 실제 반영을 이어간다.

<a id="goal"></a>
## 목표와 범위 및 수용 조건

아래는 해당 단계의 범위와 검토용 수용 조건이다. 합의된 제품 요구를 기준으로 진입 또는 관련 Issue 착수 전에 세부 수용 기준을 확정한다.

**공동 목표/기대 결과**

다음 메이저 패치까지 자료를 반영하면서, 버전 변화의 저장·조회·표현에 필요한 기능을 실제 변경을 통해 보완한다.

**포함 범위**

- 우선 패치노트를 보여줄 기본 표현을 마련한다.
- 대상 패치를 실제로 반영한다.
- 반영 과정에서 발견한 문제를 바탕으로 무엇을 추가·변경할지 논의하고 개선한다.
- 버전별 당시 상태, 개별 대상의 변경 이력, 개별 패치의 요약을 연결한다.
- 실제 게임 변경과 입력 오류 정정을 구별한다.
- 속성별 변경 항목의 적용·되돌리기와 관련 영향의 반영을 다룬다.

**완료 조건 — 검토 기준**

- 목표로 정한 다음 메이저 패치까지의 반영 범위가 충족돼 있다.
- 이전 상태와 새 상태를 보존하고, 조회 정보의 버전이 일치한다.
- 당시 상태·변경 이력·패치 요약을 확인할 수 있다.
- Phase 목표에 필요한 변경 처리·정합성 문제가 해결돼 있다.
- 새로 발견한 사항 중 필수 보완과 후속 사항이 구분돼 있다.

## 계획과 주요 의존

계획상 [Phase 003](<../phase-003/phase.md#goal>) 뒤에 진행한다. [Phase 001](<../phase-001/phase.md#goal>)부터의 기준 상태와 확보한 패치 자료를 바탕으로 실제 변경과 연결 영향을 확인한다.

실제 착수 전에는 아래 미정과 [필요한 착수 정보](<../../../docs/작업 기록 작성 기준.md#minimum>)를 확인한다.

<a id="entry-decisions"></a>
### Phase 진입 또는 Issue에서 정할 사항

- 목표 메이저 패치와 반영할 중간 패치 목록, 대상 종류.
- 패치 표시 방식과 변경 전후 정보를 이해시키는 표현.
- 최신 메이저 패치부터의 비교 구상을 구체화할 기준과 표시 범위.
- 버전별 저장·조회·정정·적용·되돌리기의 구체 방식.
- 수식·제작 관계 등 연결된 정보가 바뀔 때의 처리.

<a id="planned-checks"></a>
### 예정 확인

이전/새 상태의 보존·버전 일치·이력/요약·개별 변경 적용/되돌리기와 영향 반영을 확인할 방법을 정한다.

실제 검증 결과는 수행한 때 기록한다. 현재는 계획만 등록한 상태다.

<a id="activity"></a>
## 주요 논의와 판정 근거

아래는 계획 등록 당시 근거다. 이후 계획 변경과 실제 수행은 후속 기록으로 구별한다.

<a id="registration"></a>
### 2026-10-30 검수한 구상 수정안의 정식 계획 등록

사용자의 이관 지시에 따라 검수한 수정안의 목표·범위·검토용 완료 조건·진입/Issue 결정 사항을 이 문서에 등록했다. 미정·후속·제안은 유지했으며 등록을 Phase 착수·완료로 판정하지 않았다. 공통 도입 순서와 반영 이유는 [제품 범위 이력](<../../../docs/history/제품 범위.md#seven-phase-formalization>)에서 확인한다.

<a id="role-separation"></a>
### 2026-11-05 제품 요구와 단계 계획의 역할 정리

사용자의 전체 반영 지시에 따라 단계 경계와 제품 요구·다른 단계의 참조를 정리했다. 포함 범위·검토용 수용 조건과 예정 상태를 유지했으며 기능 구현·Phase 완료를 판정하지 않았다.

<a id="result"></a>
## 결과와 미해결

계획 등록을 마쳤으며 Phase 목표의 실행 결과나 완료 판정은 아직 없다. 남은 결정은 [진입/Issue 결정 사항](<#entry-decisions>)에서 관리한다.
