# Phase 006 — 최신 버전까지의 자료 반영과 AI 패치노트 변환 도입

<a id="summary"></a>
## 현재 요약

- 제목: 최신 버전까지의 자료 반영과 AI 패치노트 변환 도입
- 구상상 구분: P6
- 상태: 예정
- 현재 진행 위치: 제품 요구와 단계 계획의 역할에 맞춰 범위·참조를 정리했다. 기능 구현에는 착수하지 않았다.
- 다음 판단/행동: 최신까지 반영할 패치/대상 범위와 AI 입력·변환·관리자 검토/적용 절차를 구체화한다.

<a id="goal"></a>
## 목표와 범위 및 수용 조건

아래는 해당 단계의 범위와 검토용 수용 조건이다. 합의된 제품 요구를 기준으로 진입 또는 관련 Issue 착수 전에 세부 수용 기준을 확정한다.

**공동 목표/기대 결과**

자료를 최신 버전까지 확장하고, AI 변환과 관리자 검토를 거쳐 패치를 반영하는 흐름을 갖춘다.

**포함 범위**

- 기존 반영 흐름으로 패치 자료를 누적한다.
- 아이템은 시즌 1·1.0.0부터 공개 시점 최신 패치까지 정보와 변경 이력 전체를 제공한다.
- P2에서 추가한 대상은 별도로 확정한 기간·범위에 따라 반영한다.
- 앞선 주요 기능의 정상화를 확인한 뒤 AI 패치노트 변환을 도입한다.
- 패치노트 원문 → AI 해석·구조화 → 서비스 데이터 변환 → 관리자 확인·수정 → 공개 적용을 연결한다.

**완료 조건 — 검토 기준**

- 전체 기간의 아이템 정보·이력 조회 요구를 충족한다.
- 다른 대상도 이 단계에 확정한 자료 범위를 충족한다.
- AI 변환 결과를 관리자가 확인·수정하고 적용할 수 있다.
- 반영 후 정보·이력·연결 관계가 일치하는지 확인할 수 있다.
- 초기 공개에 필요한 기능·자료·사용성 조건을 확인한다.
- 공개 조회·계산과 지정 관리자의 수동 변경 권한 구분을 충족한다.

**기준 원천**

[초기 공개 조건](<../../../docs/프로젝트 목표와 범위.md#delivery>) · [AI 변환의 입·출력과 단계적 전환](<../../../docs/details/product/게임 데이터 변경 관리.md#ai-transition>)

<a id="release-proposal"></a>
### 초기 공개 배치 제안

공개 배치 제안: P6 이후·P7 이전. 채택 여부는 미확정이며, 초기 공개 여부는 [제품 공개 조건](<../../../docs/프로젝트 목표와 범위.md#delivery>)의 실제 충족을 별도로 판단한다. 이 배치에서는 딜량 계산기를 내부용 상태로 유지한다.

<a id="stage-boundary"></a>
## 단계 경계

AI가 확인·수정·공개 적용까지 최종 담당하도록 확대하는 시점·조건과 작업 배치는 후속이다. 공개용 딜량 계산기 완성은 [P7](<../phase-007/phase.md#goal>)에 둔다.

<a id="plan"></a>
## 계획과 주요 의존

계획상 [Phase 005](<../phase-005/phase.md#goal>) 뒤에 진행한다. AI 도입은 대상별 패치 이력 조회·패치 요약·루트 계산의 정상화 확인 뒤에 둔다. 그전 입력은 수동으로 관리하며 초기 자료의 채팅 변환 보조와 서비스의 AI 자동 변환을 구별한다.

실제 착수 전에는 아래 미정과 [필요한 착수 정보](<../../../docs/작업 기록 작성 기준.md#minimum>)를 확인한다.

<a id="entry-decisions"></a>
### Phase 진입 또는 Issue에서 정할 사항

- 자료 범위를 대조할 패치 목록과 최신 버전 확인 절차.
- 아이템 외 대상의 반영 기간·범위.
- AI 변환의 입력 확보·게시 감지·수집 방식.
- 변환 형식·검증·오류 교정·적용 절차.
- 관리자 확인과 공개 적용의 구체 흐름.

<a id="planned-checks"></a>
### 예정 확인

초기 공개 대상 기간의 자료/기능 충족과 변환→관리자 검토/수정→적용 및 관련 정보의 일치를 확인한다.

실제 검증 결과는 수행한 때 기록한다. 현재는 계획만 등록한 상태다.

<a id="activity"></a>
## 주요 논의와 판정 근거

아래는 계획 등록 당시 근거다. 이후 계획 변경과 실제 수행은 후속 기록으로 구별한다.

<a id="registration"></a>
### 2026-10-30 검수한 구상 수정안의 정식 계획 등록

사용자의 이관 지시에 따라 검수한 수정안의 목표·범위·검토용 완료 조건·진입/Issue 결정 사항을 이 문서에 등록했다. 미정·후속·제안은 유지했으며 등록을 Phase 착수·완료로 판정하지 않았다. 공통 도입 순서와 반영 이유는 [제품 범위 이력](<../../../docs/history/제품 범위.md#seven-phase-formalization>)에서 확인한다.

<a id="role-separation"></a>
### 2026-11-05 제품 요구와 단계 계획의 역할 정리

사용자의 전체 반영 지시에 따라 단계 경계와 제품 요구·다른 단계의 참조를 정리했다. 포함 범위·검토용 수용 조건과 예정 상태를 유지했으며 기능 구현·Phase 완료를 판정하지 않았다.

<a id="result"></a>
## 결과와 미해결

계획 등록을 마쳤으며 Phase 목표의 실행 결과나 완료 판정은 아직 없다. 남은 결정은 [진입/Issue 결정 사항](<#entry-decisions>)에서 관리한다.
