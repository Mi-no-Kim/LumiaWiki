## 현행 경로와 신규 도입 기준 확인

- 할 일: [현행 경로와 신규 도입 기준 확인](../task-001.md#work-baseline)
- 조치·판단: 기존 Task의 작성 진입점은 생성 지시서와 본문 양식이고, 검사기는 정식 경로에 동일한 보호 원문을 적용한다. 신규 양식과 검사 기준을 추가해 분리 계획을 적용하고, 이미 작성된 정식 Task는 도입 시점의 실제 경로로 기존 검사를 받게 한다. 명시 요청을 받은 개별 전환은 정확한 경로와 승인 근거, 상태·증거·참조를 대조한다.
- 확인: r001과 Issue 결정 1·2, 현행 Task·Issue 양식과 검사 정책을 대조했다. 신규 계획은 담당 Issue의 `artifacts/task-<순번>-plan.md`를 사용하고 상태·현재 위치와 완료 체크는 각 소유 원천에 둔다. 현재 승인 범위는 구현이며 실제 기존 Task의 전환 요청은 없었다.
- 잔여: 없음. 적용 결과는 다음 단계 근거에 연결한다.

## 새 양식과 절차 연결

- 할 일: [새 양식과 절차 연결](../task-001.md#work-templates)
- 조치·판단: 신규 본문과 상세 계획의 양식을 추가하고 기록 체계·작성 기준·생성 절차를 연결했다. 계획의 단계 순서·완료와 수행 근거 링크는 계획에서 관리한다.
- 확인: 실제 새 양식으로 한 단계와 여러 단계 계획을 만들어 상태, 계획 역링크와 단계 ID를 검사했다. 부모 Issue의 결과 대기와 수용 참조도 대조했다.
- 잔여: 없음.

## 신규·기존 형식 검사 연결

- 할 일: [신규·기존 형식 검사 연결](../task-001.md#work-checker)
- 조치·판단: 기존 정식 Task 경로 7건은 기존 보호 원문을 유지하고 신규 본문·계획과 명시 승인 전환의 검사를 추가했다. 승인 범위·현재 위치·완료 근거 역링크를 검증한다. 완료 재검수 지적에 따라 기존 마침표 근거 링크의 전환 대응, 계획 없는 본문의 필수 전달본·다음 행동, 본문 완료 체크 금지까지 확인한다.
- 확인: 공통 주석·상태, 작업 폴더 현황, 별도 계획·전환 회귀 26개가 통과했다. 별도 검토자가 다른 Task 위치 링크, 틀린 근거 역링크, 완료·표식 손실을 거부하는 동작을 대조했다.
- 잔여: 없음. 전체 회귀 확인은 아래 검수 단계에서 처리한다.

## 검수와 후속 전달

- 할 일: [검수와 후속 전달](../task-001.md#work-handoff)
- 조치·판단: 완료 재검수 지적을 반영해 검사와 수행 예정 위치 안내를 바로잡았다. 부모 등록 원본 일곱 개를 당시 지문과 대조해 `c6364f0`으로 보존하고 Task 브랜치에 fast-forward했다. 커밋 전 대조에서 새 정책을 읽지 못하던 상태 확인 도구를 보완했다. 후속 기준은 아래에 남겼다.
- 확인: Windows 제한 환경에서 MSYS Git 훅 프로세스 시작이 거부됐다. 제한 밖에서 같은 격리 임시 저장소 회귀를 실행해 134개가 통과했다. 상태 확인 도구의 인덱스 회귀 9개도 통과했다. 작업 폴더의 공통 검사·현황 검사, 한 단계·여러 단계 양식과 부모 Issue 결과 대기, 재검수 범위에서 r001을 대조했다. 병합 전 로컬 검수에서는 자동 훅 발동, 원격 CI, 실제 기존 기록 전환과 채팅 압축을 관찰하지 않았다.
- 반영 확인: [PR #92](https://github.com/Mi-no-Kim/LumiaWiki/pull/92)의 Ubuntu·Windows CI가 통과했다. 부모 브랜치의 squash 커밋 [`68a4862`](https://github.com/Mi-no-Kim/LumiaWiki/commit/68a4862468f2f499ab3de7e5ae9ca255d1dfd0b9)는 원래 부모 `c6364f0`를 단일 부모로 가지며 검수한 Task 커밋 `855b023`과 전체 파일 트리가 일치했다.
- 잔여: 없음.

<a id="handoff-contract"></a>

### 후속 Task에 전달할 기준

- 87-002는 신규 Task의 [본문 양식](<../../../../../harness/templates/task-with-plan.md#body>)과 [상세 계획 양식](<../../../../../harness/templates/task-plan.md#body>)을 읽는다. 본문의 요약은 현재 상태·위치·다음 행동·막힘을, 계획은 순서·고정 ID·합의·완료 체크를 소유한다.
- 계획 경로는 담당 Issue의 `artifacts/task-<순번>-plan.md`다. 미작성은 계획과 수행 기록이 없을 때 사용한다. 계획 작성 후 현재 단계는 그 계획의 `stage-…`에 연결하고, 완료 단계는 실제 `task-<순번>-execution.md#work-…`와 왕복 연결한다. 본문과 계획의 적용 전달본은 같아야 한다.
- 기존 정식 Task는 현재 형식으로 읽는다. [개별 전환 절차](<../../../../../harness/Task 공통 절차.md#task-format-migration>)에 따라 요청을 받은 경우에만 대상 경로·승인·기존 상태·완료·표식·근거를 대조한다.
- 87-003은 한 단계·여러 단계 Task와 Issue의 자식 결과 대기에서 상태·적용 전달본·실제 근거·다음 행동을 대조한다. 실제 컨텍스트 압축 후 재개와 자동 훅 필요성은 시범에서 판정한다.
