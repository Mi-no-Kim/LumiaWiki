# Task 87-001 확정 전달사항

- 태그: 조사, 논의, 결정, 실행, 검수

<a id="purpose"></a>

## 목적

Issue의 배정·수용과 Task의 실행 계획이 각자의 담당 기록에서 관리되도록 하고, 신규 Task 본문에서 현재 결론을 빠르게 찾을 수 있게 한다.

<a id="result"></a>

## 기대 결과

별도 Task 계획과 간결한 본문·수행 기록의 연결을 정의한다. Issue의 배정·의존·수용 기록과 이를 뒷받침하는 절차·양식·검사를 맞춘다. 스킬 Task가 사용할 경로·필드·상태 기준을 전달한다.

<a id="scope"></a>

## 이미 정해진 조건

- 조건: Task 계획은 별도 파일에 두고, 확인 가능한 단계와 순서가 있는 세부 작업, 완료 기준과 체크를 한 곳에서 관리한다.
  - 적용 범위: 신규 Task 계획과 본문
  - 확정 근거: [결정 1](../issue.md#decision-1) · [결정 2](../issue.md#decision-2)
- 조건: 본문에는 현재 결론과 근거 링크를, 수행 기록에는 실제 검증·실패·복구 근거를 둔다. Issue는 담당 결과·의존 관계·수용 조건을 관리한다.
  - 적용 범위: Issue·Task 본문, 적용 전달본과 수행 기록의 연결
  - 확정 근거: [결정 2](../issue.md#decision-2)
- 조건: 현행 보호 주석과 고정 기존 기록의 적용 범위를 대조한다. 보호 주석을 개정할 필요가 생기면 명시 개정 절차를 따른다.
  - 적용 범위: 신규 형식 도입과 기존 기록 호환
  - 확정 근거: [규칙 주석·상태 검사](<../../../../../harness/문서 관리.md#record-rule-comment-check>)

- 조건: 현행 Issue·Task 기준·절차·양식·검사와 Issue #87의 확정 결정을 사용한다.
  - 적용 범위: 본작업의 입력과 실행 선행 조건.
  - 확정 근거: [Issue의 Task 분해·배정](../issue.md#assignment-plan)

- 조건: 현재 사용자 요청 범위는 정식 작성과 GitHub 등록이다. Task 본작업은 착수 지시와 계획 합의 후 진행한다.
  - 적용 범위: 해당 Task의 생성과 후속 실행.
  - 확정 근거: [Issue의 배정 및 정식 작성·등록 요청](../issue.md#assignment-001)

<a id="decisions"></a>

## Task에서 결정할 사항

세부 선택의 결정 주체와 위임 범위는 착수 때 확인한다. Issue 범위나 수용 조건이 달라지는 선택은 Issue에서 합의한다.

- 결정할 사항: 신규 형식의 계획 경로·필수 필드·단계 식별을 어떻게 정의할까?
  - 결정 범위: 계획 체크의 단일 원천, 본문의 현재 위치와 수행 근거의 연결
  - 판단 기준: 한 단계와 여러 단계 Task에서 같은 기준으로 계획·진행·근거를 찾을 수 있어야 한다.
- 결정할 사항: 현행 양식과 보호 검사를 유지하면서 신규 형식을 어떻게 도입할까?
  - 결정 범위: 신규 기록의 작성·검사, 기존 정상 기록과 링크의 호환
  - 판단 기준: 새 형식의 누락을 검출하고 기존 기록은 현재의 보호·호환 조건을 충족해야 한다.

<a id="acceptance"></a>

## 완료 조건과 확인 방법

- 완료 조건: 신규 Task 본문·별도 계획·수행 기록의 위치와 역할이 기준·절차·양식에 일치한다.
  - 확인 방법: 미착수와 착수한 사례에서 목표·현재 단계·다음 행동·완료 기준·실제 근거를 각 원천에서 찾고, 완료 체크가 한 곳에 있는지 확인한다.
- 완료 조건: Issue의 배정·의존·수용과 Task의 상세 실행이 연결된다.
  - 확인 방법: 하위 결과를 기다리는 Issue 사례에서 전달본·선행 관계·수용 근거와 하위 계획을 대조한다.
- 완료 조건: 신규 형식 검사와 기존 정식 양식 호환이 확인되고, 후속 스킬과 시범의 입력이 준비된다.
  - 확인 방법: 신규 정상·누락 사례와 현행 보호 기록을 검사하고 경로·필드·상태 규칙을 후속 배정에 연결한다.
