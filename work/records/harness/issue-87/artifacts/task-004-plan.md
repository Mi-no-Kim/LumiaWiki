### 적용 조건

- 진행 보고에 현재 위치·완료 단계 수·다음 행동을 표시한다.
- 세부 작업마다 결과를 자가검수한다. 각 단계와 Task 완료 판정 전에 해당 기준을 자가검수하고 별도 검토자가 실제 대상과 근거를 읽어 검수한다. 필요한 범위가 확인되면 앞선 검수 근거를 재사용하고, 달라진 영향만 다시 확인한다.
- 사용자 합의에 따라 `issue/87-task-workflow`의 `88944eb`에서 분기한 `task/87-004-review-controls`의 전용 워크트리를 사용한다. 기존 `task/87-002-workflow-skills` 워크트리의 변경을 보존하고 승인한 기록만 대조해 가져왔다.
- 기존 템플릿을 사용한다. 기존 보호 주석 개정이나 훅 적용 범위 확대가 필요한 경우는 실제 대상·효과·한계를 제시해 합의한 뒤 반영한다.
- 검수 규칙 및 통제 변경 자체는 현행 검수·권한 규칙에 따라 검수한다. 커밋·push·PR·병합과 GitHub 상태 처리는 실제 권한에 맞춰 진행한다.

## 2. stage-procedures — 공통 규칙과 기존 작성·실행 절차 반영

- 태그: 실행, 검수
- [x] 단계 완료
- 선행 입력: 1단계에서 확정한 안내·근거·판정 기준

- 완료 기준: 공통 기준과 Task·Issue 절차, Task 생성·검수 지침에서 검수 시점과 기록·계획 확인 방법을 찾을 수 있다.
- 확인: 실제 변경을 r002에 대조하고 양식별 역할·참조·기존 보호 주석을 확인한다. 진행 AI와 별도 검토자가 주석에서 절차까지 따라가 본다.
- 확인·결정 지점: 보호 주석 변경이나 실제 권한 범위 변경이 필요한 경우에는 반영 전에 대상과 변경 이유를 확인한다.
- 수행 기록: [2단계 수행·확인](task-004-execution.md#work-procedures)

### 세부 작업

1. 세부 작업 자가검수와 단계·Task·Issue 종료 전 자가·별도 검수, 필수 근거 부족 시 완료 보류, 유효 근거 재사용 기준을 공통 원천에 반영한다.
2. Task 생성 시 본문 핵심 요약과 기존 입력 양식의 확정 전달본을 대조하는 확인을 생성 지시서와 필요한 스킬 경로에 연결한다.
3. 착수·재개에서 적용 양식을 식별하고 별도 계획의 연결·확정 상태·실제 합의 근거를 확인하게 한다. 단계 전환과 완료에서는 실제 결과와 검수 기록을 대조한다.
4. 기존 양식에서 세부 작업별 근거를 남기는 방법과 두 형식의 참조 경로를 맞추고, 영향을 받는 스킬 현황의 원천과 적용 조건을 확인한다.

## 3. stage-validation — 자동 기록 검사 보강과 정상·누락 사례 검증

- 태그: 실행, 검수
- [x] 단계 완료
- 선행 입력: 1단계의 기대 판정과 2단계의 개정 절차

- 완료 기준: 형식·근거·참조가 정상인 사례는 진행 가능하고, 필수 기록이 없거나 서로 맞지 않는 사례는 해당 판정에서 구별된다. 사후 검사와 실제 행동 확인의 한계를 기록한다.
- 확인: 관련 회귀 테스트, 작업 폴더의 보호 주석·상태 검사, 필요한 현황 검사를 실행한다. 진행 AI와 별도 검토자가 정상·누락 사례별 실측 결과를 대조한다.
- 확인·결정 지점: 저장된 증거를 확인하는 검사와 실행 전 확인을 구별한다. 적용 범위 확대가 필요한 경우에는 가능한 환경과 관찰 근거를 먼저 확인한다.
- 수행 기록: [3단계 수행·확인](task-004-execution.md#work-validation)

### 세부 작업

1. 현행 검사에 확정 전달본의 필수 내용과 부모·Task의 적용 참조, 별도 계획과 합의 근거의 정합성 중 사후 기록으로 확인할 수 있는 조건을 보강한다.
2. 정상·빈·불완전 전달본과 참조 불일치, 계획 없이 허용되는 계획·논의, 계획 미연결·제안·근거 누락 상태에서의 의존 실행 또는 완료를 각각 재현한다.
3. 신규·기존 형식과 Issue 종료에서 세부 작업·단계·Task·Issue의 검수 근거를 찾고, 근거 누락 시 완료 보류와 유효 근거 재사용을 대조한다.
4. 변경 후보의 회귀·보호 주석·상태·참조 검사 결과와 훅 또는 실제 호출에서 관찰한 범위를 기록한다. 관련 스킬·훅의 현황이 바뀌면 원천과 같은 후보에서 갱신·검사한다.

## 4. stage-handoff — 최종 검수와 87-002 선행 결과 전달

- 태그: 검수, 실행
- [ ] 단계 완료
- 선행 입력: 실제 변경 후보, 단계별 검수 결과, 정상·누락 사례의 검증 근거

- 완료 기준: r002의 완료 기준별 판정·근거·한계를 추적할 수 있고, Issue #87과 87-002에서 확정 규칙·기존/신규 경로·남은 검증을 찾을 수 있다.
- 확인: 실제 후보를 자체·별도 검수하고 지적 처리 후 영향을 재확인한다. 완료 및 허용된 제출·통합 상태를 실제 근거와 대조한다.
- 확인·결정 지점: 전체 수용, 제출·통합과 외부 기록 반영 전에 적용 권한과 선행 조건을 대조한다.
- 수행 기록: [4단계 수행·확인](task-004-execution.md#work-handoff)

### 세부 작업

1. r002의 수용 조건마다 실제 후보·검수 주체·사례·관찰과 남은 한계를 대조한다.
2. 현행 규칙에 따라 자체·별도 검수를 수행하고 필수 지적을 처리한다. 이미 검수한 범위는 대상·입력·기준·의존 관계가 동일한지 확인한다.
3. 87-002에 확정 규칙, 신규·기존 양식에서 확인할 경로와 근거, 실제로 확인한 범위를 인계하고 Issue #87의 진행 상태를 맞춘다.
4. 허용된 범위에서 제출·반영·종료 조건을 확인하고 Task 본문에 실제 판정과 근거를 갱신한다.
