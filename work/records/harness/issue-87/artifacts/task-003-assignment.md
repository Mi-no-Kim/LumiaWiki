# Task 87-003 확정 전달사항

- 태그: 조사, 논의, 결정, 실행, 검수

<a id="purpose"></a>

## 목적

실제 컨텍스트 압축이 일어난 뒤 Issue와 Task가 올바른 상태로 복귀하는지 확인하고 전체 수용에 필요한 근거를 제공한다.

<a id="result"></a>

## 기대 결과

대표 Issue의 결과 대기와 Task의 작업 중간 지점에서 압축 전·후의 복원 근거와 판정을 남긴다. 기록·재개 스킬의 결과에 따라 자동 훅의 필요 여부를 판단한다.

<a id="scope"></a>

## 이미 정해진 조건

- 조건: 두 선행 Task의 검증 가능한 결과를 같은 후보에서 대조한다.
  - 적용 범위: 통합 시범의 실행 준비
  - 확정 근거: [Task 배정](../issue.md#assignment-plan)
- 조건: 동일 대화에서 실제 압축과 후속 행동을 확인한다. 압축 관찰이 불가능하면 실제 동작은 미확인으로 기록한다.
  - 적용 범위: Issue의 결과 대기와 Task의 실행 중간 지점의 검증
  - 확정 근거: [결정 4](../issue.md#decision-4)
- 조건: 기록·재개 스킬부터 검증한다. 자동 불러오기 필요성이 확인된 경우 적용 근거와 훅의 실제 동작을 별도로 확인한다.
  - 적용 범위: 압축 후 문맥 연결과 자동화 적용 판단
  - 확정 근거: [결정 4](../issue.md#decision-4)

- 조건: [Task 87-001](../task-001.md#summary) · [Task 87-002](../task-002.md#summary)의 확정 결과를 사용한다. 해당 선행 결과가 준비된 뒤 그 결과에 의존하는 작업을 시작한다.
  - 적용 범위: 본작업의 입력과 실행 선행 조건.
  - 확정 근거: [Issue의 Task 분해·배정](../issue.md#assignment-plan)

- 조건: 현재 사용자 요청 범위는 정식 작성과 GitHub 등록이다. Task 본작업은 착수 지시와 계획 합의 후 진행한다.
  - 적용 범위: 해당 Task의 생성과 후속 실행.
  - 확정 근거: [Issue의 배정 및 정식 작성·등록 요청](../issue.md#assignment-003)

<a id="decisions"></a>

## Task에서 결정할 사항

세부 선택의 결정 주체와 위임 범위는 착수 때 확인한다. Issue 범위나 수용 조건이 달라지는 선택은 Issue에서 합의한다.

- 결정할 사항: 어떤 작업 사례와 환경에서 압축 및 재개를 관찰할까?
  - 결정 범위: Issue 결과 대기, Task 실행 중간, 판단·검증·다음 행동의 비교 기준
  - 판단 기준: 압축 발생과 이후 실제 사용 기록을 식별하고, 중복 실행이나 발급 여부를 대조할 수 있어야 한다.
- 결정할 사항: 어떤 증거가 있으면 자동 불러오기를 적용해야 할까?
  - 결정 범위: 명시적 재개의 결과, 압축 직후 현재 작업 식별, 훅 시험의 환경·범위
  - 판단 기준: 먼저 확인한 기록·재개 동작과 실제 실패 원인 또는 필요한 사용자 개입을 근거로 판단한다.

<a id="acceptance"></a>

## 완료 조건과 확인 방법

- 완료 조건: Issue가 압축 전에 대기하던 Task 결과와 다음 검사를 올바르게 복원한다.
  - 확인 방법: 압축 전후 Task 식별·결과 준비·유효한 배정·다음 행동을 대조하고 발급 중복을 확인한다.
- 완료 조건: Task가 적용한 계획과 마지막 확인 단계에서 복귀한다.
  - 확인 방법: 결정·제약·실제 파일·검증 근거를 대조하고 완료 작업의 반복 없이 다음 순서를 이어가는지 관찰한다.
- 완료 조건: 후속 자동화 필요 여부와 Issue 수용에 필요한 근거가 남는다.
  - 확인 방법: 재개 시험의 환경·관찰·판정·한계를 기록한다. 필요하여 훅을 적용한 경우 그 훅의 실제 발동과 복원 대상을 별도 확인한다.
