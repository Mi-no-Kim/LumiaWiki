# Task 87-001 전체 수행 계획

- 적용 전달본: [r001](task-001-assignment.md)
- Task: [87-001](../task-001.md#summary)
- 기준: 부모 Issue 브랜치 `issue/87-task-workflow`의 `94babc10b477`에서 분기.
- 계획 합의: 사용자가 4단계 계획의 실행을 확정했다. 이미 진행된 정식 Task는 대상이 명시된 요청과 보호 기준에 맞는 보존 절차를 통해 개별 전환할 수 있도록 한다.

<a id="contract"></a>

## 적용할 기록 구조

- 신규 Task의 상세 계획은 Issue의 `artifacts/task-<순번>-plan.md`에 둔다. 각 단계에 고정 식별자, 실행 순서, 세부 작업, 선행 입력, 완료 기준, 검증 방법, 사용자 확인 지점과 완료 표시를 둔다. 계획을 재배열해도 수행 근거가 가리키는 단계 식별자는 유지한다.
- Task 본문은 현재 상태·위치·다음 행동, 유효한 결정과 제약, 판정, 전달본과 계획·수행 근거 링크를 연결한다. 실제 실행·검증·복구 근거는 기존 수행 기록에 둔다.
- Issue에는 전체 수용 조건, 담당 Task, 의존 관계, 결과 준비 상태와 수용 결론을 둔다. 배정·의존 관계가 복잡한 경우 상세 계획을 연결할 수 있도록 한다.
- 도입 전에 생성된 정식 기록은 현행 양식과 검사로 읽는다. 신규 형식은 같은 정식 Task 경로에서 버전을 판별해 별도 검사한다. 도입 시점의 기존 정식 Task 경로에만 종전 검사를 적용한다. 개별 전환은 정확한 경로와 사용자 승인 기록을 남기고, 기존 상태·결정·검증 근거와 링크를 확인한다. 고정 기존 기록의 별도 적용 경계를 유지한다.
- 운영 스킬 여섯 개의 작성과 실제 컨텍스트 압축 시범은 [후속 Task](../issue.md#assignment-plan)의 담당 결과다. 이 Task는 해당 작업이 사용할 경로·필드·상태와 검증 사례를 전달한다.

<a id="stage-baseline"></a>

## 1. 현행 적용 경로와 전환 기준 확인

1. 등록된 Issue·Task, 본문과 수행 기록 양식, 생성 지시서에서 현재 계획·상태·검사 호출 경로를 대조한다.
2. `rule-comments.json`과 `rule_comments.py`의 자동 대상, 보호 원문, 고정 예외, 작업 폴더·인덱스 검사 범위를 확인한다.
3. 체크를 한 곳에서 관리할 필드와 단계 ID, 신규 형식을 구별할 방식, 기존 형식의 인정 범위를 정한다. 기존 보호 주석의 명시 개정이 필요하면 해당 경로와 변경 전후 원문을 제시해 승인받은 다음 진행한다.

**완료 기준** 신규·기존 양식의 적용 경계와 후속 스킬이 읽을 계획 경로·필드·상태를 설명할 수 있다.

<a id="stage-templates"></a>

## 2. 새 양식과 실제 작성·갱신 절차 연결

1. 새 Task 본문·별도 계획 양식에서 현재 상태와 단계 체크의 소유 위치, 계획과 수행 기록을 연결하는 표식을 정의한다.
2. 한 단계 Task와 여러 단계 Task의 착수 전·실행 중 읽기 경로를 준비한다. Issue의 배정·의존·결과 대기·전체 수용이 각 Task의 기록과 어떻게 연결되는지 대조한다.
3. 기록 체계·작성 기준, Task 생성 지시서·공통 절차 및 영향받는 Issue 작성·진행 안내에서 적용 경로를 맞춘다.

**완료 기준** 신규 본문에서 계획·완료 기준·상세 근거를 찾아갈 수 있고, 같은 단계의 체크가 여러 곳에 생기지 않는다.

<a id="stage-checker"></a>

## 3. 신규·기존 형식 검사 연결

1. 앞 단계의 전환 기준에 맞춰 자동 발견 경로와 형식별 검사 진입점을 추가한다. 기존 형식의 보호 주석·상태 검사는 같은 조건으로 유지한다.
2. 신규 Task에서 빠진 계획·필수 연결·형식 표식 오류를 검출하고, 별도 계획에 남긴 진행 위치와 근거가 서로 맞는지 검사할 범위를 정한다.
3. 도입 이전에 생성된 정식 Task와 고정 기존 기록, 정상·누락 신규 기록을 각각 확인한다. 적용 경로 또는 의존 원천을 바꾸면 관련 스킬·훅 현황도 맞춘다.

**완료 기준** 신규 형식의 누락이 실패하고, 기존 보호 기록과 정상 신규 기록이 기대한 방식으로 검증된다.

<a id="stage-handoff"></a>

## 4. 검수와 후속 전달

1. 현행 검사와 관련 회귀를 실행하고, 실제 양식으로 작성한 한 단계·여러 단계 Task와 결과 대기 Issue에서 수용 조건을 확인한다.
2. 대상 파일과 보호 경계를 검수하고, 발견된 필수 결함을 보완한 뒤 영향 범위를 다시 확인한다.
3. 적용 경로·필수 필드·단계 ID·완료 판정 방법과 근거를 Task 87-002에 전달한다. 87-003에서 사용할 검증 사례와 한계도 연결한다.

**완료 기준** r001의 세 수용 조건을 실제 결과와 대조하고, 후속 Task가 참조할 기준과 검증 근거를 남긴다.
