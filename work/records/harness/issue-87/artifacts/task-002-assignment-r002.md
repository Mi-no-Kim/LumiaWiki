# Task 87-002 확정 전달사항

- 태그: 조사, 논의, 결정, 실행, 검수

<a id="purpose"></a>

## 목적

Issue와 Task를 생성한 뒤 계획·실행·재개를 각각 명시적으로 지시할 수 있게 하고, 같은 계획에서 현재 위치를 찾고 보고하게 한다.

<a id="result"></a>

## 기대 결과

Issue와 Task의 운영 스킬 여섯 개와 공용 진행·재개 절차를 마련한다. 기존 생성·등록·검수 스킬은 새 계획과 기록의 원천을 읽도록 연결한다.

<a id="scope"></a>

## 이미 정해진 조건

- 조건: Issue와 Task 각각에 plan·run·resume 명령을 둔다. 계획 제안과 실제 실행, 실제 상태 대조 후 재개를 구분한다.
  - 적용 범위: $issue-plan·$issue-run·$issue-resume, $task-plan·$task-run·$task-resume
  - 확정 근거: [결정 3](../issue.md#decision-3)
- 조건: 진행 메시지는 계획상 현재 위치와 다음 행동을 표시한다. 주요 전환·결정·막힘·검증 완료의 현재 값은 담당 기록에 남긴다.
  - 적용 범위: Issue·Task 진행 보고와 재개
  - 확정 근거: [결정 1](../issue.md#decision-1) · [결정 4](../issue.md#decision-4)
- 조건: 계획·기록 Task의 확정 결과를 선행 입력으로 사용한다. 스킬의 원천·등록·의존과 현황을 함께 갱신한다.
  - 적용 범위: 계획·기록 경로를 읽고 갱신하는 구현 및 스킬 검증
  - 확정 근거: [Task 배정](../issue.md#assignment-plan) · [스킬 현황 갱신 기준](<../../../../../docs/문서 관리 기준.md#skill-hook-inventory>)

- 조건: [87-001 계획·기록 인계](task-001-execution.md#handoff-contract)와 [87-004 검수 규칙 인계](task-004-execution.md#handoff-contract)를 선행 입력으로 사용한다.
  - 적용 범위: 두 Task 양식, 공용 절차, 여섯 명령과 기존 생성·검수의 연결.
  - 확정 근거: [Issue의 Task 분해·배정](../issue.md#assignment-plan) · [공통 검수](../issue.md#decision-5) · [계획·생성 통제](../issue.md#decision-6)

- 조건: 신규 Task는 본문 주석과 별도 계획·확정 전달본·실제 합의 근거·자동 계산한 계획 지문을 대조한다. 종전 Task는 본문 계획·합의·단계 체크를 사용한다.
  - 적용 범위: 착수·재개·단계 전환과 변경된 합의에 의존하는 실행.
  - 확정 근거: [87-004 인계](task-004-execution.md#handoff-contract)

- 조건: Task 생성 시 본문의 목표·확정 조건·완료 기준·다음 행동을 확정 전달본과 대조한다. 세부 작업 전환과 단계·Task·Issue 종료에는 공통 검수 시점과 근거를 적용한다.
  - 적용 범위: 세부 작업 완료 전 자가검수와 Task 계획 단계 및 Task·Issue 종료 전 자가·서브에이전트 검수. 기존 양식과 검사 경로를 사용한다.
  - 확정 근거: [결정 5](../issue.md#decision-5) · [결정 6](../issue.md#decision-6)

- 조건: 사용자 명시 범위를 우선하고 같은 단위 안에서 승인된 행동을 연속 진행한다. 현재 위치가 불명확하면 `resume`으로 실제 상태를 대조한 뒤 실행 여부를 결정한다.
  - 적용 범위: 여섯 운영 스킬의 작업 진입과 재개.
  - 확정 근거: [진행·재개 방식 합의](task-002-plan.md#command-agreement) · [r002 배정·착수 승인](../issue.md#assignment-002)

<a id="decisions"></a>

## Task에서 결정할 사항

세부 선택의 결정 주체와 위임 범위는 착수 때 확인한다. Issue 범위나 수용 조건이 달라지는 선택은 Issue에서 합의한다.

- 결정할 사항: 여섯 스킬이 공통으로 읽고 쓰는 규칙을 어느 절차에 둘까?
  - 결정 범위: 계획 확인, 현재 위치 갱신, 실행 권한 확인, 재개 대조
  - 판단 기준: 명령별 진입점과 실행 범위가 명확하고 동일 규칙을 한 원천에서 갱신할 수 있어야 한다.
- 결정할 사항: 기존 생성·검수 스킬과 새 명령의 연결을 어디까지 고칠까?
  - 결정 범위: 배정·생성 이후 계획, 실제 결과 검수, 적용 현황
  - 판단 기준: 기존 생성·등록과 검수의 동작을 대조하고 신규 계획·기록 연결에 필요한 변경을 고른다.

<a id="acceptance"></a>

## 완료 조건과 확인 방법

- 완료 조건: 여섯 명령을 명시 호출할 수 있고 각 명령의 입력·출력·권한 경계가 맞는다.
  - 확인 방법: Issue와 Task 각각에 대해 대상 식별·계획 제안·허용된 실행·복귀를 대조한다.
- 완료 조건: 보고와 저장된 상태가 같은 계획과 실제 결과를 가리킨다.
  - 확인 방법: 단계 완료·계획 변경·막힘·Issue 결과 대기에서 메시지의 현재 위치·다음 행동을 기록과 대조한다.
- 완료 조건: 기존 생성·검수의 주요 경로와 스킬 현황을 확인했다.
  - 확인 방법: 생성 후 최초 계획 연결과 결과 근거 참조를 점검하고, 실제 스킬 원천·의존·현황과 동작 확인 근거를 대조한다.

- 완료 조건: 실행·재개에서 두 Task 형식에 맞는 계획과 권한을 확인한다. 별도 계획의 내용이 합의와 달라지면 영향받는 실행을 보류한다.
  - 확인 방법: 정상 합의, 지문이 바뀌는 계획 내용 수정, 진행 체크만 갱신한 사례, 종전 본문 계획을 대조한다.
- 완료 조건: 생성 본문의 필수 내용이 확정 전달본과 맞고, 단계와 Task·Issue의 완료 판단에서 필수 검수 근거를 찾을 수 있다.
  - 확인 방법: 본문 또는 전달본의 필수 내용·참조 누락, 세부 작업의 자가검수와 단계·Task·Issue의 별도 검수 근거 누락 및 유효 근거 재사용을 대조한다.
