- 태그: 조사, 논의, 결정, 실행, 검수

<a id="purpose"></a>

## 목적

Issue와 Task의 검수 시점을 공통 규칙으로 정하고 Task 생성·착수·재개·완료에 필요한 내용과 근거를 확인할 수 있게 한다.

<a id="result"></a>

## 기대 결과

공통 검수 기준과 Task·Issue 절차에 작업 단위별 검수·완료 판단·근거 재사용 기준을 반영한다. 기존 양식으로 작성하는 Task 본문과 전달본의 내용, 주석 안내, 별도 계획과 실제 합의 근거, 세부 작업별 검수 근거를 생성·실행·검수 과정에서 대조할 수 있게 한다.

<a id="scope"></a>

## 이미 정해진 조건

- 조건: Task의 세부 작업 완료 전에는 진행 AI가 자가검수한다. Task의 각 계획 단계 완료와 Task·Issue 종료 전에 진행 AI의 자가검수와 서브에이전트 검수를 수행한다.
  - 적용 범위: 저장소의 Task·Issue 공통 검수와 완료 판단.
- 조건: 새 규칙 적용 이후 완료를 판단하는 단계부터 적용한다. 이미 완료한 단계의 당시 판정은 유지한다.
  - 적용 범위: 신규·기존 Task와 Issue의 단계 완료·종료.
- 조건: 필수 검수 근거가 부족하면 해당 완료 판정을 보류한다. 대상·입력·기준·관련 의존이 같아 유효한 근거는 겹치는 범위에서 재사용한다.
  - 적용 범위: 검수 결과의 완료 반영과 근거 재사용.
- 조건: 규칙 변경 자체는 현행 기준에 따라 자가검수하고 별도 검수를 받는다. 확정 결과를 87-002의 착수 선행 입력으로 전달한다.
  - 적용 범위: 이 Task의 결과 검수와 후속 배정.
- 조건: Task 생성 시 본문에 목표·확정 조건·완료 기준·다음 행동의 요약을 남기고 확정 전달본의 필수 내용을 본문과 대조한다.
  - 적용 범위: 기존 Task 생성 지시와 `create-task`의 작성 후 확인. 확정 전달본은 기존 Task 입력 양식을 사용한다.
- 조건: Task 착수·재개·단계 전환·완료에 필요한 주석 안내와 공통 절차의 확인을 검토한다. 행동 전에 해야 하는 대조와 사후 기록·제출에서 확인할 수 있는 조건을 구별한다.
  - 적용 범위: 신규·기존 Task의 보호 주석, 공통 절차와 검사. 기존 보호 규칙과 양식별 계획 원천을 적용한다.
- 조건: 별도 계획 적용 Task의 의존 실행 전에는 연결된 계획과 실제 합의 근거를 대조한다. 종전 형식은 본문의 계획과 단계 체크를 기준으로 한다.
  - 적용 범위: 계획이 없거나 연결되지 않은 경우, 제안 상태, 합의 근거가 없거나 적용 계획과 불일치하는 경우의 착수·재개 판단.
- 조건: 한 단계 안의 세부 작업마다 자가검수 근거를 찾을 수 있도록 하고, 단계 완료 시 검수 근거를 실제 결과와 대조한다.
  - 적용 범위: 두 Task 양식의 수행 기록과 단계 확인.
- 조건: 기존 본문·계획·수행 기록·입력 양식을 사용한다. 신규 템플릿은 추가하지 않는다.
  - 적용 범위: 이번 Task의 양식 및 검사 보완.
- 조건: 현재 요청 범위는 배정 개정·로컬 기록 갱신·GitHub #93 반영이다. 본작업은 착수 요청과 전체 계획 합의 후 진행한다.
  - 적용 범위: 이번 개정과 후속 실행.

확정 근거는 [Issue #87의 검수 규칙 도입 결정](../issue.md#decision-5)과 [배정 개정 결정](../issue.md#decision-6)이다.

<a id="decisions"></a>

## Task에서 결정할 사항

- 결정할 사항: 주석·절차·검사에 각각 무엇을 두고, 세부 작업별 검수 근거와 정상·누락 사례를 어떻게 확인할까?
  - 결정 범위: 주석과 공통 절차의 역할, 착수 전 대조와 사후 검사, 두 Task 양식과 Issue 종료 사례, 세부 작업별 근거 위치 및 근거 재사용 확인 방법.
  - 판단 기준: 기존 양식에서 필요한 권한·계획·검수 근거로 판단을 재현할 수 있어야 한다. 실제로 대조할 수 있는 정보와 자동 검사만으로 알 수 없는 행동을 구별한다.
  - 결정 주체: 전체 계획 수립 시 사용자와 합의한다.

<a id="acceptance"></a>

## 완료 조건과 확인 방법

- 완료 조건: 공통 기준과 Task·Issue 공통 절차에서 세부 작업·Task 계획 단계·Task 종료·Issue 종료의 검수 요구를 확인할 수 있다.
  - 확인 방법: 신규·기존 Task 및 Issue 종료 대표 사례에서 검수 주체·시점과 기록 위치를 대조한다.
- 완료 조건: 필수 검수 근거가 없을 때 완료가 보류되며, 유효한 근거를 해당 범위에 재사용할 수 있다.
  - 확인 방법: 필수 검수 근거가 있는 사례와 빠진 사례의 완료 판정을 대조하고 유효 근거 재사용 범위를 확인한다.
- 완료 조건: Task 생성 시 본문만으로 배정의 핵심을 파악할 수 있다.
  - 확인 방법: 본문에서 목표·확정 조건·완료 기준·다음 행동을 읽을 수 있는 사례와 전달본 링크만 남긴 사례를 비교해 내용 확인에서 구별한다.
- 완료 조건: 착수·재개·단계 전환·완료 시 필요한 주석 안내와 확인이 작동한다.
  - 확인 방법: 기존·신규 양식에서 주석이 안내하는 행동과 절차·검사의 적용을 대조하고, 안내가 있는데 필요한 기록이 빠진 사례와 기존 보호 주석 유지 여부를 확인한다.
- 완료 조건: 별도 계획 적용 Task는 실제 합의 근거를 확인한 계획을 기준으로 실행한다.
  - 확인 방법: 계획 누락·미연결, 제안 상태, 합의 근거 누락·불일치에서 의존 실행을 보류하는지 확인한다. 승인 근거와 현재 단계가 맞는 사례 및 종전 본문 계획 형식도 확인한다.
- 완료 조건: 확정 전달본의 필수 내용과 적용 식별을 확인할 수 있다.
  - 확인 방법: 기존 입력 양식의 목적·기대 결과·확정 조건·결정할 사항·완료 조건 및 확인 방법을 대조한다. 정상본·빈 파일·필수 내용이 빠진 파일과 부모·Task 참조의 불일치 사례를 구별한다.
- 완료 조건: 세부 작업별 자가검수와 단계·Task·Issue의 별도 검수 근거를 찾을 수 있다.
  - 확인 방법: 한 단계에 여러 세부 작업이 있는 사례에서 각 작업의 자가검수 근거와 단계 완료 판정을 연결한다. 근거 누락에 따른 완료 보류와 유효한 근거의 재사용을 대조한다.
- 완료 조건: 규칙 변경을 현행 기준으로 자가검수·별도 검수했고 87-002가 사용할 확정 결과와 근거를 연결했다.
  - 확인 방법: 실제 변경 후보와 두 검수의 판정·지적 처리·한계를 대조하고 후속 Task가 공통 규칙과 근거를 찾을 수 있는지 확인한다.
