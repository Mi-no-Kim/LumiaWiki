### 합의한 세부 설계 및 진행 방식

계획 지문 자동화, 주석의 안내·통제, 별도 계획과 실제 합의 근거의 대조, 확정 전달본 검사, 세부 작업별 자가검수와 단계·Task·Issue 별도 검수를 모두 적용한다. 사용자는 위 기능을 유지하는 세부 설계와 진행 방식에 “동의한다”라고 응답했다.

1. **계획 지문과 합의 확인** 별도 계획은 Task 본문의 실제 사용자 합의로 연결한다. 합의 당시의 작업 범위·순서·완료 기준·확인 조건 지문을 자동으로 계산하고, 착수·재개와 합의 대상 변경 시 현재 계획과 대조한다. 계획 합의 표기, 완료 체크, 수행 기록 링크 등 진행만 바뀐 항목은 지문에서 제외한다. 진행 AI는 실제 응답과 적용 전달본·합의 범위를 확인한다. 지문 불일치가 의존 실행에 영향을 주면 해당 범위를 보류하고 다시 합의한다.
2. **검수와 근거 기록** 세부 작업마다 자가검수한다. 기존 수행 기록의 단계 `확인`에 해당 단계와 당시 계획 식별을 연결하고, 각 세부 작업의 확인 대상·판정과 필요한 근거를 남긴다. 단계·Task·Issue는 각각 자기 완료 조건을 자가검수하고 별도 검수를 거쳐 판정한다. 하위 검수 근거와 지적 처리는 유효 범위를 확인해 연결한다.
3. **주석·절차·자동 검사의 적용** 기존 주석과 공통 절차에서 착수·재개·전환·완료에 필요한 행동을 찾게 한다. 진행 AI가 해당 행동 전에 계획과 권한을 대조한다. 사후 기록 검사에서는 생성 본문의 핵심, 확정 전달본의 필수 내용과 참조, 계획 연결·합의 근거와 지문, 적용 양식에 따른 증거 연결을 확인한다. 종전·신규 Task와 Issue 종료에서 정상 및 누락 사례를 대조한다. 합법적인 `미작성`·`없음`·`미정`과 기존 완료 판정도 검증 대상으로 둔다.

| 길어지는 원인 | 줄이는 방식 |
|---|---|
| 합의 확인과 지문 계산 반복 | 같은 지문 계산을 합의 기록과 확인에서 사용한다. 자동 계산·비교 결과를 확인하고, 합의 범위에 영향이 있는 변경에만 사용자 판단을 요청한다. |
| 기록·보고 중복 | 계획에는 예정과 기준, 수행 기록에는 실제 확인, 본문에는 현재 결론·막힘·다음 행동을 둔다. 정상 자가검수는 세부 작업별로 짧게 남기고, 같은 근거는 링크로 재사용한다. 실패·미확인·변경 영향은 후속 판단에 필요한 만큼 적는다. |
| 자가·별도 검수 반복 | 세부 작업 자가검수를 먼저 마치고 단계 완료 판단 시점에 별도 검수를 연결한다. 같은 대상·입력·기준·관련 의존의 유효 근거는 재사용한다. 검수 후 변경은 영향받은 범위를 대조한다. Task·Issue 종료에서는 각각 전체 수용과 통합 영향도 확인한다. |
| 테스트 범위의 중복 | 완료 기준마다 필수 확인을 연결한다. 두 양식의 정상 경로와 각 실패 유형은 대표 사례로 확인하고, 같은 판정을 검증하는 조합은 공통 근거를 사용한다. 수정 중에는 실패와 영향 범위를 재검증하고 최종 후보에서 필요한 전체 확인을 수행한다. |
| 합의·대기와 재시도 | 서로 관련된 결정을 영향과 함께 한 번에 제시하고, 이미 합의한 판단은 재사용한다. 답이 필요한 행동을 보류하는 동안 독립적으로 허용된 일을 진행한다. 반복해도 새 근거가 없으면 접근이나 필요한 입력을 바꾸고 실제 막힘을 알린다. |
| 작업 범위 확장 | 변경 파일과 검증 사례를 r002 완료 조건에 연결한다. 작업 중 발견한 개선이 범위를 바꾸면 영향과 선택안을 먼저 합의한다. 필수 결함은 고치고 선택 개선은 기록해 해당 검수의 반복을 끝낸다. |

**확인 방법** 2단계에서 각 확인의 담당 위치를 정하고, 3단계에서 반드시 거부할 경우와 허용할 경우를 각각 확인한다. 특히 합의 대상만 바뀐 계획은 보류되고, 진행 정보만 갱신한 계획은 유효한 합의를 유지해야 한다. 4단계에서 짧은 검수 기록만으로도 단계·Task·Issue의 실제 판정과 근거를 추적할 수 있는지 대조한다.

## 공통 규칙과 기존 작성·실행 절차 반영

- 할 일: [2단계 — 공통 규칙과 기존 작성·실행 절차 반영](task-004-plan.md#stage-procedures)

- 조치·판단: 공통 검수 기준과 Task·Issue 절차에 완료 단위별 검수를 연결했다. 본문·전달본의 내용 대조를 생성 지시서와 스킬에 반영하고, 착수·재개 시 기존/신규 양식에서 사용할 계획과 합의 근거를 명시했다. 검사에서 계산·대조할 지문과 자동 확인은 3단계에서 구현한다.
- 확인: 합의된 2단계의 실제 후보를 자가검수했다.
  - **세부 작업 1** 공통 기준에서 단계·Task·Issue의 검수 시점과 근거 부족 시 보류, 이전 완료 판정 보존과 근거 재사용을 대조했다.
  - **세부 작업 2** 생성 지시서와 create-task에서 본문 핵심 네 항목과 실제 전달본·부모 참조를 대조하게 했다. 빈 내용과 허용된 없음·미정을 구별했다.
  - **세부 작업 3** 종전 형식의 본문과 신규 형식의 별도 계획을 각각 추적했다. 상황별 보류·진행 전 대조와 사후 검사의 범위를 기록했다.
  - **세부 작업 4** 기존 수행 기록에 세부 작업을 식별하고 짧게 검수 근거를 남기는 경로를 확인했다. 스킬 현황 3건의 지문을 갱신했다. 현황·보호 주석 검사와 변경 공백 검사에서 문제가 없었다. 기존 템플릿, 보호 정책 및 87-002 본문은 현행과 일치했다.
  - **별도 검수 통과** 지문 불일치 때 재합의·원복과 영향 없는 작업의 계속을 구분했다. 양식별 보호 주석 안내도 실제 정책에 맞췄다. 서브에이전트가 두 수정과 현황·보호 검사 및 공백 검사를 재확인했다.
- 잔여: 2단계 없음. 계획 지문 계산과 자동 검사 보강 및 실제 사례 확인은 3단계에서 진행한다.

- 확인: 세부 작업별 자가검수의 현재 결과는 다음과 같다.
  - **세부 작업 1** 새 빈 전달본·내용 누락·참조 불일치 검사를 실제 r002 형식에 대조했다. Task·계획·Issue의 링크와 지문 계산 명령을 현재 작업 폴더에서 확인했다.

  - **세부 작업 3** 87-004의 두 완료 단계에서 실제 세부 작업과 서브에이전트 근거의 연결을 자체 대조했다. 종전 본문 계획형 호환과 이전 판정 보존은 테스트로 확인했다. 확인 내용이 없는 완료 단계는 검사에서 거부됐다. 관련 근거가 없거나 실제 별도 검수가 미확인인 단계·Issue는 완료를 보류한다. 응답의 진위·개별 검수 활동과 Issue 전체 수용 여부는 진행 AI와 별도 검토자가 대조한다.
  - **세부 작업 4** 작업 폴더의 기록 및 현황, 모의 PostToolUse 입력으로 호출한 검사기, 지문 명령, 변경 공백 검사가 통과했다. 실제 설치·모든 도구 발동은 이 호출로 판정하지 않는다. 관련 훅 현황에는 현재 원천 지문과 기존 확인 범위를 연결했다.
  - **별도 재검수 통과** 전달본 구조 및 합의 근거·지문·단계 확인을 메모리 사례 10건으로 대조했다. 작업 폴더의 현황·기록·변경 공백 검사도 통과했다.

### 87-002가 사용할 선행 결과

- Task 단계 완료와 Task·Issue 종료 전에는 해당 단위의 실제 수용 조건에 자가·별도 검수를 연결한다. 세부 작업은 기존 수행 기록에서 각각의 자가검수 판정을 추적한다.
- 종전 Task의 적용 계획·현재 위치는 본문과 단계 체크를 읽고, 신규 Task는 본문의 상세 계획 링크를 따라 적용 전달본·합의 근거·계획 지문을 대조한다. 실제 응답과 실행 권한은 진행 AI가 보고 판단한다.
- 별도 계획 지문은 `check-rule-comments.py --candidate work --plan-fingerprint <Task 상대 경로>`로 계산한다. 합의 범위의 변경은 근거와 지문을 다시 확인한다. 진행 기록만 갱신할 때는 기존 합의를 사용한다.
- 생성 시 Task 본문의 목표·확정 조건·완료 기준·다음 행동을 실제 전달본과 대조한다. 검사는 필수 내용과 참조를 확인하며 실제 응답의 진위 및 검수 판정의 적절성은 담당자가 대조한다.
- 적용 시에는 87-004의 부모 반영을 확인하고 기존 87-002 워크트리에 남은 사본과 공통 Issue 변경을 대조한다. 87-002의 기존 변경을 보존하면서 개정 배정과 기존 계획의 영향을 확인한다.
