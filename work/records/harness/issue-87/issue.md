<a id="purpose"></a>

#### 목적

Task의 계획을 실행 기준으로 사용하고, 사용자에게 계획 대비 진행을 계속 알릴 수 있게 한다. Task 본문은 현재 결론 위주로 읽을 수 있게 줄인다. Issue와 Task를 스킬 명령으로 진행하며, 한 대화가 길어져 컨텍스트가 압축돼도 작업을 이어갈 수 있게 한다.

<a id="expected-results"></a>

#### 기대 결과

Task는 착수 전에 단계와 세부 작업의 순서·선행 조건·확인 방법을 정하고, 실행 중에는 합의한 계획의 현재 위치와 다음 행동을 대화에 알린다. Issue는 전체 수용 조건을 Task의 담당 결과·의존 관계·받을 근거에 연결하고, Task 결과 대기와 최종 검사를 추적한다. 두 작업 단위를 스킬로 진행하고, 저장된 현재 상태에서 재개할 수 있게 한다.

<a id="conditions"></a>

#### 이미 정해진 조건

- 조건: Task는 착수 전에 자세한 작업 순서를 정하고 작업 진행을 알릴 때마다 그 계획과 대조한 현재 위치를 대화에 표시한다.
  - 적용 범위: Task 계획·실행·진행 보고
  - 확정 근거: 사용자가 첫 번째 불편 사항과 계획 세분화 후속 요청에서 제시한 요구.
- 조건: Task 본문은 현재 결론을 중심으로 유지하고, 상세 계획·수행 근거를 어디에 둘지 결정한다.
  - 적용 범위: Task 본문과 연결 기록
  - 확정 근거: 사용자가 두 번째 불편 사항에서 제시한 선호와 결정 요청.
- 조건: Task와 Issue 모두 사용자가 스킬로 작업을 지시할 수 있게 한다. 같은 대화가 컨텍스트 압축을 거쳐도 작업의 흐름을 이어갈 수 있게 한다.
  - 적용 범위: Issue·Task 운용 스킬과 재개
  - 확정 근거: 사용자의 스킬 명령·컨텍스트 압축 요구와 Issue 적용 요청.

### 결정 1

- [x] 결정할 사항: Task의 작업 순서를 어느 수준까지 세분화하고, Issue에서는 무엇을 계획·추적할까?
  - 결정 범위: Task 단계와 세부 작업, Issue의 배정·의존 관계·전체 수용, 진행 보고의 표시 기준.
  - 판단 기준: 착수 전에 순서와 완료 기준을 확인할 수 있고, 작업 중에는 전체 위치와 다음 행동이 보인다.
  - 결정 내용: Task는 착수 전에 결과를 확인할 수 있는 단계와 순서가 있는 세부 작업을 정한다. 단계별 완료 기준과 판단이 필요한 지점을 명시한다. Issue는 담당 Task·선후 관계·결과 대기·전체 수용을 추적한다. 진행 메시지에는 계획상 현재 위치와 다음 행동을 표시한다.
  - 결정 이유·근거: 계획을 실행과 진척 확인에 함께 쓰기 위해 사용자가 이 대화의 결정 1 질문에 “제안한 기준으로 확정”이라고 응답했다.

  - 결정 범위: Task·Issue 본문의 필수 요약, 상세 계획과 수행 근거의 위치, 새 형식과 기존 기록의 적용 경계.
  - 판단 기준: 현재 결론을 짧게 읽을 수 있고, 다음 행동·권한·근거를 재개에 필요한 만큼 찾을 수 있다.
  - 결정 내용: 신규 Task 본문은 목표·현재 위치·다음 행동·유효한 결정과 제약·최종 판정·근거 링크를 담는다. 단계 순서·완료 기준·체크는 Task별 별도 계획 파일 한 곳에, 실제 검증·실패·복구 근거는 수행 기록에 둔다. Issue 본문에 요약·전체 수용 기준·결정·Task 링크·최종 판정을 두고, 배정·의존 관계가 복잡할 때 상세 계획을 분리한다.
  - 결정 이유·근거: 본문에서 현재 결론을 읽고 후속 행동에 필요한 근거를 찾을 수 있도록, 사용자가 이 대화의 결정 2 질문에 “Task 계획은 별도 파일로 관리”라고 응답했다.
