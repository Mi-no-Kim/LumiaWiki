### 구현·로컬 실행 결과

- 자동 검증: 초기 구현의 26개 통과 뒤 검수 지적의 회귀 사례를 추가했다. 최종 소스에서 `python -B -X utf8 -m unittest discover -s scripts/tests -v`는 27개·실패/error/skip 0으로 통과했다(25.117초). 후보 work/index/commit, 누락/삭제/보조 파일/내용 없는 문서 수정, 부분 스테이징, 확인 지문 재사용 거부, JSON/TOML/프로젝트 활성 조건, 경계/junction, 설치/중복/변조/기존 hook 거부·복원과 실제 격리 커밋 정상/거부를 확인했다.

- 별도 검수·보완: 읽기 전용 검토자가 허용된 15개 파일과 현재 work/별도 index·공백·입력 지문·브랜치/상태를 대조했다. JSON handler가 있는 상태에서 handler 없는 프로젝트 TOML의 `features.hooks=false`를 추가해도 누락을 놓치는 지적 1개를 합성 후보로 재현했다. 주 진행자는 격리 테스트에서 assertion 실패 1개로 재현한 뒤 프로젝트 config를 각 Codex 항목의 필수 원천으로 포함했다. 누락 거부·정상 갱신·활성 조건 재변경 거부와 기존 JSON/TOML 사례가 통과했으며 전체 27개로 회귀 확인했다. 실제 개인/전역 설정이나 Codex 신뢰는 변경하지 않았다.

## 경량성·누락 탐지의 최종 검수와 로컬 커밋 준비

- 추가 요청: 현재 #55 변경을 최종 검수하고 문제가 없으면 로컬 커밋한다. 기능에 비해 과도한 구현인지와 실제 누락 탐지를 중점 검증한다. 같은 Issue의 제출 보완이며 새 작업·브랜치를 만들지 않는다. push·PR은 금지한다. 이 커밋은 로컬 구현의 제출이며 원격 CI를 포함한 Issue 전체 수용·종료와 구별한다.
- 자체 구조 검토: 검사/원천 판독·설치/복원·Git 진입점의 역할 분리는 실제 후보 판독과 기존 hook 보존에 대응한다. 실행에는 Python 표준 라이브러리와 기존 Git CLI를 사용하며 별도 Python 패키지가 필요하지 않다. 커밋 전 검사는 테스트·설치·AI·네트워크를 실행하지 않는다. 상시 감시기·별도 실행 서비스·중복된 현황 원본은 추가하지 않았다. CI의 Windows/Ubuntu 실행 비용과 실제 원격 동작은 이번에 확인한 것으로 확대하지 않는다.
- 비용 개선: 50개 skill의 동일한 정상 index 후보를 검사할 때 이미 일괄 읽은 파일을 항목마다 Git에서 다시 조회했다. 추가 의존 파일만 읽게 수정해 실제 Git 호출이 55회에서 5회, 경과 시간이 2.2718초에서 0.2253초로 줄었다. 현재 구성의 work 검사는 3회·0.1981초였다. 이는 같은 로컬 환경의 실측이며 다른 환경의 시간 보장은 아니다.
- 탐지/보호 보완: 50개 정상 skill 후보의 허용과 마지막 원천만 변경한 후보의 정확한 항목 식별 거부를 함께 검증했다. 시간 초과나 다른 오류를 누락 탐지 성공으로 세지 않도록 거부 사유도 확인한다. 설치 metadata의 `null`이 정상 해제로 처리되는 assertion 실패 1개를 재현했고, 파일이 존재하면 형식을 검증해 `[]`·`null`·`{}`를 모두 거부하며 원래 hook/metadata를 보존하도록 보완했다.
- 최종 자동 검증: 수정 후 `python -B -X utf8 -m unittest discover -s scripts/tests -v`의 28개가 실패/error/skip 0으로 통과했다(26.922초). 기존 27개 정상/누락·추가/삭제·보조 파일·Codex 활성 조건·부분 스테이징·확인 지문·경계·설치/복원 사례에 위 규모/보호 확인을 포함한다. 기존 검수 도구 5개·skill/YAML 형식 검증은 해당 입력이 변하지 않아 유효한 근거를 재사용한다.
- 별도 검수의 필수 보완: 실제 staged 15개 파일을 대조한 검토자가 두 누락을 격리 후보/실제 커밋으로 재현했다. (1) checker/현황을 작업 폴더에서만 삭제하면 index에 구성이 남아 있어도 검사를 생략했다. (2) `post-index-change`와 P4 이벤트 4개를 수집하지 않았다. 직접 [Git 공식 문서](https://git-scm.com/docs/githooks)와 설치 문서의 전체 이벤트를 대조했다. 검토자는 추가 필수 구조 변경을 요구할 정도의 과한 무게는 발견하지 못했으며 초기 staged 검사를 0.3544초·index 무변경으로 확인했다.
