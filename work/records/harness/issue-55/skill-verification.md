# 스킬 수행 검증

[Issue #55](issue.md#summary)

Windows·Python 3.14.2·Git·현재 Codex의 별도 문맥에서 스킬을 명시적으로 읽고 합성 요청 9개를 수행했다. 적용 기준과 스킬 지침은 `aef88df`와 같은 내용으로 복사했다. 주 진행자는 요구 기반 기준과 실제 응답·파일·index·HEAD를 별도로 대조했다. 요청·응답, 핵심 명령, 입력 지문과 관찰은 [검증 근거](artifacts/skill-verification.json)에 보존했다. 자동 스킬 선택이나 모든 요청에서의 재현성을 검증한 결과는 아니다.

<a id="skill-review-work"></a>
## 작업 결과 검수

| 사례 | 실제 확인 |
|---|---|
| R1 읽기 전용 검수 | 기존 테스트 2개 통과와 별개로 상한 경계값 결함을 발견했다. 코드·index·HEAD를 보존했다. |
| R2 완료 제출 제한 | 작업 폴더 완료/index 검증 중의 불일치를 실제 검사하고 커밋을 중단했다. 문서·index·HEAD를 보존했다. |
| R3 정상 제출 | 테스트 3개와 staged 완료 상태를 확인하고 별도 읽기 전용 검수자를 호출한 뒤 격리 저장소에 커밋했다. 검수한 테스트 blob·생성 부모·변경 범위·남은 트리를 대조했다. |

R2의 첫 기본 명령에서 CP949가 출력 구분 문자 `U+2014`를 인코딩하지 못했다. 이 오류를 상태 불일치 근거로 세지 않고 UTF-8 재실행에서 실제 불일치를 확인했다. 보조 도구의 두 출력 구분 문자만 ASCII `-`로 바꿨다. 새 회귀의 assertion 실패 2개를 먼저 재현했고 보완 뒤 전체 6개가 실패/error 0으로 통과했다(1.753초). 현재 보조 도구의 기본 CP949 명령은 같은 R2/R3 저장소에서 불일치 1·정상 0과 올바른 진단을 반환했다. `SKILL.md`는 동일하며 변경한 보조 도구의 영향 범위를 재검증했다.

세 `SKILL.md` 지문은 검증 전후 동일하다. 검수 스킬의 보조 도구·회귀 파일만 인코딩 보완으로 변경했으며, 현황에는 보완 후 원천 지문과 해당 범위의 근거를 연결했다.

제출 전 자체·별도 검수에서 실제 staged 5개와 원본 응답·fixture 상태를 대조했다. 별도 검토자는 현재 CP949 명령의 R2 불일치 1/R3 정상 0과 index 보존을 직접 확인했고 staged 현황 검사는 0.5937초에 통과했다. 원천·후보·공백·근거 재사용과 제한된 확인 범위에 남은 필수 결함을 발견하지 못했다.

원격 회귀: [run 43173016983](https://github.com/Mi-no-Kim/LumiaWiki/actions/runs/43173016983)은 정확한 `b49c8db` commit 검사, 현황 도구 34개와 보조 도구 6개를 두 OS에서 통과했다. Ubuntu의 현황 테스트는 Windows junction 1개를 제외했다. 이 CI는 스킬 응답 9개를 다시 생성한 실행이 아니며, 해당 수행 근거는 위 격리 요청 기록이다. 실제 수행·현재 원천·근거 연결·오류 보완과 회귀를 대조해 이번 스킬 검증의 수용을 완료했다.

최종 완료 기록의 자체·별도 검수에서 원격 대상·결과와 AI 수행/도구 회귀의 구분을 확인했다. 기존 근거 blob과 입력은 유지됐고 staged 검사가 통과했다.

일정값이 포함된 D2는 마스킹한 발췌본으로 보존했다. 원문 지문과 기존 Git blob으로 원래 입력·응답을 대조한다.
