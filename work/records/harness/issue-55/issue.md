## 문제와 목표 및 수용 조건

skill·hook을 추가·변경·삭제했는데 현황 문서가 과거 상태로 남는 누락을 발견한다. 프로젝트 관리 대상의 역할·적용 조건·원천과 확인 범위를 한곳에서 조회한다. 상세 규칙·실행 코드는 기존 원천이 소유하며 현황은 요약과 연결을 담당한다.

포함 범위는 프로젝트 skill, Codex hook, Git hook의 현황 문서, AGENTS·문서 기준·변경/검수 절차의 갱신 의무, 실제 제출 후보의 읽기 전용 검사, 기존 hook을 보존하는 Git 연결/복원과 같은 검사의 CI 정의다. 개인·전역 설정·외부 플러그인 전수 조사/변경과 보존 영역 접근·수집·검사는 제외한다. 저장소 보호 옵션은 변경하지 않는다.

수용 조건:

1. 실제 구성과 문서의 목록·원천 대응을 확인한다. 현재 원천 지문과 마지막 동작 확인 대상 지문을 구분하며 지문 갱신을 동작 검증 완료로 판정하지 않는다.
2. 추가·변경·삭제 누락, 잘못된 경로·지문과 부분 스테이징을 발견한다. 현황 문서에 관계없는 수정을 한 것으로 통과하지 않는다.
3. 정상 후보는 통과하고 관련 없는 변경에는 현황 수정을 강제하지 않는다.
4. 정의와 지정된 실행기·보조 파일의 변경 및 미등록 관리 대상을 확인한다.
5. 검사기는 자동 수정·스테이징·설치·테스트·AI·네트워크 호출 없이 판정한다.
6. 기존 Git hook의 원형 보존·공존·중복 설치·해제를 격리 사례와 실제 연결에서 확인한다.
7. Windows·부분 스테이징·경로 경계와 기존 검수 도구의 회귀를 검증한다.
8. CI 실행 정의를 마련한다. 실제 원격 CI 정상·실패 결과는 push 허용 후의 필수 확인으로 남기고, 그 전에는 해당 범위와 Issue 전체를 완료로 표시하지 않는다.

## 해결 계획과 의존

- 하나의 독립 하네스 Issue로 직접 수행한다. Task·Phase·milestone을 추가하지 않고 제품 작업 현황에 등록하지 않는다.
- 대화 초안 검증 → 실제 GitHub 등록 → 실제 번호의 이 기록 생성 → 최신 main에서 분기 → 구현/검증 순서다.
- 현황 문서 한 파일 안에 사람이 읽는 요약과 기계 판독 정보를 둔다. 별도의 분할 원본/생성본은 만들지 않는다. 상세 규칙 본문을 복제하지 않는다.
- 표준 라이브러리 기반 검사기에서 work/index/명시 commit 후보를 구별한다. 커밋 전에는 실제 index, CI에서는 명시 commit을 읽는다. 임의 셸 편집까지 모두 사전 차단하는 것으로 주장하지 않는다.
- 검사기와 현황 판독 형식·등록 경로를 먼저 확정한 뒤 의미 있는 누락/정상/경계 사례로 검증한다. 기존 검수 skill의 변경은 Skill Creator와 기존 검수 기준을 함께 적용한다.
- 설치기는 기존 Git hook과 관련 설정을 보존하며 자기 wrapper가 그대로일 때만 해제한다. 실제 설치 상태는 저장소에 기록한 정의와 구별한다.

### 구현 계약 — 2026-11-12

- 현황은 `harness/스킬과 hook 현황.md` 한 파일에 둔다. JSON 관리 블록이 요약 메타데이터의 원본이고 같은 문서의 표는 그 데이터에서 만든다. 별도 JSON 원본/생성 문서를 만들지 않으며 검사 시 표와 데이터의 일치도 확인한다.
- 관리 원천은 후보의 `.agents/skills/*/SKILL.md`와 해당 skill 폴더의 파일, `.codex/hooks.json`·`.codex/config.toml`의 실제 handler, `scripts/hooks/`의 표준 Git hook 정의다. Git hook은 정의 안의 명시 의존 목록, Codex hook은 현황의 명시 의존 목록으로 실행기·보조 파일을 연결한다. 프로젝트 config가 존재하면 handler 유무와 관계없이 각 Codex 항목의 필수 원천에 포함해 활성 조건 변경을 확인한다. 새 등록 위치·동적 의존의 누락은 변경/검수에서 추가 확인하며 모든 임의 경로를 자동 해석한다고 주장하지 않는다.
- 항목마다 식별자·정의·담당 역할·적용 조건·파일 목록·현재 내용 지문과 별도의 마지막 확인 상태/대상 지문·날짜·환경·범위·근거를 둔다. 미확인·재확인 필요·확인을 구별한다. 현재 지문 갱신만으로 마지막 확인을 바꾸지 않는다. 텍스트 지문은 CRLF/LF 차이를 정규화하고 바이너리는 원래 바이트로 확인한다.
- 명령은 `python -B scripts/check-harness-inventory.py --candidate work|index|<commit>`이다. 기본 index 검사는 읽기 전용·정상 무출력·실패 이유/다음 행동으로 반환한다. `--describe`는 원천/지문, `--render`는 표를 stdout으로 제공하며 자동으로 파일·index를 바꾸지 않는다.
- Git 정의는 `scripts/hooks/pre-commit`, 설치/해제는 `python -B scripts/install-harness-hooks.py`·`--status`·`--remove`로 한다. core.hooksPath를 변경하지 않으며 저장소 밖의 사용자 hook 위치는 자동 수정하지 않는다. 기존 hook을 먼저 실행하고 자신의 검사만 뒤에 연결한다. 여러 설치기가 중첩되면 바깥 wrapper부터 해제해야 한다. Task 42-002 설치기/metadata는 변경하지 않는다.
- 이전 브랜치에 검사기와 현황이 모두 없으면 새 검사 단계만 생략하고 기존 hook을 실행한다. 둘 중 하나만 누락된 구성은 통과시키지 않는다. main/현재 브랜치에서 실제 Codex hook이 없는 상태와 Task 42-002의 보존된 정의/검증을 구별한다.
- 표준 라이브러리 Python 도구·격리 Git 저장소 테스트와 Windows 실제 연결을 사용한다. CI 정의는 같은 후보/테스트 명령을 호출하며 원격 실행은 미확인으로 남긴다. 기존 skill 상태 검사 테스트도 회귀 실행한다.
