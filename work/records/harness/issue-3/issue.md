## 문제와 목표 및 수용 조건

기존 기준이 독립 Issue를 records 바로 아래에 두도록 한 구조를 정정한다. 독립 제품 Issue와 독립 하네스 정비 Issue를 목적에 맞게 분리하고, 기존 Issue #1의 기록과 근거를 보존해 이관한다.

- 범위: 기록 체계·work 안내·구조 문서·Git 기준·생성 절차의 최소 수정, Issue #1 기록의 경로·상대 참조 정정, 이 담당 기록의 작성·검수.
- 제외: 제품 구현·자료·Phase 계획 변경, 저장소 설정·자동 검사 추가, main 병합.
- 수용 조건:
  - 제품 Phase 소속·독립 제품·독립 하네스·제품에 수반한 하네스 수정의 배치가 구별된다.
  - 경로 원천과 안내·절차의 연결이 일치하고 새 승인 단계나 중복 규칙을 만들지 않는다.
  - Issue #1의 번호·완료 상태·기존 본문·앵커·검수 이력을 보존하고 현재 참조를 새 위치에 맞춘다.
  - 과거 커밋의 원문과 PR #2 고정 근거를 보존하고 자체·별도 검수 및 제출 범위 확인을 마친다.
- 기준 원천: [기록 체계](<../../../../docs/작업 기록 체계.md#paths>), [참조·정정 기준](<../../../../docs/문서 참조와 변경 기준.md#correction>), [Git 작업 기준](<../../../../docs/Git 작업 기준.md#independent-issues>).
