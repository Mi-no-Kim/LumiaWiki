<a id="goal"></a>
## 문제와 목표 및 수용 조건

Task 001에서 내용 수용 뒤 완료 표시 확인이 누락되고 종료 처리 전에 다음 Task를 안내한 문제가 있었다. 반복 확인 중 기계적으로 대조할 수 있는 부분부터 적은 비용으로 점검한다. 독립 하네스 개선이며 제품 작업·중단된 다른 개선과 분리한다.

최초 계획만 제출했던 PR #37은 사용자 정정에 따라 초안으로 바꾸고 실제 구현을 추가한다. 첫 구현 범위는 계획의 비용 판단에 따라 **Task 종료 결과 제출 전의 상태 확인 한 지점**으로 한정한다.

- 수용 조건: 지정한 Task의 스테이징된 현재 상태를 기존 수용 판단에서 정한 기대 상태와 비교해 일치·불일치·미확인을 구별한다.
- 수용 조건: 작업 파일만 고친 경우를 통과시키지 않고, 누락·중복·미지원 상태와 허용되지 않은 경로를 미확인으로 반환한다. 검사 자체는 파일·GitHub 상태를 변경하지 않는다.
- 수용 조건: 기존 검수 절차에서 필요한 Task 제출에만 실행하도록 연결하고, 의미 있는 동작 확인·자체 및 별도 검수의 근거가 있다. 결과 제출은 이 독립 Issue의 PR #37에서 수행한다.
- 자기 수용을 충족하면 PR 전에도 완료로 표시할 수 있다. PR 병합을 자동 완료 근거나 일률적인 전제로 삼지 않으며 부모 완료로 전파하지 않는다.

<a id="plan"></a>
## 비용 판단과 구현

첫 검사에는 인덱스의 Task 한 파일만 필요하고, Python 표준 라이브러리와 로컬 Git 조회 두 번을 사용한다. AI·네트워크 호출이나 전체 기록 탐색은 없다. 자유 서술인 부모 요약·현황의 의미 판정까지 자동화하면 복잡도와 오판 비용이 커지므로 기존 검수에 남겼다. 실제 토큰 절감량은 측정하지 않았고 절감 효과를 단정하지 않는다.

- [상태 검사](<../../../../.agents/skills/review-work/scripts/check_task_status.py>): 저장소 상대 Task 경로와 기대 상태를 명시적으로 받는다. 현재 기록 체계의 Task 경로만 허용하며 보존 영역·경로 이탈은 Git 조회 전에 거부한다.
- [기존 검수 skill](<../../../../.agents/skills/review-work/SKILL.md#before-commit>): Task 종료 결과 제출에만 실행하고 같은 인덱스·기대 상태의 유효한 결과를 재사용한다. 독립 Issue·일반 질문·스테이징 전 리뷰에는 강제하지 않는다.
- 종료값은 일치 0, 불일치 1, 입력·원천 미확인 2다. 오류를 자동 완료나 자동 상태 수정으로 바꾸지 않는다. 다음 행동은 수용 판단·기록·스테이징 대조로 안내한다.

저장소 루트에서 실행한다. 이 예시는 완료로 수용한 Task의 제출 전 상태 검사이며, 검사가 자체적으로 수용을 결정하는 것은 아니다.

```powershell
python .agents/skills/review-work/scripts/check_task_status.py --task work/records/phase-001/issue-15/task-001.md --expect-state 완료
```

<a id="verification"></a>
## 검증 근거와 한계

- [격리 Git 인덱스 테스트](<../../../../.agents/skills/review-work/scripts/test_check_task_status.py>) 5개 통과: 작업 파일만 완료로 고쳐도 인덱스의 진행 중을 읽음, 완료·보류·취소 구별, 미등록 파일·불명확 상태의 미확인, 허용 밖 경로 거부를 확인했다. 과거 기록의 상태를 현재 상태로 읽지 않으며 입력 파일도 바뀌지 않았다.
- 제품 브랜치 `39760f3`의 인덱스를 읽기 전용으로 대조했다. Task 001 완료 기대는 0, 예정인 Task 002의 완료 기대는 1, 없는 Task는 2, Task 002의 예정 기대는 0이었다. 제품 기록·브랜치는 수정하지 않았다.
- 최초 격리 테스트는 Windows 제한 실행 환경의 임시 Git 생성 권한으로 실패했다. 허용된 전용 임시 경로에서 다시 실행해 통과했다. skill 기본 검증기는 PyYAML 미설치로 실행하지 못했고 의존성을 추가하지 않았다. 변경하지 않은 frontmatter와 실행 파일 연결은 직접 대조했다.
- 검사 통과는 Task 상태 일치만 뜻한다. 실제 수용, 부모·현황·GitHub 동기화, 검수 적정성, PR·병합·브랜치 정리와 다음 작업 안내 조건은 기존 절차로 확인한다. hook에 의한 강제 차단이나 장기 재발 방지 효과는 검증하지 않았다.
- 실제 인덱스의 skill·검사·테스트·담당 기록 네 파일을 자체·별도 에이전트가 기존 상태·경로·완료 기준과 대조했고 필수 지적은 없었다. 인덱스·작업 파일 일치와 공백 검사도 확인했다. 별도 검토자는 테스트 코드와 기록을 대조했으며 테스트 실행은 작성자의 위 근거를 사용했다.

## 후속 조건과 기준

- 매 응답의 AI 재검수·전체 work/대화 스캔·상시 원격 조회·자동 재시도·서브에이전트 반복 호출은 하지 않는다. 비용 대비 효과가 불명확하거나 토큰 낭비가 의심되면 확대하지 않고 이유와 더 작은 대안을 반환한다.
- hook은 이번 결과의 필수 범위가 아니다. 실제 사용에서 누락 방지 효과와 추가 비용을 관찰한 뒤에만 도입 필요성을 판단한다. 필요성이 확인된 때 공식 지원·신뢰 설정·중복 실행·종료 반복 방지·해제 방법을 확인한다.
- 보존 영역 `harness-design/`·`.harness-state/`은 조회·검색·실행하지 않는다.
