# Task 상태·종료 절차 점검의 최소 자동화 검토

## 현재 요약
- GitHub Issue: [#36](https://github.com/Mi-no-Kim/LumiaWiki/issues/36)
- 상태: 예정
- 현재 진행 위치: 최소 자동화 계획의 작성·검수를 마쳤고 제품 작업과 분리한 문서 제출 범위를 확정했다. 구현·설정 적용은 착수하지 않았다.
- 다음 행동: 허용된 계획 문서의 독립 커밋·PR 제출 절차를 따른다. 구현은 별도 착수 요청이 있을 때 아래 비용 판단부터 수행한다.

## 문제와 목표
Task 001에서 완료 표시 점검과 종료 처리 전에 다음 Task를 안내하는 문제가 있었다. 기존 상태·완료 기준을 바꾸지 않고, 반복 확인 중 기계적으로 대조할 수 있는 누락을 적은 비용으로 발견한다.

## 범위와 수용 조건
- 독립 하네스 개선이다. 제품 Issue·Phase, 중단된 다른 개선 작업과 분리하며 별도 Task·첨부는 현재 만들지 않는다.
- 1차 범위는 명시적으로 지정한 Task 하나와 필요한 부모 요약·현황에 대한 읽기 전용 점검이다. 기존 기록 형식을 우선 사용하며 새 상태 체계나 검수 증명 파일을 도입하지 않는다.
- 수용 조건: 현재 단계에 필요한 상태 불일치·종료 누락을 발견하고 근거 위치와 다음 미완료 절차를 짧게 반환한다. 정상·보류·미확인을 구별하며 파일·GitHub 상태를 자동 변경하지 않는다.
- 자기 수용을 충족하면 PR 전에도 완료로 표시할 수 있다. PR 병합을 무조건 완료의 전제나 자동 완료 근거로 삼지 않고, 부모 완료로 전파하지 않는다.
- 최초 요청은 Issue 문서·계획·검수까지였으며, 후속 요청으로 이 문서의 독립 커밋·PR 제출을 포함했다. 스크립트·skill·hook 구현과 설치는 포함하지 않는다.

## 최소 실행 계획
1. 구현 착수 시 실제 누락 사례와 기존 절차를 대조해, 저비용으로 판별 가능한 항목만 선택한다. 읽기 범위·호출 시점·예상 추가 호출을 먼저 설명한다. 비용 대비 효과가 불명확하거나 토큰 낭비가 의심되면 구현·추가 조사를 진행하지 않고 이유와 더 작은 대안을 반환한다.
2. 우선 지정한 Task의 상태와 부모 요약·현황의 명백한 모순을 읽기 전용으로 검사한다. 대상 경로·현재 단계는 명시적으로 받으며 브랜치명이나 응답 문구만으로 추정하지 않는다. 수용 충족 여부와 검수의 실질적 적정성은 기존 검수에서 판단한다.
3. 완료 커밋·PR 전, 병합 후, 다음 작업 안내 전의 점검은 같은 작은 검사 수단을 재사용한다. 단계마다 해당하는 항목만 실행하고, GitHub 조회는 필요한 제출·동기화 시점에만 기존 확인과 묶는다. 첫 구현은 이 중 가장 작은 한 지점에서 시작하며 세 지점을 한꺼번에 구현하지 않는다.
4. 작은 확인 사례로 정상 허용, 실제 상태 누락 발견, 의도적인 보류·명시적 전환·정보 부족을 자동 완료로 처리하지 않음을 확인한다. PR 전 완료가 유효한 경우와 부모 진행 중 유지도 대조한다. 변경된 범위만 자체·필요한 별도 검수한다.
5. 실제 누락을 잡고 추가 읽기·호출이 절약되는 근거가 있을 때만 기존 skill 연결과 hook 도입 여부를 판단한다. hook은 후속 선택지이며 첫 결과의 필수 산출물이 아니다. 도입한다면 설치된 버전 지원·신뢰 설정·중복 실행·반복 종료 방지·해제 방법을 좁은 시험으로 확인한다.

## 비용 제한과 중단 조건
- 매 응답의 AI 재검수, 전체 work·대화 이력 스캔, 상시 원격 조회, 자동 재시도·서브에이전트 반복 호출은 하지 않는다.
- 같은 대상·내용·단계의 유효한 확인은 재사용하고, 검사로 절약할 일보다 유지·호출 비용이 커지면 확대하지 않는다. 비용을 검증 없이 절감됐다고 보고하지 않는다.
- 필수 입력이 없거나 해석이 모호하면 해당 항목을 미확인으로 반환한다. 일반 질문·보류·사용자 전환을 무조건 차단하지 않는다.
- 보존 영역 `harness-design/`·`.harness-state/`은 읽기·검색·실행 대상에서 제외한다.

## 검수와 결과
- 2026-11-10 자체 검수에서 현재 상태·완료 커밋·종료 전환 기준과 대조하고 로컬 참조 4개의 대상·표식을 확인했다. 별도 에이전트 한 명이 이 계획과 해당 기준 구역만 읽어 범위·비용 중단·PR 전 자기 완료·부모 자동완료 금지의 일치를 확인했으며 필수 결함은 없었다. 반복 검수나 전체 기록 조사는 수행하지 않았다.
- 계획 작성·검수는 완료했다. 구현 효과·자동 차단·기능 지원·실제 비용과 토큰 절감은 아직 확인하지 않았다.
- 계획 등록 뒤 Issue 상태는 예정으로 유지한다. 계획 작성 완료를 자동화 구현 완료로 표시하지 않는다.
- 후속 제출은 `main` 기준 `issue/36-task-status-plan`에서 이 문서 하나만 대상으로 한다. 검수한 계획의 내용은 유지하고 제출 범위·현재 요청만 맞추며, 제품 브랜치와 중단된 다른 작업은 변경하지 않는다. 커밋 전 실제 후보의 자체·별도 검수와 제출 후 원격 비교를 수행한다.
- 제출 전 자체·별도 에이전트 검수에서 기존 계획을 재사용하고 제출 관련 변경만 대조했다. `main` 기준 문서 한 파일, 인덱스·작업 파일 일치, 공백 및 로컬 참조 4개를 확인했으며 필수 지적은 없었다. 이 문장은 확인한 검수 결과의 요약이며 구현 검증을 뜻하지 않는다.
