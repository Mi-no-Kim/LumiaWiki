# 기록 날짜·Task/Issue 이력 누적 방지와 길이 경고

<a id="summary"></a>
## 현재 요약

- GitHub Issue: [#60](https://github.com/Mi-no-Kim/LumiaWiki/issues/60)
- 소속: main 기준 독립 하네스 Issue. Phase·하위 Task 없음.
- 상태: 완료
- 현재 결과: 기존 지침·양식과 읽기 전용 제출 검사를 반영했다. 100줄 초과는 비차단 경고로 연결했다.
- 다음 행동: 원격 반영·CI 결과는 GitHub Issue에 연결된 PR의 실제 상태를 따른다. 후속 작업은 별도 범위다.

<a id="goal"></a>
## 목표·범위·수용 조건

- Task·Issue에는 목표·조건·현재 유효한 결정/이유·승인·제약·막힘·수용 결과와 근거를 허용하고 같은 항목의 현재 내용을 교체한다. 필요한 상세 실행 근거만 artifacts에 보존한다.
- 기존 진입 지침·기록 기준·로컬/GitHub 양식을 교체한다. 새 문서 체계·스킬·AI 판별 hook과 과거 기록 전수 정리를 추가하지 않는다.
- 새로 추가·변경한 명시적 기록 날짜, 날짜형 기록 파일명, 본문의 실행 근거 전용 블록은 기존 Git hook·CI의 읽기 전용 공용 검사로 차단한다. 제품 날짜·원본 실행 ID/시각은 보존한다.
- 변경된 `work/records/**/issue.md`·`task-번호.md`가 빈 줄 포함 100줄을 초과하면 경고한다. 경고는 커밋·CI를 실패시키지 않으며 artifacts·미변경 문서를 검사 대상으로 늘리지 않는다.
- 필요한 기록의 허용과 이력 누적은 기존 문서 검수에서 판단한다. 자동 검사는 일반 문장의 의미를 판정하지 않는다.

<a id="plan"></a>
## 계획과 예정 검증

- 작성 경계를 기존 기준·양식에 반영하고 제출 검사 하나를 기존 hook·CI에 연결한다.
- 명시적 날짜/근거 블록 거부, 필요한 기록·제품 날짜·원본 근거 허용, 기존 위반 미증가, 정확한 index/commit 후보, 100/101줄 경계와 경고 시 성공을 확인한다.
- 기존 hook의 정상·거부·이전 hook 보존과 변경된 CI 입력을 대조한다. 관련 없는 제품 테스트와 기존 스킬 검증은 재실행하지 않는다.

<a id="verification"></a>
## 수용 판단과 근거

- 새 검사 10개·관련 hook 테스트 6개와 실제 설치 hook의 정상/경고/거부, 자체·별도 검수와 최종 후보 대조를 통과했다. 상세 범위·입력·한계는 [검증 근거](artifacts/verification.md#verification)에 연결한다.
- 자동 검사는 일반 문장의 의미를 판정하지 않는다. 제품 테스트는 실행하지 않았으며 원격 CI 결과는 연결 PR의 검사를 따른다.
