<a id="purpose"></a>

#### 목적

실제 GitHub Issue 생성과 로컬 정식 기록·등록의 대응을 검증할 독립 하네스 Issue를 마련한다.

<a id="expected-results"></a>

#### 기대 결과

실제 GitHub 번호·URL과 로컬 원본, unit:issue·status:planned 및 독립 Issue의 관계를 갖춘다. 실제 업무로 이어가지 않고 등록 검증 후 취소 종료한다.

<a id="conditions"></a>

#### 이미 정해진 조건

- 조건: 검증용 객체만 생성·등록하고 제품 본작업·DB 변경·브랜치 조작·push·PR은 진행하지 않는다.
  - 적용 범위: 이번 등록 검증용 Issue와 담당 #72의 검증 작업.
  - 확정 근거: 사용자의 실제 Issue·Task 생성·부모 연결 검증 요청과 담당 #72의 검증 범위.

<a id="scope"></a>

#### 대상·범위·권한

- 생성 근거: 사용자의 실제 등록 검증 요청. 부모 Phase 배정이 없는 독립 하네스 Issue다.
- GitHub Issue: Mi-no-Kim/LumiaWiki #73 — https://github.com/Mi-no-Kim/LumiaWiki/issues/73 — Closed/Not planned·unit:issue/status:cancelled 재조회 확인
- 대상·입력: 원천은 이번 사용자 요청이다. 등록 검증의 목적·기대 결과·제약은 위 구역에 반영했다. 초기 질문 목록은 미확인으로 본작업 착수 전에 확인한다.
- 범위·권한: 실제 등록·생성 상태·원본 연결 확인과 검증용 객체의 취소 종료까지다. 본작업의 결정·수행·수용은 진행하지 않는다. Task는 관련 #72 아래에서 생성·연결을 검증하며 이 Issue의 자식으로 만들지 않는다.
- 적용 지침: 생성 기본 범위·등록 절차·GitHub 게시 양식을 적용한다. 등록 검증 결과는 담당 #72가 소유한다.
- 준비 근거: 실제 발급 응답에서 #73·URL·Open·unit:issue/status:planned를 확인했다. 독립 Issue로 milestone·부모 Phase는 없으며 기존 브랜치에서 기록만 작성한다. 본작업 환경은 준비하지 않았다.
