- 동작 수정: 격리한 결합본에서 `FoundationService`의 `slow` 분기를 제거했다. 새 기대값 HTTP 400에 대해 원본은 200을 반환해 실제 단언 실패했다. 변경 후 같은 테스트가 통과했다. 정상·빈 JSON, 요청 ID, 오류 응답과 로그, 405, 프로필을 포함해 유지 대상 6건과 변경 테스트 1건이 통과했다. 정확한 수정·테스트 범위와 TDD 증거를 연결한 스테이징 트리 `1cea4def2d659ee108d8e3a7730d647c309016f9`이 통과했다.

#### 기준 제출 판독기의 로컬 예외 검증

- 대상: 기준 `bd75af8c69928a26fd91e0b71fb47f56c0ab349d`, 직접 자손 후보 `900ff308e9c3874656c2289490db7dc774ce4c95`, 트리 `2ce65d83bb65c9ba71dc72bdac345c9d6c95ff68`. 허용 목록 밖의 테스트 패키지에 `PhaseSubmissionProbeTests.java` 한 파일만 추가했다. 후보 파일 SHA-256은 `9a622a01b943c1927b8d7fc4d6bd56b35fd1f4cacc359f6b1879059e73e3b073`다.
- 확인 방법: 기준의 `check-java-submission.py`와 호출되는 네 의존 파일을 체크아웃 밖에 Git 원본 그대로 추출했다. 같은 기준과 후보를 쓰고, 같은 테스트 파일의 생성 범위·합성 예외 범위·원천·한계를 고정한 입력에서 예외 효력만 변경해 세 번 실행했다. 승인 자료는 각 실행에서 작업 트리 밖의 `--approval-context`로 공급했다. 실행과 승인 자료는 합성 검증 범위다.
- 결과: 유효 `verified` → 통과 `pass`, 종료 0. 만료 `expired` → 위반 `violation`, 종료 1. 효력 미확인 `unconfirmed` → 미확인, 종료 2. 두 거부의 이유가 각각 유효한 승인 없음과 승인 효력 미확인임을 대조했다. 세 결과에서 같은 경로, 설정 변경 없음, 승인·모듈·HTTP 선택과 백엔드 존재를 확인했다.
- 검수: 별도 에이전트가 기준·후보 관계와 단일 추가 파일, 기준 판독기 바이트, 효력만 다른 입력을 확인하고 세 판정과 종료값을 독립 재현했다. 문서 별도 검수는 r001 보존 및 Issue·r002·Task 연결을 확인했다. 지적에 따라 Issue 수용표의 범위를 관련 검사 선택과 제출 승인 판정으로 명시했다.
- 한계: 이 로컬 실행의 범위는 제출 승인 판독과 후속 검사 선택이다. 이 합성 후보의 모듈·Spring 작업 실행과 공식 GitHub 승인 자료 공급은 미확인으로 기록한다. 정상 결합의 실제 원격 작업 결과는 [원격 CI](#work-phase-ci)에 연결한다.
