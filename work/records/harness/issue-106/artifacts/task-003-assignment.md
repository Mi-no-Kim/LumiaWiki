# Task 106-003 전달사항 — 모듈 의존·공개 HTTP API 검사와 CI 연동

<a id="assignment-body"></a>

- 태그: 조사, 논의, 결정, 실행, 검수

<a id="purpose"></a>

## 목적

업무 모듈의 공개 경계와 승인된 HTTP API가 제출 후보에서 지켜졌는지 자동으로 확인한다.

<a id="result"></a>

## 기대 결과

모듈 구조 검사기, 승인 근거가 연결된 최초 공개 HTTP API 목록, Spring 매핑 대조기와 실제 Spring 검증 사례, 제출 후보에 대한 CI 실행 연결을 제공한다.

<a id="scope"></a>

## 이미 정해진 조건

- 조건: 다른 모듈의 내부 타입 참조와 직접·간접 업무 모듈 순환을 검사한다. 공개 계약을 통한 비순환 의존을 허용하고, 발견된 순환 경로를 표시한다.
  - 적용 범위: 업무 모듈 구조 검사
  - 확정 근거: [결정 2](../issue.md#decision-2) · [결정 3](../issue.md#decision-3)

  - 적용 범위: 공개 HTTP API 목록, Spring 매핑 검사 및 검증 사례
  - 확정 근거: [결정 3](../issue.md#decision-3) · [Issue 수용 조건](../issue.md#acceptance-criteria) · [확정 배정](../issue.md#task-allocation)
- 조건: 규칙·API 승인 목록·예외·검사 설정만 바뀌어도 관련 검사를 실행한다. 판정 입력 자체의 변경은 승인된 원천에 대조한다.
  - 적용 범위: CI 실행 조건 및 실제 제출 후보

  - 적용 범위: 선행 산출물 및 CI 책임

<a id="decisions"></a>

## Task에서 결정할 사항

- 결정할 사항: 모듈 의존과 실제 HTTP 매핑을 어떤 방식으로 수집·검사할까?
  - 결정 범위: 구조 검사 도구, 실제 Spring 매핑의 공개 판정, 승인 목록의 형식과 대표 검증 사례
  - 판단 기준: 공개 계약·내부 타입·순환을 구별하고 승인된 목록과 실제 등록 결과를 대조할 수 있어야 한다.
  - 결정 주체: 검사 도구·형식은 위임한다. 최초 공개 API 목록은 프로젝트 결정권자 또는 명시적으로 위임된 승인권자가 승인한다.
- 결정할 사항: 판정 입력만 바뀐 후보에도 CI를 어떻게 연결할까?
  - 결정 범위: 변경 분류, 실제 제출 후보 식별, 승인 검사 진입점과 각 검사 결과 표시
  - 판단 기준: 유효한 기준과 후보 사이의 증분 변경에서 관련 개별 검사가 실행되어야 한다.
  - 결정 주체: 연결 설계는 위임한다. 실제 원격 실행은 승인된 대상·이벤트·권한 범위를 따른다.

<a id="acceptance"></a>

## 완료 조건과 확인 방법

- 완료 조건: 업무 모듈 구조 검사의 판정
  - 확인 방법: 비순환 공개 참조, 타 모듈 내부 참조, 직접·간접 순환을 검증용 모듈로 재현하고 순환 경로를 확인한다.
- 완료 조건: 최초 승인 목록과 실제 Spring 매핑 대조
  - 확인 방법: 승인 근거가 연결된 목록에서 실제 URL·HTTP 메서드의 일치, 미승인 추가·삭제·변경, 개발 전용 경로의 판정을 검증한다.
- 완료 조건: CI 연결과 조건별 후보
  - 확인 방법: 유효한 기준·후보 커밋의 증분 사례에서 규칙·목록·예외·설정만 바꿔 관련 개별 검사가 선택·실행되는지 확인한다. 제출 후보용 승인 검사 진입점과 지속 가능한 CI 연결을 남긴다.
