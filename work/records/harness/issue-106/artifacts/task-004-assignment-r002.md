# Task 106-004 확정 전달사항 r002 — 최종 후보 통합 검증과 사용·복구 안내

<a id="assignment-body"></a>

- 태그: 조사, 논의, 결정, 실행, 검수

<a id="purpose"></a>

## 목적

백엔드가 없는 기준 후보와 실제 Spring 소스가 있는 Phase 1 결합 후보에서 전체 검사의 적용·판정을 확인한다.

<a id="result"></a>

## 기대 결과

정확한 후보에 대응하는 통합 검증 근거, 재현 가능한 사용·복구 안내, Issue 수용에 필요한 최종 후보 대조 결과를 제공한다.

<a id="scope"></a>

## 이미 정해진 조건

- 조건: 백엔드의 존재 여부를 실제 Git 후보로 판정한다. 백엔드가 없는 기준 후보의 Java·Spring 검사에 적용 대상 없음과 정상 종료를 확인한다.
  - 적용 범위: main 기준 후보
  - 확정 근거: [결정 5](../issue.md#decision-5)
- 조건: 별도 worktree에서 Phase 1 기준과 #106 후보의 결합 결과를 식별한다. 실제 편집 훅·커밋 전 검사에서 정상·위반·예외를 확인하고 기존 동작의 보존을 대조한다. 정상 통합의 실제 원격 CI와 Spring 등록을 확인하고 예외·설정 사례의 제출 승인 판정은 아래 증거 기준을 적용한다.
  - 적용 범위: Phase 1 실소스 통합 검증
  - 확정 근거: [결정 1](../issue.md#decision-1) · [결정 4](../issue.md#decision-4) · [결정 5](../issue.md#decision-5)
- 조건: Phase 1의 예외·설정 사례는 기존 원격 회귀와 기준 이력의 격리 제출 판독으로 확인한다. 공식 CI의 외부 승인 공급과 해당 원격 사례의 실행은 미확인으로 기록한다.
  - 적용 범위: 예외·설정 단독 변경의 제출 승인 판정. 정확한 기준·후보 SHA에 묶인 합성 승인 자료를 작업 트리 밖에서 공급해, 기준 이력의 `check-java-submission.py`로 판정과 검사 선택 및 종료값을 확인한다. 저장소 설정 변경 없이 검증한다.
  - 확정 근거: [Phase 1 제출 승인 검증 기준](../issue.md#decision-5-submission-evidence)
- 조건: 원격 CI 실행 전에 대상 저장소·브랜치·이벤트·실행 주체와 push, 결과·로그 조회, 필요한 재실행 및 정리 권한을 실제로 확인한다. 미확인 상태에서는 그 결과에 의존하는 수용과 병합을 보류한다.
  - 적용 범위: Phase 1 원격 CI 실행 조건
  - 확정 근거: [위임·승인 및 실행 조건](../issue.md#task-execution-conditions) · [결정 5](../issue.md#decision-5)
- 조건: 마지막 후보의 커밋 또는 동일 내용의 Git 트리와 개별 필수 검사 결과를 연결한다. 후보나 조건이 바뀌면 영향을 받는 검사를 다시 확인한다. Issue가 전체 수용을 판단한다.
  - 적용 범위: 최종 후보 근거의 재현 및 인계
  - 확정 근거: [결정 4](../issue.md#decision-4) · [결정 5](../issue.md#decision-5) · [Issue 수용 조건](../issue.md#acceptance-criteria)
- 조건: 도구·입력 형식·메시지·재실행 방법과 검증용 코드의 구현은 합의 범위 안에서 위임한다. 정책·승인 범위나 실행 권한의 변경은 해당 승인 원천에 대조한다.
  - 적용 범위: 이 Task의 상세 설계 및 실행 준비
  - 확정 근거: [위임·승인 및 실행 조건](../issue.md#task-execution-conditions)

<a id="decisions"></a>

## Task에서 결정할 사항

- 결정할 사항: 실제 Phase 1 결합 후보와 CI 실행 경로를 어떻게 고정할까?
  - 결정 범위: 기준·결합 후보 식별, 워크플로에 맞는 검증용 브랜치와 이벤트, 실행·조회·정리 범위
  - 판단 기준: 최종 후보와 동일한 내용의 검증 근거를 남기고 실제 원격 권한을 확인할 수 있어야 한다.
  - 결정 주체: 검증 설계는 위임한다. 원격 동작은 명시 승인·접근 확인 범위에서 진행한다.
- 결정할 사항: 어떤 사례와 안내로 실제 사용·재개를 확인할까?
  - 결정 범위: 정상·위반·예외·미확인 검증, 기존 동작 유지, 실제 사용·복구 절차
  - 판단 기준: 최종 main 후보의 내용과 Phase 1 기준으로 결과를 재현하고 필요한 다음 행동을 알 수 있어야 한다.
  - 결정 주체: 검증용 코드, 결과 기록 및 안내 구현은 위임한다.

<a id="acceptance"></a>

## 완료 조건과 확인 방법

- 완료 조건: 두 기준 환경의 실제 실행 결과
  - 확인 방법: 백엔드가 없는 Git 후보의 적용 대상 없음과 Phase 1 결합 후보의 편집·커밋·CI 판정을 확인한다. 기존 Java의 승인된 수정·삭제 범위와 유지 동작을 회귀 사례로 대조한다.
- 완료 조건: 실제 제출 후보에 맞는 CI와 판정 근거
  - 확인 방법: Phase 기준 커밋, 실행한 결합 커밋 또는 동등한 Git 트리, CI 실행 ID와 필수 개별 job 결과를 연결한다. 규칙·승인 목록·설정만 바뀐 후보와 배치 예외의 제출 승인 판정은 기존 원격 회귀와 격리 제출 판독으로 확인한다. 유효 예외는 통과, 만료는 위반, 효력 미확인은 미확인으로 판정한다. 공식 CI의 외부 공급과 해당 사례별 원격 job 실행은 미확인으로 남긴다.
- 완료 조건: 최종 후보 재현과 사용·복구 안내
  - 확인 방법: 최종 main 후보가 필요한 산출물·등록 정의·현황을 포함하는지 대조한다. 사용과 실패 조치가 재현되는 안내와 확인 근거를 Issue 수용에 제공한다.
