# Task 106-002 전달사항 — 편집·커밋 훅 구현과 TDD 연동

<a id="assignment-body"></a>

- 태그: 조사, 논의, 결정, 실행, 검수

<a id="purpose"></a>

## 목적

편집 중 파일 배치 문제를 발견하고, 실제 커밋 후보에서 배치와 승인·TDD 근거의 불일치를 판정할 수 있게 한다.

<a id="result"></a>

## 기대 결과

Codex 편집 전·직후 및 Git 커밋 전 검사, 승인을 확인하는 재사용 진입점, 훅 등록과 현황, 단계별 판정·재개 안내를 제공한다.

<a id="scope"></a>

## 이미 정해진 조건

- 조건: 지원 편집 도구로 운영 Java의 동작을 바꾸기 전 유효한 Red 또는 승인된 예외를 확인한다. 생성·이동의 경로·패키지·이름 위반은 편집 직후 알린다.
  - 적용 범위: Codex 편집 트리거
  - 확정 근거: [결정 4](../issue.md#decision-4)
- 조건: 커밋 전에는 실제 스테이징 후보에서 생성·이동 범위를 검사하고, 동작 변경의 Red·Green 또는 승인 예외를 후보와 대조한다. 순수 리팩터링에는 변경 전후 관련 테스트와 근거를 확인한다.
  - 적용 범위: Git pre-commit 및 테스트 실행 기록
  - 확정 근거: [결정 1](../issue.md#decision-1) · [결정 4](../issue.md#decision-4)
- 조건: 만료 예외나 확인 가능한 무승인 확대는 위반, 필수 근거 판독 실패는 미확인으로 처리한다. 승인 검사 진입점은 CI의 제출 후보에도 재사용할 수 있어야 한다.
  - 적용 범위: 패키지 승인·위임·예외 검사와 후속 CI 연결
  - 확정 근거: [결정 4](../issue.md#decision-4) · [결정 6](../issue.md#decision-6) · [확정 배정](../issue.md#task-allocation)
- 조건: 공통 정책과 입력은 Task 106-001이 제공한다. 기존 TDD·포맷·기록 검사와 함께 동작하도록 하고, 훅 등록 정의와 현황을 같은 변경에 맞춘다.
  - 적용 범위: 로컬 훅·승인 검사 구현의 선행 조건과 등록
  - 확정 근거: [확정 배정](../issue.md#task-allocation) · [이미 정해진 조건](../issue.md#conditions)
- 조건: 도구·입력 형식·메시지·재실행 방법과 검증용 코드의 구현은 합의 범위 안에서 위임한다. 정책·승인 범위나 실행 권한의 변경은 해당 승인 원천에 대조한다.
  - 적용 범위: 이 Task의 상세 설계 및 실행 준비
  - 확정 근거: [위임·승인 및 실행 조건](../issue.md#task-execution-conditions)

<a id="decisions"></a>

## Task에서 결정할 사항

- 결정할 사항: 기존 TDD 검사기와 편집 후 검사 경로를 어떻게 재사용할까?
  - 결정 범위: 지원 편집 도구 및 실제 트리거, 배치 검사 시점과 후보 식별, 기존 포맷·기록 검사 연동
  - 판단 기준: 동작 변경과 생성·이동의 검사 범위가 맞고 지원되는 기존 동작을 유지해야 한다.
  - 결정 주체: 도구와 연동 방식은 위임한다. 적용 범위와 강제 수준의 변경은 사전 확인한다.
- 결정할 사항: 패키지 승인 검사 결과를 로컬과 CI에서 어떻게 공유할까?
  - 결정 범위: 실제 인덱스·제출 후보 입력과 검사 결과 형식, 오류 메시지·재실행 방법
  - 판단 기준: 후보와 승인 원천 대조가 일관되고 위반·미확인 및 허용된 다음 행동을 알려야 한다.
  - 결정 주체: 데이터 형식과 구현은 위임한다. 승인 효력과 위임 한도는 결정 6을 따른다.

<a id="acceptance"></a>

## 완료 조건과 확인 방법

- 완료 조건: 실제 편집과 커밋에서 적용 범위와 차단 수준이 동작
  - 확인 방법: 지원 편집의 Red·예외 유무, 경로 위반 알림, 커밋의 유효·누락 TDD 근거를 재현한다. 작업 트리만 정상인 경우와 인덱스만 정상인 경우를 함께 검사한다.
- 완료 조건: 패키지 승인 판정과 제출 후보 입력 지원
  - 확인 방법: 정상 위임, 같은 후보의 무승인 규칙 및 패키지 변경, 만료 예외, 근거 판독 실패를 서로 구분한다. CI가 제출 후보를 지정해 호출할 수 있는지 대조한다.
- 완료 조건: 등록과 안내
  - 확인 방법: 로컬 훅 등록 정의와 현황이 일치하고 메시지에서 대상·이유·다음 행동을 확인할 수 있는지 검증한다.
