# Task 106-001 전달사항 — Java 작성·관리 규칙과 승인 기준 수립

<a id="assignment-body"></a>

- 태그: 조사, 논의, 결정, 실행, 검수

<a id="purpose"></a>

## 목적

운영·테스트 Java 파일의 위치·책임·공개 범위와 패키지 승인 판단을 일관되게 적용할 수 있는 작성·관리 규칙을 마련한다.

<a id="result"></a>

## 기대 결과

Java 작성·관리 규칙, 공통 검사 입력 규격과 허용 경로 기준, 정상·위반·예외 예시, 사례별 기대 판정을 제공한다.

<a id="scope"></a>

## 이미 정해진 조건

- 조건: 경로·패키지·이름 검사의 첫 적용은 운영·테스트 Java 생성·이동으로 한정한다. 기존 Java 내용 수정과 동작을 제거하는 삭제는 승인된 범위와 유지 동작을 검수한다.
  - 적용 범위: Java 규칙 및 생성·수정·이동·삭제 예시
  - 확정 근거: [결정 1](../issue.md#decision-1)
- 조건: 업무 모듈별 소유 기능·데이터와 공개 계약을 명시한다. 계약을 통한 모듈 간 접근과 용도별 공개 계약을 허용하며, 공용 기술 코드의 허용 참조를 정한다.
  - 적용 범위: 업무 모듈, common, dev, 테스트 픽스처와 운영·테스트 소스 배치
  - 확정 근거: [결정 2](../issue.md#decision-2)
- 조건: 허용 경로 기준과 승인 근거 확인 방법을 정한다. 새 경계와 공통 범위 확대에는 사전 승인이 필요하고, 위임과 임시 예외에는 적용 한계·근거 및 해당 시 종료 조건·정리 책임이 필요하다.
  - 적용 범위: 공통 승인 기준과 검사 입력
  - 확정 근거: [결정 6](../issue.md#decision-6)
- 조건: 공개 HTTP API의 범위·승인 목록의 근거 기준과 검사 입력을 정의한다. 최초 승인 목록의 확정 및 실제 매핑 대조는 후속 CI 검사 Task가 담당한다.
  - 적용 범위: 타 모듈 참조 및 공개 HTTP API 검사 입력
  - 확정 근거: [확정 배정](../issue.md#task-allocation)
- 조건: 도구·입력 형식·메시지·재실행 방법과 검증용 코드의 구현은 합의 범위 안에서 위임한다. 정책·승인 범위나 실행 권한의 변경은 해당 승인 원천에 대조한다.
  - 적용 범위: 이 Task의 상세 설계 및 실행 준비
  - 확정 근거: [위임·승인 및 실행 조건](../issue.md#task-execution-conditions)

<a id="decisions"></a>

## Task에서 결정할 사항

- 결정할 사항: 업무 모듈과 운영·테스트 패키지의 배치·공개 범위를 어떻게 표현할까?
  - 결정 범위: 모듈 내부 계층과 역할 패키지, common·dev와 테스트 픽스처의 위치 및 공개 가능한 타입
  - 판단 기준: 소유 업무, 공개 계약, 정상 및 위반 사례를 규칙만으로 구별할 수 있어야 한다.
  - 결정 주체: 합의 범위 안의 세부 설계는 위임한다. 새 공통 허용 범위·모듈 경계는 사전 승인 조건을 따른다.
- 결정할 사항: 허용 경로와 승인 근거를 검사기에서 어떤 규격으로 읽을까?
  - 결정 범위: 공통 입력과 승인 기록의 참조·효력 표현, 공개 HTTP API 범위와 승인 기준 표현
  - 판단 기준: 후속 두 구현이 같은 기준을 읽을 수 있고 정책 파일만 바꿔 승인 범위를 늘릴 수 없어야 한다.
  - 결정 주체: 데이터 형식은 위임한다. 기준의 확대와 최초 공개 API 목록은 승인 조건을 따른다.

<a id="acceptance"></a>

## 완료 조건과 확인 방법

- 완료 조건: 작성·관리 규칙과 정상·위반·예외 예시
  - 확인 방법: 운영 Java와 대응 테스트 한 쌍, 경로·패키지 불일치, 미공개 타입 참조, 새 패키지 승인 예시에서 위치·위반·수정 방법을 식별할 수 있는지 대조한다.
- 완료 조건: 독립적으로 검토 가능한 공통 검사 입력과 기대 판정
  - 확인 방법: 입력 예시에서 기존 허용, 위임된 추가, 만료 예외, 승인 원천 및 공개 API 범위를 구별하고 문서의 기대 판정과 대조한다.
- 완료 조건: 기존 수정·삭제의 범위 검수와 회귀 확인 방법
  - 확인 방법: 운영 코드·테스트 기대값을 승인 범위에 대조하고 유지할 동작을 회귀 확인하는 예시를 검토한다.
