## 제출 승인 판독기와 CI 입력

- 할 일: [Task 계획](../task-003.md#work-ci-candidates)
- 조치·판단: 실제 Git 기준의 기존 승인 판독기와 독립 자료를 사용한다. 입력 추가·변경·삭제는 Git 파일의 전후 지문을 대조한다. 검사기가 포함된 최초 기준을 별도로 수용하도록 분리했다.
- 확인: 실제 Git 후보 회귀 6건에서 최초 빈 목록, 후보 자체 승인 거부, 메서드 교체 양쪽 승인, 규칙·목록·예외·설정 및 검사기 의존 단독 변경을 확인했다. 동일 게이트 검증의 Red `004d2dbdef2f428ba515fa6243b6bac6`와 Green `9a98920e4728488cac0ab5a863044dff`를 실제 인덱스와 대조했다.
- 최초 설정 승인 보완: 전체 파일 묶음의 전후 지문이 일치하고 워크플로가 기준 전체 이력에 없을 때만 적용한다. 부분 추가와 삭제 후 재추가는 차단하고 얕은 비교 기준은 미확인으로 남긴다. 같은 회귀의 Red `1eb86b3c5190407d8aece8a3315254aa`, Green `27caf1305df64a78aece731432115afc`를 대조했다.
- 잔여: [독립 판독 기준 PR #116](https://github.com/Mi-no-Kim/LumiaWiki/pull/116)의 양 OS CI와 부모 `cc2be36` 반영을 확인했다. 같은 트리를 기준으로 후속 구현 PR의 개별 검사 결과를 대조한다. 전체 Phase 1을 실제 CI에 넣는 비교 기준에도 선행 승인 원천과 판독기가 이미 있어야 한다.
