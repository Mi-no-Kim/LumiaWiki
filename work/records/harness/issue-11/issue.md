<a id="goal"></a>
## 문제와 목표 및 수용 조건

[Issue #9](https://github.com/Mi-no-Kim/LumiaWiki/issues/9)에서 본문으로 충분한 API 출력 JSON을 별도 보존했고, 자체·별도 검수가 파일의 정합성에 치우쳐 첨부 필요성 판단을 놓쳤다. 기존 첨부 기준의 실행·검수 누락을 보완한다.

- 범위: [문서 관리 절차의 생성과 등록](<../../../../harness/문서 관리.md#create>), [검증과 완료 기준](<../../../../docs/details/operations/검증과 완료.md>) 및 이 담당 기록.
- 원천: [기록 체계의 첨부 기준](<../../../../docs/작업 기록 체계.md#paths>)을 유지한다. 별도 규칙 전문·양식·첨부를 새로 만들지 않는다.
- 수용 조건: 요청 외 첨부를 추가하기 전에 본문·기존 이력으로 충분하지 않은 용도를 판단하고 알린다. 자체·별도 검수는 필요성·중복을 먼저 확인하고 작성자의 파일 목록도 검토 대상으로 삼는다.
- 제한: JSON 전면 금지나 모든 파일에 대한 추가 승인을 만들지 않는다. 요청한 산출물과 실제 기계 소비 등에 별도 형식이 필요한 결과는 유지할 수 있어야 한다.
- 제외: Issue #9의 본문 정정·GitHub 설정·제품 변경, 보류한 skill 추가, PR 병합.

<a id="plan"></a>
## 해결 계획과 의존

기존 기준 자체를 복제하지 않고 생성 절차와 검수 기준에서 필요한 위치로 연결한다. 문구가 이번 실패를 걸러내면서 필요한 산출물을 막지 않는지 대조하고 자체·별도 검수한다. 담당 기록과 같은 목적의 커밋·push·PR로 제출한다.

관련 [PR #10](https://github.com/Mi-no-Kim/LumiaWiki/pull/10)의 변경 내용에는 JSON 제거와 본문 통합이 반영되어 있고 아직 미병합이다. 그 정정은 이 변경에 포함하지 않는다. 이 작업은 main에서 별도 분기하고 새로운 부모·자식 관계나 skill을 만들지 않는다.

<a id="verification"></a>
## 검증과 수용 판단

아래는 문구의 적용 판단을 대조한 내용이다. 실제로 새 JSON·복구 파일을 생성하거나 후속 제품 작업을 실행한 시험은 아니다.

| 대조 상황 | 기대·문구 적용 판단 |
|---|---|
| Issue #9처럼 본문·기존 이력으로 충분한 API 원문 | 별도 보존 용도를 설명할 수 없으므로 최종 첨부로 추가하지 않는다. 작성자가 이미 넣었더라도 검수 대상이다. |
| 사용자가 JSON 등 특정 형식을 산출물로 요청한 경우 | 요청한 산출물이므로 첨부 추가 알림을 이유로 다시 승인받지 않고 요청한 형식으로 작성한다. |
| 기계 입력·검증·복구 등에 별도 형식이 필요한 경우 | 본문·기존 이력으로 충족되지 않는 실제 용도를 확인한다. 요청 외 첨부라면 용도·이유를 추가 전에 알리며 형식 자체를 금지하지 않는다. |
| 검증에 사용했지만 최종 사용처가 없는 중간 출력 | 사용했다는 사실만으로 보존하지 않고 최종 제출 파일에서 제외한다. |

자체·별도 검수에서 세 문서의 필요성·역할·기존 기준과의 중복·수용 범위를 대조했고 추가 지적이 없었다. 요청 외 첨부 알림이 추가 승인이 아니며 JSON 전면 금지나 필요한 형식의 제한이 아님을 확인했다. 내부 링크 35개와 표식·변경 형식 검사를 통과했다. 기존 첨부 원천·다른 기록·skill은 변경하지 않았고 새 첨부·체크리스트도 없다.

문구 보완과 사례 대조를 실제 후속 사용의 재발 방지 효과가 검증된 것으로 확대하지 않는다. 검수는 기준·절차·기록의 내용·참조와 문구 적용 판단에 한정한다.
