- 다음 행동: 검수한 실제 후보를 커밋·PR로 제출하고 head·base·파일 범위를 확인한다. 제출·종료 처리가 남은 동안 다음 작업을 안내하지 않는다.

<a id="goal"></a>
## 문제와 목표 및 수용 조건

Task 001의 내용 수용 뒤 제출·종료 처리가 남아 있는데 Task 002를 바로 안내한 문제가 있었다. 사용자는 현재 작업의 종료 처리가 남으면 그 절차를 다음 행동으로 반환하는 조건을 공용 절차에 반영하고 제품 PR과 분리하도록 요청했다.

- 범위: [공용 절차의 완료·인계](<../../../../harness/공용 절차.md#finish>)와 이 담당 기록. 하나의 독립 Issue로 직접 수행한다.
- 수용 조건: 내용 수용·로컬 완료만으로 다음 작업을 안내하지 않고, 남은 종료 절차를 다음 행동으로 반환하며, 기존 권한·상태·명시적 전환 절차와 양립한다. 실제 후보의 자체·별도 검수 뒤 커밋·PR을 제출한다.
- 분리: [제품 PR #33](https://github.com/Mi-no-Kim/LumiaWiki/pull/33)의 head `a06b665`와 제품 브랜치는 수정하지 않는다. 중단된 기존 하네스 개선을 재개하지 않는다. 보존 영역 두 곳은 조회·검색·수정 대상에서 제외한다.

<a id="plan"></a>
## 계획과 수행

- 완료·인계에 전환 조건을 추가하고 종료 범위는 요청·권한과 기존 Git 절차를 따르도록 연결했다. 사용자 명시적 전환은 기존 보존·전환 절차를 따른다.
- 기존 로컬 완료 상태의 의미나 커밋·PR의 권한을 바꾸지 않고, 제품 현황에는 이 독립 하네스 개선을 등록하지 않는다.

비교 기준은 main `32b7a42`와 사용자 지시, 기존 공용 절차·종료/Git 절차·로컬 상태 기준이다. 다음은 문서상 조건 대조이며 제품 기능 실행이나 장기 재발 방지 효과를 검증한 결과가 아니다.

| 요청 범위의 종료 처리 완료 | 다음 작업 안내 가능. PR 전 로컬 완료 표시를 금지하는 규칙으로 확대하지 않음 |
| 실행 권한 또는 필수 확인 부족 | 미해결 조건·필요 판단을 반환하고 미허용 Git 작업을 강제하지 않음 |
| 사용자 명시적 작업 전환 | 기존 전환 절차로 현재 작업을 보존하고 전환. 자율적인 다음 Task 안내와 구별 |
