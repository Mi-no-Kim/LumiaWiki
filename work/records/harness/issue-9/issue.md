## 문제와 목표 및 수용 조건

[GitHub 저장소 설정 기준](<../../../../docs/GitHub 저장소 설정 기준.md#current>)에 합의한 값을 실제 저장소 옵션·브랜치 보호로 적용한다.

- 범위: 일반 옵션, main과 `phase/*`·`issue/*`·`task/*`의 branch Ruleset, 실제 전후 상태·변경·검증 기록.
- 최초 설정 적용의 제외: 기준값 변경, 제품 구현, 추가 요청 판단 skill, 커밋·push·PR 생성. 기록 제출의 후속 승인은 아래 사건에서 구별한다.
- 수용 조건: 일반 옵션과 브랜치별 유효 규칙이 기준과 일치하고 이름·재개 차수 패턴을 포함한다. 하위 브랜치의 생성·일반 push·상위 일반 merge·삭제는 허용하며 불필요한 승인·검사·우회 요구를 추가하지 않는다. 자체·별도 검수의 필수 지적을 해소한다.
- 보호 대상: main 커밋·기존 기록·로컬 보존 브랜치를 유지한다.
- 기록 정정의 수용 조건: 필요한 전후 값·실패 결과·검증 대상·방법·판정을 이 본문에서 확인할 수 있고, PR의 최종 파일에 불필요한 JSON 첨부나 대체 백업이 없어야 한다. 지속적인 재발 방지 보완은 별도 작업으로 구분한다.

## 해결 계획과 예정 확인

1. 적용 직전 옵션·Ruleset·기존 보호를 재조회하고 필요한 차이만 적용한다.
2. 일반 옵션에서 rebase를 해제하고 나머지 합의값을 유지한다.
3. 작업 브랜치에는 force push 차단만, main에는 PR 필수·merge commit만 허용·force push 및 삭제 차단·대화 해결 필수를 설정한다. 두 Ruleset은 active·우회 목록 없음으로 둔다.
4. 필수 승인 0명과 별도 승인·상태 검사·선형 이력·서명·배포·merge queue 미요구를 확인한다.
5. 저장값과 브랜치별 유효 규칙을 재조회해 자체·별도 검수한다. 실제 브랜치 생성·위험한 push·삭제 시험 없이 이름·재개 차수·비대상 패턴을 조회한다. 규칙 확인을 실제 push 거부 시험으로 확대하지 않는다.
