# 격리 시범의 보존 기준

## 보존 목적과 범위

사용자는 현재 상황을 먼저 커밋한 뒤 추천한 1차 반영안을 Issue에 기록하고 개선 정도를 비교하도록 요청했다. 이 묶음은 그 이전 상태를 보존한다. 기존 #72 본문과 과거 작성안·시험 입력은 수정하지 않고 보존하며 현재 상태의 수용으로 취급하지 않는다.

현행 정식 원천의 비교 기준은 `22854d6d159b74e3b54aedc5c3f33264463c541c`다. 해당 커밋에는 새 Issue·Task 양식과 생성·검사 절차가 이미 반영돼 있다. 보존하는 #72 본문과 GitHub 게시물의 미착수·미커밋 설명에는 그 이후 진행이 아직 반영되지 않았으며 다음 작업에서 정정할 대상이다.

`.tmp/issue-task-pilot-2/`는 Git 제외 임시 영역으로 유지한다. `.env`, 제품 폴더와 `node_modules`는 이 변경에 포함하지 않는다. 보존 영역에는 접근하지 않는다.

커밋 전 실제 index와 작업 파일을 대조해 JSON 41개의 CRLF 정규화 차이를 확인했다. 기존 원문·지문을 보존하도록 `harness/issue-rule-comments.json`과 #72의 artifacts JSON에만 `-text`를 지정했다. 다른 경로의 Git 속성·파일 내용은 바꾸지 않으며 index blob도 원문 바이트와 대조한다.

## 현재 시범 결과

| 항목 | 보존한 사실과 근거 |
|---|---|
| 안내 변경 | 원본 대비 README·STRUCTURE 2개 파일. [문서 제안](proposal-documents.patch) |
| 하네스 변경 | 양식·skill·검사·기준·현황 20개 파일. 새 초안 CLI·초안 상태 일반화도 함께 들어 있어 바로 채택할 1차 범위와 섞여 있음. [전체 하네스 제안](proposal-harness.patch) |
| 검증 | 전체 관련 회귀 114개 통과 후 마지막 profile 보완에 영향받은 26개를 재검증함. 두 수를 서로 다른 검사 수로 합산하지 않음. [전체 출력](regression.txt) · [영향 범위 출력](focused-regression.txt) |
| 직접 호출 | 명시 초안·현황·index·hook 직접 호출 18개가 기대 결과를 충족함. [당시 결과 원문](verification.json) |
| 최종 대조 | 참조 294개와 원천 83개·원래 Git 상태·index·HEAD, 최초 시범 보관본을 확인함 |
| 별도 검수 | cwd 조상 경계·CRLF 진단·교차 profile 길이 계산을 보완하고 재검토함. 시범 성공을 실제 자동 발동·정식 업무 전체 성공으로 확대하지 않음 |

`verification.json`은 당시 실행의 원문 payload다. 내부 상대 경로는 `.tmp/issue-task-pilot-2/` 기준이며 경로를 바꾸어 당시 실행을 새로 구성한 것으로 표시하지 않는다. 두 patch는 위 비교 기준의 정식 원천으로부터 제안된 변경을 재구성할 자료다.

## 다음 작업의 추천 범위

- 1차 후보: 안내 동선, 질문 없음/목록 미확인 구별, 현황 오류 진단과 CRLF 비교, 고정 보호 주석을 제외한 길이 경고. 구현·기준·해당 시험·현황을 함께 묶는다.
- 후속 보류: 새 명시 초안 CLI와 초안 상태 규칙의 일반화. 실제 링크 경계·지원 환경과 별도 문맥의 작성·재개·종료 행동을 추가 확인한다.
- 운영 확인: 바뀐 두 생성 skill과 두 hook의 과거 확인은 stale다. 실제 자동 hook 발동·설치 경유 실행·정식 객체 등록과 부모 수용을 확인한 것으로 승격하지 않는다.
- 비교 관점: 원래 22개 파일에 섞인 변경을 1차/후속으로 실제 분리했는지, 보류 기능을 참조하는 안내·시험·현황이 남지 않는지, 현재 Issue 요약이 실제 근거·다음 행동과 맞는지 대조한다. 시험 수 증가를 행동 개선율로 바꾸지 않는다.
