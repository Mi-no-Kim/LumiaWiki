# 1차 원천 실제 적용과 동일 입력 전후 비교

## 실제 적용

사용자가 준비에 그치지 말고 원천에 반영한 뒤 비교하도록 요청했다. 비교 기준은 `446bc75c794819384cf42ff2c9f946b8449e0229`다. 검수한 1차안 17개를 실제 README·STRUCTURE·입력/본문 안내·Issue 생성 skill·검사 구현·기준·현황·회귀에 적용했다. 실제 적용 원천과 검수 후보의 내용 지문이 모두 일치한다.

새 `--draft` CLI와 초안 상태 일반화는 보류했다. 해당 Task 원천·CLI adapter 다섯 개, 정식·과거 정책과 모든 규칙 주석·자동 발견 구현은 적용 전과 같다. 기존 기록을 새 양식으로 변환하지 않았다.

## 동일 조건의 실제 동작 비교

적용 전에 원천과 입력을 고정했다. before는 기준 원천의 사본을 실행했고 after는 실제 저장소의 `scripts/` 검사기를 실행했다. 시험 데이터와 Git index만 별도 가상 저장소에 뒀다. 두 입력의 SHA-256과 보호 정책·훼손 대상 예시 원문은 전후 동일하다. 정식 Issue·Task를 발급한 시험이 아니다.

| 같은 입력·조건 | 적용 전 | 실제 적용 후 | 판정 |
|---|---|---|---|
| 137줄 Task: 고정 보호 주석 71줄·작성 분량 66줄 | 137줄 초과 경고 | 불필요한 경고 없음 | 양식 주석 때문에 생기던 오경고 제거 |
| 같은 Task에 실제 작성 분량을 101줄로 늘림 | 총 172줄로 경고 | 작성 분량 101줄로 경고 | 실제 긴 본문 경고 유지 |
| 보호 start 주석을 삭제한 index, 작업 파일은 정상 복구 | 종료값 2로 거부 | 같은 위반을 종료값 2로 거부 | 보호를 약화하지 않음 |
| 보호 대상 예시를 훼손해 index에 올리고 작업 파일만 복구 | hook 식별자·현황 지문 오류와 현황 갱신 안내 | 실제 문제 파일명과 의도하지 않은 내용 복구·동일 후보 재검사 안내 | 잘못된 파일을 찾는 데 필요한 정보 제공 |

[관찰·명령별 결과](comparison.json) · [입력·기준 정의](definition.json) · [짧은 입력](task-small.md) · [긴 입력](task-long.md)

이는 파일 수나 patch 줄 수 감소가 아닌 실제 검사 동작의 변화다. 네 사례 중 오경고·진단 두 사례가 개선됐고, 긴 본문 경고·위반 거부 두 사례는 유지됐다. 이 네 사례로 전체 AI 규칙 준수율·누락 감소율을 추정하지 않는다.

## 실제 저장소의 확인

- 실제 저장소에서 전체 회귀 **106개 통과**: [실행 로그](actual-regression.txt).
- 실제 원천 17개는 검수된 1차 후보와 CRLF 정규화 기준으로 일치한다. [적용 지문·검사 결과](application.json).
- 실제 work 및 최종 index의 현황·기록·공통 주석 검사를 통과했다. 최종 참조 190개와 같은 제출 후보를 자체·별도 대조했고 남은 필수 결함은 없다. 게시 후 원격 #72의 실제 적용 본문 일치도 확인했다.
- 기존 고정 기록·정책·보호 주석과 미반영 기능 경계는 보존한다. create-issue와 두 hook의 과거 확인은 stale로 유지하며 이번 직접 호출을 자동 발동 확인으로 바꾸지 않는다.

## 문서와 생성 지침의 변화

README의 상황별 진입·설치·검사·실패 대응 링크와 STRUCTURE의 실제 경로 안내가 이제 원천에 반영됐다. 초기 질문이 없음을 확인한 입력은 예시 결정 항목을 만들지 않고, 목록 미확인은 입력 확인에 두도록 실제 양식·지시서·공통 절차·skill을 맞췄다. 문서 변경과 실제 AI 생성 행동의 효과는 구별한다.

## 남은 확인

질문 처리의 별도 문맥 생성 행동, 실제 hook 자동 발동과 전체 업무 수명주기의 개선은 이번 동일 입력 비교의 측정 대상이 아니다. 보류한 CLI·초안 상태 일반화도 적용하지 않았다. #72 전체는 해당 운영 확인이 남아 진행 중이며, 이번 1차 원천 적용·네 사례 비교·106개 회귀는 실제로 수행했다.
