# Task 구조 합의 — 임시 정리

사용자가 합의한 Task 구조를 이번 작성안 수정의 대조 기준으로 정리한다. [담당 Issue](../issue.md#small-work-rules)에서 연결하며, 현행 원천 적용·실제 Task 발급·운영 검증은 별도다. 실행 규칙과 양식은 아래 담당 파일에서 관리한다.

## 파일별 역할

| 파일 | 둘 내용 |
|---|---|
| [생성 지시서](task-file-creation-guide-draft.md) | Issue가 확정한 전달사항을 입력으로 최초 Task 본문 작성. 입력 반영·미정/미확인·예정 경로·링크 보정·작성 후 확인. 전달사항이나 전체 계획을 대신 확정하지 않는다. |
| [공통 절차](task-common-procedure-draft.md) | 상태·전환의 의미, 전체 계획의 확정 수준과 준비 확인, 할 일의 실행 지시·진행 제어·계획 갱신, 합의와 AI 판단의 경계, 전달사항 변경과 영향 확인, 수행 기록·검수·커밋·종료 규칙. |
| [본문 양식](task-body-template-draft.md) | 최초 Task 생성에 한 번 사용하는 본문 네 구역과 복사할 `task-rule:` 주석. 생성 이후에는 실제 Task의 주석을 사용한다. |
| [수행 기록 생성 양식](task-execution-template-draft.md) | 첫 할 일 착수 때 한 번 사용하는 Task당 수행 기록 파일의 틀과 복사할 `execution-rule:` 주석. 생성 이후에는 실제 기록의 주석·구역 구조를 사용한다. |

Task 입력 양식은 목적·기대 결과·이미 정해진 조건·Task에서 결정할 사항·완료 조건과 확인 방법의 다섯 구역에 짧은 설명과 작성란을 두고 Task의 복수 태그 한 줄을 함께 전달한다. Issue가 확정한 배정을 넘기되 Task에서 답을 정할 질문은 생성 후 논의 대상으로 남긴다. 전달본·개정 정보는 입력란에서 빼고 생성 지시서·공통 절차에 따라 Issue의 배정 기준 기록과 Task 본문의 참조에서 관리한다. 작은 작업의 판단 조건은 공통 절차에 두고 지속 작성·갱신 규칙은 생성된 문서의 주석에 남긴다. 수행 기록 양식과 예시는 본문 양식에서 분리했다. 초기 Task 초안 세 파일과 통합된 연결 안내 두 파일은 사용자 요청에 따라 previous/에 보관한다. [현재 사용·이전 자료 안내](../issue.md#task-file-layout)에서 구분한다.

| Task 본문 구역 | 기록할 내용 |
|---|---|
| 현재 요약 | 상태·현재 위치·다음 행동·막힌 조건 |
| 전달사항 참조 | 부모 Issue·적용 전달본·전달본 식별·확정 근거와 Issue의 배정 기준 기록 |
| 계획과 합의 | 실제 대상·입력·준비 상태, 전체 할 일과 의존 관계, 현재 유효한 결정·이유·합의·위임 범위 |
| 결과 | Task 전체 반영 결과, 완료 조건별 판정·근거·한계, 잔여와 다음 행동 |

### 상태와 초기값

Task 작성안의 상태는 **예정·진행 중·중단·완료·취소**, 신규 생성·미착수 초기값은 **예정**으로 채택했다. 의미·전환 조건은 [공통 절차의 상태 규칙](task-common-procedure-draft.md#state-rules), 실제 상태 우선과 기존 상태 보존을 포함한 초기 기입은 [생성 지시서](task-file-creation-guide-draft.md#initial-state)를 따른다. 현행 일곱 상태·검사기·라벨·실제 Task 상태는 유지하며 현행 적용은 별도다.

## 태그

Task와 각 할 일은 조사·논의·결정·실행·검수·커밋 중 필요한 여러 태그를 쉼표로 구분해 표시한다. Task 태그는 전체 활동을 요약하고 할 일 태그는 해당 행동을 표시한다. 계획을 구체화·조정하면 둘을 함께 맞춘다. 태그는 권한·상태·결정 위임을 추가하지 않으며 기존 조건을 생략하는 근거가 아니다.

진행 AI가 배정·합의 범위 안에서 현재 Task의 태그를 보완·정정한다. 생성 입력은 배정 당시 정보로 보존하고 완료된 행동의 태그도 유지한다. 태그 종류·의미는 공통 규칙을 따르며 개별 Task에서 임의로 늘리지 않는다.

논의는 실제 사용자 응답·논의 근거를, 결정은 지정 주체의 선택 또는 명시 위임 근거를 확인한다. 필요한 논의·결정 전의 값 확정과 의존 실행을 제한하고 이미 허용된 독립 준비는 유지한다. 복수 태그·미정 처리·검수의 상세는 [태그 기준](task-common-procedure-draft.md#tag-rules)을 따른다. 지속 규칙은 복사되는 `task-rule:tags` 주석에도 남긴다.

## 전체 계획과 할 일

- Issue는 생성 시 담당 결과·범위·완료 조건, 이미 결정한 동작/계약·제약, 선행 입력, AI에 위임한 판단과 사용자 확인이 필요한 선택을 확정해 전달한다. Task의 구체적인 하위 계획은 생성 후 실행 전에 작성·합의한다.
- 작은 작업은 Task 안의 할 일로 유지한다. 의미 있는 결과와 필요한 검증·보완·기록까지 묶으며 명령·파일마다 나누지 않는다.
- 본문의 `### 전체 수행 계획` 아래에 할 일별 `####` 행동 제목·복수 태그·완료 체크·할 일·확인·수행 기록을 둔다. 조사·실행·논의·결정·검수·커밋 등 필요한 행동 단위를 드러내되 같은 결과·근거로 충족되는 행동은 묶을 수 있다. 행동 종류·단계 수·순서를 모든 Task에 고정하지 않는다.
- Task 파일을 만든 뒤 실행 전에 목표 달성부터 검증·검수·커밋·종료까지 전체 계획을 세우고 합의한다. 할 일의 개수·순서는 Task별로 정한다.
- 각 할 일은 실행자가 해당 지시와 연결된 원천을 읽고 결과·범위·선행 조건·기존 결정·제약·위임된 판단·사용자 확인 조건·검증 방법·커밋 범위를 구분할 수 있는 수준으로 계획한다. 짧은 지시문과 공통 조건으로 표현하고 공통 준비·전체 확인·커밋 묶음은 한 번만 둔다.
- 조사 결과가 필요한 부분은 조사할 내용과 결정 시점·후속 계획을 구체화할 시점을 함께 계획하고 해당 결론에 의존하는 실행 전에 선택을 확정한다. 계획 작성·논의를 위한 허용된 준비는 계속할 수 있고 전체 계획과 공통 실행 준비가 갖춰진 뒤 첫 할 일을 실행한다.
- 각 할 일 시작·재개·주요 전환·조건 변경 때 필요한 실제 입력·권한·선행 결과·등록·브랜치 등을 확인한다. 부족하거나 충돌하는 조건에 의존하는 행동은 제한한다. 전체 계획과 공통 준비를 충족한 상태에서는 이미 허용된 독립적인 일을 진행할 수 있다. 사용자 확인 조건에 도달하면 관련 후속 실행 전에 확인받는다.
- 실행 중 합의된 목표·범위·완료 기준·동작/계약·권한과 위임 범위 안에서 AI가 할 일을 수정·추가·삭제·재배열·분할·병합할 수 있다. 중요한 변경 이유를 남기고 다음 의존 행동 전에 현재 계획을 갱신한다.
- 논의 응답·새 사실·조건 변경이 영향을 주면 다음 관련 행동 전에 합의·남은 결정·할 일·확인 방법·태그·연결을 함께 갱신하고 달라진 다음 행동·막힘을 현재 요약에 반영한다. 실제 근거는 보존하며 상세 흐름은 [공통 절차](task-common-procedure-draft.md#plan-update)를 따른다.
- 목표·범위·완료 기준·기존 합의·권한을 바꾸거나 필수 확인을 생략할 필요가 있으면 관련 실행 전에 사용자와 논의한다. 통상적인 조정마다 재승인을 요구하지 않는다.

## 수행 기록

- 수행 기록은 Task당 `artifacts/task-<실제 순번>-execution.md` 한 파일에 둔다. 첫 할 일 착수 때 파일을 만들고 이후 할 일은 같은 파일의 구역으로 추가한다.
- 첫 수행 기록 파일을 만들 때만 별도 생성 양식을 사용한다. 규칙 주석은 파일 머리말에 한 번만 두고 이후 할 일은 주석 없는 구역 구조만 추가한다. 생성된 파일의 기록 기준·머리말 규칙을 따르며 양식을 다시 참조하지 않는다. Task 본문의 해당 할 일과 왕복 연결하고 구역 식별자는 실행 순서와 분리한다.
- 예정 원본은 Task 본문에 두고 수행 기록은 할 일별 조치·판단 / 확인 / 잔여로 쓴다. 착수 때 연결하고 실제 수행·확인 뒤 채우며 잔여는 해당 할 일의 미해결로 한정한다. 본문은 현재 합의·이유·제약·전체 판정·후속 계획과 근거 연결을 유지한다.
- 파일 수정 없는 논의·결정과 세부 선택·대안/기각 이유·조건·유보/철회 근거도 수행 기록에 둔다. 제안·미결·합의·철회를 구별하고 적용 범위·주체·근거를 남긴다. 후속 행동·검수·수용 판단·진행 조건에 필요한 결정은 Task 현재 합의에 결론·핵심 이유·조건과 상세 링크를 반영한다. 공통 결정의 상세는 한 구역을 참조하며 여러 Task의 계약·기준은 담당 원천의 변경 절차를 따른다.
- 코드·diff·테스트 정의는 원본에서 관리하고 기록에 복사하지 않는다. 변경본을 검증했으면 버전·변경 범위와 실제 확인 결과를 식별한다. 단순 확인마다 별도 로그·증명 파일을 만들지 않는다. 필요한 원자료의 보존·재확인은 [공통 절차](task-common-procedure-draft.md#recording-proposal)를 따른다.
- 보완·재시도는 같은 구역에서 갱신한다. 계획의 할 일을 삭제·분할·병합해도 이미 수행한 사실과 유효한 검증 근거·연결은 보존한다. 예정 삭제로 실제 결과를 없애지 않는다.
- 실제 결과·필수 확인·기록을 갖춘 뒤 할 일을 완료 표시한다. 할 일 완료·변경 목적별 커밋·Task 전체 완료는 구분한다.

## 유지하는 경계

확정 전달사항의 원본 참조·배정 변경 합의·기존 원본을 보존한 새 개정본·영향 확인, Issue 배정과 Task 상세의 책임, 본문 네 구역과 예정/실제의 구분은 유지한다. 지문 계산·기대 지문 관리 절차는 두지 않으며 필요한 검사 도입은 구조 확정 뒤 별도로 판단한다. 과거 지문값·계산 대상 원문·검수 사실은 담당 기록의 과거 근거로 보존한다. Task 상태 값·초기값은 위 작성안 합의로 확정하며 독립 Issue 문안·현행 적용·실제 운영 확인은 별도다. 이전 Task 자료의 내용과 실제 제품 기록·코드·환경도 유지한다.
