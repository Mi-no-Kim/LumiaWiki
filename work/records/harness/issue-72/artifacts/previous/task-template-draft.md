# Task 작성 양식 — 작성안

<a id="summary"></a>

## 역할과 현재 범위

- 담당 Issue: [Issue #72](../../issue.md#summary).
- 생성자는 [Task 생성 지침](task-creation-guide.md#summary)에 따라 아래 본문을 채운다. Task 실행자는 생성된 문서의 목적·작업 단위와 작업 지침을 계속 확인한다.
- 현재는 제목·역할, 목적·작업 단위, 시작 시 보완과 작업 지침을 담았다. 전체 Task 양식의 완성·최종 채택을 뜻하지 않는다.
- 아래 본문은 실제 생성될 Task에 남긴다. 역할 설명과 작업 지침은 유지하고, 목적·작업 단위는 Issue의 최소 배정을 출발점으로 Task 시작 시 근거에 따라 보완한다.
- 작성 기준·설명·예시는 생성 지침에서 관리하며 이 본문에 일괄 복사하지 않는다. 미정 사항과 이후 논의 범위도 [생성 지침의 미정 사항](task-creation-guide.md#pending)에서 확인한다.
- 현행 [Task 양식](../../../../../../harness/templates/task.md)은 아직 수정하지 않는다.

<a id="body"></a>

## 양식 본문

```markdown
# Task <부모 Issue 번호>-<로컬 순번> — <작업 제목>

Task는 부모 Issue가 정한 실행 단위를 맡아 계획·수행·검증하고,
그 판단과 실제 결과를 기록한다.

**목적**
- 배정 근거: <Issue의 구역·요구 항목> — <이번 Task에 배정한 내용>
- 목적: <대상의 현재 부족한 상태>를 <목표 상태>로 바꾼다.

**작업 단위**
- 담당 결과: <남길 결과의 종류와 내용>
- 수행 범위: <대상>에 대해 <수행할 행동>
- 경계·제약: <이 Task에서 넘지 않을 범위·다른 작업과의 접점>

**시작 시 보완할 내용**
부족한 항목이 있을 때만 항목별로 다음 형식을 작성한다.
- 부족한 내용: <항목 이름과 아직 불명확한 내용>
- 보완 방법: <확인할 원천이나 논의할 선택·필요시 결정 주체>
- 필요한 시점·진행 제한: <어떤 행동 전에 해결해야 하는가>

작업 지침:
- Task를 시작하면 목적·작업 단위를 배정 근거와 대조해 누락·모호함·충돌을 확인한다.
- 기존 원천에서 확인할 수 있는 사실과 이미 위임된 범위의 상세는 직접 보완하고 근거·판단 이유를 남긴다.
- 보완 과정에서 새로운 목표·범위·미위임 선택이 필요하면 제안으로 구분해 관련 행동 전에 논의한다.
  배정된 것으로 간주해 실행하지 않는다.
- 남은 부족 사항에는 보완 방법과 필요한 시점·진행 제한을 적는다.
  실제 수정·실행 전에 그 행동에 필요한 내용을 보완하고, 독립적으로 허용된 일은 계속한다.
- 대상 수정·실행 전에 그 행동에 필요한 허용 범위·계획·적용 지침과 담당 브랜치·필요한 등록의 실제 상태를 대조한다.
- 재개·계획 변경·주요 단계 전환 시 합의한 내용과 실제 상태를 다시 대조한다.
  추가 논의가 필요한 선택은 관련 행동 전에 논의한다.
- 계획과 실제 수행 결과를 구별하며, 발생하지 않은 승인·성공을 기록하지 않는다.
- 현재 내용을 갱신하되 유효한 결정과 이유·승인 범위·필요한 근거를 유지한다.
```
