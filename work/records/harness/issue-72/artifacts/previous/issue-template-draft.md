# Phase 하위 Issue 작성 양식 — 작성안

> 이전 통합 양식이며 비교용으로 보존한다. 현재 검토 대상은 [Issue 본문 양식](../issue-body-template-draft.md)이며 [담당 기록](../../issue.md#draft-map)에서 사용 경로를 구분한다. 아래 본문은 현행 양식을 대체하지 않는다.

[지시서](issue-guide-draft.md#writing-requirements)에 따라 기본 본문에 아는 내용부터 적는다. 시작 전 보완 구역은 본작업 전에 채우고, 진행·결과 구역은 실제 필요한 부분만 붙인다. 복사한 위치에서 링크를 맞춘다.

<a id="body"></a>

## 기본 본문

```markdown
# Issue <실제 GitHub 번호> — <과제 제목>

<!-- issue-rule:start
이 문서의 issue-rule 주석은 식별자·내용·경계를 유지한다. 사용자가 해당 규칙 변경을 명시적으로 요청한 범위에서만 수정·삭제한다.
목적·담당 결과, 대상·범위·권한, 완료 조건과 확인 방법, 진행 순서·준비 근거 등 필수 내용이 하나라도 비어 있거나 미정·미확인이면 본작업을 시작·재개할 수 없다. 진행 순서의 체크와 별개로 실제 내용과 근거를 확인한다.
그전에는 필수 정보 보완과 허용된 시작 준비만 한다. 착수·재개·조건 변경·주요 단계 전환·수용 판단 때 이 기록과 적용 지침을 실제 상태에 대조한다.
-->

<a id="summary"></a>

## 현재 요약

<!-- issue-rule:status
상태는 '- 상태: 값' 형식으로 한 줄에 작성한다.
허용 값: 예정 / 진행 중 / 중단 / 완료 / 취소.
허용 값 중 현재 상태 하나만 작성하며, 선택지를 임의로 추가하거나 변경하지 않는다.
-->
- 상태: <현재 상태 하나>

<!-- issue-rule:position
현재 진행 위치는 '현재 요약'을 제외한 이 문서의 작업 구역 링크 하나로 작성한다.
링크의 표시명과 연결 표식은 해당 구역의 제목·표식을 그대로 사용한다.
실제로 존재하는 구역만 가리키며 별도의 설명·결과·다음 행동을 덧붙이지 않는다.
-->
- 현재 진행 위치: [Task 분해 전 결정 사항](#decisions)

<!-- issue-rule:next
다음 행동은 'N번 — 대상과 행동' 형식으로 하나만 작성하며 N은 진행 순서에 존재하는 번호다.
진행 순서의 첫 미완료 항목 안에서 현재 허용된 행동을 선택하고, 막혔다면 조건 해소를 위한 확인·논의를 작성한다.
순서가 비었거나 자리표시자뿐이면 '미정 — 진행 순서 합의 필요'로 작성한다.
필수 행동이 남았지만 현재 순서의 번호로 표현할 수 없으면 '미정 — 진행 순서 보완 합의 필요'로 작성하고 대화로 순서를 보완한다.
필수 종료·관련 반영·잔여 처리까지 마쳐 남은 행동이 없음을 확인한 경우에만 '없음 — ' 뒤에 실제 종료 근거 구역의 Markdown 링크 하나를 붙인다. 순서의 체크만으로 없음·종료를 판정하지 않는다.
-->
- 다음 행동: 미정 — 진행 순서 합의 필요

<!-- issue-rule:blockers
막힌 조건은 'N번 — 미충족 조건 — 해소 조건' 형식의 하위 목록으로 작성하며 N은 진행 순서에 존재하는 번호다.
여기서 번호는 제한되는 행동의 위치다. 후속 항목이 막혀 있어도 현재 항목의 허용된 확인·논의는 계속할 수 있다.
순서가 아직 없거나 제한할 행동에 대응하는 번호가 없으면 '번호 미정 — 미충족 조건 — 해소 조건'으로 작성하고 이미 아는 조건을 유지한다. 번호가 정해지면 해당 조건을 그 번호에 연결한다.
제한 여부 자체가 미확인이면 '미확인 — 확인할 대상·방법'으로 남긴다. 제한이 없음을 실제 확인한 경우에만 '없음'을 값으로 작성한다.
미확인 조건을 임의로 '없음'으로 처리하거나 조건을 지워 제한을 해제하지 않는다.
-->
- 막힌 조건: 미확인 — 제한 여부·조건 확인 필요

<a id="decisions"></a>

## Task 분해 전 결정 사항

<!-- issue-rule:decisions
이 목록에는 Issue의 방향·범위 등 Task로 나누기 전에 결정할 사항을 적는다.
항목은 대화에서 추가하기로 합의한 경우에만 추가한다. AI가 발견한 후보는 먼저 대화에서 제안한다.
첫 항목을 작성할 때 아래 자리표시자를 합의한 항목으로 교체한다. 빈 목록이나 자리표시자만 있는 상태는 결정 완료가 아니다.
미결정 항목이 하나라도 남아 있으면 기존 항목은 체크 표시만 변경한다. 문구·순서를 유지하고 삭제·축약·병합·다른 구역 이동을 하지 않는다.
결정 내용·이유·근거는 목적·범위·완료 조건 등 해당 구역에 기록한 뒤 [x]로 표시한다. 결정이 다시 미정이 되면 [ ]로 되돌린다.
이 편집 제한은 체크리스트의 기존 항목에 적용하며, 다른 구역의 작성·보완은 허용한다.
모든 항목을 결정하기 전에는 Task 분해·배정을 확정하지 않는다. Issue 본작업의 시작·재개는 기존 시작 필수 조건을 따르며, 체크리스트 완료만으로 허용됐다고 판단하지 않는다.
-->
- [ ] <대화에서 추가하기로 합의한 결정 사항>

<a id="sequence"></a>

## 진행 순서

<!-- issue-rule:sequence
Issue 생성 시 목적·배정·미정 사항에 맞춰 대화로 합의한 할 일과 순서를 기록한다. 공통 단계 목록을 일괄 복사하지 않는다.
항목 형식은 '번호. [ ] 할 일 — 완료 조건: 조건'이며 번호는 1부터 중복 없이 증가시킨다.
첫 실제 항목을 넣을 때만 자리표시자를 합의한 항목으로 교체한다. 빈 목록·자리표시자는 합의·완료가 아니다.
AI는 합의 없이 항목을 추가·삭제·축약·변경·재배열하지 않는다. 합의한 순서 변경 뒤에는 다음 행동·막힌 조건의 번호도 맞춘다.
완료 조건을 실제 충족하고 담당 본문·Task 기록에 근거를 남긴 뒤 [x]로 바꾼다. 조건이 다시 미충족이면 영향받은 항목을 [ ]로 되돌린다.
미정 상세는 이를 결정할 일을 순서에 넣고 이후 대화로 구체화한다. 각 항목의 선행 조건과 기존 시작 필수 조건·허용 범위를 충족한 행동만 실행한다.
첫 미완료 항목을 마치기 위한 정보 확인·대화·담당 구역의 기록 보완은 허용한다. 본작업 결과물의 완성을 준비 조건으로 요구하지 않는다.
제품 기능은 화면 디자인 검토 → 동작 구현 → 화면을 통한 동작 확인의 선후 관계와 사용할 화면의 위치·검증 흐름을 순서에 연결한다. 기존 화면을 사용할 때도 이번 기능과의 관계를 확인하며, 디자인 검토와 구현 후 동작 확인을 구분한다.
-->
1. [ ] <대화로 합의한 할 일> — 완료 조건: <충족 여부를 확인할 조건>
```

<a id="planning-body"></a>

## 시작 전에 보완할 내용

미정·미확인은 해당 항목에 확인·결정 방법과 필요한 시점을 적는다. 실제 내용과 근거를 확인하고 미충족 조건은 막힌 조건에 기록한다.

```markdown
<a id="scope"></a>

## 대상·범위·권한

- 대상·입력: <실제 파일·자료·환경 등>
- 범위·권한: <할 일·경계·허용 근거와 직접 정할 수 있는 상세>
- 적용 지침: <이번 작업에 적용할 기준·절차>
- 준비 근거: <실제 브랜치·등록과 연결·입력·환경·선행 결과의 값·확인 결과와 근거>

<a id="plan"></a>

## 완료 조건과 확인 방법

<!-- issue-rule:completion
Issue 전체가 달성할 결과 기준과 기준별 확인 방법을 한 행씩 작성한다.
진행 순서의 개별 할 일 완료 조건과 구분하며, 실제 관찰·판정·한계·근거는 검증 구역에 기록한다.
검증 구역에는 이 표의 각 조건을 식별할 수 있는 문구·참조로 연결하고 조건별 판정·이유·근거·한계를 남긴다. 조건을 생략하거나 종합 성공 한 줄로 대신하지 않는다.
판정은 충족·불충족·미확인·해당 없음으로 구분하고 해당 없음의 이유를 남긴다. 수행하지 못한 필수 확인은 미확인으로 남긴다.
-->
| 완료 조건 | 확인 방법 |
|---|---|
| <Issue 전체가 달성할 결과의 기준> | <확인 대상·기대 결과·방법과 필요한 검수·화면 확인> |

```
