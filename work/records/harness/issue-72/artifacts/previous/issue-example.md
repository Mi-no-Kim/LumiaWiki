## 대상·범위·권한

- 대상·입력: 부모 Phase 계획과 선행 [Issue #15](https://github.com/Mi-no-Kim/LumiaWiki/issues/15)의 기술·공통 전제를 입력으로 확인한다. 실제 작업 경로·기존 설정·도구 상태는 미확인이며, 본작업 착수 전에 실제 내용을 확인한다.
- 범위·권한: 배정 개요는 실행·DB 접속·테스트/hook·공통 골격·품질/CI다. 테이블 설계·실제 게임 자료 등록·제품 기능은 별도 과제로 둔다. 구체 변경 대상·허용 행동·제외 경계는 미정으로, 대화와 기존 원천 확인을 통해 본작업 착수 전에 확정한다. 실제 자료 작업 보류는 유지한다.
- 적용 지침: [Issue 지시서](issue-guide-draft.md#writing-requirements), [기록 작성 기준](<../../../../../../docs/작업 기록 작성 기준.md#minimum>), [Git 작업 시작 절차](<../../../../../../harness/Git 작업 절차.md#start>). 부모의 기술·테스트/hook 요구는 입력으로 확인하고 구체 실현 방법과 판정 기준을 정한다. 제품 기능을 이번 범위에 포함하기로 변경하는 경우에는 [화면 기준](<../../../../../../docs/details/operations/검증과 완료.md#screen-first>)에 따라 화면 디자인 검토 선행·사용할 화면의 위치·검증 흐름을 진행 순서와 완료 조건에 연결한다.
- 준비 근거: Issue 등록만 마쳤다고 가정한다. 부모 보유 목록·원본 연결·담당 브랜치·실행 환경·입력·권한은 미확인이다. 진행 순서 3번에서 실제 값과 확인 근거를 해당 본문에 보완한다.
