# Task 본문 생성 지시서 — 작성안

Issue에서 확정한 전달사항을 본문 양식에 반영해 최초 Task 본문을 작성한다. 생성 후 전체 계획 수립·실행·기록 갱신은 Task 공통 절차를 따른다.

## 사용할 입력

- 부모 Issue의 배정 기록과 확정된 전달사항 파일
- Issue의 배정 결정에서 기록·참조한 Task 식별자·저장 경로와 순번 충돌 확인 근거
- [Task 본문 양식](task-body-template-draft.md)

## 본문 작성

1. 부모 Issue의 배정 기록과 적용할 전달사항을 확인한다. 전달된 목적·담당 결과·범위·기존 결정·완료 조건을 읽는다.
2. 본문 양식의 **Task 본문 코드 블록**을 사용한다. 제목·식별자·부모 관계를 실제 입력에 맞게 작성한다.
3. 아래 기준으로 본문 네 구역을 채운다.
4. 최종 저장 위치를 기준으로 상대링크를 보정한다.

식별자·저장 경로는 [경로·식별 기준](<../../../../../docs/작업 기록 체계.md#paths>)과 Issue의 확인 근거에 대조한다. 필요한 정보·확인 근거가 없으면 부모 보유 목록·실제 파일을 확인하고 미확인을 남기며, 기존 파일을 덮어쓰거나 번호·경로를 추론해 정식 본문을 완성하지 않는다.

| 구역 | 작성할 내용 |
|---|---|
| **현재 요약** | Task의 상태·현재 위치·다음 행동·막힌 조건 중 확정하거나 확인한 내용 |
| **전달사항 참조** | 부모 Issue, 적용 전달사항 파일과 전달본 식별, 배정의 확정 근거 |
| **계획과 합의** | 전달받은 실제 대상·입력·준비 상태·유효한 합의와 이미 합의한 계획. 배정 합의와 현재 전체 계획의 제안/합의 사실·적용 범위·근거를 구별하고 미정은 보완 내용·시점을 표시 |
| **결과** | 실제 결과가 발생한 뒤 작성할 자리로 유지. 검증·승인·완료 결과를 미리 채우지 않음 |

전달사항 원문은 확정된 파일에서 관리하고 Task 본문은 이를 참조한다. 목적·범위·완료 조건의 사본을 본문에서 별도로 관리하지 않는다.

미정인 선택과 미확인 사실을 구분하고, 필요한 확인·보완 내용과 시점을 남긴다. 부족한 배정·권한·승인을 추론해 채우지 않는다.

방법을 논의하는 배정이 확정됐다면 미선정 방법은 본문의 계획과 합의한 위임·사용자 확인 대상으로 넘긴다. 방법 값을 임의로 채우거나 그 미정만으로 본문 생성을 막지 않는다. 후보 제안·권고안·최종 선정 중 맡은 결과 범위와 결정 주체·실제 실행의 허용은 전달사항에서 확인한다. [DB 생성 방법 논의 예시](task-creation-input-draft.md#db-method-assignment-example)를 참고한다.

수행 기록은 Task당 한 파일의 **예정 경로**를 둔다. 이미 계획한 할 일이 있으면 해당 기록의 예정 구역도 표시한다. 실제 수행 기록의 작성은 공통 절차를 따른다.

Task 파일을 만든 뒤 실행 전에 전체 계획을 수립·합의한다. 생성 시 전달되지 않은 전체 계획을 이 지시서에 따라 임의로 확정하지 않는다.

현재 허용·실행 선행 조건은 계획과 연결하고, 전체 계획의 합의와 실제 착수 조건은 각각 [실행 전 전체 계획](task-common-procedure-draft.md#sequence-rules)·[착수 확인](task-common-procedure-draft.md#start-check)을 따른다. 배정 합의·계획 합의·계획에 적힌 구현/커밋을 실행 권한의 추가로 해석하지 않는다.

<a id="initial-state"></a>
### 상태 초기 기입

이 작성안에서 신규 생성 직후 아직 Task의 허용된 활동을 시작하지 않았다면 상태는 **예정**으로 기입한다. 이미 계획·논의가 진행 중이거나 실제 중단 사유가 확인된 경우 실제 상태를 우선하고 기존 Task의 재개·복구·이관 상태를 초기화하지 않는다. 참조 예시의 미확정 상태를 실제 값으로 추론해 채우지 않는다. 허용 상태와 의미·전환 조건은 [Task 공통 절차의 상태 규칙](task-common-procedure-draft.md#state-rules)을 따른다.

## 작성 후 확인

- Task 식별자·저장 경로·부모 관계가 입력과 일치한다.
- 확정된 전달사항을 정확히 참조하며, 그 내용을 누락하거나 다르게 해석해 반영하지 않았다.
- 본문 네 구역이 양식에 맞고, 미정·미확인과 보완할 시점이 드러난다.
- 신규 생성·미착수 상태는 예정이며 이미 확인된 활동·중단 사실·기존 상태를 초기값으로 덮지 않았다.
- 상대링크가 최종 위치에서 올바른 파일·구역을 가리킨다.
- 실제로 발생하지 않은 준비·수행·검증·승인·완료 결과를 작성하지 않았다.
