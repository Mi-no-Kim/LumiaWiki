# Issue 하위 Task 전달사항 양식 — 작성안

> Task별 확정 전달사항 파일을 만드는 양식이다. 현행 원천 적용과 실제 Task 발급은 별도다.

[전달사항 예시](task-creation-input-example-43-002.md) · [이를 참조하는 Task 본문 예시](task-body-example-43-002.md)

## 역할과 작성 범위

Issue가 확정한 네 묶음의 배정을 `artifacts/task-<순번>-assignment.md`에 보존한다. 배정과 Task의 책임은 [공통 절차](task-common-procedure-draft.md#agreement-rules)를, 원본·기준 기록은 [기록 책임](task-common-procedure-draft.md#assignment-record)을 따른다.

Issue에서 확인할 내용과 전달사항의 네 묶음은 다음과 같이 연결한다.

| Issue에서 확인할 내용 | 전달사항에 작성할 묶음 |
|---|---|
| 과제 목적과 Task 분해·배정 결정 | 배정 근거·목적 |
| 해당 Task에 맡긴 결과의 종류와 핵심 내용 | 담당 결과 |
| 배정 전체 범위와 현재 허용된 행동, 기존 결정·제약, 선행 입력, 위임·사용자 확인 조건 | 수행 범위·이미 결정된 사항 |
| 해당 Task 결과의 수용 기준과 확인할 대상·방법 | 완료 조건·확인 방법 |

이번 Task에 필요한 결정의 핵심·적용 범위·채택 근거를 적고 상세 이유·대안·논의는 Issue가 채택한 원천으로 연결한다. 자료의 귀속·필수 참조·일치 조건·보존 기준처럼 결과를 바꾸는 기존 결정도 누락 없이 대조한다. 같은 조건의 상세는 한곳에 두고 다른 항목에서는 요약과 해당 위치를 참조한다. 공통 규칙 전문·실행 계획·진행 기록은 복사하지 않는다.

방법 논의가 담당 과제라면 확정된 것은 그 논의의 배정·범위·판정 기준이다. 미선정 방법은 Task의 논의 대상으로 남기고 합의한 위임·사용자 확인 조건을 구별해 전달한다. 이미 결정된 사항 표에 임의의 후보를 확정값으로 넣지 않는다. 자료 검토·명령 초안 작성과 실제 환경의 시험 실행을 구별해 현재 허용·경계에 적는다.

일반 수행 판단과 위임·사용자 확인의 경계는 [수행 판단](task-common-procedure-draft.md#judgment)을, 부족·충돌 조건의 처리는 [부분 막힘](task-common-procedure-draft.md#integrity-failure)을 따른다.

<a id="assignment-body"></a>
## 전달사항 파일 본문

Issue의 확정된 결정·배정을 아래 코드 블록에 작성하고 최종 저장 위치의 링크·전달본 식별·확정 근거를 확인한다. Issue의 해당 배정 기록에 원본 경로·전달본 식별·확정 근거를 연결한다.

확정된 전달사항과 Issue의 배정 기준 기록은 [Task 본문 생성 지시서](task-file-creation-guide-draft.md#creation)의 입력으로 전달한다. Task 본문은 적용 전달본을 참조한다.

```markdown
# Task <부모 Issue 번호>-<로컬 순번> 전달사항

<!-- 전달본·이전 전달본·개정 이유의 값은 초판 기준 초기값이다. 개정 시에는 공통 절차에 따라 실제 값으로 작성한다. -->
- 전달본: r001
- 확정 근거: <이 배정을 확정한 Issue의 결정 기록, 합의·위임에 따른 채택 근거와 적용 범위. 당시 기준의 식별이 필요하면 해당 커밋을 함께 참조>
- 이전 전달본: 없음
- 개정 이유·합의: 초판

<a id="purpose"></a>
## 배정 근거·목적

- 배정 근거: <부모 Issue의 Task 분해·배정 결정 링크> — <이번 Task에 맡긴 내용과 배정 이유>
- 목적: <이 Task가 해결할 문제 또는 줄일 불확실성과 Issue 목표에 기여하는 부분>

<a id="result"></a>
## 담당 결과

- 담당 결과: <남길 결과의 종류와 핵심 내용. 논의 과제는 후보 제안·권고안·최종 선정 등 담당할 결과 범위와 결정 주체를, 조사·설계는 필요한 판단 자료와 결과의 범위를 명시>

<a id="scope"></a>
## 수행 범위·이미 결정된 사항

- 수행 범위: <Issue가 배정한 전체 대상·행동>
  - 현재 허용: <현재 허용된 행동·근거와 제한. 배정 전체 범위와 같으면 그 사실과 근거를 참조>
- 경계·제약: <넘지 않을 범위·관련 작업과의 접점·필요한 실행 제한. 다른 항목에 상세가 있으면 해당 위치를 참조>
- AI에 위임한 판단: <Issue에서 정한 개별 위임 대상·허용 범위와 근거. 공통 절차의 일반 수행 판단과 구분>
- 사용자 확인 조건: <확인할 선택·필요한 시점 또는 조건·확인 전 제한되는 후속 행동과 근거>
- 선행 입력·의존: <입력별로 필요한 결과·자료, 제공 담당/원천, 필요한 행동·시점, 확인된 확보 상태, 미확보 시 제한되는 행동>

| 결정 내용 | 적용 범위 | 근거 |
|---|---|---|
| <이번 Task에 적용되는 확정된 요구·동작·계약·제약·선택. 자료의 귀속·필수 참조·일치·보존 등 기존 계약의 핵심 포함> | <적용 대상·부분> | <Issue의 확정 결정 또는 채택한 원천의 해당 구역과 채택 근거. 필요한 커밋으로 당시 기준 식별> |

<a id="acceptance"></a>
## 완료 조건·확인 방법

| 완료 조건 | 확인 방법 |
|---|---|
| <Issue가 정한 이 Task 결과의 목표 상태와 수용 기준. 조사·설계는 필요한 범위·근거·판단 자료 등 결과의 충분성을 명시> | <관찰·대조할 대상·결과와 충족·불충족 판정 기준. 구체적인 명령·도구·수행 순서는 Task에서 계획> |
```

## 확정과 개정

적용할 내용이 없음을 확인했을 때만 `없음`으로 쓴다. 미정인 배정·미확인 사실·미발생 승인을 확정값으로 채우지 않는다.

구체 설계·수행 순서·구현 방법·검증 절차 등 Task에서 합의할 상세가 남아 있다는 이유만으로 확정된 배정의 전달을 막지 않는다. 생성 후 전체 계획·준비는 [실행 전 전체 계획](task-common-procedure-draft.md#sequence-rules)을 따른다.

원본 참조·기준 기록은 [기록 책임](task-common-procedure-draft.md#assignment-record)을, 배정 변경은 [전달사항 변경 절차](task-common-procedure-draft.md#revision)를 따른다.

<a id="db-method-assignment-example"></a>
## DB 생성 방법 논의의 가상 배정·전달사항 예시

실제 Issue·Task 번호·전달본·승인·실행 결과가 없는 설명용 사례다. 가상 부모는 DB 생성 방법의 후보 비교와 사용자 논의·선정 결과 정리까지 맡겼고, 대상 환경·기존 제약·판정 기준과 식별/저장 경로의 확인 근거를 제공했다고 가정한다. 생성 방법은 아직 미정이며 실제 DB 생성·DDL 실행·기존 DB 변경·커밋은 허용하지 않았다.

Issue 배정란에는 담당 결과를 아래와 같이 요약하고 근거 결정·전달사항·본문을 연결한다. 근거 결정은 방법의 최종 선정이 아닌 논의 과제의 배정과 식별/경로 확인을 뜻한다. 이 사례의 연결은 설명을 위한 것이며 실제 등록·확정 기록을 만들지 않는다.

| 전달사항의 묶음 | 가상 입력 |
|---|---|
| 배정 근거·목적 | 부모가 DB 생성 방법의 논의·선정을 이 Task에 맡겼다. 방법의 불확실성을 사용자 논의로 해소한다. |
| 담당 결과 | 후보 비교 자료와 사용자 선정 내용·이유·후속 실행 조건을 정리한다. 실제 DB를 생성한 결과는 담당하지 않는다. |
| 수행 범위·이미 결정된 사항 | 방법 조사·비교·논의·선정 기록을 맡는다. 현재 허용은 계획·자료 검토·사용자 논의다. AI는 조사 순서·비교 자료 구성을 판단하며 방법 자체는 후보 비교 후 사용자와 선정한다. 대상 환경·기존 제약·판정 기준은 제공됐다고 가정하고 시험 실행 환경·권한은 미확보로 둔다. |
| 완료 조건·확인 방법 | 비교 자료가 배정 기준에 맞고 사용자 선정 내용·이유·남은 실행 조건이 논의 근거로 확인돼야 한다. 이 기준은 앞으로 확인할 조건이며 선정·완료 사실을 미리 채우지 않는다. |

이미 결정된 사항에는 논의의 배정·기존 제약·실제 DB 작업의 미허용을 적는다. 미정 방법을 배정 미정으로 취급하거나 임의로 선정하지 않는다. 시험 실행이 필요해지면 필요한 권한·대상 환경·확인 시점을 계획에 남기며 논의 허용으로 실행 권한을 대신하지 않는다.

선정 결과의 기록 위치와 이후 계획은 [가상 Task 본문·전체 계획 예시](task-body-template-draft.md#db-method-plan-example)를 따른다.
