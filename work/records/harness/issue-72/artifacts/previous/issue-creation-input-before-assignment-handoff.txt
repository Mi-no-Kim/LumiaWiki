# Phase 하위 Issue 생성 시 입력 양식 — 작성안

[Issue 파일 생성 지시서](issue-file-creation-guide-draft.md)

[입력 예시: Issue #42](issue-creation-input-example-42.md)

각 구역에는 전달받은 내용을 적는다. 다음 경우에는 해당 표시를 쓴다.

- `없음`: 적용할 내용이 없음을 확인한 경우.
- `미정`: 아직 결정하지 않은 경우.
- `미확인`: 확인하지 못한 경우.

전달되지 않은 내용을 임의로 `없음`이나 확정된 값으로 채우지 않는다.

## 목적

어떤 대상의 어떤 문제를 왜 해결하려는지 적는다.

<과제가 다루는 대상·해결하려는 문제·해결이 필요한 이유>

## 기대 결과

과제가 끝난 뒤 달성할 상태나 남길 산출물을 적는다. 아직 정하지 않은 구현 상세를 확정된 것처럼 쓰지 않는다.

<과제가 끝난 뒤 달성할 상태나 남길 산출물. 정하지 않은 상세는 미정으로 표시>

## 이미 정해진 조건

입력을 전달할 때 이미 확정되어 이번 Issue가 따라야 하는 요구·제약·선택을 한 항목에 한 조건씩 적는다.

적용 범위는 조건이 적용되는 대상이나 부분을 알아볼 수 있게 적는다. 제안·미정 사항·단순한 현황 사실을 확정된 조건으로 쓰지 않는다.

- 조건: <반드시 지켜야 할 구체적인 내용>
  - 적용 범위: <이번 Issue의 어떤 대상·부분에 적용되는가>
  - 확정 근거: <원천의 해당 구역 링크 또는 사용자 합의 내용>

## Issue에서 결정할 사항

Issue 파일을 생성할 때 아직 답이 없고, 이번 Issue에서 Task를 분해·배정하기 전에 답을 확정하도록 맡긴 초기 질문을 한 항목에 하나씩 적는다.

결정 범위는 답을 정할 대상과 경계다. 그 범위 안의 내용을 AI가 스스로 결정해도 된다는 뜻은 아니다. Issue 파일을 생성하면서 질문의 답을 대신 작성하지 않는다.

- 결정할 사항: <Task 분해·배정 전에 이번 Issue에서 답을 확정할 초기 질문 하나>
  - 결정 범위: <답을 정해야 할 구체적인 대상과 경계>
  - 판단 기준: <결정할 때 충족하거나 비교해야 할 기준>
