# Task 생성 지침 — 작성안

<a id="summary"></a>

## 역할과 범위

- 담당 Issue: [Issue #72](../../issue.md#summary).
- 사용할 양식: [Task 작성 양식](task-template-draft.md#body). 논의 근거는 [기존 양식 요소별 검토](task-template-review.md#summary)에 있다.
- 읽는 주체와 시점: Issue에서 Task를 분해·배정·생성하는 진행자가 사용한다.
- 이 문서는 작성 근거·형식·설명·예시를 담는다. 실제 Task에는 양식의 본문을 채워 사용하고, 이 지침의 설명·예시·미정 사항을 일괄 복사하지 않는다.
- 현재까지 논의한 범위의 작성안이다. 전체 양식·생성 절차의 최종 채택이나 현행 양식 적용·운영 효과 검증을 완료한 것으로 취급하지 않는다.
- 아직 논의하지 않은 항목을 임의로 채우거나 기존 양식에서 가져오지 않는다. 나머지 구역은 이후 논의에서 정한 내용으로 이어 작성한다.

<a id="creation"></a>

## 생성·배정과 등록

- 기존 Task의 보완인지 별도로 실행·수용할 단위가 필요한지 [기록 체계](<../../../../../../docs/작업 기록 체계.md#ownership>)에 따라 판단한다. 실제 실행 단위가 필요할 때 Task를 만든다.
- Task 분해·배정과 번호·경로·부모 등록·필요한 GitHub 등록은 현재 [기록 체계](<../../../../../../docs/작업 기록 체계.md#paths>)와 [생성·등록 절차](<../../../../../../harness/문서 관리.md#create>)에 연결한다. 실제 등록 결과와 부모·자식 및 원본 연결을 확인한다.
- 생성 책임과 착수 확인은 구분한다. Task 실행자는 담당 브랜치·필요한 등록·허용 범위를 실제 상태와 대조한다. 시작 시 보완 지침은 작성 양식에도 남긴다.

### 제목·역할과 생성 책임

- 제목은 부모 Issue 번호·Issue 안의 로컬 Task 순번·작업 제목으로 채운다.
- 역할 설명은 실제 생성된 Task에도 공통으로 남긴다.
- Task는 Issue가 만든다는 전제를 적용한다. 새 Task의 필요성 판단·생성·분해·부모 등록 안내는 Issue 쪽에서 다루며, 실제 Task의 header에는 Task 자신을 생성하라는 안내를 넣지 않는다.

<a id="fields"></a>

## 목적·작업 단위의 작성 기준

### Issue가 생성할 때

Issue는 부모의 현재 목표·수용 조건·분담 결정과 사용자 합의를 근거로 최소 배정 내용을 기입한다. 왜 배정했는지, 어떤 결과를 남겨야 하는지, 어디까지 맡겼는지는 알아볼 수 있어야 한다. 모든 상세를 생성 시 확정할 필요는 없다.

상세를 정하는 일 자체가 목적이면 담당 결과를 설계안 제안·조사 결과 등으로 명시한다. 알려지지 않은 입력·경계는 부족 사항으로 연결하고, 빈칸이나 “추후 결정”만 남기지 않는다.

| 항목 | 작성 형식 | 근거와 기입 기준 |
|---|---|---|
| 배정 근거 | `<Issue의 구역·요구 항목> — <이번 Task에 배정한 내용>` | Issue의 현재 목표·수용 조건·분담 결정. 링크만 적지 않고 배정 내용을 함께 쓴다. |
| 목적 | `<대상의 현재 부족한 상태>를 <목표 상태>로 바꾼다.` | 배정 근거와 확인된 현재 문제. Issue 전체 목표나 “품질 개선” 같은 포괄적인 표현만 반복하지 않는다. |
| 담당 결과 | `<남길 결과의 종류와 내용>` | 배정된 결과. 문서라면 담을 내용, 기능이라면 제공할 동작을 식별한다. |
| 수행 범위 | `<대상>에 대해 <수행할 행동>` | 배정 범위·허용된 행동과 실제 대상. 경로만으로 행동 범위를 대신하지 않는다. |
| 경계·제약 | `<이 Task에서 넘지 않을 범위·다른 작업과의 접점>` | 명시된 제한과 실제 분담 관계. 존재하지 않는 후속 Task나 분담을 만들지 않는다. |

<a id="startup"></a>

## 시작 시 부족한 내용의 보완

### Task를 시작할 때

생성 시 기입한 내용을 출발점으로 삼아 구체적인 대상·입력·관련 기준·분담 경계를 확인해 보완한다. 표현의 구체화 과정에서 목표·범위를 임의로 확대하지 않는다.

| 부족한 내용의 종류 | 처리 방법 |
|---|---|
| 기존 원천에 있는 사실·경로·현재 상태 | 허용된 조회로 확인하고 근거와 함께 채운다. |
| 기존 기준이나 명시적으로 위임된 범위의 실행 상세 | 기준에 따라 구체화하고 판단 이유를 남긴다. |
| 배정 범위 확대·새 요구·미위임 선택·기준 간 충돌 | 제안이나 충돌로 구분해 논의한다. 결정된 것으로 채우거나 관련 행동을 먼저 실행하지 않는다. |

부족 사항마다 내용·보완 방법·필요한 시점과 진행 제한을 기록한다. 결정 주체가 불명확하면 보완 방법에 함께 적는다. 모든 미정 때문에 Task 전체를 멈추지 않고, 그 정보에 의존하는 행동과 독립적으로 허용된 일을 구분한다.

이 구역은 작성 방법을 설명한다. 실제 Task 실행자가 따를 보완 지침과 부족 사항의 기록란은 [작성 양식 본문](task-template-draft.md#body)에 그대로 둔다.

<a id="example"></a>

## 작성 예시

아래는 Issue #72를 이용한 형식 설명용 예시이며, 실제 배정·발급한 Task가 아니다. 예시의 “상단 문안”은 목적·작업 단위 작성안을 가리킨다.

```markdown
목적
- 배정 근거: Issue #72의 합의한 변경 방향 2·6 —
  Task의 목적과 담당 범위를 구체적으로 기록하는 형식을 설계한다.
- 목적: 목적·작업 단위를 포괄적인 문장으로 임의 해석할 수 있는 상태를,
  배정 근거와 담당 결과·범위를 확인할 수 있는 작성 형식으로 바꾼다.

작업 단위
- 담당 결과: 목적·작업 단위의 작성안.
  항목별 기입 규칙, 작성 예시, 시작 시 부족한 내용을 보완하는 지침을 포함한다.
- 수행 범위: 현재 초안과 관련 기준을 검토해 문안을 제안하고 비교한다.
- 경계·제약: 현행 Task 양식의 수정과 다른 본문 구역의 개편은 포함하지 않는다.

착수 시 보완할 내용
- 부족한 내용: 이후 목적·범위 구역과 정보를 어떻게 나눌지 미정이다.
- 보완 방법: 현재 양식의 중복 항목을 확인하고 배치안을 제안해 논의한다.
- 필요한 시점·진행 제한: 상단 문안의 제안·비교는 진행할 수 있다.
  전체 양식의 배치는 관련 구역을 함께 논의한 뒤 확정한다.
```

## 미정 사항과 추가 검토

- Issue 쪽 생성·분해·등록 안내의 구체적인 형식과 적용은 Issue 양식 논의에서 다룬다.
- 이후 목적·범위 관련 구역과 중복 관리하지 않도록 정보의 소유 위치와 배치를 정한다.
- 작업별 적용 지침과 등록·브랜치의 실제 확인값을 본문의 어느 구역에 어떻게 기록할지 정한다.
- “주요 단계 전환”의 단계 구분·재확인 시점과 해당 시점에 확인할 대상을 정한다.
- “합의한 내용과 실제 상태를 대조”할 때의 기준 원천·기대값·실제값·판정과 불일치 시 행동을 구체화한다.
- 계획과 실제 결과의 작성 형식, 승인·성공 판단에 필요한 근거, 유효한 결정·필요한 보존 근거를 유지하는 조건을 구체화한다.

구역 이동·문서 통합을 지침의 완성으로 판단하지 않는다. 특히 재확인 시점·대조 판정·기록과 근거 유지 조건은 계속 구체화해야 한다.
