# Task 문서 관리의 추가 충돌 사례

기존 [12개 사례](task-document-management-test-cases.md#case-list)에 다음 세 사례를 더한다. 재사용할 입력·행동·관찰 기준이며 실제 실행 상태·결과는 [담당 Issue](../issue.md#task-generation-test)에서 연결한 새 시험 묶음이 관리한다. 사용자가 승인한 고정 입력 모의 방식으로 수행하며 실제 사용자 승인·정식 발급으로 쓰지 않는다.

<a id="case-13"></a>
## TC-13. 부모와 Task의 적용 전달본 불일치

**입력·시작점**

부모는 r002를 확정해 새 전달사항과 적용 조건을 제공했지만 기존 Task는 r001을 참조한다. 기존 원문·이전 전달사항·수행 기록을 보존한다. 모의 선택은 입력에 제공돼 있지만 그 선택이 전달본 불일치를 해소하지는 않는다.

**진행 방법**

1. 현재 부모·Task의 참조와 실제 원문을 대조한다. 의존 반영이나 완료를 시도하면 거절되고 파일이 바뀌지 않는지 확인한다.
2. 이미 확정된 부모 결정과 새 원문을 확인한 뒤 Task의 참조·현재 합의·영향받는 계획과 확인을 맞춘다. 새 배정을 대신 정하지 않는다.
3. r002의 조건으로 허용된 결과를 반영·확인한다. Task 완료 뒤 부모가 자기 전체 조건을 별도로 대조한다.

**관찰·기대 결과**

- 선택·완료 체크가 있어도 전달본 불일치가 남으면 의존 실행·수용을 허용하지 않는다.
- 거절 시 원문·Task·부모·실제 대상이 그대로다. 이전 전달본·그에 근거한 수행 사실을 새 원문으로 덮어쓰지 않는다.
- 정합성을 회복한 뒤 현재 원문의 조건으로 실제 결과를 검사한다. 부모를 자식 완료에 따라 자동 완료하지 않는다.

<a id="case-14"></a>
## TC-14. 같은 문장에 겹치는 사용자 수정

**입력·시작점**

이전 모의 A안 선택과 작업 기준 원문이 있다. 이후 가상 사용자가 같은 문장을 “별도 합의 전 줄이지 말라”는 내용으로 수정했다. 새 충돌 해소 선택은 제공하지 않았다. 실제 변경 파일과 이전 기준 원문은 구별해 제공한다.

**진행 방법**

현재 파일과 이전 기준을 대조하고 반영 조건을 확인한다. 같은 문장의 충돌을 발견하면 관련 반영을 제한하고 선택이 필요한 쟁점·범위·해소 조건을 남긴다. 다른 독립 활동이 있으면 그 범위에서 진행한다.

**관찰·기대 결과**

- 이전 A안 선택만으로 이후의 사용자 변경을 덮어쓰지 않는다. 반영 거절 전후 파일이 같다.
- AI가 두 요구 중 하나를 채택하거나 충돌을 없는 것으로 처리하지 않는다.
- 사용자의 새 문장과 기존 근거를 보존한다. 제공되지 않은 답을 만들지 않으며 관련 다음 행동이 막혔다면 중단과 구체 재개 조건을 기록한다.
- 이 사례의 충족은 충돌 검출·보존·제한을 확인한 결과다. 원래 과제의 목표 달성이나 정상 완료가 아니다.

<a id="case-15"></a>
## TC-15. 실제 조건 실패와 완료 표시의 모순

**입력·시작점**

Task에는 완료 체크와 완료 상태가 있지만 실제 링크 표식이 잘못됐고 일부 확인 근거도 없다. 모의 A안 선택은 제공돼 있다. 현재 범위 안에서 실제 오류를 보완할 수 있으나 상태 표시만 맞춰 수용할 수는 없다.

**진행 방법**

1. 읽기 전용 검사로 실제 조건과 완료 표시의 모순을 찾는다. 검사는 파일을 바꾸지 않아야 한다.
2. Task 완료·부모 수용을 각각 요청해 실제 조건 실패로 거절되는지, 거절 전후 파일이 같은지 확인한다.
3. 발견한 모순과 실패 근거를 보존하고 허용된 대상의 실제 오류를 보완한다. 누락된 확인·기록·종료 조건도 충족시킨다.
4. 실제 결과를 재검증한 뒤 Task를 완료하고, 부모는 별도 조건 검사로 수용한다.

**관찰·기대 결과**

- Task의 완료 상태·체크·성공 문구를 실제 수용의 증거로 대신하지 않는다.
- 검사·거절은 무변경이고 실제 오류가 남으면 완료·부모 수용을 제한한다.
- 보완·재확인은 같은 할 일에서 관리하고 원래의 실패·표시 모순을 없던 것으로 바꾸지 않는다.
- 실제 파일·선택·조건별 근거·필수 종료 처리까지 충족한 뒤에만 정상 완료할 수 있다.

## 실행·판정 분리

실행자에게는 중립적인 입력 이름, 목표·조건·현재 파일·모의 사건의 전달 경로와 조작 지침을 제공한다. 이 문서의 예상 결과·판정표·과거 출력은 제공하지 않는다. 판정자는 실행 이후 기존 12개와 이 세 사례의 기준을 실제 파일·거절 근거·별도 수용 검사에 대조한다. 같은 모델의 별도 문맥 역할 분리이며 OS 접근 격리나 다른 모델 검증으로 보고하지 않는다.
