## 현재 판정

기계적 상태·원본·관리 참조 대조는 당시 17개 입력에서 오류 0건이었으나, 별도 문맥의 검토자가 원래 사례와 실제 입력·행동을 대조해 의미 결함을 확인했다. **B 묶음 전체를 원래 15개 사례의 최종 성공 근거로 수용하지 않는다.** 입력·실제 출력·관찰·실행 코드는 실패 분석 원문으로 보존하고 결과를 새 성공 상태로 덮어쓰지 않는다.

| 대상 | 확인한 문제·한계 | 원문 |
|---|---|---|
| TC-02 | 결과·수용 기준을 누락했다고 했으나 다른 담당 원천에는 답이 남음. 특정 JSON 키 누락에 대한 거절만 확인 | [결과 부족](cases/sample-b/assignment.md) · [기준 부족](cases/sample-c/assignment.md) |

| TC-08 | 초기 계획이 이미 한 반영·확인 단위여서 실질 병합·재배열은 미확인 | [계획 기록](cases/sample-j/task.md#execution-plan) |

## 보존과 수정 범위

사용자는 완료·부모 수용 검사 → 읽기 전용 재검증 → 실행·판정 분리 → 충돌 사례 추가 순서의 반영과 재검증을 요청했다. 실행자는 중립 입력·지침·조작 API를, 별도 검토자는 원래 기대 매핑·실제 파일·조작 코드를 받았다. 같은 모델의 별도 문맥이며 접근의 보안 격리를 주장하지 않는다.

이 묶음의 사례 입력·대상·수행 기록은 정정하지 않는다. 당시 [입력 정의](sealed/source-cases.json)·[사건](sealed/events.json)·[예상 상태](sealed/oracle.json)와 [실제 조작](actor.py)을 보존한다. 이 자료는 실행자에게 점수표로 전달하지 않았다. 지적을 반영한 새 C 입력에서 다시 수행하고 별도로 판정한다. 실제 제품·정식 번호·GitHub·커밋은 이번 시험 범위가 아니다.
