# Issue → Task 생성 테스트 케이스

검토용 초안·미실행. Task 입력은 [입력 양식](task-creation-input-draft.md#assignment-body)의 Task 태그와 다섯 구역을 따른다. 부모 배정 기록·전달본 식별·경로·순번 확인 근거는 [생성 지시서](task-file-creation-guide-draft.md#creation)의 생성·관리 정보로 구분한다. 기존 여섯 사례의 조건·예상 결과를 유지해 입력 형식만 맞췄으며 시험 설계 합의·실행을 뜻하지 않는다.

각 케이스는 독립된 가상 상태다. 기존 Issue #42의 번호와 경로를 빌렸으며 실제 #42의 배정·승인·등록 사실을 뜻하지 않는다. 아래 원천·목록·파일에 관한 사실은 케이스 입력으로 제공할 내용이다.

## N1. 정상 — 확정된 문서 정리 배정

### 입력

```text
생성·관리 정보:
부모 Issue 배정 기록: work/records/phase-001/issue-42/issue.md#assignment-n1
확정 근거: 위 배정 기록의 case-n1-decision. 아래 명시한 내용에 한해 적용한다.
Task 식별·본문 경로: 42-001 / work/records/phase-001/issue-42/task-001.md
전달사항 원본 경로: artifacts/task-001-assignment.md
전달본: r001 / 이전 전달본: 없음 / 개정 이유·합의: 초판
순번 확인: 가상 부모 보유 목록·파일 트리·과거 사용 순번을 대조했고 001 충돌 없음이 기록돼 있다.
Task 활동: 미착수. 전체 계획은 아직 수립·합의하지 않았다.

Task 입력:
태그: 조사, 검수
목적: Issue가 개발 실행 안내의 누락 확인을 맡겼다. 후속 작업자가 실행 조건을 파악하도록 한다.
기대 결과: README와 프로젝트 명령 정의의 차이 목록, 안내 수정 문안, 남은 확인 사항.
이미 정해진 조건:
- 수행 범위: 두 문서의 읽기 전용 대조와 수정 문안 제안.
- 현재 허용: 확정 배정을 반영한 최초 Task 본문 작성·대조. 이후 활동은 전체 계획 합의와 준비 확인 후 진행한다.
- 경계·제약: 실제 파일 수정·명령 실행·환경 설치·외부 등록·커밋은 제외한다.
- AI에 위임한 판단: 비교표의 구성.
- 사용자 확인 조건: 안내 채택과 실제 파일 변경은 사용자 확인 대상이며 이번 배정에 실제 변경은 포함하지 않는다.
- 선행 입력·의존: README와 명령 정의의 경로·본문이 부모 기록에 제공돼 있다. 후속 대조에서 사용한다.
- 기존 결정: 프로젝트 정의에 없는 명령을 확정 안내로 쓰거나 실행한 것으로 보고하지 않는다. 적용 범위는 차이 목록·수정 문안이며 근거는 위 부모 배정 기록이다.
Task에서 결정할 사항: 비교표 구성은 AI에 위임됐다. 안내 문안의 채택·실제 변경은 사용자 확인 대상이며 이번 배정의 실제 변경 범위 밖이다.
완료 조건과 확인 방법: 차이 항목의 근거가 두 원문의 위치로 추적되고 수정 문안과 미확인 조건이 구별돼야 한다. 결과와 두 원문을 대조한다. 사용자 채택·명령 실행 성공은 완료 기준에 포함하지 않는다.
```

### 예상 결과

- Task 본문을 작성하며 부모 배정 기록·r001·전달사항 원본을 정확히 참조한다.
- 신규 미착수 상태는 예정으로 두고, 전체 계획·실행·검증 결과를 이미 합의하거나 수행한 것으로 채우지 않는다.

## N2. 정상 — 방법 선정 자체를 맡긴 배정

### 입력

```text
생성·관리 정보:
부모 Issue 배정 기록: work/records/phase-001/issue-42/issue.md#assignment-n2
확정 근거: 위 배정 기록의 case-n2-decision. 아래 명시한 내용에 한해 적용한다.
Task 식별·본문 경로: 42-001 / work/records/phase-001/issue-42/task-001.md
전달사항 원본 경로: artifacts/task-001-assignment.md
전달본: r001 / 이전 전달본: 없음 / 개정 이유·합의: 초판
순번 확인: 가상 부모 보유 목록·파일 트리·과거 사용 순번을 대조했고 001 충돌 없음이 기록돼 있다.
Task 활동: 미착수. 전체 계획은 아직 수립·합의하지 않았다.

Task 입력:
태그: 조사, 논의, 결정, 검수
목적: Issue가 DB 생성 방법의 비교·사용자 논의·선정 기록을 맡겼다. 방법의 불확실성을 줄인다.
기대 결과: 후보 비교 자료와 사용자가 최종 선정한 방법·이유·후속 실행 조건. 실제 DB 생성 결과는 맡지 않는다.
이미 정해진 조건:
- 수행 범위: 방법 조사·비교·사용자 논의·선정 내용 정리. 생성 방법 자체는 아직 미정이다.
- 현재 허용: 최초 Task 본문 작성·대조. 이후 자료 검토·논의는 전체 계획 합의와 준비 확인 후 진행한다.
- 경계·제약: DB 생성·DDL 시험 실행·기존 DB 변경·커밋은 허용하지 않았다.
- AI에 위임한 판단: 자료 조사 순서와 비교 자료 구성.
- 사용자 확인 조건: 최종 방법은 후보 비교 후 사용자가 선정한다.
- 선행 입력·의존: 대상은 PostgreSQL 개발 환경이며 환경 설명과 기존 제약은 제공됐다. 실제 시험 환경·권한은 미확보이고 시험 실행이 필요해질 때 그 전에 확인한다.
- 기존 결정: 기존 데이터를 보존하며 반복 재현성·되돌릴 수 있는지·기존 개발 흐름과의 일치로 비교한다. 적용 범위는 후보 비교·선정이며 근거는 위 부모 배정 기록이다.
Task에서 결정할 사항: 채택할 DB 생성 방법은 미정이다. 위 기존 제약·비교 기준 안에서 후보를 비교한 뒤 사용자가 최종 선정한다. AI에는 조사 순서·자료 구성만 위임됐다.
완료 조건과 확인 방법: 후보 비교가 위 세 기준을 다루고 사용자 선정 내용·이유·남은 실행 조건이 논의 근거로 확인돼야 한다. 비교 자료·논의 근거·선정 기록을 대조한다.
```

### 예상 결과

- 방법 미선정을 배정 부족으로 취급하지 않고 Task 본문을 작성한다. 방법은 Task의 논의 대상으로 남긴다.
- 사용자의 최종 선정이나 DB 실행 허용을 만들지 않으며 전체 계획·선정·완료 결과는 미발생으로 유지한다.

## N3. 정상 — 후속 실행 자료만 미확보

### 입력

```text
생성·관리 정보:
부모 Issue 배정 기록: work/records/phase-001/issue-42/issue.md#assignment-n3
확정 근거: 위 배정 기록의 case-n3-decision. 아래 명시한 내용에 한해 적용한다.
Task 식별·본문 경로: 42-001 / work/records/phase-001/issue-42/task-001.md
전달사항 원본 경로: artifacts/task-001-assignment.md
전달본: r001 / 이전 전달본: 없음 / 개정 이유·합의: 초판
순번 확인: 가상 부모 보유 목록·파일 트리·과거 사용 순번을 대조했고 001 충돌 없음이 기록돼 있다.
Task 활동: 미착수. 전체 계획은 아직 수립·합의하지 않았다.

Task 입력:
태그: 논의, 결정, 실행, 검수
목적: Issue가 아이템 검색 화면과 조회 기능을 맡겼다. 선택한 버전에서 이름으로 아이템을 찾게 한다.
기대 결과: 검색 화면 설계·조회 기능·화면 연결과 화면/내부 검증 근거.
이미 정해진 조건:
- 수행 범위: 선택한 버전 하나에서 이름 부분 검색을 제공한다. 결과에는 아이템 식별자·이름·버전을 표시한다.
- 현재 허용: 최초 Task 본문 작성·대조. 현재 시험 요청이 제품 수행 권한을 부여하지 않는다.
- 경계·제약: 자료 수정·DB 구조 변경·피해량·루트 계산은 제외한다. 실제 게임 자료 조사·확보 보류를 유지한다.
- AI에 위임한 판단: 확정 범위 안의 자료 정리.
- 사용자 확인 조건: 구체 화면·API 설계는 Task에서 합의하며 데이터 의존 값·동작 확정·구현 전에는 원자료와 사용자 확인이 필요하다.
- 선행 입력·의존: 실제 자료의 제공 담당은 사용자다. 지정할 원자료·버전별 실제 값은 미확보이며 데이터 의존 확정·구현 전에 필요하다. 미확보 상태에서는 그에 의존하는 실행·검증·완료 판정을 제한한다.
- 기존 결정: 화면 디자인 검토를 동작 구현보다 먼저 하고 화면 조작과 내부 결과를 함께 확인한다. 적용 범위는 설계·구현·검증 순서이며 근거는 위 부모 배정 기록이다.
Task에서 결정할 사항: 구체 화면·API 설계는 Task에서 사용자와 합의한다. 데이터 의존 값·동작 확정·구현 전 원자료·사용자 확인 조건은 위 배정을 따른다.
완료 조건과 확인 방법: 선택한 버전의 등록 자료로 이름 부분 검색·빈 검색어 안내·결과 없음 표시가 동작하고 화면과 내부 결과가 일치해야 한다. 실제 자료와 화면/내부 결과를 대조한다. 구체 절차는 Task에서 합의한다.
```

### 예상 결과

- 후속 실행 자료의 미확보와 생성 조건을 구분해 Task 본문을 작성한다.
- 원자료 미확보·자료 작업 보류·전체 계획 미합의를 남기고, 생성만으로 제품 수행이나 자료 확보를 시작하지 않는다.

## M1. 부족 — 담당할 결과가 미확정

### 입력

```text

부모 Issue 배정 기록: work/records/phase-001/issue-42/issue.md#assignment-m1
확정 근거: 위 배정 기록의 case-m1-decision. 아래 명시한 내용에 한해 적용한다.

전달사항 원본 경로: artifacts/task-001-assignment.md
전달본: r001 / 이전 전달본: 없음 / 개정 이유·합의: 초판
순번 확인: 가상 부모 보유 목록·파일 트리·과거 사용 순번을 대조했고 001 충돌 없음이 기록돼 있다.

Task 입력:
태그: 미정
목적: Issue가 DB 생성 방법 검토를 맡기려 한다. 방법 선택에 필요한 판단 자료를 마련하려는 목적은 정해졌다.
기대 결과: 미정. 후보 비교 자료만 제안할지, 사용자 최종 선정 기록까지 맡길지 채택한 결정이 없다.
이미 정해진 조건:
- 수행 범위: 방법 검토. 비교 결과를 어디까지 책임질지는 미정이다.
- 현재 허용: 입력 확인과 필요한 보완 요청.
- 경계·제약: 실제 DB 생성·DDL 실행·기존 DB 변경·커밋은 허용하지 않았다.
- AI에 위임한 판단: 자료 구성. 담당 결과의 범위와 최종 결정 주체를 대신 정할 권한은 없다.

Task에서 결정할 사항: 미정. 담당 결과의 범위·결정 주체를 Issue에서 먼저 확정해야 하며 이를 Task 내부의 방법 선택으로 대신하지 않는다.
완료 조건과 확인 방법: 담당 결과 미확정으로 아직 정하지 않았다. 다른 원천에도 확정 내용이 없다.
```

### 예상 결과

- 후보 비교만 맡기는지 최종 선정 기록까지 맡기는지, 결정 주체와 결과의 수용 기준을 보완 요청한다.
- 논의할 방법 값의 미정과 담당 결과 자체의 미확정을 구분하고, 배정을 대신 선택해 확정 전달사항·정식 Task 본문을 만들지 않는다.
