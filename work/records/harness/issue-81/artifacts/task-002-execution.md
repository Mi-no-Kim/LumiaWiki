## 브랜치 이름 검사 훅 구현과 격리 검증

- 할 일: [훅 구현과 격리 검증](../task-002.md#work-branch-hook-implementation)

- 조치·판단: 공통 검사기와 설치 가능한 `reference-transaction`·`pre-push`를 추가했다. 백업의 커밋을 설치본에 고정해 이름·별칭이 바뀐 뒤에도 그 이력이 전송되지 않게 했다. 검사 설치본은 동일 Git 디렉터리를 사용하는 다른 워크트리에서 검사기를 찾을 수 있도록 검사기 내용을 포함한다. Git 2.52.0의 기본 이름 변경은 `files`에서 새 이름을 훅에 전달하지 않고, `reftable`에서는 이름 변경 동안 훅을 호출하지 않았다. 같은 Git 구현을 사용하는 기본 브랜치 복사에도 이 한계가 있어, 공통 규칙으로 대상 이름을 검사한 뒤 Git을 실행하는 `rename`·`copy` 진입점을 추가했다.
- 확인: Windows·Git 2.52.0.windows.1·Python 3.14.2에서 [독립 저장소 회귀 7개](../../../../../scripts/tests/test_branch_name_hooks.py)가 통과했다. 정상 브랜치와 재개 이름, 중간에 대소문자 혼합 `codex` 거부, 이름 변경 거부 시 원본 보존, 로컬 백업 ref 보존, 다른 이름·커밋 해시·태그를 통한 백업 이력 전송 차단, 정상 태그·원격 삭제, 이전 훅 입력 전달·거부·복구와 연결 워크트리 적용을 확인했다. 기본 Git 이름 변경의 모든 경로에 대한 자동 차단이나 실제 복제본에 설치한 결과까지 검증한 것은 아니다.
- 사용자 결정: 격리 검증 결과와 기본 Git 명령의 제한을 확인한 뒤, 이름 변경과 복사에는 `rename`·`copy` 검사 명령을 쓰기로 했다.
- 잔여: 없음. 실제 복제본 확인 근거는 [실제 설치 및 로컬 검사](#work-branch-hook-live-install)에 기록했다.

## 실제 저장소 훅 적용과 확인

- 할 일: [실제 저장소 훅 적용과 확인](../task-002.md#work-branch-hook-live-install)

- 조치·판단: 사용자 승인에 따라 같은 Git 디렉터리를 공유하는 Task 원천을 `--source-worktree`로 지정해, 기본 체크아웃에서 `reference-transaction`과 `pre-push`를 공용 `.git/hooks`에 설치했다. 설치기·검사기·두 훅 원천의 지문을 사전에 대조했다. 격리 회귀 8개에서 같은 저장소의 연결 워크트리 설치·제거와 다른 저장소 원천 거부를 포함해 확인했다. 첫 실제 설치는 PowerShell 줄바꿈을 받은 확인 명령이 실패해 두 훅을 원복했다. 입력을 LF 바이트로 수정하고 격리 확인 뒤 재설치했다.
- 확인: Windows·Git 2.52.0.windows.1·Python 3.14.2의 실제 공용 경로에서 두 설치를 검증했다. 참조 트랜잭션 검사 3개로 정상 이름 준비·중단, 금지 이름 거부와 백업 삭제 거부를 확인했다. 설치된 `pre-push`의 로컬 입력 검사 3개로 정상 대상 허용, 대소문자 혼합 `codex` 대상 거부와 백업 커밋을 다른 이름으로 전송할 경우 거부를 확인했다. 검사 참조가 생성되지 않았고 외부로 푸시하지 않았다. 기존 `pre-commit`·`commit-msg` 지문 및 백업 `76283e719dc29c054d3f41720b6438f53ed1b6ce`는 유지됐다. 설치본 SHA-256은 `pre-push` `e62cee8722d38867e0152685f18daf64e7201c4362720605766f69a3a010eea5`, `reference-transaction` `e7395dc80e647f7b6381f9499fd3a55ed4703d2c1ccf5ad57fe1a4bda101c0c1`이다.
- 잔여: 없음. 상위 반영 상태는 [부모 Issue](../issue.md#step-3)에서 확인한다.
