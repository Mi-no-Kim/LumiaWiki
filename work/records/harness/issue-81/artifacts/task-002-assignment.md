# Task 81-002 확정 전달사항

- 태그: 조사, 논의, 검수

<a id="purpose"></a>

## 목적

저장소의 브랜치 이름 규칙을 벗어난 작업 브랜치를 만들거나 전송하는 일이 반복되지 않도록 예방 방법을 검토한다.

<a id="result"></a>

## 기대 결과

Git 훅이 로컬 브랜치 생성과 원격 전송에서 검사할 범위, 기존 브랜치와 로컬 보존용 예외의 처리, 검증 방법을 정리한다. 검토 결과를 바탕으로 적용 범위와 채택 여부를 사용자와 확정한다.

<a id="scope"></a>

## 이미 정해진 조건

- 조건: 저장소의 현재 브랜치 이름 규칙을 적용 기준으로 삼고 `codex/local-history-before-init`의 로컬 보존 전용 조건을 유지한다.
  - 적용 범위: 새 작업 브랜치 이름과 원격 전송 대상의 검사 방안.
  - 확정 근거: [브랜치 관리 기준](<../../../../../docs/details/git/브랜치 관리 기준.md#branches>) · [부모 Issue의 배정](../issue.md#branch-hook-assignment).
- 조건: 훅의 설계·검토를 Ubuntu CI 작업과 별도 Task로 다룬다. 훅 구현·설치는 적용 범위와 착수를 합의한 뒤 진행할 수 있다.
  - 적용 범위: 이번 Task 배정과 후속 실행 권한.
  - 확정 근거: [부모 Issue의 배정](../issue.md#branch-hook-assignment).

<a id="decisions"></a>

## Task에서 결정할 사항

- 결정할 사항: 브랜치 이름 검사를 어느 단계에 두고 어떤 예외를 허용할 것인가?
  - 결정 범위: 로컬 생성과 원격 전송의 검사 시점, 기존 브랜치와 로컬 보존 예외, 훅 채택 여부.
  - 판단 기준: 규칙 위반을 예방하면서 정상 작업과 기존 보존 이력을 보호하는가.
  - 결정 주체: 사용자가 채택 여부와 적용 범위를 확정한다. AI는 비교와 검증 방안 제안을 맡는다.

<a id="acceptance"></a>

## 완료 조건과 확인 방법

- 완료 조건: 유효·무효 이름, 원격 대상 이름이 다른 전송, 기존 브랜치와 로컬 보존용 예외를 다룬 설계와 검증 계획이 있고, 사용자의 채택 여부와 범위가 기록돼 있다.
  - 확인 방법: 검사 시점과 각 사례의 예상 처리를 브랜치 이름 규칙과 대조하고 사용자 결정의 근거를 확인한다.
