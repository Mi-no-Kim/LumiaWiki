# Task 81-002 확정 전달사항 r002

- 태그: 조사, 논의, 결정, 실행, 검수

<a id="purpose"></a>

## 목적

저장소 브랜치 이름 규칙을 로컬 생성·이름 변경과 원격 전송에 적용한다. 초기화 전 로컬 백업을 보존한다.

<a id="result"></a>

## 기대 결과

Git 훅을 구현하고 독립 로컬 저장소와 전송 대상 저장소에서 허용·거부 동작 및 기존 훅과의 공존을 확인한다. 실제 저장소 설치는 별도 승인 대상이다.

<a id="scope"></a>

## 이미 정해진 조건

- 조건: `main` 및 정해진 Phase·Issue·Task 이름을 허용한다. 이름 어디에든 `codex`가 포함되면 대소문자 구분 없이 금지한다.
  - 적용 범위: 새 로컬 브랜치와 이름 변경 대상, 원격 브랜치 생성 및 갱신 대상.
  - 확정 근거: [부모 Issue의 배정 개정](../issue.md#branch-hook-assignment-r002).
- 조건: 기존 `codex/local-history-before-init`은 로컬 이력을 지키고 원격으로 보내지 않는다. 다른 기존 미준수 브랜치의 삭제와 정상 이름으로의 이동은 허용한다. 일반 태그, 정상 브랜치 갱신, 원격 추적 ref는 기존 작업 흐름을 유지한다.
  - 적용 범위: 기존 참조, 로컬 백업 및 원격 전송.
  - 확정 근거: [부모 Issue의 배정 개정](../issue.md#branch-hook-assignment-r002).
- 조건: 훅 구현과 격리 검증을 수행한다. 실제 저장소의 훅 설치나 GitHub 설정 변경은 별도 승인 후 가능하다.
  - 적용 범위: 훅 원천·등록 및 격리 검증.
  - 확정 근거: [부모 Issue의 배정 개정](../issue.md#branch-hook-assignment-r002).

<a id="decisions"></a>

## Task에서 결정할 사항

검사 범위와 예외는 사용자가 확정했다. 구현 세부와 격리 검증 대상은 확정 조건 안에서 정한다.

<a id="acceptance"></a>

## 완료 조건과 확인 방법

- 완료 조건: 이름 규칙 및 `codex` 포함 금지가 로컬 생성·이름 변경과 원격 대상 생성·갱신에 적용된다.
  - 확인 방법: 정상 이름, 다른 이름으로 향하는 push, 대소문자가 섞인 금지어, 이름 변경 실패 시 기존 브랜치 보존을 실제 Git 명령으로 확인한다.
- 완료 조건: 로컬 전용 백업을 보존하며 다른 이름으로 전송해도 거부한다. 정상 작업 및 기존 훅이 계속 동작한다.
  - 확인 방법: 백업 참조와 커밋을 다른 원격 이름으로 보내는 경우, 기존 미준수 브랜치 정리, 일반 태그, 기존 훅 연동과 복구를 격리 저장소에서 확인한다.
