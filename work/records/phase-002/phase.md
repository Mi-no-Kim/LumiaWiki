# Phase 002 — 캐릭터·특성·기타 대상의 기준 정보와 개별 페이지

<a id="summary"></a>
## 현재 요약

- 제목: 캐릭터·특성·기타 대상의 기준 정보와 개별 페이지
- 구상상 구분: P2
- 상태: 예정
- 현재 진행 위치: 제품 요구와 단계 계획의 역할에 맞춰 범위·참조를 정리했다. 기능 구현에는 착수하지 않았다.
- 다음 판단/행동: 대상·정보·과거 제공 범위의 제품 요구를 합의하고, 이번 단계의 등록 범위·기준 버전과 준비 조건을 정한다.

<a id="goal"></a>
## 목표와 범위 및 수용 조건

아래는 해당 단계의 범위와 검토용 수용 조건이다. 합의된 제품 요구를 기준으로 진입 또는 관련 Issue 착수 전에 세부 수용 기준을 확정한다.

**공동 목표/기대 결과**

아이템 외에 다루기로 정한 대상의 정보를 등록하고, 각 대상의 정보를 조회할 수 있게 한다.

**포함 범위**

- 캐릭터 관련 정보를 등록한다.
- 특성과 그 밖에 포함하기로 확정한 대상의 정보를 등록한다.
- 해당 대상의 개별 페이지를 만든다.
- 아이템 등 기존 자료와 필요한 참조 관계를 연결한다.

**완료 조건 — 검토 기준**

- 확정한 대상 목록과 정보 범위가 등록돼 있다.
- 개별 페이지에서 등록 내용을 확인할 수 있다.
- 함께 사용하는 자료의 기준 버전과 참조 관계가 일치한다.
- 남은 대상·정보 항목이 누락인지 후속 범위인지 구별돼 있다.

**기준 원천**

[프로젝트 범위](<../../../docs/프로젝트 목표와 범위.md#scope>) · [자료 준비와 변경 관리](<../../../docs/details/product/게임 데이터 변경 관리.md#initial-data>)

<a id="stage-boundary"></a>
## 단계 경계

공개 대상 화면의 완성은 [P5](<../phase-005/phase.md#goal>)에 둔다. 아이템 외 대상의 과거 기간은 이번 계획 등록으로 확정하지 않는다.

<a id="plan"></a>
## 계획과 주요 의존

계획상 [Phase 001](<../phase-001/phase.md#goal>)의 기준 정보/참조 구조를 이어 사용한다. 실제 착수에 필요한 자료·조건은 진입 시 확인한다.

실제 착수 전에는 아래 미정과 [필요한 착수 정보](<../../../docs/작업 기록 작성 기준.md#minimum>)를 확인한다.

<a id="entry-decisions"></a>
### Phase 진입 또는 Issue에서 정할 사항

**제품 요구로 합의·반영할 사항**

- 기타 대상의 구체 목록, 대상별 정보 항목·개별 페이지의 표시 범위, 이후 패치에서 갱신할 대상과 과거 정보 제공 범위. 결정은 [프로젝트 범위](<../../../docs/프로젝트 목표와 범위.md#scope>)와 [자료 요구](<../../../docs/details/product/게임 데이터 변경 관리.md#initial-data>)에 반영한다.

**이 단계의 준비·구현 선택**

- 합의된 요구 안에서 이번에 등록할 자료·기준 버전과 참조 관계의 구현.
- P3 계산에 필요한 자료와 추가 확보할 게임 규칙, 등록·조회·버전 일치의 확인 방법.

<a id="planned-checks"></a>
### 예정 확인

선정한 대상의 등록·조회와 참조/버전 일치를 확인할 범위와 방법을 진입 시 정한다.

실제 검증 결과는 수행한 때 기록한다. 현재는 계획만 등록한 상태다.

<a id="activity"></a>
## 주요 논의와 판정 근거

아래는 계획 등록 당시 근거다. 이후 계획 변경과 실제 수행은 후속 기록으로 구별한다.

<a id="registration"></a>
### 2026-10-30 검수한 구상 수정안의 정식 계획 등록

사용자의 이관 지시에 따라 검수한 수정안의 목표·범위·검토용 완료 조건·진입/Issue 결정 사항을 이 문서에 등록했다. 미정·후속·제안은 유지했으며 등록을 Phase 착수·완료로 판정하지 않았다. 공통 도입 순서와 반영 이유는 [제품 범위 이력](<../../../docs/history/제품 범위.md#seven-phase-formalization>)에서 확인한다.

<a id="role-separation"></a>
### 2026-11-05 제품 요구와 단계 계획의 역할 정리

사용자의 전체 반영 지시에 따라 단계 경계와 제품 요구·다른 단계의 참조를 정리했다. 포함 범위·검토용 수용 조건과 예정 상태를 유지했으며 기능 구현·Phase 완료를 판정하지 않았다.

<a id="result"></a>
## 결과와 미해결

계획 등록을 마쳤으며 Phase 목표의 실행 결과나 완료 판정은 아직 없다. 남은 결정은 [진입/Issue 결정 사항](<#entry-decisions>)에서 관리한다.
